# 决策记录：为什么长这样

> 这里记**取舍**——用户拍板的事、以及实施时自行拍板的小事。它是"这些规则为什么长这样"的最终依据：
> 与"按原版应该……"冲突时以这里为准（`验证约定.md` §9：对用户有决定权的事实不查资料）。
> 代码里凡是写了"用户答复 / 用户要求"的注释，指的都是这张表。
>
> 与别处的分工：
> - `00-架构总览与开发路线.md` §0.2 是**规划期**已确认的技术决策（D1~D15，约束全部文档）；
> - 本文件是**落地期**的取舍（实施中途问的、当场定的）；
> - "现象 → 定论"的历史在 `架构变更记录.md`，本文件只留**结论与理由**，不写排查过程。
> - 某一份设计文档内部的决策（例如编辑器那六条）留在该文档自己的 §0，本文件 §4 只做索引。

| 玉米加农炮的装填数字 | 首发 **5 秒**、之后 **34.75 秒**（原版 wiki 的 reload time），伤害与范围沿用樱桃炸弹那一份（1800 / 3×3），卡的价格 20000 金币 | 原版数字优先于自造；同一次查证里另有 36.41 / 30 秒两种说法，取 wiki.gg 信息框那一个并写进内容 JSON，要调只改 `plants/cob_cannon.json` |
| 吸金磁只捡金币、不捡阳光 | 保持原版的语义（它是磁力菇改吸钱，不是自动阳光机） | 阳光的收集是玩家自己的节奏；自动收阳光已经有 `auto_collect` 增益那条路，两件事不该由一株植物合并 |
| 项目的代码许可证 | **GPL-3.0**（`LICENSE`，官方全文未改一字） | 用户在 MIT / Apache-2.0 / GPL-3.0 / 自定义非商业 里选了 GPL-3.0；loader 模块是 Apache-2.0 的 Fabric Loader fork，而 Apache-2.0 **单向**可并入 GPLv3（[ASF 官方说明](https://www.apache.org/licenses/GPL-compatibility.html)），所以方向成立 |
| 素材的排除范围 | **只排除「从 `refer/` 转换或搬运的原版素材」**（1719 个 / 65 MB），二次创作与原创都留在仓库 | 用户拍板。边界与理由写在 `THIRD-PARTY.md` §4，逐条判决在 `素材对照表.md` |
| 角色立绘的归属口径 | 归**原创**，不是"二次创作" | 所有者 2026-09 指出：立绘只参考了豌豆/蘑菇这类**通用**形象，没有用原版素材、也没照原版的具体造型（发型/服装/配色/性格都是自己的）。分界口径因此定为"**有没有照原版的具体造型**"，不是"题材像不像"——我原先按目录名推断成"原版角色的拟人化"，判错了一次 |
| zombotany 的 4 个动画 | 与 `PvZ` 同类，一并排除 | 它是 `make_zombotany_assets.py` 用**原版零件**拼合的：动画逻辑算创作，零件不是。用户选"一并排除" |
| 原版素材的留存方式 | 移到仓库根的 `local-assets/`（`.gitignore` 排除）+ `pvzce-game/build.gradle` 里一个构建期钩子（把该目录接回 `test`/`run` 的 classpath） | 用户要求"不 push 但留存在本地"。比删除安全（可 `--rm` 搬回），比外置仓库可行（沙箱不允许写仓库外），比"留在原地只 ignore"清晰（工作区里看得出它被隔离了） |
| git 历史**不**重写 | 先备份（`.backup/pvzce-full-*.bundle`），是否 `git filter-repo` 以后再说 | 用户选"不洗，但先备份"。代价是历史里仍能取出原版素材、`.git` 仍在 283 MB；首次 push 之前是唯一的干净窗口期，已记进 `todo.md` |
| GPL 版权行写在哪 | 写进根 `README.md` 的"许可"一节，**不**写进 `LICENSE` 文件 | `LICENSE` 是 FSF 的许可原文，一个字节都不该改；末节 "How to Apply These Terms" 是给人抄的模板，填进正文会让许可文件的版本不可辨认。代码侧的单一出处是 `PvzceLicense.COPYRIGHT` |
| 法律声明放哪里 | **启动日志一行 + 设置里的"关于"页全文** | 用户选的形式。启动日志刻意只给一行：每次启动刷十几行法律文本会被当噪声跳过，比不写更糟；GPL-3.0 §5(d) 对界面作品给的就是 about box |
| git 历史重写范围 | 按**路径整棵清除** `assets/pvzce/animations/`、`sounds/`、`font/ui.png`，不留任何历史版本 | HEAD 里 `assets/pvzce/` 留下的都是自产与二次创作素材（更早的提交里也一直存在），所以整棵清除不会误删现在还要的文件；`assets/java/icon.png` 不在此列——`ModInfo` 认 id 为 `java` 的内置 mod |
| 第一株原创植物的美术来源 | **文生图源图 + 一份可复跑的生成脚本**（`tools/art/iceboom_*.png` → `tools/gen_iceboom_shroom.py` → 部件贴图 / 动画 JSON / 卡面 / 冰弹），源图随 GPL-3.0 入库、归**原创** | 用户答"我给你 AI 生图工具"。走脚本而不是手工改图，是因为抠底、分层、降采样、写关键帧这四步每一步都会再跑一次；源图留仓库则让"这株是我们自己产的"可复查（`classify_assets.py` 里三条规则指回它们）。判据沿用所有者口径：**有没有照原版的具体造型**——"冰蓝色蘑菇"是通用形象 |
| 冰爆菇的机制 | **冰层累积（3 发）→ 冻结 3.25 秒 → 那一发碎冰 ×3**，另立伤害类型 `pvzce:shatter` | 用户在三案里选了它。原版没有这套机制，所以它是**本项目自己的设计**，不是复刻；数值没有参照物这一条已写进 `todo.md` |
| 仓库 README 的项目自我定位 | **"独立桌面塔防引擎 + PvZ 风格示例"**，不写成"桌面重制版" | 调研指出 EA 2024 年那封信的红线是 `the explicit use of our IP to create new or alternate versions of our games`；自我定位直接影响暴露面，不只是措辞 |
