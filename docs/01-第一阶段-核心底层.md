# 第一阶段：核心底层（最小可玩 demo）

> 目标：完成**模组加载器移植、双注册表（静态/动态）、Mini 渲染系统、资源/数据包加载、60tps 服务端、实体与关卡/Team 最小集、MC 风格内存连接网络骨架、NBT 存档初步引入**，最终交付一个可运行的最小可玩 demo。Cloth 配置按已确认决策整体后置到第二阶段。

## 1.3 步骤 A：模组加载器移植（fork fabric-loader）

### 1.3.1 裁剪与保留清单

先阅读 [refer/fabric-loader/README.md](../refer/fabric-loader/README.md) 了解模块构成，再对照下表裁剪：

| fabric-loader 部件 | 处置 | 依据 |
|---|---|---|
| `src/main/java/net/fabricmc/loader/impl/discovery/` | **保留** | 模组发现：`ModDiscoverer.java`、`ClasspathModCandidateFinder.java`（jar/目录候选）、`DirectoryModCandidateFinder.java`（`mods/` 目录）、`ModResolver.java`/`ModSolver.java`（依赖解析） |
| `impl/metadata/` | **保留** | `V1ModMetadataParser.java` 解析 `fabric.mod.json`；`EntrypointMetadata.java`；`MetadataVerifier.java` |
| `impl/entrypoint/` | **保留** | `EntrypointUtils.java`（main/client/server/preLaunch 分环境调用） |
| `impl/launch/knot/` | **保留并改造** | `Knot.java`（入口）、`KnotClient.java`、`KnotServer.java`、`KnotClassLoader.java` + `KnotClassDelegate.java`（类加载委托——启动即入口） |
| `impl/game/GameProvider.java` | **保留接口，新增实现** `PvzceGameProvider` | 见 1.3.2 |
| `impl/game/patch/`、`transformer/` | **裁剪**（可留空壳） | 这是给 MC 类打的补丁（mixins/访问宽限）；PVZCE 本体无混淆、mod 的 mixin 支持后置（见 1.3.6） |
| `minecraft/`（含 MinecraftGameProvider、映射处理、`minecraft/` 模块） | **整体不复制** | 专属 MC；`impl/util/mappings` 与 LoaderUtil 的 MC 特化路径不进入 PVZCE 分支 |
| `impl/mrj/` | 裁剪（或保留空实现） | Java 模块化处理，LWJGL 环境不需要 |
| `impl/gui/` | **保留** | 类加载失败时的图形化错误窗口（PVZCE 直接复用） |
| `impl/lib/gson` | 保留 | 内置 Gson（loader 自带，保证元数据解析无外部依赖） |
| `impl/util/log/` | 保留 | 日志桥（SLF4J） |

**fork 后存放**：`pvzce-loader/src/main/java/...`，沿用原包名 `net.fabricmc.*`（决策 D2）。

### 1.3.2 新增 `PvzceGameProvider`

Loader 通过 `ServiceLoader<GameProvider>` 发现游戏提供者（见 [refer/fabric-loader/src/main/java/net/fabricmc/loader/impl/game/GameProvider.java](../refer/fabric-loader/src/main/java/net/fabricmc/loader/impl/game/GameProvider.java)）。实现一个 PVZCE 版：

```java
package com.pvzce.launcher;

/** 实现 net.fabricmc.loader.impl.game.GameProvider，并在 META-INF/services 注册 */
public final class PvzceGameProvider implements GameProvider {
    @Override public String getGameId() { return "pvzce"; }
    @Override public String getGameName() { return "PVZ Community Edition"; }
    @Override public String getRawGameVersion() { return PvzceVersions.GAME_VERSION; } // 1.0-SNAPSHOT
    @Override public String getNormalizedGameVersion() { return PvzceVersions.GAME_VERSION; }
    @Override public Collection<BuiltinMod> getBuiltinMods() {
        // 把游戏本体注册为"内置模组 pvzce"，使 addon 可用 dependsOn: pvzce
        return List.of(new BuiltinMod(Paths.get("pvzce.jar"), "pvzce"));
    }
    @Override public String getEntrypoint() { return "net.fabricmc.loader.impl.launch.knot.KnotClient"; }
    @Override public Path getLaunchDirectory() { return Paths.get(".").toAbsolutePath(); }
    @Override public boolean requiresUrlClassLoader() { return true; }
    @Override public Set<BuiltinTransform> getBuiltinTransforms(String className) { return Set.of(); }
}
```

改造点（与原 `KnotClient.main` 的差异，参考 [KnotClient.java](../refer/fabric-loader/src/main/java/net/fabricmc/loader/impl/launch/knot/KnotClient.java)）：

```
KnotClient.main(args)                     [冻结原样]
  └─ Knot.start(...)                      [冻结]
       └─ findGameProvider()   → ServiceLoader 找到 PvzceGameProvider（MC 版即 MinecraftGameProvider）
       └─ FabricLoaderImpl.load()         [冻结]（自动发现 mods/，解析依赖，注册 metadata）
  └─ 调用 entrypoint: preLaunch → main → client（PVZCE 映射见 1.3.3）
```

> `Knot`/`KnotClassLoader` 只依赖 `GameProvider` 的抽象（getGameId/getEntrypoint/...），因此**无需修改 Knot 本体**即可接入 PVZCE——这是裁剪成本最低的路径。

### 1.3.3 入口点（Entrypoint）语义映射

PVZCE 沿用 fabric 标准入口点名（[impl/entrypoint](../refer/fabric-loader/src/main/java/net/fabricmc/loader/impl/entrypoint/)），语义对齐 MC 但有 PVZCE 特有补充：

| 入口点 | 调用时机（PVZCE） | 典型用途 |
|---|---|---|
| `preLaunch` | 加载器启动最早期，窗口创建前 | 设置系统属性、注册日志分流 |
| `main` | 服务端与客户端**共同**初始化（仿 MC `main`） | **静态注册表注册**（植物/僵尸/子弹/工具/资源/场景元素/规则）——对应 Fabric 的 `onInitialize` |
| `client` | 仅客户端（渲染初始化前） | 注册动画后端、纹理路径、键位、HUD 扩展 |
| `server` | 仅服务端（集成服务器同样会执行） | 服务器专属逻辑（波次引擎、AI 钩子） |

自定义扩展（PVZCE 特有，新增 `pvzce.modmenu`、`pvzce.config`、`pvzce.content` 等入口名，通过 `EntrypointUtils` 的注册机制扩展，参考 [V1ModMetadataParser.java](../refer/fabric-loader/src/main/java/net/fabricmc/loader/impl/metadata/V1ModMetadataParser.java) 中 `entrypoints` map 的解析）：

```jsonc
// mods/example/fabric.mod.json
{
  "schemaVersion": 1,
  "id": "example",
  "version": "1.0.0",
  "environment": "*",
  "entrypoints": {
    "main":   ["com.example.PvzceInit"],        // 注册游戏内容
    "client": ["com.example.ClientInit"],       // 客户端扩展
    "server": ["com.example.ServerInit"],       // 服务器扩展
    "pvzce.modmenu": ["com.example.ModMenuEntry"] // mod 菜单贡献（参考 ModMenuApi）
  },
  "depends": { "pvzce": "*" },
  "custom": { "pvzce": { "modmenu": { "badges": ["library"] } } }
}
```

### 1.3.5 Mod 发现目录（与 MC 一致）

```
游戏根目录/
├─ pvzce-1.0.jar            # 本体（含 loader + 自研 com.pvzce.api）
├─ mods/                    # 模组 jar（自动发现，参考 ClasspathModCandidateFinder）
├─ resourcepacks/           # 资源包（参照 MC 优先级，见 1.6）
```

### 1.3.6 本阶段不做的 loader 能力（后置）

| 能力 | 阶段 | 说明 |
|---|---|---|
| Mixin（`fabric-mixin`、`MixinServiceKnot`） | 后置（第三阶段或之后） | 本体无需 mixin；若为 mod 支持 mixin，需引入 mixin 库并保留 Knot 的 mixin 钩子 |
| 访问宽限（access widener）/ 深度补丁 | 后置 | 同上，依赖 transformer 机制 |
| 多游戏版本支持（旧版映射/remap） | 永不 | PVZCE 不混淆、不 remap |
| Mod 解析的"运行环境区分" | 保留 | `ModEnvironment`（client/server/*）机制原样可用 |

## 1.4 步骤 B：标识符与基础类型

### 1.4.1 Identifier

自研实现（API 对齐 [identifier](../refer/decompiled-26.1.2-client/net/minecraft/resources/Identifier.java)，实现自研）：

```java
package com.pvzce.api.util;

public record Identifier(String namespace, String path) {
    public static Identifier parse(String s) {
        // "ns:path"（defaultNamespace 为 "pvzce"，无冒号时补 pvzce，与 MC 行为一致）
    }
    public static boolean isValidPath(String path)  { /* 同 MC 规则：[a-z0-9_.-]+，允许 / */ }
    public static boolean isValidNamespace(String ns){ /* [a-z0-9_.-]+，无 / */ }
    public String toPath() { return namespace + "/" + path; }   // 资源定位用
    @Override public String toString() { return namespace + ":" + path; }
}
```

规则与 MC 完全一致（文件路径用小写 `_` 分隔；`pvzce` 为游戏保留命名空间）。Gson/Codec 适配器：`Identifier.CODEC`（DFU BoundCodec），参考 MC 的同名实现。

## 1.5 步骤 C：注册表系统（本阶段最核心交付物）

### 1.5.1 设计目标

与 MC 同构的三段式：

```
静态（代码）注册：可在代码中直接 register（mod 的 main entrypoint 内）
动态（数据）注册：服务端启动/重载时从数据包 JSON 加载，可 freeze、可同步（后期）、可热重载
查询统一：Registry<T>（接口）同时服务两种来源；数据驱动内容可被 mod 代码引用（Holder/Factory）
```

### 1.5.2 核心类型（自研实现，API 对齐）

| PVZCE 类 | 参考 MC 文件 | 职责 |
|---|---|---|
| `com.pvzce.api.registry.Registry<T>` | [core/Registry.java](../refer/decompiled-26.1.2-client/net/minecraft/core/Registry.java) | `get/key/getId/getValue/register/freeze/iterator` |
| `MappedRegistry<T>` | [core/MappedRegistry.java](../refer/decompiled-26.1.2-client/net/minecraft/core/MappedRegistry.java) | 双向表（id↔value + id 索引；静态条目跨 reload 保留、动态条目可清理重建） |
| `DefaultedRegistry<T>` / `Holder<T>` | [core/DefaultedRegistry.java](../refer/decompiled-26.1.2-client/net/minecraft/core/DefaultedRegistry.java) | 第一阶段不实现，第二阶段随 tags/HolderSet 补齐 |
| `ResourceKey<T>` | [resources/ResourceKey.java](../refer/decompiled-26.1.2-client/net/minecraft/resources/ResourceKey.java) | `ResourceKey.create(registryKey, id)` |
| `RegistryAccess` / `RegistryKey` | [core/RegistryAccess.java](../refer/decompiled-26.1.2-client/net/minecraft/core/RegistryAccess.java) | 注册表集合的持有与分层（静态层/动态层） |
| `Holder<T>` | [core/Holder.java](../refer/decompiled-26.1.2-client/net/minecraft/core/Holder.java) | 引用封装（直接值或 Key 引用） |
| `IdMap`/`IdMapper` | [core/IdMap.java](../refer/decompiled-26.1.2-client/net/minecraft/core/IdMap.java) | int 索引接口 |

接口最小面（对齐 MC 签名，自研实现）：

```java
public interface Registry<T> extends IdMap<T>, Iterable<T> {
    ResourceKey<? extends Registry<T>> key();
    @Nullable T get(@Nullable Identifier key);
    @Nullable T getById(int rawId);
    @Nullable Identifier getKey(T value);
    int getId(@Nullable T value);
    boolean containsKey(Identifier key);
    Registry<T> freeze();                         // 冻结后不允许 register/remove
    void unfreeze();                              // 重载前解冻
    int size();
    @Override Iterator<T> iterator();

    // 静态注册入口（别名与 MC 一致）
    static <V, T extends V> T register(Registry<V> reg, Identifier id, T value);
    static <V, T extends V> T register(Registry<V> reg, String id, T value);      // 自动加默认命名空间
}
```

### 1.5.3 PVZCE 注册表清单（静态 + 动态）

以 `ResourceKey<PvzceRegistry>` 枚举形式组织（参考 [core/registries/Registries.java](../refer/decompiled-26.1.2-client/net/minecraft/core/registries/Registries.java)）：

```java
public final class PvzceRegistries {

    public static final ResourceKey<Registry<Plant>>            PLANTS            = key("pvzce", "plant");
    public static final ResourceKey<Registry<Zombie>>           ZOMBIES           = key("pvzce", "zombie");
    public static final ResourceKey<Registry<Projectile>>       PROJECTILES       = key("pvzce", "projectile");
    public static final ResourceKey<Registry<ResourceDef>>      RESOURCES         = key("pvzce", "resource");   // 阳光/红石/能量豆
    public static final ResourceKey<Registry<SlotDef>>          SLOT_TYPES        = key("pvzce", "slot");        // 资源卡/植物卡/工具卡
    public static final ResourceKey<Registry<ToolDef>>          TOOLS             = key("pvzce", "tool");
    public static final ResourceKey<Registry<SceneElement>>     SCENE_ELEMENTS    = key("pvzce", "scene_element");
    public static final ResourceKey<Registry<GameRuleType>>     GAME_RULES        = key("pvzce", "game_rule");
    public static final ResourceKey<Registry<EnvVarType>>       ENV_VAR_TYPES     = key("pvzce", "env_var_type");
    public static final ResourceKey<Registry<AnimationState>>   ANIMATIONS        = key("pvzce", "animation");
    public static final ResourceKey<Registry<SoundEvent>>       SOUND_EVENTS      = key("pvzce", "sound_event");
    // —— 关卡（动态注册表为主）——
    public static final ResourceKey<Registry<LevelDef>>         LEVELS            = key("pvzce", "level");

```

> 注：`ANIMATIONS` 动画状态注册表已在后续实现中删除；当前动画资源走 `assets/<ns>/animations/*.json`，见 [mod-guide/animation.md](mod-guide/animation.md)。

静态/动态归属表（**关卡主要由动态注册表负责**）：

| 注册表 | 静态(代码) | 动态(数据包) | 说明 |
|---|---|---|---|
| plant / zombie / projectile | ✅ 骨架内容 | ✅ 具体数值内容 | 两种都可；数据包 JSON 定义见 1.5.4 |
| resource / slot / tool / scene_element / game_rule / env_var_type / animation / sound_event | ✅ 类型注册 | ✅ 常驻定义 | 类型骨架（类+Codec）由代码提供，实例存动态表 |
| **level** | ❌（仅内置 dev 关卡） | ✅ **主通道** | 关卡文件、波次、规则覆盖、环境变量注入 |

### 1.5.4 动态注册：数据包加载（仿 RegistryDataLoader）

核心参考 [resources/RegistryDataLoader.java](../refer/decompiled-26.1.2-client/net/minecraft/resources/RegistryDataLoader.java) 与 [RegistryFileCodec.java](../refer/decompiled-26.1.2-client/net/minecraft/resources/RegistryFileCodec.java)、[FileToIdConverter.java](../refer/decompiled-26.1.2-client/net/minecraft/resources/FileToIdConverter.java)：

- 数据目录约定：`data/<namespace>/<registry_path>/<id>.json`
- 例如：
  - `data/pvzce/levels/yard/adventure/demo_level.json`
  - `data/example/pvzce/plants/peashooter.json`

```java
        new RegistryData<>(PvzceRegistries.PROJECTILES,Projectile.CODEC,    id("pvzce/projectiles"), true),
        // ... resources/slots/tools/scene_elements/game_rules/env_var_types/animations/sound_events
    );

    public static CompletableFuture<RegistryAccess.Frozen> load(ResourceManager rm, RegistryAccess base) {
        // 1. 为每个 RegistryData 打开目录，扫描 <path>.json
        // 2. RegistryOps<JsonElement> 解码 → 注册到 (可解冻的) MappedRegistry
        // 3. 全部完成后 freeze；isSynchronized 标记将用于客户端同步（第一阶段仅归档）
```

### 1.5.5 注册生命周期


### 1.8.2 60tps 的实现

MC 用 `TickRateManager` 持有 `nanosecondsPerTick`（默认 50ms→20tps）。PVZCE：

```java
public final class PvzceTickRateManager {
    // 1_000_000_000 / 60 = 16_666_666.67 ns —— 用长整微调：每隔 3 tick 补偿 1ns 以消除误差
    public static final long NANOS_PER_TICK = 16_666_666L;   // ≈60.0000Hz（0.0024‰ 误差）
    private long accumulator;   // 纳秒累加器（参考 MC 的 tickRateManager 主循环写法）
    private long tickCount;     // 当前关卡 tick 数（可悬浮）

    public boolean advance(long frameNanos) {
        accumulator += frameNanos;
        if (accumulator >= NANOS_PER_TICK) { accumulator -= NANOS_PER_TICK; return true; }
        return false;
    }
}
```

主循环（`PvzceServer.runServer`，参考 [MinecraftServer.java 的 runServer/tick 段](../refer/decompiled-26.1.2-client/net/minecraft/server/MinecraftServer.java)）：

```java
while (running) {
    long now = System.nanoTime();
    long elapsed = now - lastTickTime; lastTickTime = now;

    // 60tps 自适应：单帧处理 1~N 个 tick（卡顿时补偿，受 maxTicksPerFrame 上限约束）
    int ticks = 0;
    while (tickRate.advance(elapsed) && ticks++ < MAX_TICKS_PER_FRAME) {
        tick();
    }
    if (ticks == MAX_TICKS_PER_FRAME) { tickRate.reset(); /* 追不上则丢弃时间，防止死亡螺旋 */ }
    sleepUntilNextTick();   // 用 LockSupport.parkNanos(剩余时间)，空闲时省 CPU
}
```

> **与 MC 的差异说明**：MC 是 20tps 固定 50ms 循环；PVZCE 60tps 是 16.6667ms。渲染帧率与 tick 解耦：客户端渲染 60~240fps 自由，逻辑 tick 恒 60Hz（冲刺/冻结规则与 MC 的 sprint/freeze 机制对齐，后续阶段实现）。

### 1.8.3 tick 顺序（LevelServer.tick）

```
1. 时间推进（昼夜计数，GameRule: day_length=0 恒白昼）
2. 环境变量结算（本阶段为空）
3. 游戏规则副作用（阳光生成：每 tick 概率 p=0.001 → 生成天空阳光实体；参考"阳光生成概率"规则）
4. TEAMS→实体：植物 tick（攻击检查/产资源/冷却）
5. 僵尸 tick（移动/啃咬/挖掘）
6. 子弹 tick（位移/命中检测）
7. 特效/墓碑/弹坑恢复计时（弹坑恢复 = 6000 tick，规则可配）
8. 胜负判定（僵尸到达最左 / 波次全清）
9. 实体清理（死亡回收、离屏移除）
```

实体集合用 `EntityTickList`（参考 [world/level/entity/EntityTickList.java](../refer/decompiled-26.1.2-client/net/minecraft/world/level/entity/EntityTickList.java)）延迟增删防并发修改。

### 1.8.4 时间与昼夜（最小实现）

`PvzceClock`：`dayTicks`（当前关卡计时），`isNight`。规则（对齐用户设计）：

| 规则 | 默认 | 说明 |
|---|---|---|
| `pvzce:day_length` | 0 | 白昼 tick 数；**0 = 恒为白昼** |
| `pvzce:night_length` | -1 | 夜晚 tick 数；**-1 = 不启用夜晚** |
| `pvzce:sun_spawn_chance` | 0.001 | 每 tick 生成天空阳光的概率 |

实现：`if (dayLength > 0 && tick % (dayLength+nightLength) >= dayLength && nightLength > 0) → night`；冲突时以白昼设置为准（文档规约：当 night_length=0 且 day_length>0 时视为白昼）。

### 1.9.3 植物基础逻辑（对齐用户设计）

```java
public abstract class PlantEntity extends PvzceEntity {
    protected final Plant def;             // 注册表定义（数值/能力）
    protected int age;                     // 出生以来 tick
    protected int attackCooldown;          // 攻击冷却
    protected int health = def.health();

    @Override public void tick() {
        super.tick();
        age++;
        if (canProduce()) maybeProduce();          // 生产者
        if (this instanceof AttackingPlant ap) {
            if (--attackCooldown <= 0) {
                if (ap.checkCanAttack(context)) {  // 范围/层/目标检查
                    ap.attack(AttackReason.NORMAL);
                    attackCooldown = def.attackIntervalTicks();
                }
            }
        }
    }
    // 播放动画（服务端仲裁 → 客户端事件）
    protected void setAnimation(AnimationState state) { registry.get().broadcastState(entityId, state); }
}

public interface ShooterTypePlant  { Projectile spawnProjectile(ProjectileRef ref, Direction dir); } // 一次函数：直线
public interface ThrowerTypePlant  { Projectile spawnProjectile(ProjectileRef ref, Direction dir); } // 二次函数：初速+重力
```

```java
    protected MovementKind kind;      // WALK / EAT / UNDERGROUND / FLY / CLIMB（第一阶段仅 WALK/EAT）
    public void tick() {
        // 1. 找本层所在单元格上的可啃咬植物（叠放最上层、类型匹配）
        // 2. EAT：每 60 tick 咬一次，伤害 = def.biteDamage()（基准 100/s → 每 60tick 100）
```

## 1.12 步骤 J：网络最小骨架（联机"能连"基础）

### 1.12.1 原则

网络层不做深（决策 D7），但**所有跨线程/跨端互动一律走包**：

```
com.pvzce.common.network
├─ PacketRegistry           # Class → packet id + id → decoder（单 JVM 双侧共用）
├─ PvzcePacket              # 接口：direction + encode（数据流：VarInt + String + Int/Float——对齐 MC packet 序列化风格）
├─ PacketByteBuf            # Netty ByteBuf 包装：VarInt/String/Identifier 读写
├─ Connection              # 仿 MC 26.1.2 Connection/PacketListener 分层
├─ MemoryPacketTransport   # 第一阶段：同进程全双工内存管道（编码后字节包交换）
└─ 包定义（第一阶段清单）
    C2S: PickCard / PlacePlant / CollectResource / Command / RequestLevel
    S2C: LevelInit / EntitySpawn / EntityUpdate(位置+动画) / EntityDespawn /
         ResourceDelta / GameState(胜负) / SlotSync(冷却/可用) / ServerMessage
```

包编解码参考 [network/protocol/common/ServerboundCustomPayloadPacket.java](../refer/decompiled-26.1.2-client/net/minecraft/network/protocol/common/ServerboundCustomPayloadPacket.java) 与 fabric 的 `payload/` 组织方式（[fabric-networking-api-v1/impl/networking/payload](../refer/fabric-api/fabric-networking-api-v1/src/main/java/net/fabricmc/fabric/impl/networking/payload/)）。API 侧暴露（对齐 fabric 风格）：

```java
// com.pvzce.api.network（自研 API 面，位于 pvzce-game 模块）
PvzceNetworking.setReceiver(serverConnection, packet -> { /* 处理 C2S */ });
PvzceNetworking.send(clientConnection, new PlantActionPacket(...));
```

### 1.12.2 集成服务器启动顺序

```
Launcher.main
  → Knot.start（loader 就绪）
  → PvzceGame：创建 Connection 内存连接对（Connection.createMemoryPair()）
  → new PvzceServer(connection)  （服务线程：load registry → load levels → start loop）
  → new PvzceClient(connection)  （主线程：窗口 + 渲染 + 输入 → C2S）
  → 服务端按需推送 LevelInit；客户端进入关卡画面
```

专用服务器（dedicated）与局域网联机（第二阶段末/第三阶段）：把 `MemoryPacketTransport` 换成 TCP 传输实现即复用全部逻辑——这就是第一阶段用"包分离"架构的意义。

## 1.15 第一阶段风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 60tps 下实体数量大（数十植物×数百僵尸×子弹）导致服务器 tick 超时 | 卡顿 | 第一阶段先正确后优化：实体 tick 分帧（每次 tick 只 tick 1/2 分片）、子弹用网格邻居查询（第一阶段直接 O(行内实体) 也可）；性能属第四阶段 |
| 中文文本无法渲染（缺字体） | demo UI 显示方块 | 内置最小 TTF（思源黑体 3000 常用字切片）+ 运行时图集；资源包可覆盖 |
| Core Profile 下 VAO 绑定错误（macOS） | 黑屏/崩溃 | 严格 VAO 生命周期管理；错误用 `glGetError` 轮询并输出（参考 MC GpuWarnlistManager 思路） |
| Loader fork 的类加载与 lwjgl native 冲突 | 启动失败 | `KnotClassLoader` 的 **URL 列表**必须包含 pvzce 本体 jar（build 时写入 manifest 的 `Class-Path` 或 loader 的 systemProps，参考 [SystemProperties.java](../refer/fabric-loader/src/main/java/net/fabricmc/loader/impl/util/SystemProperties.java)） |
| datafixerupper 版本漂移 | Codec 编译错误 | 锁定唯一版本（gradle.properties），与 MC 同版本号选近 |
