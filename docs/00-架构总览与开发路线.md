## 0.1 项目定位

PVZCE 是一个**独立运行的桌面游戏**（不是 Minecraft 模组），同时具备与 Minecraft 相似的三层扩展能力：

| 扩展形态 | 与 MC 的对应 | 说明 |
|---|---|---|
| **模组（Mod）** | Fabric 模组 | 含代码的游戏扩展，通过自研（fork 自 Fabric Loader 的）模组加载器加载 |
| **资源包（Resource Pack）** | MC 资源包 | 覆盖纹理、音效、语言、动画等表现资源，`assets/<ns>/...` 目录约定 |
| **数据包（Data Pack）** | MC 数据包 | 数据驱动注册内容（植物、僵尸、子弹、卡槽、关卡、游戏规则……），`data/<ns>/...` 目录约定 |

核心设计原则：**标识符、资源路径、JSON 数据格式、注册表机制、客户端/服务端分离、tick 循环等一切机制"尽量与 MC 相同"**；渲染底层为 LWJGL，抽象层对齐 `com.mojang.blaze3d` 与 `net.minecraft.client.renderer` 的结构。

### 与常规 MC 模组开发的关键差异

- 游戏本体与加载器**打包为同一个可执行 jar**（shadow/fat jar）。
- 游戏时钟为 **60 tick/s**（MC 为 20），全部逻辑时序按 60tps 设计。
- 每个关卡内存在**多 Team、多玩家**（PlantTeam / ZombieTeam），Team 共享资源、独立显示、独立掉落。
- 关卡内实体为**网格制**（默认 5×9），不是 MC 的自由三维世界；叠加（场景元素/植物）规则自成一系。

## 0.2 已确认的技术决策（问答结论汇总）

以下决策已在规划阶段与项目所有者确认，是全部文档的约束条件：

| # | 决策项 | 结论 |
|---|---|---|
| D1 | 模组加载器 | **不另写**。直接 fork 整个 [Fabric Loader](../refer/fabric-loader/) 源码，裁剪 Minecraft 专属部分后改造，**以 shadow 方式打包进游戏本体** |
| D2 | 包名 | **不重定位**，保留 `net.fabricmc.*` 原包名（游戏自包含、无环境冲突） |
| D3 | 游戏内置 API | **自研 `com.pvzce.api`**（仅参考 Fabric API 的事件/生命周期/网络设计，不复制源码、不提供 `net.fabricmc.fabric.*`） |
| D4 | Cloth Config / ModMenu / GeckoLib | 第二阶段按用户修订：**不保留原包名**，在 `com.pvzce.*` 自研必要子集（GeckoLib 后置） |
| D5 | mod 开发环境 | **无需 remap/混淆**：第三方 mod = 普通 Gradle 工程 + 依赖 `pvzce-game`（API 面）与 `pvzce-loader` 两个 jar，无需 Loom |
| D6 | 画面形态 | **3D 渲染引擎 + 锁定侧视相机**（PvZ2 风格）；第二阶段实际交付 sprite 后端，Spine/GeckoLib/方块后端接口预留 |
| D7 | 网络架构 | 参考 MC 的**服务器/客户端分离**：单机 = 集成服务器（同进程双线程）；多客户端联机第一阶段仅要求"能连"，网络协议骨架在第一阶段建好，细节后续阶段打磨 |
| D8 | 存档 | **NBT**，对齐 MC（`level.dat` 风格 + `data/` 目录分类），NBT 结构自研、API 对齐 [net/minecraft/nbt](../refer/decompiled-26.1.2-client/net/minecraft/nbt/) |
| D9 | 数据文件格式 | **与 MC 完全对齐**：`pack.mcmeta`、`assets/<ns>/`、`data/<ns>/`、Identifier（`namespace:path`）、Codec（DFU）驱动的 JSON 注册表、tags |
| D10 | 配置文件 | 第二阶段使用 **Cloth Config API**（fork 版）；第一阶段配置功能整体后置，TOML 库（toml4j）留待第二阶段接入 |
| D11 | 数值基准 | 默认内容数值表取**原版 PvZ1 近似平衡值**，第三阶段做校准（见 03 文档） |
| D12 | Java 版本 | **Java 21**（LTS，与 MC 1.20.5+ 同代）；构建 Gradle 8.x |
| D13 | 第一阶段范围 | 最小可玩 demo（窗口 + 渲染管线 + 双注册表 + 最小关卡 + 1 植物 + 1 僵尸 + 子弹 + 种植消耗 + 胜负） |
| D14 | GUI 框架 | **第二阶段**（仿 MC Screen/Widget）；第一阶段只做最小交互（种子卡槽 + 鼠标拖拽） |
| D15 | 第三阶段重点 | **玩法平衡与新手体验、联机与 AI 打磨**；性能/特效/社区工具链排入第四阶段 |

## 0.3 术语表

| 术语 | 定义 |
|---|---|
| tick | 游戏逻辑最小时间单位；PVZCE 固定 **60 tick/s**，服务端循环执行 |
| 注册表 / Registry | 类型化 ID→对象表；分**静态**（代码注册）与**动态**（数据包注册，关卡主要由动态注册承担） |
| 关卡 / Level | 一局游戏；含场景大小、场景元素、团队、规则、环境变量、出怪配置 |
| Team | 关卡内的阵营（PlantTeam / ZombieTeam / System）；Team 共享资源，非本 Team 不能操作其实体 |
| 玩家 / Player | 真人或 AI；每个至少两人的 Team 若无真人则由 AI 玩家代管 |
| 场景元素 / SceneElement | 占据 1×1 格子的地形类元素（草地/裸地/水池/平直屋顶/倾斜屋顶/墓碑/弹坑…），有叠放规则 |
| 卡槽 / Slot | 资源卡 / 植物卡 / 工具卡三类；是玩家可拖放的操作入口 |
| 资源 / Resource | 阳光、红石、能量豆等；有对应资源卡才可收集 |
| 环境变量 | 关卡作用域的 KV 数据通道，任意组件可读写、关卡 JSON 可注入 |
| 游戏规则 / GameRule | 可注册的关卡级规则（如白昼长度、阳光概率、弹坑恢复时间），关卡可启用/禁用/设值 |
| 实体 / Entity | 植物、僵尸、子弹；均为服务端权威逻辑对象 |
| 动画状态 | 服务端仲裁、客户机播放的具名动画事件（idle/attack/death…） |
| 模组 / Mod | `fabric.mod.json` + 代码 + 附带资源/数据包的 jar；加载器 fork 自 Fabric Loader |
| 资源包/数据包 | 仅含资源与数据的覆盖包，无代码 |
| Identifier | `namespace:path` 标识符，规则与 MC 相同（只允许小写字母、数字、`_`、`-`、`.`、`/`） |

## 0.4 版权与"代码参考"边界（重要）

| 参考源 | 许可 | 处理方式 |
|---|---|---|
| [refer/fabric-loader](../refer/fabric-loader/) | Apache-2.0 | **直接 fork 修改**，保留 License 头 |
| [refer/fabric-api](../refer/fabric-api/) | Apache-2.0 | **仅作设计参考**（事件/生命周期/网络 API 形状），不复制源码 |
| [refer/cloth-config](../refer/cloth-config/) | LGPL-2.1 | 第二阶段 **fork 修改**（适配 PVZCE 的 Screen 体系），保留许可 |
| [refer/ModMenu](../refer/ModMenu/) | MIT | 第二阶段 **fork 修改** |
| [refer/geckolib](../refer/geckolib/) | MIT | 第二阶段 **fork 修改**（适配 PVZCE 渲染 API） |
| [refer/decompiled-26.1.2-client](../refer/decompiled-26.1.2-client/) | Mojang EULA（**不可复制源码**） | **仅作设计参考**：类名、方法签名、机制照抄为"自研实现"，逐文件改写，不复制注释与实现 |

> 因此：`com.mojang.blaze3d` 下的 RenderSystem/BufferBuilder 等**由 PVZCE 重新实现**（接口形态对齐、实现自研，包名用 `com.pvzce.client.renderer`），文档中凡标注"参考"的 MC 类均遵循此边界。fork 的三方库可直接使用其实现。

## 0.5 三阶段路线总表

| 阶段 | 主题 | 核心产出 | 验收 |
|---|---|---|---|
| **一（01 文档）** | 核心底层 | 模组加载器移植、双注册表（静态+动态）、Mini 渲染系统、资源/数据包加载、60tps 服务端、实体/关卡/Team 最小集、网络骨架、NBT 存档（配置/Cloth 本轮后置） | **最小可玩 demo**：窗口 + 渲染 + 1 植物 + 1 僵尸 + 子弹 + 种植 + 胜负 |
| **二（02 文档）** | 广度开发 | 全品类植物/僵尸/子弹、卡槽/资源/工具、场景元素全量、游戏规则、环境变量、动画双后端（flipbook + 自研 2D 控制器）、声音/粒子、AI 玩家、GUI 框架（含 ModMenu/Cloth 界面）、关卡编辑器、存档、命令、mod API 面 | **"能做"：全功能覆盖，体验粗糙但无缺环** |
| **三（03 文档）** | 精修完善 | 玩法平衡校准、新手体验与可访问性、联机打磨（断线重连/观战/回放）、AI 打磨 | **完整可发布版本** |
| 四（03 文档附录） | 远期 | 性能与渲染优化、特效音效美化、社区工具链（mod 市场/文档站/版本兼容）、mixin/访问宽限支持 | —— |
