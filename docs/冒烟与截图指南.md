# 无头冒烟与截图（`pvzce.smoke*`）

> 这篇是 `pvzce.smoke*` / `pvzce.capture*` / 开发用 `-D` 开关的**唯一完整清单**。
> **什么时候才需要跑它**（以及一轮改动验到什么程度）见 `验证约定.md`：默认不跑，界面/渲染改动才拍一次图。
> `当前项目架构.md` §9 的"测试"一节只留摘要并指向这两份文档。
> 相关代码：`client/PvzceClient.java`（全部钩子）、`pvzce-game/build.gradle`（`run` 任务的转发）。
>
> 这一层本身不属于 UI 架构（屏幕栈与关卡入场见 `UI切换与导航架构.md`），
> 但它们是**目前验证界面的唯一手段**：`@PvzceGametest` 与离屏渲染比对都还没建。

---

## 1. 它是什么

界面目前靠**截图人工核对**（`@PvzceGametest` 注册式集成测试与离屏 FBO 图 diff 还没建）。
冒烟钩子的作用是：让一次运行自己走到某个界面、摆出某个场面、然后**在指定帧存一张 PNG 并退出**，
不需要有人在鼠标前操作。

```bash
./gradlew :pvzce-game:run -Ppvzce.smoke="pvzce.smokeEditor=pvzce:yard/adventure/demo_level \
    pvzce.smokeEditorPage=rule pvzce.smokeFrames=150 pvzce.captureFrame=140 \
    pvzce.capturePath=.smoke/editor.png" \
    -Ppvzce.gameDir=$PWD/.smoke/gd
```

## 2. 两个**必须**知道的坑

### 2.1 进了不该进的关卡会**静默失败**（只停在标题页）

`smokeLevel` 走的是正常入场路径，**受关卡解锁门槛约束**：

```bash
# 1-2 需要先通关 1-1。全新世界里它是锁着的，
# 服务端拒绝后只发一条 ServerMessageS2C，而菜单里没有消息显示通道。
-Ppvzce.smoke="pvzce.smokeLevel=pvzce:yard/adventure/1_2 pvzce.smokeFrames=200"
# → [SMOKE] frame 200 rendered, screen=TitleScreen     ← 看起来像钩子没生效
```

**症状**：帧数跑完了，但 `screen=` 不是 `InGameScreen`，磁盘上也没有
`<gameDir>/saves/<world>/session.lock`（世界目录本身就没被建出来）。

**判据**：只要日志里没有 `PVZCE/Server - Saved ` 且 `<gameDir>/saves/<world>/session.lock` 不存在，
就说明 `createLevel` 在校验处提前 return 了，钩子本身没问题。
（存档日志走 slf4j，所以行首是时间戳与 logger 名；按 `Saved` 这个词 grep 最省事。）

**解决**：

| 目的 | 做法 |
|---|---|
| 拍**冒险模式**的关卡 | 用 `pvzce:yard/adventure/1_1`（默认解锁），**完全自动**，能进 CI |
| 拍任何关卡（推荐） | 先跑一次 `-Ppvzce.smoke="pvzce.smokeScreen=levels"` 进列表页，在名字框里输入世界名、勾上**「全解锁」**再建世界；之后那个 `-Ppvzce.gameDir` 下所有关卡都能直接开 |
| 解锁单关 | 用同一个 `-Ppvzce.gameDir`，按 `/` 打开控制台（**覆盖层，标题页也能开**）敲 `/profile unlock pvzce:yard/adventure/1_2`；或 `/profile unlockall` 一次全开 |
| 改数据 | 关卡 JSON 的 `unlock` 块里去掉 `requires`（会改动内置关卡文件，只在临时环境这么做） |

> 后三条都需要**人工敲一次**：冒烟钩子不会打字（`smokeClick` 只发鼠标按键与坐标，
> `smokeCommands` 又要求关卡已经起来）。所以"要进锁着的关卡"的截图**不能全自动**——
> 先把世界解锁好，之后的截图批次才能一次接一次地跑。

### 2.2 不带 `-Ppvzce.gameDir` 会写进**真正的游戏目录**

默认 `~/.pvzce`。冒烟会建世界、写存档、`/reload` 覆盖数据包——
**截图冒烟请务必带上 `-Ppvzce.gameDir=<临时目录>`**。这是 Gradle 属性（`-P`），
不是 `pvzce.smoke*` 里的键，因为它要变成进程参数 `--gameDir` 而不是系统属性。

## 3. 怎么传参数

- **必须用 `-Ppvzce.smoke="…"`**（Gradle 属性）。`run` 任务把它按空白切分，
  逐项转成游戏 JVM 的 `-D`。Gradle 自己的 `-D` 只到 daemon，进不了 fork 的 `JavaExec`。
- 每项写成 `key=value`；只写 `key` 等于 `key=true`。
- **值里不能有空格**（会被切分）。命令、参数要用空格的地方写成 `+`，见 `smokeCommands`。
- 路径值里**不要有空格**：含空格的 checkout 路径会把参数切断。
  路径**必须落在仓库内**（`.smoke/`）且**写成绝对路径** —— 写 `/tmp` 会被沙箱静默吞掉，
  而相对路径的基准是 **`pvzce-game/`**（`JavaExec` 的工作目录是模块目录，不是仓库根），
  写 `.smoke/x.png` 会落到 `pvzce-game/.smoke/` 或直接写失败。

## 4. 钩子清单

### 4.1 帧、截图、退出

| 属性 | 默认 | 作用 |
|---|---|---|
| `smokeFrames=<n>` | `0`（不退出） | 渲染到第 n 帧时打印 `screen=<当前界面类名>` 并退出。**这是冒烟的主开关**，也是判断"走到没走到"的唯一依据 |
| `captureFrame=<n>` | `-1` | 在第 n 帧把 framebuffer 存成 PNG |
| `capturePath=<路径>` | 无 | PNG 路径，**要落在仓库内**（写 `/tmp` 会被沙箱静默吞掉）。写出的图方向正确（`capture()` 只翻一次行） |
| `captureEvery=<n>` | `0`（单张） | **拍一条帧带**：从 `captureFrame` 起每 n 帧存一张，文件名变成 `<capturePath>_<帧号>.png`。给会动的东西用——服务端 60tps 在**自己的线程**里跑而客户端按显示器刷新率画，所以"爆炸后第三帧"在 60Hz 上是 60 帧后、在 120Hz 上是 120 帧后，猜不出来；半秒的特效落在帧带里的某处，落不进任何一次猜测 |

> `captureEvery` 与 `captureFrame` 是两个独立的计时器：常见写法是
> `smokeFrames=150 captureFrame=140`，先存图再退出（同一帧也行）。
>
> **帧的含义**：截图在 `afterFrame` 里、`swapBuffers` 之后跑，`glReadPixels` 读到的是
> **刚呈现的那一帧**，所以 `captureFrame=N` 拍到的就是第 N 帧。反过来说，**同一帧里改的状态
> 要下一帧才看得见** —— 冒烟钩子因此在 `beforeFrame` 里改动界面（`applyAlmanacShots`），
> 这样"第 N 帧翻页 + 第 N 帧截图"是对得上的。

### 4.2 直接进关卡

| 属性 | 默认 | 作用 |
|---|---|---|
| `smokeLevel=<关卡 id>` | — | 第 2 帧后请求开局（等价于"重开一局"），走正常入场路径。**受解锁门槛约束**，见 §2.1 |
| `smokeLevelRestart=<bool>` | `true` | `false` = 已有存档就继续它（用于拍"存档恢复后"的画面） |
| `smokeDialogue` | 关 | 把 `smokeLevel` 当成**直接进关卡**（不经过选卡），于是关卡的开场对话在草坪上播。默认关，因为拍棋盘时对话会挡住画面 |
| `smokeSeedLevel=<关卡 id>` | — | 只等关卡列表回来，然后打开**选卡界面**（拍选卡页 / 测卡池）。它不开始游戏。**注意它走的是"没有返回目标"那条重载**（`openSeedSelection(info, false)`）：`hasNothingToChoose()` 为真的关卡在这里是 `previewOnly`，**木牌与卡池不画**，只有草坪与对话。要拍卡池/卡槽计数请挑一关有得选的（1-6、变异关卡），或者用游戏内那条路 |

### 4.3 直接打开某个界面

| 属性 | 作用 |
|---|---|
| `smokeScreen=levels` | 关卡列表。**需要 `smokeWorld`**（列表是按世界下发的） |
| `smokeScreen=create` | 关卡列表 + 真实的「新建关卡」对话框 |
| `smokeScreen=almanac` | 图鉴（开在索引页；进哪一页见下面三行） |
| `smokeAlmanacPage=index/plants/zombies/resources` | 图鉴直接翻开某一页（`index` 即索引） |
| `smokeAlmanacEntry=<n>` | 再翻到该页第 n 条（0 起，自动取模） |
| `smokeAlmanacShots=<帧>:<页>[:<条>],…` | **一次启动拍全图鉴**：每到那一帧就翻到那一页并选中第 n 条，与 `captureFrame`/`captureEvery` 配合。翻页发生在 `beforeFrame`（渲染前），所以同一帧的截图就是翻过之后的那一页 —— 钩子里也先 `initIfNeeded()`，否则那一页会被 `init()` 重建目录时丢掉 |
| `smokeUnlockAll` | 让服务端下发的档案 `unlockAll=true`，于是图鉴画的是「已解锁」的样子（没有它就只能拍到未解锁那一种） |
| `smokeScreen=award` | 结算页，合成奖励包里带解锁卡（种子卡落进相框那个分支） |
| `smokeScreen=award_money` | 结算页的钱袋分支（没有解锁卡） |
| `smokeScreen=console` | 标题页 + **控制台覆盖层**（控制台是浮层，需要一个屏在它下面） |
| `smokeScreen=mods` / `settings` | 模组列表 / 设置 |
| `smokeConfirm=restart` / `sun` | 开局后自动弹出二次确认框（重开 / 未选阳光）。这两个框各有两个父级（暂停菜单与选卡页），从标题页点过去要猜坐标，所以留了这个直达钩子 |
| `smokeWorld=<世界名>` | `smokeScreen=levels` 用哪个世界，默认 `world` |
| `smokeTab=<主题>/<类别>` | 关卡列表直接翻开某一页（默认停在第 0 页，其余页签不点开就拍不到） |

### 4.4 编辑器

| 属性 | 作用 |
|---|---|
| `smokeEditor=<关卡 id>` | 打开编辑器编辑某一关 |
| `smokeNewEditor=<新 id>` | 走「新建关卡」路径（id 与名称分离后的新流程） |
| `smokeEditorPage=<页 key>` | 切到某页：`terrain` / `plant` / `zombie` / `rule` / `wave` / `cards` / `music` / `info` / `unlock` / `dialogue` |
| `smokeWaveEditor` | 叠开波次表格 |
| `smokePlace=<kind=id@x,y;…>` | 在画布上放预设实体，`kind` 取 `p`(植物) / `z`(僵尸)。**先放置后保存**，所以与 `smokeSave` 同时用时写的是放置后的棋盘 |
| `smokeSave` | 保存一次（验证写入往返） |

### 4.5 合成输入

| 属性 | 默认 | 作用 |
|---|---|---|
| `smokeClick=<guiX,guiY>` | — | 在逻辑 GUI 坐标点一下。坐标是"左下为原点"的 GUI 坐标，不是窗口像素（raw 与 GUI 的换算由钩子自己做） |
| `smokeClickFrame=<n>` | `45` | 第几帧按下。**`smokeClickLabel` 也用这个帧号**，两者不能各配一个时刻 |
| `smokeClickRepeat=<n>` | `1` | 点几次。对话要一句一句点、卡槽要一张一张填，一次点击拍不到另一头 |
| `smokeClickPeriod=<n>` | `12` | 两次点击间隔多少帧（第 `smokeClickFrame + k × period` 帧各点一次） |
| `smokeClickLabel=<按钮文字>` | — | **按标签找按钮**并点它，不受窗口尺寸影响，比硬编码坐标可靠。只在**当前屏的对话框**里找（`currentScreen().dialogs()` 的子控件），所以它点不了非对话框里的按钮——那种情况只能用 `smokeClick` 给坐标 |
| `smokeDragTo=<guiX,guiY>` | — | 从 `smokeClick` 的按下点拖到这里再松手 |
| `smokeDragFrame=<n>` | `60` | 第几帧拖动与松手 |
| `smokeHover=<guiX,guiY>` | — | 把指针**钉**在这个 GUI 点上（`smokeHoverFrame` 起每帧都钉）。`smokeClick` 只投递点击事件、不移动指针，而"悬停在哪里"是另一类界面状态的输入：格子高亮、可种性提示、拖动时跟随光标的种植幽灵都读 `window().cursorX/Y` |
| `smokeHoverFrame=<n>` | `3` | 从第几帧开始钉。默认在第 2 帧的开局请求之后，所以进关卡后立刻生效 |

> `smokeHover` 既记录坐标也请求平台移动指针（GLFW `glfwSetCursorPos`）：**没有聚焦的窗口，平台会忽略这个请求**（Wayland 尤其如此），只靠平台回调的话悬停态永远拍不到。窗口和 framebuffer 像素不一致的缩放桌面上，指针会落在 framebuffer 坐标处，也就是游戏读取的那个位置。
>
> 坐标是**左下为原点**的 GUI 坐标，和 `smokeClick` 一样（指针本身是自上而下报告的，钩子替你做那次翻转）。写反了不会报错：悬停会落在目标格**关于屏幕水平中线对称**的那一格上——拍摄"光标指到哪"的界面时，这正是最容易骗过肉眼的一种错。

> `smokeHover` 让悬停态可以被截图，典型用法是先 `smokeClick` 点一张植物卡、再 `smokeHover` 指到草坪格子上，`captureFrame` 就会拍到那个半透明的种植预览。

> `smokeClick` 与 `smokeClickLabel` **不要同时用**：两者都由 `smokeClickFrame` 触发、
> 都把同一次点击记为"已发过"，谁先命中就只发谁。

> 按下与松手在同一点就是点击，所以 `smokeClick` 单独测不出拖拽手势——
> **拖动放卡**与**按住扫过拾取**都要靠 `smokeDragTo`。

### 4.6 关卡起来之后

| 属性 | 作用 |
|---|---|
| `smokeCommands=<cmd>\|<cmd>` | 关卡起来后按**真命令路径**执行控制台命令（`/spawn`、`/resource`…），用于摆出关卡文件表达不了的场面。命令里的空格写成 `+`：`smokeCommands=/spawn+resource+pvzce:sun+3+1` |
| `smokeReward=unlock` | 在 `smokeLevel` 开的关卡里合成一次通关奖励，落一张**解锁卡**（奖励落到草坪 → 可点击 → 领完进结算页） |
| `smokeReward=money` | 同上，落**钱袋** |

### 4.7 诊断（不是冒烟钩子，但常一起用）

| 属性 | 作用 |
|---|---|
| `-Dpvzce.traceSounds=true` | 按秒打印实际播放的音效事件计数（诊断"某个音效在循环"） |
| `-Dpvzce.traceMessages=true` | 把服务端的 `ServerMessageS2C` 打进日志。**排查 §2.1 那类静默拒绝就靠它** |
| `-Dpvzce.traceFrames=true` | 每秒打印一行 `[FRAME] <fps> | tick <ms> | render <ms> | other <ms>`。**"这一关很卡"先用它变成数字**：一次实测就定位到"波次条每帧遍历 3990 个波次"（见 `架构变更记录.md`） |
| `-Dpvzce.traceInput=true` | 每次点击打进日志：落在哪一屏、哪些控件、`isMouseOver` 命中谁。**`smokeClick` 点空是完全静默的**，这是唯一能看出它到底点到哪的办法 |
| `-Dpvzce.traceTextures=true` | 缺贴图时连调用栈一起打 |
| `-Dpvzce.traceMusic=true` | 每次切轨打一行，并列出**四条轨道各自在播什么**。音乐控制器有四条独立轨道（menu / background / battle / stinger），所以"两首歌一起响"不会报错也不会进截图——这条是唯一能看见它的办法 |
| `--versionType=<字符串>` | 只影响标题页那行版本文字（发布版标记） |

## 5. 典型组合

> **`capturePath` 必须落在仓库内**（`.smoke/<主题>/`，目录要先建好）。
> 写到 `/tmp` 之类的外部路径在本环境的沙箱里会被**静默吞掉**：不报错、也没有文件，
> 看起来像"冒烟根本没跑"。一次改动最多启动一次冒烟 —— 要看多个时刻就用 `captureEvery` 拍帧带。

```bash
export GD=$PWD/.smoke/gd            # 一次性的游戏目录，见 §2.2

# 关卡内棋盘（最常用）
./gradlew :pvzce-game:run -Ppvzce.gameDir=$GD -Ppvzce.smoke="\
pvzce.smokeLevel=pvzce:yard/adventure/1_1 \
pvzce.smokeFrames=300 pvzce.captureFrame=290 pvzce.capturePath=.smoke/board.png"

# 摆一个需要特定场面的截图：先放三颗阳光，再拍
./gradlew :pvzce-game:run -Ppvzce.gameDir=$GD -Ppvzce.smoke="\
pvzce.smokeLevel=pvzce:yard/adventure/1_1 \
pvzce.smokeCommands=/spawn+resource+pvzce:sun+3+2 \
pvzce.smokeFrames=400 pvzce.captureFrame=380 pvzce.capturePath=.smoke/drops.png"

# 选卡界面（关卡列表 → 选卡）
./gradlew :pvzce-game:run -Ppvzce.gameDir=$GD -Ppvzce.smoke="\
pvzce.smokeSeedLevel=pvzce:yard/adventure/1_2 pvzce.smokeFrames=220 \
pvzce.captureFrame=210 pvzce.capturePath=.smoke/seeds.png"

# 会动的东西：拍一条帧带再挑（爆炸、孢子锥、动画速率）
# 关卡是游戏目录里的冒烟特供 `pvzce:yard/smoke/fx_board`（.smoke/gd/datapacks/fx_smoke）：
# 夜、空草坪、没有墓碑，大喷菇 + 一只僵尸在第 2 行，樱桃炸弹与毁灭菇摆在第 0 行（画面最下排，
# 不会被卡槽条和暂停面板挡住），两个植物的引信在数据包里被拉长到 250/300 tick，爆炸落在开场
# "Ready...Set...Plant!" 横幅之后。同一关卡也在 .smoke/shots/fx_final/ 留了三张证据图。
./gradlew :pvzce-game:run -Ppvzce.gameDir=$GD -Ppvzce.smoke="\
pvzce.smokeLevel=pvzce:yard/smoke/fx_board pvzce.captureFrame=190 \
pvzce.captureEvery=2 pvzce.smokeFrames=330 pvzce.capturePath=.smoke/fx/s.png"

# 结算页的两个分支
./gradlew :pvzce-game:run -Ppvzce.gameDir=$GD -Ppvzce.smoke="\
pvzce.smokeScreen=award pvzce.smokeFrames=150 pvzce.captureFrame=140 \
pvzce.capturePath=.smoke/award.png"

# 拖拽放卡（按下在卡上，拖到格子里松手）
# 卡坐标要按 §4.5 的算法算：1280x720 窗口下 guiHeight=240、GUI 缩放 3，卡行在 GUI x 94 起、
# y 176..232（本例用 combat_test：初始 300 阳光，豌豆射手 100 付得起）。
./gradlew :pvzce-game:run -Ppvzce.gameDir=$GD -Ppvzce.smoke="\
pvzce.smokeLevel=pvzce:yard/adventure/combat_test \
pvzce.smokeClick=114,204 pvzce.smokeDragTo=83,140 pvzce.smokeDragFrame=140 \
pvzce.smokeFrames=300 pvzce.captureFrame=290 pvzce.capturePath=.smoke/planted.png"
```

> **坐标不是随手写的常数**（这一节的例子曾经点空过：它按"卡槽条在底部"给了 `60,40`，而那之后
> 卡行一直在**左上角**，紧跟阳光银行）。1280x720 窗口下的算法：
> `guiWidth/guiHeight` 由 GUI 缩放决定（此处 427x240），`SeedCardBar.updateLayout` 给出
> 卡行左缘 `CardBarLayout.cardsLeft(有阳光银行)` = 8+78+8 = **94**、高 `clamp(guiH/6,56,74)` = 56、
> 纵向 `guiH - 卡高 - 8` = 176..232，所以第一张卡的中心约 **(114, 204)**。
> 悬停的草坪格子用同一套换算从截图量：GUI x = 图 x / 缩放，GUI y = (窗口高 - 图 y) / 缩放。
> **要选一个阳光够的关卡**：1-1 只有 50 阳光，点 100 的豌豆射手只会得到"阳光不足"，
> 拍不到种植幽灵（`combat_test` 的 300 阳光够）。

## 7. 已经用它验过什么（2026-09 的一次全面核查）

一次授权后的核查跑了 15 轮（11 个界面/路径 + 交互钩子 + 编辑器 + 两轮重拍），记录见
`架构变更记录.md` 的「界面冒烟（一次性全面核查）」。可复用的结论：

- **交互钩子都通了**：`smokeClick`（点卡）、`smokeHover`（悬停出种植幽灵）、
  `smokeDragTo`（拖拽放卡，阳光真的扣、卡真的进冷却）、`smokeClickLabel`（按文字命中对话框按钮）。
- **HUD 布局可以从截图量**：1280x720 的 GUI 是 427x240、缩放 3；阳光银行左缘 GUI 8、
  卡行左缘 GUI **94**（`CardBarLayout` 的三个数：边距 8 + 银行宽 78 + 间隙 8）。
- **编辑器画布**：`smokeEditor` + `smokeEditorPage=terrain` 能拍到整块棋盘与水面；
  画布在装不下时会整体等比缩小（见该轮的画布修复），所以截图上应当看到**完整**的
  `width x height` 格，看不到就是又退化了。
- **缺贴图**：`pvzce.traceTextures=true` 会把 `Missing texture reference: …` 打进日志 ——
  洋红方块 + 这行日志就是结论，不必靠眼睛找。
