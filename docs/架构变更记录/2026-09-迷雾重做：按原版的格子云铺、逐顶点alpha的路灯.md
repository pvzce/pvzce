# 迷雾重做：按原版的格子云铺，逐顶点 alpha 的路灯

> 用户一句话：「4-x 关卡的迷雾渲染完全错误，很糟糕，应该按照原版的迷雾来渲染。`refer/im7` 里面有能用的
> fog 贴图。」四个取舍事先问过并得到确认：雾按原版是实的（盖住的草坪几乎看不见）、覆盖范围伸出棋盘、
> 贴图用 `fog_.jpg` 的 8 帧云朵、每格的缓慢流动照原版做。

## 现象与根因

- **原版画的是云，我们画的是一块黑幕**。`FogClientMechanic` 把云图**拉满整条雾带高度**垫在下面，
  再用 16 级**黑 quad** 按 alpha 叠在上面，深处再补一块纯黑矩形。且绘制走的是 `FogData.alphaAt`
  的斜坡：`start=6, end=9` 时第 6 列只有 0.31、到第 7.8 列才到 0.75（隐藏阈值），所以整片实际上
  是"边缘一条硬竖线的黑块"，云被完全盖住。玩家自己种在那几列的植物也被这块黑盖掉。
- **真正的原因是没有照原版的模型画**。原版 `Board::DrawFog` 是**逐格铺云**：每格画一张
  `IMAGE_FOG` 的帧，位置 `x*80-15, y*85-30`，每格一个 alpha（起始列 200/255，其余 255），
  再叠一个逐格缓慢变化的颜色。云是实心的，所以"看不见"是云本身给的，不是黑幕给的。
- **"引擎没有逐顶点颜色"这条注释是错的**。`VertexConsumer.color` 一直存在，只是 `SpriteRenderer`
  与 `PvzceClient` 的每个入口都只收一个色——所以路灯花的圆洞只能靠 8 分格的小 quad 拼，边界是马赛克。
- **贴图本身也被烘错了**：`tools/gen_fog_texture.py` 读的是 `fog.jpg`（一条近乎均匀的灰带，不是云），
  还按"铺满整条带"的思路在上下做了羽化——那是为旧画法服务的。
- **两个坐标空间被混为一谈**。原版的 `x*80-15` 是**背景图自己的像素**，而这个项目里棋盘在
  1920×1080 下每格是 144px（`PvzceCamera.boardScale()` = 1.8）；而且世界格与屏幕像素之间还有
  棋盘原点与相机投影。第一次修完，雾在屏幕上整个不见了——两处各错一次。

## 定论

- **云是一条带子，不是八朵云**：`fog_.jpg` 是**一整条连续云带切成 8 片**（1680×190 = 8×210×190，
  水平周期 420/840、内容上下留 10px 重叠）。所以帧号由格子的 x 位置决定
  （`frameFor = cellX*80/210 mod 8`），不是随机挑的——原版 `mGridCelLook = Rand(20)` 能成立是因为
  它那 8 帧是八朵可互换的云。挑错帧相邻格就对不上、整条带出现接缝。
- **烘焙曲线只有一个目的：让这张图当 alpha 用**（`tools/gen_fog_texture.py`）：灰阶去掉 JPEG 的
  黑底振铃、提为 alpha，颜色染成**夜色蓝灰** `(0.58,0.63,0.75)`（三份候选烘出来实机比对后选的——
  源图是白云，白云压在夜池上是一堵白墙）。`ALPHA_LIFT=0.25` 是因为单帧有大量空隙，按 80px 步长
  合成后一条带只有 0.76 均值、十分位 0.17，像一层纱；抬四分之一后同一测量是 0.92 / 0.71。
- **绘制照原版**：逐格 `x*80-15, y*85-30`（背景图像素）× `camera.boardScale()`，**世界格**交给
  `client.drawTextureShaded`（不是自己乘 `unitX` 画屏幕像素——那样整条带会离开屏幕）。每格一个
  alpha（= 关卡的 `max_alpha`）与一个明暗漂移（原版两个正弦：周期 5.2s / 9.4s，逐格相位
  `6π/9`、`6π/7`，下限 0.55）。行数比棋盘多一行、列多一列，与 `x < MAX_GRID_SIZE_X` 同一读法。
- **隐藏判据仍是 `FogData.alphaAt` 的唯一读数**：`hidingColumn()` = 关卡自己 span 里
  **0.1875 格**处（格子左边 0.1875 是云开始的地方，也就是原版"第一个有雾的格子就藏"）。
  曾试过"从云的合成 alpha 反推边界"，已回退：云的 alpha 是个阶跃（半个格子内就吃满），
  从它推出来的线会让 `start_column` 失去意义；那条推理留在 `hidingColumn` 的注释里。
- **路灯是逐顶点 alpha**：新增 `PvzceClient.drawTextureShaded` / `SpriteRenderer.texturedQuad`
  的逐角 alpha 重载，路灯覆盖到的格子按 **4×4 细分**、逐角取 `FogMechanic.alphaAt`。一个半径 2.5 的
  灯因此有约二十级 alpha 跨过自己的边——从"十边形"变成圆。
- **死掉的东西删掉**：`fog_alpha.png` 与 `tools/gen_fog_gradient.py`（渐变不再被任何绘制读），
  对应的对拍测试换成"云图在 classpath 上、且是有空隙的云而不是一块黑"。
- **`fog.jpg` 没被用上**：它是那条近乎均匀的灰带（1%/99% 分位 151/221），当底雾可以、当云不行，
  所以留作参考不动。

## 验到了什么

- 冒烟（`.smoke/fog-original/`，两次启动）：`tint_b.png` 是 4-1（雾从第 6 列），
  `deep49.png` 是 4-9（雾从第 4 列，能看到整片絮状云与逐格的明暗差），
  `lamp.png` 是两株路灯花在雾里抠出的**平滑圆洞**（这一张同时验了逐顶点 alpha 那条新路）。
- 三份 tint 候选先渲染成剪贴图比对再定色；`tints.png` 留在同一目录。
- `FogClientMechanicTest`（新，7 例）：4-1 上"clear → 雾第一列 → 深处"的隐藏行为与
  `hidingColumn` 的两侧各差 0.01；路灯把自己的格子照亮但不影响它照不到的地方；没有雾的关卡
  什么都不藏也不画；`max_alpha=0` 时 overlay 与隐藏一起消失；树格偏移/尺寸与 1.8 倍缩放；
  云图确实是 8×210×190。
- `FogMechanicTest`：云图在 classpath 上、且明暗两面都存在（防止烘成一块黑）；
  `FogWorldLevelsTest` / `StormClientMechanicTest` / `OriginalAdventureLevelsTest` 全绿——
  隐藏规则变了，关卡表那几条断言仍然成立（4-1 第 6 列起被藏，与 `start_column` 一致）。
