# 第二轮出怪节奏：补上原版的血量加速，传送带关开局再砍一半

> 用户复报（在第一轮修好之后）："1-5，从正式开始到第一波，从第一波到第二波，都要等十几秒才会出两只僵尸。"

## 现象与根因

- 第一轮的探针证明"两只"那半已经修好（第一波两只同时出），但第一波前还有 20 秒、波间还有十几秒。
- **根因三（这一轮补的，也是最大的一条）：原版的"本波血量消耗"加速这一整套本项目没有。**
  `Board::UpdateZombieSpawning` 在 `mZombieCountDown > 200 && 已跑过 400 拍 &&
  TotalZombiesHealthInWave(上一波) <= mZombieHealthToNextWave` 时把倒计时**直接压到 200 拍**；
  那个阈值是开波时掷的"本波血量的 50%~65%"。1-5 第一波只有 2 只路障，打死一只就过线 ——
  原版里第二波是三秒后的事，而本项目要把 3034 拍的 `delay` 数完。表里的 `delay` 是原版的数值，
  但原版从来不让玩家把它数完。
- 传送带关的开局 1200 拍（20 秒）仍然只是干等：这类关卡没有"布置"这回事。

## 定论

1. **血量加速照原版实现**（`WaveDirector.healthDrainApplies` / `rollHealthDrainTarget`）：线 = 该波已放出血量 × 50%~65%
   （`host.random()`，开波时掷一次），场上该波剩余血量（身体 + 护甲）掉到线下就把目标压到 200 拍。
   两个实现的坑都踩过了，写在代码注释里：线要在**倒计时开始那一拍**掷（波触发与上一波最后一只出生同拍，
   触发时掷会掷到 0），而且只能**往前压**（`Math.min`，这个计数器往上数，"每拍重新定终点"会让倒计时永远到不了）。
2. **`pvzce:wave_pacing` 新增 `"health_drain"`（缺省 true）**，变异教程写 false：它的重点是剧本顺序，
   玩家秒清每一波会在最后一个剧本事件之前把关卡打完（`MutationTutorialTest` 就是这么红的）。
   `clearRewardOff()` 一并关掉它 —— 两个都是"倒计时可以被砍短"这同一个承诺。
3. **传送带关（1-5 / 2-5 / 3-5 / 4-10）开局 delay 1200 → 600**（`CONVEYOR_FIRST_WAVE`）。
4. 1-5 现在的时间线（探针实测，玩家 2 秒清一只）：**10.0 秒**第一波两只同时出 →
   **13.3 / 16.6 / 20.1 / 24.2 / 28.1 / 32.3 / 36.9 秒**逐波，40 秒打完 8 波 44 只。
   `WavePacingMetricsTest` 里全 40 关的"最长空场"从 ~1000 拍掉到 82~134 拍（1.4~2.2 秒）。
