# 架构变更记录 · 节奏草坪返工：跟着歌的谱面、一个方向的操作、无冷却的卡槽

> **归档（冻结）**：这是从 `架构变更记录.md` 分卷出去的原文，只搬家不改写，**不再修订**。
> 索引见 [../架构变更记录.md](../架构变更记录.md)。

> 用户一次报了六条（卡槽该无冷却却还有、按键指代不明、草坪上没有按键提示、初始阳光太少、
> 谱面对音乐约等于没有适配），并要求"用这首歌按 BPM 生成一个可玩的铺面，铺面和音乐同时开始"。
> 排查下来六条里有四条是**同一个根**：谱面从来没跟音乐发生过关系。

### 现象与根因

- **"跟着音乐"这件事从来没成立过**。四档各自发明了一个 BPM（100/110/125/140），当成"同一首歌
  的四种速度"；而音乐是 `pvzce:music/cerebrawl`（另一首曲子，115.7 秒）。音符从第 4 拍起、以
  `1/density` 拍步进，简单档是 2.94 拍一颗 —— **拍点连整除都不是**。速度、长度、起点三样全无关。
- **谱面与音乐不是同一个钟**。谱面时钟从"准备阶段结束"起算（`RhythmMechanic.State.startTick`），
  而音乐 cue 是 `at_tick: 0`，在准备阶段就响了 —— 就算 BPM 对上了，谱面也会晚"玩家摆阵花掉的时间"。
- **每关同时挂行 lane 与列 lane**（简单档就是"行 2 + 列 4"），而草坪上**一个按键提示都没有**：
  `InGameScreen` 只在屏幕右侧列一行"行 2 / 列 4"。玩家要从这两种读法里猜，指代不明是必然的。
  关卡描述里的列键还写错一处（`Q W E R Y U I O P`，漏了 T、多了 P）。
- **冷却其实早就有开关**：`LevelServer.effectiveCooldownTicks` 是唯一的换算点，`CardCooldown.effective`
  对 `multiplier <= 0` 直接返回 0 —— 也就是"无冷却"这件事**只要关卡写 `seed_cooldown_multiplier: 0`**。
  节奏草坪没写（=1），而准备阶段则完全没有豁免：`last_stand`（谁笑到最后）摆阵时也要一张张等冷却，
  这正是用户报的那条。
- **初始阳光 250**。
- **用户给的 BPM 与文件对不上**：说 109，而这份 ogg 实测是 **110.00 BPM**（109 的网格在第 47~94 秒
  那一段直接失配、相位得分转负）。差 1 BPM 在 3 分钟里漂 2~3 拍，正好是"后半段没踩上"。

### 定论

- **一首歌一张表，表是量出来的**（`RhythmCharts.ONSETS`）：`tools/rhythm_onsets.py` 用 ffmpeg 解码、
  spectral flux 做起始包络、与各种 BPM 的脉冲串做含谐波的互相关定速、再在 0.25 ms 粒度上定相，
  最后以 1/4 拍为格、σ=25 ms 高斯核采样成每格一个十六进制数字（0 没有东西落下去、F 最响）。
  这条链**可复跑**：`python3 tools/rhythm_onsets.py --check` 量一遍并与代码里的常量逐字符比，
  当前是 OK（BPM 110.000、第 0 拍 0.2385 s、表尾第 340 拍）。游戏本身不做音频分析。
- **谱面 = 网格 × 强度门槛 + 保底 + 和弦**：档位给"每几拍一个格"（4 分 / 4 分 / 8 分 / 16 分）与
  "取最强的多少颗"（约 124 / 170 / 330 / 490），音符落在音乐真打了的拍上；每 4 拍的窗口没有音符时
  补一颗最强的（否则歌的几处间奏会变成二十秒没事干）；困难与专家在最强且孤立的拍上要两个键。
  落哪一行是固定种子的伪随机（不是轮转：轮转三分钟下来是同一串手指动作，而且低档位只有一行时
  轮转没有意义）。歌最快的打击是 8 分音符，16 分格上只有 13 处真加花，专家档正好把它们捡起来。
- **一首歌对应一个时钟，而那个时钟是"波次开始"**：`LevelDef.MusicCue` 加了 `trigger`
  （`level_start` / `waves_start`），服务端在 `beginWaves()` 记下 `wavesStartTick`，
  `processMusicCues` 对两组 cue 各按自己的基准判定。谱面机制本来就从这一刻起算，所以歌和音符
  同 tick 起 —— 两个 `fade_seconds` 都写 0，因为淡入就是一个不等于 cue 时刻的起始时刻。
  准备阶段由一条 `level_start` 的 stop cue 保持安静（客户端进场默认放 grasswalk）。
- **每关只有一个操作逻辑，而且这条被钉死**：四档都用满 D F G H J 五行；混用行列现在是
  `RhythmMechanic.validate` 的一条**关卡数据错误**（"一个方向的操作，提示才有唯一的位置"）。
- **准备阶段一律无冷却**：写在 `effectiveCooldownTicks` 里（准备中直接返回 0），因为它是唯一的
  换算点，牌堆 / 传送带 / 工具全都走这里；同一处也让卡槽条画出"已就绪"。开打后恢复各关自己的规则。
  节奏草坪则是整关 `seed_cooldown_multiplier: 0`，`initial_sun: 1000`。
- **谱面结束就是关卡结束**：`RhythmChartData` 加了 `end_beat`（歌的最后一个小节，340 拍 = 185.7 s）。
  走到那一 tick 时 `RhythmMechanic` 先 `sweepLawn()` 再 `declareVictory()` —— 残敌**即死但不算击杀**
  （`ZombieEntity.sweptAway` 走普通死亡路径：尸体、clip、head、波次导演都照常，只是不付阳光与金币，
  与自爆的小丑共用一条 `unearned()` 判据）。漏音符不判负：这一关的胜负是"活到歌尾"。
- **按键提示画在草坪上**：`InGameScreen.renderRhythmLaneKeys` 给每条真有音符的 lane 在**该行左端**
  （或该列下端）画一个按键胶囊，字母取自**玩家当前的绑定表**（改了 D 就显示改后的键，没绑就不画），
  命中闪成 PERFECT 的黄。右侧那份"行 0…4"清单删掉：它是常量，而它唯一有用的那半（哪个键打哪一行）
  现在写在行上。胶囊画在**拖拽种植预览之后**——否则第一格上的半透明方格会把它冲淡。
- **编辑器跟着改**：`RhythmPage` 的"密度"换成"音符数"，多一个"初始阳光"；曲目字段指向没有分析的
  曲子时，生成器退回**匀速拍点谱**（`end_beat` 为 0，关卡按波次表正常结束），并在状态行说明 —— 
  宁可是"这首歌没有分析"，也不是拿别人的鼓点当它的。
- 顺带：`GameStateS2C` 的胜负路径本来就有一条"机制自己宣布胜利"（4-5 的花瓶用的 `declareVictory`），
  这一轮是第二个用户。

### 判据

- `RhythmChartsTest`：生成器确定性；四档与仓库文件逐字段一致（`mechanics` 与 `waves` 都比）；四档
  只有 row lane；音符数递增；**easy 档七成以上的音符落在强度 ≥8 的拍上**（"跟着音乐"的量化判据）、
  所有音符都在 `[FIRST_BEAT, END_BEAT)` 内；`end_beat` 等于 340 且没有音符在它之后；
  music 块是"先静音、再由 `waves_start` 起歌、不循环、不淡入"；`seed_cooldown_multiplier` 为 0 且
  `initial_sun >= 1000`；生成器点名的曲子真的注册过。
- `RhythmTest`：新增"到 `end_beat` 清场并判胜"、"没有 `end_beat` 的谱面不结束关卡"、
  "混用行列被校验器拒绝"、"有音符在 `end_beat` 之后被拒绝"；原有的判定/窗口/漏音符/准备阶段四例照旧。
- `PreparationTest`：新增"准备阶段 `effectiveCooldownTicks` 为 0、开打后回到卡自己的冷却"与
  "写在 waves_start 上的 cue 在准备阶段不响、`beginWaves()` 那一 tick 才响且不淡入"。
- `tools/rhythm_onsets.py --check`：实测与 `RhythmCharts.ONSETS` 逐字符一致（BPM 110.000 /
  0.2385 s / 340 拍）。
- 冒烟（`.smoke/rhythm/`，一次启动拍一条胶片）：`easy_180.png` 是准备阶段——1000 阳光、卡面无冷却、
  D F G H J 五个胶囊与五行小推车**逐行对齐**；`easy_420.png` 是按了"开始"之后——波次条出现、
  右侧只剩 PERFECT/GOOD/连击；`easy_460.png` 拍到一次命中——判定字 `GOOD`、H 键胶囊正亮着，
  计数 `GOOD 1 · 连击 1`。头两次冒烟各抓到一个真问题：胶囊原本放在棋盘**外面**（16:9 下被 cover
  缩放裁掉，屏幕上一片空），以及 `drawSolid` 第 5 个参数是 z 不是圆角半径（胶囊底框压根没画出来）。
