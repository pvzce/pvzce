# 4-5 恐怖花瓶：阳光一束三只、植物卡掉在地上、回合之间清场

> 用户报的三条（阳光瓶只掉 1 个阳光、有"空瓶"、所有花瓶都不掉植物卡）查下来是四件事：阳光数量写错、
> 植物卡从来没掉在地上过、**续档会把 run 的卡槽重新截成关卡固定卡**（攒的卡全被抹掉）、
> 以及下一回合摆瓶会被玩家的植物挤掉。取舍见 `决策记录.md` Q34~Q39。

## 阳光瓶只掉 1 个阳光（该掉 3 个）

- **现象**（玩家报）：砸开阳光瓶只掉 1 个阳光，"一般来说一个花瓶如果要掉阳光的话，需要掉落 3 个才对"。
- **根因**：`LevelServer.smashPot` 的资源分支按资源自己的 `defaultValue` 只发**一份**。第 1 回合两只阳光瓶
  因此只有 50 阳光，而这一关唯一的卡（樱桃炸弹）要 150 —— 一轮打完都买不起。
- **定论**：`PvzceConstants.SCARY_POT_SUN_DROPS = 3` 只、每只 25 点，落点按
  `SCARY_POT_SUN_SPREAD = 0.42` 格错开（阳光画出来近一格宽，0.1 格等于没分开）；**最右列的瓶子整束往里挪
  0.42 格**，否则每一束都有一只悬在马路上。错开用的是 `ResourceDropEntity.driftX` 的第二种用法：
  `FALL` 的掉落物现在也吃这个偏移（原来只有 `RISE` 的抛物线用它）。
- **判据**：`ScaryPotterTest.breakingASunPotDropsItsBundleOfSuns`（3 只、各 25、一回合共 150 = 一颗樱桃炸弹、
  束内间距 = 2×spread、不靠边的瓶子整束在自己格里）；冒烟里砸一只阳光瓶后阳光银行 +75。

## 植物卡从来没掉在地上过，而"进了卡槽"在画面上等于没发生

- **现象**（玩家报）："存在空瓶，且所有花瓶都不会掉落植物卡"。实测第 1 回合：4 只豌豆瓶 + 5 只倭瓜瓶，
  砸开只有**第一次**会让卡槽多一张卡；同种植物的第二只瓶子走 `addCardToBar` 的"已有该卡"分支，
  卡槽画面**一点变化都没有**，而提示照样说"掉出了一张卡"。
- **定论**：容器（恐怖花瓶与玩家的花瓶）里的植物改成**掉在地上的种子包**（新实体 `CardDropEntity`，
  新 `EntityKind.CARD_DROP`）：躺 20 秒、最后 5 秒闪烁，点一下**拿到手上**（`HeldCardS2C`），
  再点草坪格**免费**种下（`PlantHeldCardC2S`），右键放回原地（`ReleaseHeldCardC2S`）。
  **它不进卡槽** —— 卡槽里始终只有关卡自己的卡。协议 33 → 34。
  - 包的"血"就是它的**剩余时间**：一个数既能进存档、又每 3 tick 流给客户端，客户端的闪烁因此读的是
    服务器时钟（续档回来的包按它自己剩的时间闪，不是按客户端什么时候听说它）。
  - 手里那一株**不超时**：20 秒是"注意地上"的窗口，不是"用掉它"的期限。存档时手里的包回到地上
    （手是玩家的，不是关卡的状态），包本身照旧存下来。
  - 非植物卡（作者往 `vase_field` 里塞的工具）仍走 `CardSource.receiveCard` 进条：能"拿到手上"的
    只有能种下去的东西。
  - 判据：`ScaryPotterTest.breakingAPlantPotDropsASeedPacket` / `anUnclaimedPacketExpires` /
    `aHeldPacketIsOffTheClockAndOneAtATime`、`VaseTest.smashingAVaseDropsItsCardAsASeedPacket`；
    冒烟 `.smoke/shots/vase_packet/`（砸开掉包 → 拿到手上 → 种下三张图 + 两句日志）。

## 续档把 run 的卡槽重新截成关卡的固定卡（"攒的卡全没了"）

- **现象**（从玩家存档读出来的现场）：`Slots: [sun, cherry_bomb]`、`ScaryPotter.pots: []`、场上 3 只僵尸、
  阳光 0、植物 0 —— 15 只瓶子全砸完了，卡槽里却只剩关卡自己那两张，回合卡在"没有植物、没有阳光"的死局里。
- **根因**：`SeedSelection.plan(loadSave=true)` 把存档里的 `Slots` 交给 `sanitize`，而 `sanitize` 回答的是
  "这些**选卡请求**能带哪些进这一关"：它按 `max_seed_slots` 截断。4-5 的 `max_seed_slots = 2`，于是续档时
  瓶子给玩家的植物卡**全部被切掉**；而文档与注释写的是"续档恢复玩家当时的卡槽"。
- **定论**：续档走新的 `SeedSelection.sanitizeSaved`：整份恢复，只丢掉**今天解析不出来的卡 id**
  （数据包被删了）。run 的卡槽是 run 的状态，不是一份请求。
- **判据**：`SeedSelectionTest.aContinuedSaveKeepsACardTheLevelDoesNotDeal`（两张固定卡 + 一张瓶子给的卡，
  续档后三张都在）与 `aContinuedSaveDropsACardThatNoLongerExists`。

## 下一回合摆瓶被玩家的植物挤掉

- **现象**：第 2 回合声明 20 只瓶子、只摆下 14 只，丢掉的 6 只**全是僵尸瓶** —— 瓶子按声明顺序取格子，
  玩家种在候选列上的植物把格子吃掉了，缺的从队尾开始丢。那一回合因此没有僵尸，谁都不会输。
- **定论**：**回合之间清理场地**（原版行为，用户拍板）：`ScaryPotterMechanic.tick` 在摆下一回合之前调
  `LevelServer.clearPlants()` 把场上植物全部移除（纯移除：不回阳光、不掉落、不触发死亡效果），
  并播报"第 N/M 回合：场地已清理，清掉了 X 株植物，新的花瓶出现了。"于是每回合都摆满它声明的格子数。
- **判据**：`ScaryPotterTest.everyRoundStandsUpItsWholeBoardEvenWithPlantsInTheWay`（每回合在上一回合的
  植物被种满之后仍摆满声明数，且播报出现）。
