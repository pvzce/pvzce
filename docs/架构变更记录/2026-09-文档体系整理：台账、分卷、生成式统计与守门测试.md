# 文档体系整理：台账、分卷、生成式统计与守门测试

> 起因：用户要求"找出文档的臃肿与不合理之处，并让文档能够在每一次任务结束后更新；
> 明确哪些文档需要更新、哪些不需要；任务完成后反思并更新文档"。
> 这一轮**只动文档、AGENTS.md、测试与一个工具脚本**，不动游戏逻辑。

## 手写的规模数字已经全部腐坏

- **现象**：`当前项目架构.md` 开头写着"`pvzce-game` 主源码 418 个文件 / 约 7.4 万行、测试 132 个文件、
  资源 591 个 JSON；`pvzce-loader` 141 个文件；`pvzce-api` 11 个文件；32 种植物、26 种僵尸、153 个粒子、28 个关卡"。
  实测是 **511 / 94394 行 / 159 / 660；161；11；41 / 32 / 155 / 44**。写的时候是对的，错是因为**没有任何东西重新生成它**
  —— 散文里的数字没有主人。两份报告里还留着"339 个用例""394 个用例全绿"，而 `验证约定.md` §6 明令不记用例数。
- **定论**：那一行改成**带标记的生成式统计块**（`<!-- BEGIN/END DOC STATS -->`），由 `DocStatsTest` 计算并校验；
  跑测试时对不上就红，带 `-Ppvzce.smoke=pvzce.updateDocStats=true` 则写回。生成器只有 Java 一处实现
  （另写一个 Python 脚本就是第二份计数规则，迟早会分叉）。用例数**不生成、不记录**。
  报告是冻结快照，里面的旧数字**不改** —— 它们是当时的记录。

## "已知缺口"有三份，"一个事实只写一处"没有落地

- **现象**：同一件事写在 `当前项目架构.md` §9（59 行、占全文 29%、多层嵌套）、`todo.md` 与各 `架构-*.md` 分册里
  （编辑器不认识 `buffs`、图鉴三件事、增益缺口……至少三处逐字重复）。而 §9 的标题是"已知缺口与预留接口"，
  里面却混着**持久的设计事实**（批合并的三条前提、粒子单位、泳池常数）—— 那些是 as-built 内容，不是待办。
- **定论**：**`todo.md` 是"已知未做"的唯一出处**，`§9` 缩成 11 行的"能力差距概览"表（只分类 + 指向分册与 `todo.md`）；
  持久事实搬进对应分册（批合并三条前提 → `架构-客户端.md` §6.3；粒子单位三条 → `架构-实体与能力.md` §5.2；
  装备档位精度 → §5.2.1；变异存档约定 → `架构-服务端.md` §4.10；AI 与关卡分类缺口 → §4.7/§4.8）。
  同时 `todo.md` 去掉编号改主题分组（历史上出现过两个 `## 0.`，而且编号一重排就与别处的引用对不上）。

## as-built 里混着历史，"只写现状"从来没人检查

- **现象**：`当前项目架构.md` §9 有"曾经举的第二个例子 `MusicEditorDialog` 已不存在""曾有一版编辑器自己逐格画"，
  `UI切换与导航架构.md` 有一整节叫"这一层**曾经**的三处不一致（已修）"，分册里还有几段"这里曾经写错过两次"的长叙事。
  规矩（只写现状）写在 `验证约定.md` §8，但没有任何东西检查它。
- **定论**：`UI切换与导航架构.md` §9 整节搬进 `架构变更记录/2026-09-UI导航的三处不一致（补记）.md`，原文位置改成
  一节"这一层的现状"；分册里最长的六段叙事改写成 **`**约束：…**` + 判据** 的句式（保留"为什么不能改回去"，
  删掉排查经过），叙事本身早在归档里。句式规则写进 `验证约定.md` §8：as-built 写约束，不写"曾经…"。

## 变更记录长到 319KB / 262 节，没有索引，还并存两套组织方式

- **现象**：`架构变更记录.md` 2166 行，开头按架构层编号（`# 3. 框架层`…但**没有 §1/§2**），后面按"轮"（19 轮），
  一共 262 条定论，**没有目录**；读者找一条旧定论只能全文搜索。它内部还有一个 `# 8. 约定（避免重新长出重复实现）`，
  与 `架构-扩展点与约定.md` §8 同名撞车。
- **定论**：主文件 = **按层定论索引（262 条一条一行，链到归档）+ 最近 3 轮全文**；更早的每一轮按
  `架构变更记录/YYYY-MM-<轮名>.md` 分卷（现有 17 份，全部是 2026-09）；按层 5 份（`按层-框架层/服务端/
  实体与能力/客户端/约定.md`）也搬过去。分卷**只搬家不改写**，条目总数守恒（262 = 202 归档 + 60 保留）。
  顺带修掉一处历史误置：图鉴那一节原在 `# 3. 框架层` 之下，搬进 `按层-客户端.md`。
  `# 8. 约定` 那一节改标题为"约定清单的由来"，不再与分册 §8 撞名。
  一个坑：文件名里不能带空格与 ` / `（Markdown 链接要么百分号转义、要么一串 `%E6%8C%89`，可读性归零），
  所以归档文件名去掉空格、` / ` 换成 `、`。

## 收尾没有执行点：文档义务藏在一份叫"验证约定"的文件里

- **现象**：仓库根**没有 `AGENTS.md`**，唯一的文档义务清单是 `验证约定.md` §8 —— 一份名字听起来只管验证的文件，
  收尾时不会有人去翻它；21 份文档里也没有任何一份在开头说"我这一轮要不要改"。
- **定论**：新增**仓库根 `AGENTS.md`**（DSH 每次会话自动加载）：命令、铁律、开工确认门、**收尾 7 步**、文档地图；
  新增 **`docs/README.md` 文档台账**（每份文档一行：是什么 / 哪一档 / 什么时候改），三档 = 活·每轮过一遍 /
  活·按条件写 / 冻结。`验证约定.md` §8 只留**规则**（为什么这么分档 + 三条老规矩）并指向台账，
  避免"义务清单"两处维护。守门：`DocLedgerTest` 要求 `docs/` 下每一份 `.md` 都在台账里、
  每一份归档卷都被索引链到。
- 顺带明确**冻结档**：`01/02/03`、编辑器设计方案、`报告/*`、`mod-guide/*` 永不回写（`01` 里那一轮被加进去的
  "已完成并已移除"注释也删掉了，内容本来就在 as-built 里）。两份报告移进 `docs/报告/` 并加冻结横幅；
  `总结报告` §6b 那两张"最终依据"表搬进新建的 **`docs/决策记录.md`**（权威内容不该住在快照文件里）。

## 00 回到"总纲"，规划细节归 01

- **现象**：`00-架构总览与开发路线.md` 同时是总纲、决策表、refer 速查、文档导航四合一；它的分层图与工程结构
  是规划期的设想（Cloth Config / ModMenu / GeckoLib 的 fork 至今没有），却和 as-built 并列摆在入口位置。
- **定论**：`00` 只留**项目定位 / 决策表 D1~D15 / 术语表 / 版权边界 / 三阶段路线总表 / 文档导航**六节；
  原 §0.4 总体架构、§0.5 构建与分发、§0.8 refer 地图整体搬进 `01-第一阶段-核心底层.md` §1.16~§1.18（冻结）。
  版权边界留在 `00` 并重编号为 §0.4（它是项目级约束、不是某个阶段的事；这是对"§0.4~§0.8 全归 01~03"的一处
  有意偏离，两处引用已同步）。

## 分卷规则与搬迁审计：两处"看起来做完了"

- **现象 A（分卷规则没人守）**："主文件留最近 3 轮"只是文件头里的一句话。下一轮顺手在末尾再加一轮，
  谁也不会发现 —— 而它正是这样长到 2166 行 / 262 节的。
- **定论 A**：`DocLedgerTest.theChangelogKeepsOnlyTheThreeMostRecentRounds` 数主文件里的一级标题数，
  超过 3 就红并在消息里给出分卷步骤；按这个项目的惯例用**注入验证**过（临时加一个假轮次 → 确实红）。
- **现象 B（搬家会静默丢东西）**：`§9` 拆到"分册 + `todo.md` + 概览表"三处之后，逐条对照才发现
  `CanvasPage` 的 `palette.selected()` 回读这一处没有落地。搬的时候"看起来搬完了"。
- **定论 B**：搬家式整理的验收判据是**关键词回查**——把原 bullet 的关键词逐个在现有文档里搜一遍，
  缺哪个补哪个（这一轮 36 组关键词里查出 1 处缺失）。这条也记进了 `踩坑清单.md`。

## 一条新踩的坑

- **现象**：`git status --porcelain` 默认 `core.quotePath=true`，中文路径被写成 `\346\236\266...`，
  于是 `tools/doc_check.py` 的前缀匹配全部落空，脚本"看起来在跑"却什么也没提醒。
- **定论**：调用处统一加 `-c core.quotePath=false`；判据是"输出里看得见中文文件名"。
