# 架构变更记录 · 体验修正（选卡 / 锤子 / 孢子 / 魅惑 / 缩头 / 续档音乐 / 冰锥）

## 选卡页记得上一局的卡，而"我上次选了什么"不是关卡的一部分
- **现象**：`PvzceClient` 按 `世界|关卡` 记住玩家上次的选卡（`config/pvzce-seed-selections.json`），下次打开这一关的选卡页就把它填回去；没有记录时退一步"卡池的前 N 张"。于是"我想换一套打法"要先一张一张把上一局的卡取消掉，"第一次进这一关"也是别人（上一次的自己）替玩家选的。
- **定论**：**选卡页一律从空开始**，只保留关卡自己钉死的卡（那是关卡的设计，不是玩家的选择）。删掉整套记忆：字段、文件读写、`seedSelectionOrDefault` 与它的四个调用点（列表进入、存档提示框重开、暂停菜单重开、重启同一关）。同时把"正在进行的这一局的卡"与"下一局要选的卡"分开：前者由存档恢复（`SeedSelection.plan` 的 `loadSave` 分支），后者永远是空的。

## 木槌：30 秒冷却、50 阳光 → 20 秒、免费
- **现象**：`tools/hammer.json` 写的是 `use_cost.resources.pvzce:sun = 50` + `cooldown = 1800`（卡片自己的 `slots/hammer.json` 也是 1800）。2-5 那一关把它覆盖成"无冷却、不花阳光"，于是同一把锤子在两处的手感差得很远。
- **定论**：`use_cost` 清空、`cooldown` 与卡槽的冷却都改成 **1200 tick（20 秒）**；2-5 的关卡覆盖照旧（那一关的鼠标就是锤子，本来就不该有价格与冷却）。测试随之改成盯住新数字。

## 小喷菇的孢子是灰白色的，落地还炸出一团紫色的"啃咬云"
- **现象**：孢子贴图用的是原版 `Puff.reanim` 那套灰白烟雾的一帧，而命中特效指向 `pvzce:puff_splat` —— 那是**啃咬**（`PvzceParticles.CHOMP`）用的八个紫色大孢子团，于是每一发落地看起来都像被咬了一口。
- **定论**：两处都换成"孢子本来的样子"：孢子改用原版孢子粒子的紫色贴图（`refer/im7/particles/PuffShroom_puff1.png`，54×53 画布），命中特效新建 `pvzce:spore_splat`（三颗小孢子、0.2 秒淡出、轻微外扩）。`pvzce:puff_splat` 留给大嘴花与啃咬，两个效果不再共用一份定义。

## 被魅惑的僵尸继续朝房子走
- **现象**：`isCharmed()` 分支只改了"不吃植物、改咬僵尸"，移动方向仍然是 `cellX() - speed`，索敌也仍然只看左边。于是被魅惑的僵尸背对着自己要走的方向倒着走，走到房子前站着不动（`checkReachedLeft` 对它不上报，它就一直留在最左边）。
- **定论**：方向收敛成一处 —— `ZombieEntity.walkDirection()`（`-1` 朝房子 / `+1` 被魅惑）。移动、索敌（`enemyZombieInFront` 用同一个方向乘 delta）、离场判定（`checkReachedEdge`：往回走的从右缘离场并移除）都读它。**客户端把整只立绘水平镜像**：`AnimationPlayback.flipX`，控制器后端翻转每个 quad 的 x（逐角保留自己的 UV，绕序反过来无所谓——面剔除本来就是关的），帧序列后端交换 u0/u1，平面贴图兜底路径换 `drawTextureRegion` 的 u 区间。不镜像的话它会倒着走完整条车道。

## 大喷菇的喷雾无视一切护甲，于是橄榄球僵尸和普通僵尸一样脆
- **现象**：喷雾的伤害类型 `pvzce:spray` 写着 `ignores_armor: true`，`ArmorCapability` 根本不被征询 —— 铁桶、路障、橄榄球面罩全都不吃伤害。原版的喷雾是**穿门不穿帽**：纱门/报纸挡不住气体，帽子照样吸收。
- **定论**：`DamageTypeDef` 多一个 **`ignores_front_armor`**（缺省 false），`spray` 改成 `ignores_armor: false, ignores_front_armor: true`；`ArmorCapability` 在两条命中路径上都读它（`onProjectileHit` 直接按它选槽位，另加一个带类型的 `onImpact` 重载）。于是喷雾穿过 `front` 的那一件，落回 `top` 的那一件上。

## 用过一次铲子之后，点植物就铲掉
- **现象**：`InGameScreen.spendSelectedCard` 对**每一个**工具都记下 `carrySlot`（那是手套"拿着植物等第二下点击"用的），而清除它的 `syncCarry` 只在**携带的植物发生变化**时才动 —— 铲子从不携带植物，"空 → 空"不算变化，于是这个槽位永远留着。此后板子上任何一次点击都走"放下手里那株"的分支，把 `carrySlot` 里的铲子再发一次：没有选卡、卡面也不亮，但植物照样被铲掉。重进关卡时界面重建，`carrySlot` 归零，所以它"自己好了"。
- **定论**：只有会拿起植物的工具才留下"这一手还没完"（`carrySlotFor` = 手套才记，铲子/锤子立刻归 -1，测试钉住这条）；同时 `syncCarry` 改成**每帧**都按服务端的携带状态对齐（不再只对变化作出反应），槽位丢了也能从携带的植物 id 反查回来（`cardGranting`），所以丢槽位不会退化成"必须再点一次手套"。

## 手套抬起植物之后放不下：左下角说"不是工具卡"
- **现象**：手套的第一下把植物拿起来，第二下点草坪却放不下，服务端回一句"不是工具卡。"，植物一直拿在手上（只能等超时）。根因是**第二下用的卡不对**：`InGameScreen` 原本把"这次搬运是从哪个卡槽开始的"记在 `carrySlot` 里，而那一版为了修"点过一次铲子之后点植物就铲掉"把清除逻辑改成了"每帧按携带状态对齐"，于是抬起的下一帧（服务端还没回 `CarrySyncS2C`）槽位就被清掉了；等到携带状态真的到达，回填用的却是 `cardGranting(carried)` —— 那个查的是**携带的那株植物自己的卡**（一张植物卡），于是第二下把植物卡发上了工具路径，服务端自然回答"不是工具卡"。
- **定论**：**这一手归哪张卡不需要记**：两次点击都发给手套自己的卡槽，而它在卡栏里查（`gloveSlotIn` / `gloveInBar`，一场最多一张手套）。判定"现在手上有没有植物"用服务端的 `ClientLevel.carriedPlant()`（本来就画着那只跟随光标的幽灵），于是没有本地状态可以过期：没拿着植物时点击走普通路径，拿着时点击就是把植物放下。`carrySlot` 字段、`carrySlotFor` 与它们的分支一并删除，测试改成盯住"放下发给手套、不发给植物卡"这条查找规则。

## 毁灭菇的弹坑是整个爆炸范围，而不是它脚下那一格
- **现象**：`ExplosiveCapability` 把弹坑的覆盖范围直接用了 `blastRadius`（毁灭菇 = 3.0 → 7×7 格），于是炸过之后半个草坪都变成不能种的弹坑，恢复期长达 `crater_recovery`。
- **定论**：弹坑是**植物自己那一格**（`CRATER_RADIUS = 0.5`，与土豆雷"半径 0.5 = 自己这格"同一个读法），与爆炸范围解耦 —— 原版的毁灭菇留下的就是一个下沉的格子（那也是"把它种在哪"这个决定真正的代价）。测试逐格断言：除它自己那一格外，整块草坪都不是弹坑。

## 胆小菇只有半个向日葵高，缩起头之后就再也不动了
- **现象**：两件事。其一，它被拟合进"小蘑菇"的 0.38 格框，而它的 reanim 比小喷菇高近一倍（71.3px vs 38px），照原版比例它该有 0.726 格。其二，`hide` clip 写的是 `"on_end": "hide_loop"`，而 `AnimationClip.OnEnd.parse` 只认 `idle` / `next`，**其它值一律当 hold** —— 于是低头那一下播完就停在最后一帧，看起来就是"缩进去以后没有动画了"。同一条静默回退还压着墓碑破坏者（`on_end: chew`，落地之后不嚼）与阳光菇（`grow → idle_big`）。
- **定论**：`AnimationResourceLoader` 现在把 `on_end` 里的**clip 名字**解析成 `NEXT` + 该名字（`idle`/`next`/`hold` 三个关键字照旧），名字在这个文件里不存在时才退回 hold **并打一行日志**（诊断"这个动画停住了"原先指向不了任何地方）。加载器测试用真实文件钉住 `scaredy_shroom.hide → hide_loop` 与 `grave_buster.idle → chew`，以及"名字写错 → hold"。胆小菇的框改成按原版比例算出来的 `SCAREDY_SHROOM_BOX`（0.530 × 0.726），寒冰菇从同一个"小蘑菇"框放回 `PLANT_BOX`（0.83 × 0.76）。

## 续档之后音乐变成 grasswalk
- **现象**：音乐是一串**事件**（`LevelDef.music.cues` 按 tick 发 `MusicEventS2C`），服务端的游标 `NextMusicCueIndex` 随存档保存，但"现在在放哪一首"没有任何地方记着。续一局打到一半的关卡时，游标已经越过了 0 tick 的那条 cue，客户端只按"进入关卡"播了默认曲（grasswalk），夜晚的 `moongrains` 再也不会来。
- **定论**：`LevelServer` 记下**当前曲目**（`currentMusicCue`：每发一条 cue 更新，`stop` 或无事件的 cue 清空），`restore` 时按保存的游标把 cue 表重放到该位置（而不是把曲目本身写进存档 —— 那会是关卡音乐块的第二份副本），`sendFullState` 在 init 之后把它作为一条 `MusicEventS2C` 重发。重发同曲在客户端是幂等的，所以顺带覆盖了"第二个玩家加入"与"同一局 resync"（`ServerMenuFlowTest` 断言 resync 不停任何轨道、只说当前曲目）。

## 舞王的召唤没有动画，而且补人补得太快
- **现象**：`SummonDancersCapability` 靠 `walkState()` 返回 `armraise`，但召唤期间它自己 `tickMovement` 返回 true —— **走路循环整个不跑**，而那是 `walkState` 唯一的调用方。于是举手这一拍被选中了却从没发布出去。补人的间隔还是 120 tick（2 秒），一队伴舞刚被清掉就又站满了，玩家永远清不完。
- **定论**：召唤期间由能力自己每 tick 发布 `ARM_RAISE`（与蓄力地雷每 tick 发布 `armed` 同一个做法），间隔默认与数据都改成 **1200 tick（20 秒）**：清掉一队之后有二十秒的窗口，这才是"他带来的是一次压力"而不是"打不完"。

## 寒冰菇只冻 3.25 秒，冻住的僵尸还在原地走路
- **现象**：`freeze_ticks` 是 195（3.25 秒）；`IMMOBILIZED` 只让服务端停止移动，客户端既不知道有这回事（`EntityUpdateS2C` 只有 `chilled`，那只是"变慢"），也没有任何画面 —— 被冻住的僵尸原地走完走路循环，看起来像卡住了。
- **定论**：冻结改成 **6 秒**，并把 `frozen` 作为一个新的状态位发出去（`EntityUpdateS2C.frozen`，协议 21 → 22；`ZombieEntity.frozen()` = `IMMOBILIZED` 且还活着）。客户端据此做两件事：在僵尸脚下画原版 `icetrap` 那张冰锥图（`textures/entities/status/frozen_spikes`，0.675 × 0.375 格，z 在影子与僵尸之间），并**按住这条 clip 的时钟**（`AnimationPlayback.setPaused`：暂停时把时间锚在当前帧，解冻时把锚整体后移，动画从那一帧接着放）。测试断言更新包里的 `frozen` 与被冻/被豁免的两类僵尸。
