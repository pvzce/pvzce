# 节奏草坪的僵尸改成自动计算：没有波表、只有一段曲线

> 用户两条：能量两档 3000/5000 "太容易达到"，改成 **6000/12000**；以及"这几关不要有波数了，
> 无限出僵尸，过关条件必须是完成铺面，关卡只需要设置一个难度系数，后面出什么、出多少完全由
> 自动计算得出"。第一条是调参，第二条是把这一关的**出怪**从"写一张表"换成"算一条曲线"。

## 现象与根因

- **能量条的上限比第二档还低**：上一轮把上限定在 6000，而这一轮要把第二档抬到 12000——那样
  ×3 是个永远拿不到的数。上限必须高于最高那一档（改成 15000，第二档再加四分之一）。
- **四张谱面各写了一张六波的波次表**（`RhythmCharts.WAVES`，每档 6 波、总量递增、每波五行全点名），
  而这一关的时钟是歌：表在歌之前发完就只剩站着，歌放完却没发完就是白送。上一轮的生成器为了
  "表刚好铺满歌"把 delay 手写成一万 tick 左右——**那是一张一次性算好的表，改一个 BPM 就全错**。
- **"无限出僵尸"这件事已经有现成机制**：`pvzce:endless` 的数据表（`EndlessScheduleDef`：僵尸池
  按"轮"解锁）+ 纯生成器（`EndlessWaves`）+ 导演（`WaveDirector` 通过 `Host.waveAt(round, index)`
  一次要一波）。缺的不是机制，是**"轮"在节奏关卡里该是什么意思**。
- **导演的回合滚动是要玩家选卡的**：`rounds=true` 的关卡每轮结束走 `tickRoundClear`，弹"选卡进
  下一轮"并等玩家（超时才自动继续）。节奏关卡不能要这个——歌中间没有选卡这回事。
- **右下角那条波次条是 `totalWaves()` 画的**：只要它不为 0，屏幕上就有"第 N 波 / 共 M 波"。
- 顺带发现 `EndlessMechanic.previewWaves`（"生成波的关卡该拿第一轮当预览"）**没有任何调用方**，
  于是无尽关卡与节奏关卡的选卡页一直是空的僵尸预览。

## 定论

- **`RhythmChartData` 多一个 `difficulty`，默认 0 = 关**。0 表示"照旧用关卡自己的波表"（手写谱面与
  所有既有测试都不受影响），正数才打开模式自己的僵尸时钟。它同时是**关卡关于出怪说的唯一一句话**：
  **池子、解锁顺序、数量、间隔、血量成长全部自动算**。四档的系数是用户给的 **0.6 / 1.0 / 1.5 / 2.2**
  （`RhythmCharts.TIER_DIFFICULTY`）；上一轮那三张速度/间隔规则保留，它们说的是"僵尸走多快"，
  不是"来的是什么"。
- **"轮"= 歌里的位置**（`RhythmWaves.roundFor`）：`1 + 谱面进度 × 调度表的 count_ramp_rounds × 系数`。
  于是系数 1 表示"整首歌刚好把调度表走一遍"（最后一小节到池子顶部），2.2 表示"走两遍还多、收尾时
  每条曲线都进了封顶段"。谱面时钟只往前走，所以轮数单调——**池子只会越来越强，不会回头**。
  生成器一行没改：`EndlessWaves.wave(schedule, 轮, index, 水陆行, random)` 原样复用，
  连"水行只放会水的"这条行安全也是白拿的。
- **共享调度表 `EndlessSchedules.rhythmLawn()`**（id `pvzce:rhythm_lawn`）：普通僵尸开场，逐段解锁
  路障 / 旗帜 / 撑杆 / 铁桶 / 读报 / 橄榄 / 门板；**没有巨人**（键盘回答不了的墙）、**没有矿工与气球**
  （判定线盖不到的层）、没有水生（节奏草坪是草坪）。间隔取 360→120、波间空档 420→180
  （比无尽那两条紧：一首歌三分钟，不是一晚上）。
- **没有波表，也没有波数**：`waves: []`；`LevelServer` 里"生成波"的关卡现在有两种（无尽 / 节奏），
  共用 `waveAt` / `wavesInRound` 两条分支。`Host.showsWaveCount()` 是新增的那一问：节奏关卡答 false，
  于是 `WaveProgressS2C.totalWaves` 与 `LevelServer.totalWaves()` 都是 0，**右下角那条进度条整条不画**。
  **大波横幅保留**（用户要求）：预警走的是 `warningActive` 而不是总数，所以"一大波僵尸正在接近"
  照旧；而 `WaveWarningFinal` 需要 `WaveType.FINAL`，生成器只发 HUGE/SMALL，所以**永远不会误报
  "最后一波"**。
- **回合滚动是静默的**：`tickRoundClear` 对节奏关卡直接 `beginNextRound(bridge, false)` ——
  不弹选卡框，也不发"第 N 轮开始"那行消息。一轮 12 波（`RhythmWaves.WAVES_PER_ROUND`）纯属记账：
  歌长到超出它才会发生，玩家看不到任何痕迹。
- **赢法就是歌放完**（原来就是这样，现在成了唯一一条）：`end_beat` 到点 → `sweepLawn` +
  `declareVictory`；波次导演在"波是生成的"关卡上从不自行判胜（`endless` 位）。因此校验加了两条：
  **带系数的谱面必须写 `end_beat`**（否则是一局只能输的关卡），**也不能再写波表**（两个答案，一个会输）。
- **预览补上了**：`payloadFor` 里新的 `previewZombies` 先读关卡自己的表，读不到就问生成器要
  "开场那一波"——`EndlessMechanic.previewWaves` 那个死方法终于有了调用方，无尽的选卡页也一并有了
  僵尸预览。
- **能量**：`ENERGY_DOUBLE_AT` 3000→**6000**、`ENERGY_TRIPLE_AT` 5000→**12000**、
  `ENERGY_MAX` 6000→**15000**（上限必须高于最高那一档，否则那一档是个够不着的数）。
- **编辑器**多一栏"出怪难度系数"：只填一个（普通档的），四档按 `TIER_DIFFICULTY` 的比例摊开——
  "一个系数"这句话在编辑器里也成立。

## 验到了什么

- `RhythmTest` 增补：轮数=歌里的位置（第一小节是第 1 轮、最后一小节在系数 1 下正好走完一遍、
  **全程单调不回退**、超出歌尾也不再爬）；同一个位置在 2.2 档比 1.0 档更深；收尾那一波的池子比
  开场深、开场没有橄榄球而收尾有；生成波的关卡 `isEndlessRun()` 为真、`showsWaveCount()` 为假、
  `totalWaves()==0`、`waveAt(1,0)` 拿到一波且每只都点名五行；带系数但没有 `end_beat` **被校验拒绝**；
  带系数又写波表**被校验拒绝**；不带系数的谱面仍走关卡自己的表；开场预览非空且只含开场那一档。
- 能量那三条按新档位重算：62 个 PERFECT 过 6000（得 ×2）、124 个过 12000（得 ×3）、
  155 个填满 15000 封顶。
- `RhythmChartsTest.everyTierIsAHorde` 改写成"曲线"：四档的 `waves` 必须是空的、每档的
  `difficulty` 比上一档高、每档都有 `end_beat`，速度与间隔规则照旧钉住。
- 四张已发布谱面由生成器重写（`-Ppvzce.smoke=pvzce.writeRhythmLevels=true`）：**删掉 1233 行波次表**，
  换成一行 `"difficulty"` 与 `"waves": []`。
- 冒烟（`.smoke/rhythm-spawn/`，一次启动 25 秒）：节奏关卡里僵尸照常从右边走进来（画面里有普通僵尸、
  路障、撑杆），**右下角没有进度条**，能量条与判定照旧；同一张胶片还拍到红色的 **MISS** 判定字。
  一整首歌（约 11k tick）的通关没有跑过——记在 `todo.md`。
