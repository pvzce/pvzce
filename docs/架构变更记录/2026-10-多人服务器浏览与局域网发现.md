# 多人服务器浏览与局域网发现（2026-10-30）

现象：多人入口只能手填地址，常用服务器不能保存，也看不到同局域网房间；真人对战沿用地图植物开局资源，玩家反馈过高。

- 多人首页使用已保存服务器列表与局域网游戏列表，保留昵称和创建合作/对战入口。直接连接、添加/编辑共用表单；保存后保留选择，取消保留原列表，删除先确认。
- 服务器名称、规范化地址和昵称落入游戏目录 `config/servers.json`，直接连接与发现记录不写入书签，不保存凭证。保存和连接共用无 DNS 解析的地址校验，支持 IPv6；损坏列表不覆盖并明确提示。
- 房间持续向可用 IPv4 网卡发布 UDP 组播公告，浏览器后台扫描并按实例标识去重、过期移除，显示模式/人数/状态。点击局域网房间走原 TCP 握手，已满、版本不符与已开始的对战禁入；合作中途加入保留。
- 广播与扫描具有明确关闭生命周期，退出客户端释放屏幕栈持有的资源；连接中返回取消任务、恢复本地服，迟到暂停确认不再继续连接。
- 真人对战植物初始阳光改为 50，数值收口常量；人机经济和僵尸地图配置保留。回归覆盖房主选择两侧时的真实 TCP 开局资源与动作。
- 定向回归覆盖保存后重载、编辑/删除、损坏列表保留、地址校验、表单取消/缩放、点击加入、连接取消、真实 UDP 收发、同房间多网卡去重和过期。真实服务端组播发现探针验证去重后的唯一房间，日志 `.smoke/server-browser/regression.log`、`cancel-tests.log`、`lan-dedup.log`。
- 游戏/API 全量回归通过，沿用逐类独立 JVM 和扩大堆的临时测试配置；协议往返、文档符号/统计/台账及分层守门通过，日志 `.smoke/server-browser/full-tests.log`。
- 唯一一次 1080p / 2× UI 冒烟核对列表、添加、直接连接和合作大厅，截图 `.smoke/server-browser/film_180.png`、`film_360.png`、`film_720.png`、`film_1080.png`。冒烟期间并行重编译导致新旧类混用，末段广播线程出现链接错误，不能记为整次冒烟无异常；最终代码的独立组播探针与自动回归另行通过，未再次启动游戏。
