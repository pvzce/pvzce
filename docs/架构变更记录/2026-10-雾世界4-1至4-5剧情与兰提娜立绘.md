# 4-1~4-5 的剧情：兰提娜登场、立绘的「站多高」，以及一次缩小演出

## 现象 → 定论

用户给了 4-1~4-5 五段台词（沿用 3-1~3-10 那种 `4-N` / `左，角色，表情，台词` 的记法），
其中 4-2 写着「（lantina滑入，同时将purwhite的scale缩放到0.33并作用于该关卡之后所有purwhite）」——
这句话现有数据表达不了两件事：`lantina` 这个角色不存在，而 `animation` 只作用于**当前说话人**
（`DialogueOverlay` 里写死 `speaker && ...isShake()`），所以「她说话、另一个人在她这句话里变小」
没有地方可写。用户确认了两条边界：0.33 **只做到 4-5**（4-6~4-10 以后写了对话再说），
并且**只是立绘变小**（紫夜白在关卡里没有实体）。

- **新角色「兰提娜」（`pvzce:lantina`）**：14 张立绘从 `refer/char/lantina/` 拷进
  `assets/pvzce/textures/gui/dialogue/lantina/`（`refer` 只读，贴图是往仓库里搬），
  `data/pvzce/dialogue_characters/lantina.json` 给显示名"兰提娜"，`portrait_insets` 按既有口径
  离线量出（一列/一行有 5% 像素不透明才算"有画"；只有非零的那些进表）。素材对照表与汇总
  跟着更新（+14 文件 / 27.90 MB，原创 97 个；`excited` / `halloween_smile` / `hallowen_confused`
  三张是 4-7~4-10 用了之后补的量，`hallowen_confused` 的拼写照文件名原样保留）。
  她的"发光"用参考图自带的 `glowing` 立绘 +
  已有的 `scale` 演出表达，没有新机制、没有屏幕特效。
- **`DialogueAnimation` 多一个 `target`**：不写 = 说话人（**所有老台词一字不变**），
  `"all"` = 台上每个人，或者一个角色 id（`"target":"pvzce:purwhite"`）。**多一个 `duration`（秒）**：
  不写 = 这一类自己的时长（抖动 0.35s、缩放 0.25s），写了就按它插值。
  4-2 那一句因此可以写成"兰提娜一走进来，紫夜白就在她这句话里矮下去，用 0.7 秒"——
  用户的修正正在这里：**身高差要在滑入的同时发生**，而滑入只有 0.35s，缩放默认 0.25s
  会在人还没站定时就缩完，看起来像硬切。`duration` 就是为了让"走进来"和"矮下去"共处一段画面。
- **`scale` 是"这个人站多高"，不是这一句的姿势**：它写进
  `DialogueScript.StagePortrait.baseScale`（字段由 final 改成可变），之后的每一句——包括一个字都
  没提大小的那些——都按这个尺寸画，直到另一句再改它。所以 4-2 只写一次，4-3~4-5 各在自己的
  第一句上再写一次（**一段对话是一个独立的世界，上一关留下的尺寸带不过来**）。点到不在台上的人
  时什么都不做并在日志里点一行（名字打错不会让立绘抽一下再变回来）。`shake` 仍然是"这一句"的
  事，不改尺寸；它现在也按 `target` 生效（`DialogueScript.effectTargets` 是那份"这句话动了谁"
  的唯一答案，`DialogueOverlay.shakes` 直接问它）。
- **缩小的立绘站在窗口底部**：0.33 的人不再是"贴着窗口下沿画 90% 高"的那张图，
  `y` 就是 0、绘制高度是 `layoutHeight * scale`，所以她的脚在**窗口下沿**（与大个子同一个底边，
  而不是与大个子的头顶同一条线）。同时 `laidOutScale()` 把"两人并排要缩多少"变成**整块舞台**
  的一个系数（谁最高谁占满 0.9H），每个人再乘自己的 `baseScale` —— 旁边站一个小个子不会再被
  算进另一个人的高度里，占位宽度也按画出来的尺寸算。
  40 关已有的对话（1-1~2-10、3-1~3-10、5-x）里所有角色 `scale` 都是角色默认值，
  新算式与旧算式逐像素等价（旧代码里唯一的 `scale` 来源是整段对话的逐行动画，而它默认 1.0）。
- **编辑器不丢字段，而且把它们写出来**：`LineModel.animationTarget` / `animationDuration` 读进来
  再原样写回（`animationJson`），动画按钮的文案带上它们（`动画：缩放→紫夜白 0.7s`）。页面还没有
  编辑这两个字段的控件，但保存时丢掉等于把"她说话、另一个人变矮"改成"说话人变小"，
  是改剧情而不是丢装饰；而只显示"缩放"和数值框里的 0.33，会让人以为缩的是说话人自己。
- **九段台词写进关卡**（4-1~4-5 与 4-7~4-10；4-6 作者没给）：
  4-7（9 行，星星果那段——4-6 首通发的正是杨桃，0.33 钉在兰提娜的第一句上）、
  4-8（7 行，万圣节：兰提娜穿 `halloween_smile` / `hallowen_confused`，紫夜白没有节日装，
  作者确认就用平时的立绘）、4-9（5 行，作者指定磁力菇那段留在这里——它是 4-8 首通发的植物，
  这一关自己发的是迷雾退缩增益）、4-10（7 行，雷雨：第一句紫夜白发抖、第二句才写 0.33，
  因为**一句台词只带一个 animation**，两个都塞进第一句时后写的 `scale` 会把 `shake` 挤掉）。
  最早的 4-1（紫夜白一个人的独白、7 行）、4-2（兰提娜滑入 + 缩小，21 行）、
  4-3（7 行；紫夜白的第一张立绘按作者要求用 `smile`——她刚夸完姐姐，`star` 留给她下一句）、
  4-4（6 行）、4-5（5 行），都插在 `music` 之后、`unlock` 之前（与其它有对话的关卡同一位置）。
  4-2 起兰提娜在左、紫夜白在右；双人场面的每一句都显式写 `slots`（3-2 踩过的坑：不写 `slots`
  的句子虽然不动舞台，但这种场面靠"上一句留下的"太脆），非说话人的立绘沿用上一句。
  4-1~4-5 与 4-7~4-10 的 `dialogue` 块都由 `tools/write_adventure_levels.py` 的 `CARRIED_BLOCKS`
  原样搬回，重生成关卡不会吃掉它。

## 验证与边界

`DialogueStageTest` 新增三例：`scale` + `target` 改的是被点名那个人的**常驻**尺寸（下一句没写动画
也还是 0.33）、抖动不附带改尺寸、`"all"` 同时作用于台上两个人；`DialogueMotionTest` 新增一例钉住
`duration`（0.7s 的那一刻，内置时长早就结束、它还在路上，到点又确实落位；不写就是内置时长，
不是瞬间完成）；`LevelFileWriterTest` 的动画往返用例补了 `target` 与 `duration` 必须原样写回。
全量 1469 例通过（DocStats 的规模块按生成命令写回）。

实机冒烟（`.smoke/4x-dialogue/`，4-2、4-3 与 4-8）：4-8 的 `shots4/h_480.png` 是万圣节那一段
（兰提娜穿节日装占满她那一侧、紫夜白 0.33 在右下、两人脚都在窗口下沿）。`shots/s_490.png` 是前五句（紫夜白一个人，正常大小），
`4-2-兰提娜滑入并缩小.png` 是滑入那一句说完之后（兰提娜满高，紫夜白已经矮下去），
`4-2-缩小后同台.png` 是她接着说、紫夜白回嘴的那一句——两个人各站在自己那一侧、
**两个人的下沿都是 0（窗口底）**。`[DLG]` 的 trace 在 4-2 的"好小一只"那一句是
`line=6/21 portraits=2 ... at purwhite=3,0 71x107 lantina=419,0 216x324*`（GUI 640x360）：
小的人 71x107 站在 (3,0)，大的人 216x324 站在 (419,0)——**同一个 y**。

**这一轮抓出三个"只有看图才会发现"的错，都已修**（算法与坐标都没问题，错在"用哪个高度"／"地面在哪"）：

1. 并排要占多宽时忘了乘每个人的尺寸。0.33 的人被当成整宽去排队，两个人一起被压到
   `MIN_PAIR_SCALE = 0.62`，而"脚踩地"是按 layout 高度算的——两条规则一叠加，那位小个子
   **贴着右上角悬空**（`three_119.png`）。现在 `laidOutScale()` 按"画出来的宽"量。
2. 右侧立绘还留着旧布局的"以中心线缩放"补偿（`x += (width - scaledWidth) / 2`）。旧布局把框按整尺寸
   摆好、只缩绘制，所以需要它；现在框本身就按画出来的尺寸摆在窗口边距上，这个补偿把右侧的人
   **推出了屏幕**——trace 里紫夜白是 `x=638`（GUI 宽只有 640）而她自己宽 71。删掉即可。
3. **小个子的"地面"选错了**（用户看过第二版截图之后指出："位置错误，应该在最下面而不是上面"）。
   前两条修完之后 0.33 的紫夜白仍然**飘在画面上方**：我把 floor 理解成"大个子的脚下"
   （layout 高度那条线，窗口高度的 90% 处），而她比大个子矮得多，那条线在她看来就在半空。
   定论：**floor 就是窗口下沿，对每个人都是**（`y = 0`，立绘本来就从下往上画）。

三条都进了 `踩坑清单.md`（第 203、204、206 条），trace 也因此在 `[DLG]` 行里多印了每个人落点与尺寸：
截图里"人不见了"和"人被画到窗口外"长得一模一样，"飘着"和"站在底"也只有数字能分开。

4-6~4-10 还没有对话，0.33 因此**不在**那些关卡里（用户已确认只做到 4-5）；给它们写对话时
照 4-3 的第一句抄一行 `{"type":"scale","scale":0.33,"target":"pvzce:purwhite"}` 即可。
编辑器还没有"这句话动谁"的输入框（只保留字段），已记在 `todo.md`。
