# Linux 默认后端切回 X11/XWayland：系统标题栏换触控

> 用户在我确认"Wayland 上拖不动窗口"之后拍板："暂时先把 wayland 支持禁用掉，回退到 X，
> 不要删除现在的代码，只是禁用功能。"

## 现象与根因

- 三条路连着走完，原生 Wayland 在**这套栈**里能给的只有"能触控"：窗口装饰靠 libdecor 而它的 GTK
  插件在 JVM 里必然拒载（`踩坑清单` 118）、GNOME 不给服务端装饰（119）、拖动要 GLFW 私有的
  `xdg_toplevel` 而那个指针够不到（125）。自绘标题栏只补上了"能关能最小化能最大化"这半件事。
- 用户要的是能用的窗口：系统标题栏 + 能拖动。这需要换后端，而不是继续在 Wayland 上加补丁。

## 定论

1. **新增配置 `prefer_x11`（`PvzceClientConfig`，默认 `true`）**：Wayland 会话下若 `DISPLAY` 存在，
   改用 X11/XWayland。显式 `-Dpvzce.platform=wayland|x11` 仍然最高优先；既没有 XWayland 也没有
   Wayland 时照旧回落到 `GLFW_ANY_PLATFORM`。
2. **Wayland 那条路一行没删**：`WaylandTouch`、`WaylandWindowMove` 的结论、自绘标题栏全部保留，
   切回去只要 `-Dpvzce.platform=wayland`（或 `prefer_x11 = false`）。实测三种情形：
   默认 → `platform=393220 边框=[0, 37, 0, 0] 自绘标题栏=false`；
   `pvzce.platform=wayland` → `platform=393219 边框=[0, 0, 0, 0] 自绘标题栏=true` 且"触控：已接管"；
   `pvzce.platform=x11` → 同默认。
3. **取舍写在明面上**：X11/XWayland 下 Wayland 桌面的触摸不会进游戏（XWayland 只转发指针），
   日志也从"手指由系统提升成鼠标事件，无需接管"改成**分清两种 X11**（真触摸屏由 XInput2 变成
   指针事件；Wayland 会话下的 XWayland 不转发触摸）——原来那句话在后一种情形下是错的。
4. **自绘标题栏自动让位**：`frameInsets` 非 0（X11 的 37 像素标题栏）时不画、不吃点击，
   所以不会出现两条标题栏。这一点不需要额外开关，判据就是启动行的 `自绘标题栏=false`。

# 自绘标题栏点不动：Y 轴两个原点，以及"画出来的"不等于"可点的"

> 用户报："这三个键好像也点不动。" 我自己先用三条冒烟路径验过三键全绿——**那三条路径都在骗人**，
> 这一轮的主要内容其实是把验证方法修对。

## 现象与根因

- **用户侧的判据**：`[标题栏] 按下 x=1268 距顶=713.65 … 命中=null`。原始指针 `y=12.7`（窗口顶部
  12.7 像素，正是三个符号所在），却被算成"距底部 713"。
- **根因一：同一个指针被两种 Y 表达混用。** GLFW 的回调报"距顶部"，GUI 投影的原点在底部，
  `guiMouseY` 把前者翻成后者。标题栏按 **GUI 的 Y** 判定、按 **距顶部** 画，于是"红十字明明压在 `▢` 上、
  按下却说不命中"——两个原点，一个指针。
- **根因二：靶子太薄。** 高度按 GUI 高度算（`720/240 = 3`，被下限夹到 18 GUI 单位 = 36 设备像素），
  而**可点区域就是那 36 像素**、边界以外一律不认。用户的几次点击分别落在距顶 12.7 / 14.5 / 19.0 像素——
  全都在"看起来是栏、判定不认"的那条缝里。Windows 的标题栏是 46 设备像素、GNOME 是 47。
- **根因三（这一轮的教训）：我的三条冒烟路径都没走真路。** `smokeClick`/`smokeRelease` 直接调
  `dispatchMouseClicked`，跳过帧循环；`smokeHold` 又靠 `warpCursor` 摆指针，而**这台合成器直接忽略
  `glfwSetCursorPos`**，于是指针留在原处、命中判定用的却是别处的坐标。绿的是一条设备不会走的路
  （`踩坑清单` 第 116 条的老毛病，第三次犯）。

## 定论

1. **标题栏只在"距顶部"这一个 Y 空间里工作**：`PvzceClient.guiMouseYTopDown()` 在边界处换算一次
   （比例是 `窗口高 / gui高`，**不是** `guiScale`——两者只在窗口与 framebuffer 等大时相等），
   `WindowTitleBar`/`TitleBarGesture` 全部按它判定，屏幕探针也按它画。
2. **栏有了物理下限**：`MIN_PHYSICAL_HEIGHT = 44`（`ceil(44/scale)` 个 GUI 单位，用 `ceil` 免得差半像素），
   与 GUI 高度 1/240 取大者。上报那台 1440p/gui_scale 2 的窗口因此是 22 GUI 单位 = 44 设备像素。
3. **可点区域比画出来的略高**（`ACTIVATION_OF_HEIGHT = 1.2`）：栏下沿再宽限一点，"看着像栏"就不会白点；
   再往下仍归游戏，免得吃掉卡槽那一行。
4. **`pvzce.smokeHold=<x,yFromTop>`：真正走帧循环的按住钩子**，并且**每帧重新记录指针位置**
   （合成器忽略 warp，且指针回调会覆盖）——`y` 与指针回调、与标题栏同向（距顶部），不跟别的钩子的
   "左下原点"混。判据：`[标题栏] 按下/抬起` + `标题栏：按下 X`。
5. **`-Dpvzce.traceTitleBar` / `-Dpvzce.tracePointer`**：一条按一行打出按键区间、命中结果、
   回调指针与现场指针；另一个把指针位置和两条边界（画的栏下沿、可点带下沿）画在屏幕上。
   这一轮就是靠它们把"两个原点"和"靶子太薄"分开的。
6. **`pvzce.smokeClick` 只发按下**（见 `踩坑清单` 120），要"按下再抬起"用 `pvzce.smokeRelease=<帧数>`。
