# 商店钱包的"必须先进一次关卡"、左下角托盘的尺寸与标题页排版

> 归档自 `../架构变更记录.md` §2（该轮加入时它是最近 3 轮之外最老的一轮）。
> 归档只搬家不改写：正文与当时写下的一字不差。

> 用户第二批反馈："左下角按钮太小了，你在测试 UI 合不合适的时候，最好按照 1080p 2x UI 来测试，
> 这是大部分玩家的环境（记得写入文档便于之后的工作）"；"商店有 bug，必须要点击一次开始游戏，
> 再回到主菜单，点进去商店才显示金币数量，否则显示的就是 0（可能是因为存档还没有被加载到内存的缘故？）"

## 钱包显示 0：档案只在关卡列表那条路上来

- **现象**：全新会话里直接从标题页进商店，钱包写 **0 金币**；开一局、退回主菜单、再进商店就对了。
- **根因**（与用户的猜测一致，只是"存档"的落点更具体）：客户端在**每次换世界**时都会
  `profile.reset()`（这是有意的：新世界的列表还在加载时不能显示上一个世界的钱），而档案
  （钱包 / 卡槽 / 解锁）**只**由 `ProfileS2C` 填进来，那个包只有 `sendLevelList` 会发 ——
  商店却可以在**从不打开关卡列表**的情况下进去（标题页左下角的托盘直达）。
- **定论**：新增 `RequestProfileC2S(worldName)`（协议 34 → **35**，C2S id 27）。标题页那两个格子在
  `openScreen` 之前先 `client.requestProfile()`；`PvzceClient.profileLoaded` 在换世界时清掉、
  由到达的快照置位（**发送时也置位**，否则两次点击就是两个包），所以"问一次"是幂等的，
  而先开过关卡列表的客户端**一次都不会问**。服务端沿用 `menuWorld()` 与 `profilePacket`，
  与关卡列表那条路回答的是同一个世界。
- **判据**：`MenuProfileFlowTest.theServerAnswersWithTheWorldsWallet`（真起服务端，内存连接，
  世界 `aaa` 的存档里 1234 金币 → 收到的 `ProfileS2C.coins == 1234`）、
  `…theRequestIsNotRepeatedOnceTheProfileHasArrived`（两次问只发一个包；快照到达后再问不发；
  换世界后可以再问）。

## 左下角托盘：尺寸改成随菜单按钮与窗口算

- **现象**：1080p + 2x UI 下（GUI 960x540）菜单按钮 68 单位高，托盘却还是固定的 22 单位图标，
  像个涂鸦；而按"随按钮放大"改之后，它在默认窗口又压到了玩家木牌上 —— 木牌的点击判定在托盘之前，
  于是点商店格子弹出的是**玩家选择器**。
- **定论**：托盘几何抽成一个纯函数 `TitleScreen.TrayLayout.forCorner(buttonHeight, availableWidth)`，
  两个约束取小者：
  - **纵向**：一格 = 1.5 个菜单按钮高（图标因此始终与旁边的按钮同量级）；
  - **横向**：两格 + 留白必须放得进**窗口左缘到菜单列左缘**之间（`menuGap`），
    因为菜单列居中且 280 宽 —— 默认窗口只有 65 单位，这正是"图标 + 文字"当年放不下的原因。
  - 图标下的木牌按**图标宽度**取，不按格子高度取：短格子里"牌子占三分之一高度"会把图标压成一条
    （GUI 427x240 下只剩 8 单位）。
  - 托盘与菜单列**共处同一条带**（都锚在底边）。曾经按玩家木牌的下沿定位，而木牌锚在**顶边**，
    1080p 下托盘被摆到屏幕外 —— 截图上是"左下角什么都没有"。
- **判据**：`TitleScreenTrayTest`（三档窗口尺寸：托盘在窗口内、不越菜单列、图标 ≥ 按钮的 40% 且 ≤ 110%）。
- **冒烟**：新增 `pvzce.smokeTray=<格>@<帧>`（坐标由 `TitleScreen.trayCell` 给，与命中判定同一处）
  与 `pvzce.smokeCoins=<n>`（走 `/profile coins` 真命令路径，等关卡列表回来再发）。

## 验界面的参考环境写进文档

- **1080p + `gui_scale=2`（GUI 960x540）**，写进 `冒烟与截图指南.md` §2.3 与 `决策记录.md`。
  窗口尺寸与 GUI 缩放只能写在 `config/pvzce-client.toml`，所以要事先把那份 toml 放进占位游戏目录。
  默认的 1280x720 只有参考环境**六分之一**的面积，不能当"够不够大"的判据 —— 左下角托盘连着三版
  都是"在 1280x720 看着挺好"放过去的。

## 顺带

- `/profile coins <n>`：把金币发给菜单当前的世界（`PvzceServer.grantCoinsToWorld`），
  给"买得起东西"的商店页截图用；这也是第一条能从控制台改钱包的命令。
- `PacketProtocolTest` 的样本集与黄金字节流跟着新增的包更新（`RequestProfileC2S:1b05776f726c64`，
  `LevelInitS2C` 里的协议号 0x22 → 0x23）。
