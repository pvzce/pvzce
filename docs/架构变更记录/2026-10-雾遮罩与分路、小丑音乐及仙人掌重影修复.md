# 雾改成"盖住"而不是"删掉"、出怪分路、小丑的音乐盒与仙人掌的重影：一轮十一项修复

## 现象 → 定论

用户一次给了十一条（雾六条、出怪两条、小丑音频、仙人掌动画、荷叶高度），逐条查完的定论：

1. **选卡页与开场对话里没有雾**（"关卡正式开始前"）。`ChooseSeedsScreen` 只画背景、草坪与预览僵尸，
   而它手里的 `LevelPayload` 本来就带着关卡的 `pvzce:fog` 块。定论：`FogClientMechanic.declaredIn`
   把它读出来，草坪之后、预览僵尸之前用同一个 `FogCloud` 画一遍——云要伸出棋盘右缘（预览僵尸站在
   马路上，那是"名单"不是棋盘上的东西，所以画在它之后）。
2. **雾里的僵尸直接消失**。原来是"命中 `hides()` 就不画实体"，而云画在实体**之前**，所以去掉剔除
   只会变成僵尸盖在雾上。定论：云改到实体之上（`ClientMechanic.WorldOverlay.renderOver`，在
   `InGameScreen` 的实体循环之后、玩家手上的幽灵与粒子之前），`FogClientMechanic.hides()`、
   `FogData.hidingColumn()` 与 `HIDE_FRACTION` 一起删掉——"看不见"从"删实体"变成"盖住它"。
   唯一保留的判据是 `covers(x,y)`（"云盖在这儿吗"），给画在云之上的 HUD 标签用（`EchoLilyLinks`
   的主机标签），否则标签会把雾要藏的东西说出来。
3. **云贴图被乘了两次相机缩放**：`tileOrigin`/`tileSize` 在"背景图像素→格"（÷80、÷85）之后又乘了
   `camera.boardScale()`，1080p 下每片云大 1.8 倍；同一个类里 `hidingColumn` 用的却是没乘过的
   0.1875 格——一个事实两个值。定论：网格全部在**格**里（`client/renderer/FogCloud` 的常量），
   `FogCloudTest` 按格断言，并断言"换个窗口它们不变"。
4. **路灯花的光圈缺失**：清雾是 `1 - t²` 的从中心衰减，而云是两三片叠着画的，压到 70% 再叠起来与
   没压一样。定论：改成原版 `Board::ClearFogAroundPlant` 的形状——核心整片清空（半径的
   `LAMP_CORE = 0.72` 以内 `clear = 1`）、只留一圈边缘；路灯花半径 2.5→3.0（原版清 ±3 列 / ±2 行）。
   画法随之改成**逐格浓度** `max_alpha × FogMechanic.revealCoverage(...)`：被清空的格子干脆不画，
   洞是真的洞（原先的"每格 4×4 细分、逐角取 alpha"整段删掉）。`alphaAt` 的斜坡只决定哪些格有雾。
5. **火炬树桩也应该有微弱照明**：原版 `Board::UpdateFog` 里除了路灯花还有 `SEED_TORCHWOOD`
   （`ClearFogAroundPlant(plant, 1)`）。定论：`torchwood.json` 加一条 `pvzce:reveal`
   （radius 1.4 / strength 0.8）——自己的格子留 20% 雾、四邻约 60%、两格以外不动。
6. **雾不是慢慢移动的**：服务端一调 `blowFog` 就把 span 跳到"全清"，最后 180 tick 线性长回来。
   定论：服务端保持 40 秒完全无雾，回来的斜坡 180→**480 tick（8 秒）**；客户端 `Fog` overlay 用
   `slideStep()` 把**整条云**按速率滑过去（吹走 1.2 秒、回来 8 秒，都按 span 宽度算，卡帧钳 20 tick）。
   于是三叶草吹雾是"云被推走、再慢慢飘回来"，不是开关。
7. **出怪挤在最下两路**：`WaveDirector.rowFor` 只在 entry 写的 `rows` 里轮转，而
   `tools/original_levels.py` **每波把路游标重置为 0**，于是 1 只的波永远写 `rows:[0]`（0 是最下面
   一路）。4_1 实测下两路 19 只 / 水面 2 只 / 上两路 0 只。定论：游标提到**关级**（一行搬家，RNG
   流不动，所以僵尸构成一字不变），只重生成迷雾世界（`write_adventure_levels.py` 新增 `--levels`）：
   4_1 变成 3/3/3/2/5/5，1~5 章其余世界留在原样并进 `todo.md`。
8. **预览与实际出怪不一致**：`LevelDef.previewZombieIds()` 只读 `waves`（4-5 是 0 波的花瓶关，
   预览因此是空的），客户端又硬性只画 10 种（4-10 有 11 种，被截掉的正好是新加的鸭子桶头）。
   定论：新增 `LevelMechanic.previewZombieIds(def, data)` 钩子，`LevelMechanics.previewZombieIds`
   把 wave 表放前、机制放后拼起来（`ScaryPotterMechanic` 报罐子里的、`GraveSpawnerMechanic` 报墓碑
   里的）；客户端上限 10→16（`ChooseSeedsScreen.PREVIEW_ZOMBIE_LIMIT`）。
9. **小丑僵尸的音频缺失**：6 秒的音乐盒只在**开盒那一刻**放一次，而开盒到爆炸只有 110 tick
   （1.83 秒），所以走路全程无声、音乐只听到前 1.8 秒。原版是 `StartZombieSound()`（走到棋盘上起
   `FOLEY_JACKINTHEBOX`）与 `StopZombieSound()`（开盒停）。定论：`ZombieSounds` 新增 `walk`
   （`sounds.walk`），客户端 `client/sound/EntityLoops` 按"动画是 walk 且在棋盘内"起一条**循环**
   音轨、状态一变（开盒 / 被磁铁吸走箱子的 `walk_no_box` / 死亡 / 离开关卡）就停；
   `SoundEngine.startLoop/stopLoop` 是新的可停循环 API（占 16 个音效源之一，`nextSource` 不再把它
   抢走）；开盒改放本来没有任何调用方的 `jack_surprise2`，爆炸那一下照旧。
10. **仙人掌攻击动画重叠**：`body_overlay` 与 `body_overlay_2` 是**同一条源轨道的两张图**，
    导出器的 `force_visible_hidden` 把两条都"救活"，位置完全相同（两张 48×13 贴图 536/538 像素
    重合）。定论：生成器里给两个攻击片段各排除对方（`shoot` 留 `body_overlay`、`shoot_high` 留
    `body_overlay_2`，与 `idle`/`idle_high` 一致），重新导出，并加 `CactusClipTest` 逐帧采样断言
    "不会两张同时可见"。
11. **荷叶上的植物偏低**：`LILY_PAD_TOP` 是 0.10 格，而荷叶的盘面（按 `lily_pad.json` 与
    `body.png` 的不透明带量）在 cellY−0.26..+0.19，所以植物的脚落在盘的**下沿**。定论：改成
    **0.30**（花盆 0.38 是同一量级的上限），并顺手修掉种植幽灵：它原来只写格中心与地形高度，
    现在 `client/renderer/ClientPlacement.anchoredAt()` 问同一个 `PlantPlacement.placementHeight`，
    幽灵因此也吃到 carrier 的 0.06 格横移。
12. **顺带查出的第三个缺陷**（不在清单里，但不修就动不了第 11 条）：**弹丸与僵尸的高度容差是
    0.2 格，比任何一个 carrier 都矮**。实测花盆里的豌豆射手十秒打出 0 伤害；荷叶抬到 0.30 之后，
    同样的毛病会落到每个泳池关的水路（这也是最后一战与回声温室两条用例在本轮中途变红的直接原因）。
    定论：`ProjectileEntity.HIT_TOLERANCE_Y` 改成由摆放常量推导
    （`max(FLOWER_POT_TOP, LILY_PAD_TOP) + 0.12`），空中/地面的区分仍旧只归能力标志，
    `CombatSystemsTest.aShooterOnACarrierStillHitsTheLane` 按"打中没打中"钉住它。

## 验证与边界

- 单元测试：`FogCloudTest`（网格按格、帧号、漂移区间、贴图切片；清雾的核心/边缘/半径外）、
  `FogClientMechanicTest`（声明的 span、sync 覆盖、`covers`、payload 里的块、两个滑动速度与卡帧
  钳制）、`FogMechanicTest`（清的形状）、`FogWorldLevelsTest`（每路都分到怪、最下两路不超过六成；
  4-5 的预览来自罐子）、`EntityLoopsTest`（音乐盒只在走路且在棋盘上；开盒 / `walk_no_box` / 出界都
  不响）、`CactusClipTest`、`ClientPlacementTest`、`CombatSystemsTest` 新例。
- 反向验证（这轮的重点）：把仙人掌的排除表改回去，`CactusClipTest` 立刻红
  （`shoot draws both body overlays at t=0.0`）；把高度容差改回 0.2，新用例红（伤害 0）；
  荷叶 0.30 + 旧容差下 `MiniGameRepairTest`（最后一战）与 `EchoConservatoryTest` 都红，
  修容差后绿——两条都不是"雾"的事，是被第 11 条牵出来的。
- 冒烟（`.smoke/fog-fix/`）：4_1 上摆路灯花 / 火炬树桩 / 荷叶+豌豆 / 仙人掌与两只僵尸的一条胶片。
  看到的：雾成了有洞有絮的云带（不再是压实的墙）、火炬树桩周围有可见的一圈亮、**植物与僵尸都在
  云之下**（火炬树桩的右半边被云压住）、荷叶上的豌豆坐在盘面上、仙人掌在气球僵尸靠近时升起。
- 冒烟第二跑（`.smoke/fog-chooser/`）：`pvzce.smokeSeedLevel` 打开 4-1 的选卡页，图上雾盖在草坪右半边、
  开场对话正常播、右侧预览名单六种僵尸（含两种鸭子）——"关卡正式开始前/对话时没有雾"这一条闭合。
- 没验到的：1~5 章其余世界的分路偏差仍在（见 `todo.md`）；水行僵尸的服务端高度仍是 0，
  弹丸靠容差兜着（见 `todo.md`）。
