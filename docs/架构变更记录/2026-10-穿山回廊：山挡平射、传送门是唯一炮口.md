# 穿山回廊：山挡平射、传送门是唯一炮口（2026-10-05）

用户要求再做一个能用地形高度游玩的关卡，选定了"会换位的传送门 + 一道高台"。做法是把高度做成**实心墙**
而不是可站的平台：山脊够高，任何在草坪高度飞的子弹都死在山面。第一版交上去后用户反馈"难度太高、
僵尸很快、来不及发育、门可能挪到很靠房子的位置"，于是这一轮同时落了两个修正：给门的换位加下限约束，
并把山头降到投手也能抛过去的高度，让玩家永远有第二条路。

- 新关 `yard/minigame/tunnel_corridor.json`：11×6，山体占第 6~9 列（上坡 / 两列山脊 / 下坡，
  `pvzce:tunnel_slope_up`、`tunnel_ridge`、`tunnel_slope_down`，0.3 / 0.6 / 0.3，三个元素都进 `#c:unplantable`），
  两侧草坪可种。山脊高度让每一行的平射都撞在坡面上，所以山那侧只能靠传送门或抛射打到。
- 三对传送门：左端都在第 5 列山脚（射手从这里"开炮"），右端在对面海岸，其中两条是斜的（换行）。
  `PortalMechanic` 覆盖僵尸、平射与滑行中的小推车，所以斜门会把僵尸换到别的行——门既是玩家的炮口也是威胁。
  `initial_relocate_ticks` 1200 / `relocate_interval_ticks` 1500：每 25 秒随机挪走一个门（提前 300 tick 提示）。
- **门的换位范围由数据约束**：`PortalData` 新增 `relocate_min_x`（默认 0 = 整块棋盘，现有关卡行为不变），
  `PortalMechanic.relocate` 只在这一列及右边挑新位置；本关设 3，门下再留着三列反应纵深，
  不会出现"僵尸被门直接送到房前"。校验器挡住越界的下限值。
- 关卡因此把**铲子与手套**钉进卡槽（`slots` 只有 `pvzce:shovel` 与 `pvzce:glove`，不钉任何植物卡），
  玩家可以跟着门把植物挪过去；卡组与增益照旧自选、不设上限。
- **降难度按"改节奏与山头、保留快速僵尸"落地**：首波 30 秒 → 50 秒、波次更稀、总量 67 → 53；
  开局阳光 200 → 300、天降阳光 480~720 → 360~540；`zombie_speed_multiplier` 0.85（关卡规则，
  1-5 用 1.5、2-5 用 2.6 那条的同一出处）；山头 0.8 → 0.6，`cabbage_pult` 的弧线能抛过去，
  于是"不带手套/不带投手"的玩家也还有解。
- **修掉一个只在"有墙的关卡"里才会暴露的旧 bug**：子弹穿门后，`ProjectileEntity` 仍用
  "穿门前的位置 → 穿门后的位置"这条直线做遮挡判定，于是会被它刚刚绕过的那道墙打死——
  斗转星移是平地，这段线是空地，所以从来没暴露。现在穿门的那一 tick 跳过遮挡判定
  （门是瞬移、不是弹道）；出口本身落在实心地形里时，下一 tick 从出口起算的判定仍会销毁子弹。
- 定向验证：`TunnelCorridorTest`（逐列山体高度、山体不可种而两侧草坪可种且每行平射都被挡、
  子弹只有穿门才够得到山那边、投手弧线也能跨山、僵尸穿直门保行/穿斜门换行、门按 1500 tick 挪位且
  客户端收到新状态与预警、声明的换位下限是 3、只钉工具不钉植物卡）；`PortalMechanicTest` 新增两例
  （子弹穿过门而不是穿过门之间的墙、换位后的门全部落在下限右侧）。一次 1920×1080、2x UI 冒烟胶片
  `.smoke/tunnel-eased/s_*.png` 拍到降低后的山体、飞过山头的卷心菜与门前留出的三列纵深。真人平衡见 `todo.md`。
