# 架构变更记录 · 触控支持：单指点击与滑动，六处"滚动区域"声明让滑动接管滚轮

> **归档（冻结）**：这是从 `架构变更记录.md` 分卷出去的原文，只搬家不改写，**不再修订**。
> 索引见 [../架构变更记录.md](../架构变更记录.md)。

> 用户要求："只做一个简单的支持：Linux X11 和 Windows……目前只需要单指点击逻辑和滑动这两个逻辑，
> 并且允许使用启动参数关闭触控支持。"（五条问答见 `决策记录.md` §1）

## 现象与根因

- **点击与拖动本来就能用，缺的是"滑动 = 滚轮"**：Windows 把单指事件提升成鼠标消息、X11/XInput2 对首个
  触点做指针模拟，所以这轮没有任何原生代码（不用 FFM、不用升 Java、不用动 loader）；而滑动不能天真地合成 ——
  点击是**按下即发**（`PvzceWindow` 只收 `GLFW_PRESS`），全仓库没有位移阈值，滑动会在起点**多触发一次点击**：
  商店行按下就是买、玩家选择器按下就是切换玩家、卡条按下就是选卡。
- **够不到的东西是主线级的**：默认画质（1280x720 auto → GUI 427×240）下卡条可视宽 120、卡距 44，只看得见
  2~3 张，而 `DEFAULT_SEED_SLOTS = 8`；滚轮是唯一的滚动手段，所以触控下大部分卡**点不到**。选卡页卡池、
  `AbstractSelectionList`（11 个宿主）同理。

## 定论

1. **手势只接管"按下点落在滚动区域里"的那一次按下**（`client/input/PointerGesture`）：区域内把点击留到松手，
   位移超过 `TAP_SLOP`（8 GUI px）就只发滚动、不发点击；区域之外一个字不变 —— 棋盘的按住扫阳光、
   拖卡到格子、小推车按住 500 ms 放车都依赖"按下即发 + 每帧拖动"，因此全部照旧。
2. **滚动区域是声明出来的，且必须复用滚轮处理器已有的那个矩形**（`ScrollRegion`）：`AbstractSelectionList`
   （纵向，一步 = `entryHeight`）、卡条（横向，一步 = `cardWidth + cardGap`）、选卡页卡池、关卡网格、图鉴、
   控制台。判据只有一份：`InGameScreen.cardBarScrollsAt` / `ChooseSeedsScreen.poolScrollsAt` /
   `LevelSelectScreen.gridTurnsPageAt` 同时喂滚轮与手势，所以"能滚"和"滑得动"不会分家。
3. **方向由区域自己的版式决定**（`ScrollRegion.Swipe`）：`AbstractSelectionList` 的行是自下而上排的，
   镜像滚轮即自然；卡池与关卡网格从上往下排，跟手；横向两者等价。
4. **滚轮下沉带坐标**（`PointerGesture.ScrollSink` → `PvzceClient.dispatchGuiScrolled`）：下游要命中判定
   （`SeedCardBar.scroll` 的 `contains`），而"从实时鼠标位置取坐标"只在帧循环驱动时成立。
5. **对话框替子控件回答**：`PlayerPickerDialog` / `CardPoolEditorDialog` / 编辑器各页的列表不在
   `Screen.widgets` 里，`Dialog.scrollRegionAt` 少这一步它们就滑不动。
6. **`Slider` 声明 `claimsDrag()`**：压在列表上的滑条不会被抢走"按下-拖动-松手"三连。
7. **开关是 `-Dpvzce.touch=false`**（默认开）：系统级的鼠标提升关不掉，这个开关关的是我们这层。
8. **验证**：`PointerGestureTest`（12 例）+ `ScreenScrollRegionTest`（4 例）；冒烟新增 `pvzce.smokeSwipe`
   （`smokeDragTo` 直接调 `dispatchMouseDragged`，绕过事件循环，验不了手势路径）。
   一次启动拍四帧（`combat_test`，14 槽）：第 90 帧卡条正好位移一张卡**且没有任何卡被高亮**
   （选中态是 `SeedCardRenderer` 的 `(1,1,0.2)×0.35` 黄罩，量化后蓝色通道 108 未降），第 120 帧那次点击
   让卡片变黄（蓝色通道降到 70）—— 滑动不误点与点击仍生效在同一卷胶片里。
