# 屋顶夜深、鼓点层、天气预告与西瓜溅射（2026-10-04）

用户给了 `refer/ms2/` 的两条音轨（主曲 + 鼓点），要求作为原创曲目用于 6-x、僵尸多于十只时
启用鼓点；天气变化前 10 秒用红大字预告；并修掉"西瓜溅射伤害太高"。

- **音乐是一首歌的两层**：`sounds/original/roof_after_dark.ogg` 与 `_drums.ogg` 由
  `tools/build_roof_after_dark.sh` 原样复制（同一场演奏的两条分轨，同为 144.006 秒），
  `MusicCue.many_zombies_layer` 让两条 cue 在同一 tick 发到 `background` 与 `battle` 两条轨道上。
  鼓点**不重新起播**：客户端把它按 0 音量放着，僵尸超过 `PvzceConstants.MANY_ZOMBIES`(10) 时
  只把它的音量淡入（2.5 秒），低于阈值再淡出——重新起播会让鼓点回到第一小节而与主曲错位。
  谁是"拥挤"由客户端按 `ClientLevel.aliveZombieCount()` 判断：实体本来就在客户端，且暂停时它仍在跑。
- **预告挂在天气相位上，不是自己的计时器**：`WaveDirector.countdownToWave(i)` 把"到第 i 波还有多少
  tick"（当前倒计时剩余 + 后面每个 delay）算给 `WeatherMechanic`，后者在 `<= WEATHER_WARNING_TICKS`
  (600) 时把 `WeatherState.warning` 置上并 +1 一个 `sequence`；客户端认序列号而不是认文案，
  于是"多云→雨→多云"这种同文案的两次预告不会被读成一条不消失的横幅。四句文案由
  `WeatherState.warningFor` 一处决定：转晴按"雨→晴=月光要出来了 / 阴→晴=乌云要消散了"，
  转阴雨按"晴→阴雨=月光要被遮挡了 / 阴→雨=乌云要来了"，各带 `gui.pvzce.weather.warn.*` 语言键。
  场上僵尸超过十只时**不喊**：满场僵尸本身就是警告。
- **西瓜溅射是半伤**：`SplashImpactCapability` 以前把投射物满伤害发给半径内每一只，
  包括主目标（80 打一片）。现在命中目标吃满伤、其余吃 `splash_damage`（melon / winter_melon
  都写 40，原版数值），字段默认 0 = 投射物伤害的一半。
- 验证：`NightRoofShowTest` 五条（预告正好提前 600 tick、四句映射、单相位不喊、6-1~6-4 两条 cue
  同 tick 同长度、层级标记与加入快照），`CombatSystemsTest`/`RoofMechanicsTest` 的溅射断言按
  半伤更新（屋顶那条改用一只无甲僵尸把"满伤 vs 半伤"分开）；协议 57 → 58，wire dump 与规模块重生成。
  一次冒烟（临时快速关，拍完即删）确认：`background=roof_after_dark` + `battle=..._drums` 同时起播、
  13 只僵尸时 `layered track 2 in (crowded)`、以及红字预告的出现与随相位结束消失。
