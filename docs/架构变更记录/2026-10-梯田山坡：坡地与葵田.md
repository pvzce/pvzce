# 梯田山坡：坡地一层 + 梯田下葵田一层（2026-10-05）

用户要求利用既有地形机制做一关、多利用地图高度与"可自定义性"，随后把结构收敛成两层：
**坡地（含左侧后院）一层 + 梯田下面一层**，层内要有斜坡过渡，并改成自选卡、自选增益、梯田下两列葵田。

- 新关 `yard/minigame/terraced_hillside.json`：默认地表做**坡地**——后院草坪（0）经一列
  `pvzce:hillside_bank_low`（`slope_x` 0→0.4）升到 `hillside_mid`（平顶 0.4），再经 `hillside_bank_high`
  升到 `hillside_high`（平顶 0.8），上层三格落石弹坑；两级梯田与左侧后院同属一层、靠斜坡过渡，
  僵尸从上层一路走下来。第二层是 `pvzce:under_terrace`（平顶 0，只盖第 4~8 列），
  第 4、5 列草坪当葵田、其余裸地（要花盆），它排在坡地之下、只在梯田边缘那条缝里露出来；
  PgUp/PgDn 切过去种，僵尸不会下到那一层，所以葵田是安全的。
- 为什么坡地必须是默认地表：`MowerMechanic` 只认默认地表（小推车是这一关有效的一层防线），
  且关卡校验要求默认地表铺满——"左侧后院与梯田同属一层"只能落在默认地表上、靠元素曲线给高度；
  能被切换的第二层则必须是另一条通路，于是做成梯田正下方的稀疏通路。
- 地形要借内置草地/裸地图集，所以上一轮为"单层高度"加的 `SceneElementArt.tiled`
  （数据声明瓦片表、格子按 `(x mod 6, y mod 6)` 取样，`grass`/`ground` 的旧拼写保留为兼容回落）
  与四个 `hillside_*` 元素在这一轮**重新启用**：它曾随"三层通路"那一版一起删掉，而"坡地要有斜坡"又必须用它。
- 卡组与增益都自选：`slots` 清空、`max_seed_slots` 与 `max_buff_slots` 都不写（跟随背包），
  `buffs` 写 `pvzce:player_choice`——没写 `buffs` 的关卡是 `LevelBuffPlan.NONE`（既没有固定增益也不提供选择），
  选卡页那一页因此是空的，玩家解锁的增益要靠 `player_choice` 才会出现。
- 波表里巨人/舞王回来了：僵尸全走在**铺满的默认地表**上，它们按偏移多生成的那一只不会落空
  （稀疏通路那一版才必须去掉，见 `todo.md` 的多层通路一条）。
- 定向验证重写为 `TerracedHillsideTest`（坡地是逐列曲线且第二层排在其下、土坡不可种而梯田与葵田可种、
  一格上下两株、低处平射死在坡面而同层射手与投手各能命中、僵尸下坡时脚跟着地形、卡组与增益自选无上限）；
  `SceneArtTilingTest` 随瓦片表一起回来。一次 1920×1080、2x UI 冒烟胶片 `.smoke/terrace-v2/s_*.png`
  用 `smokeKeys` 按 PgDn 切层：坡地层拍到土坡与下坡的僵尸，葵田层拍到梯田正下方的两列草坪。真人平衡见 `todo.md`。
