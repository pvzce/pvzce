# 下一波按钮（2026-10-04）

用户要求按 PvZ2 中文版的形状加一个「下一波」：当前波僵尸打完后，下一波还没来时，
在暂停按钮下方出现，按下即让下一波提前到来。

- **判定放在服务端**（`WaveDirector.nextWaveAvailable`）：客户端只被发给"能叫"，因为
  「这一波的僵尸都死了」需要知道哪只僵尸属于哪一波，而客户端只知道场上有哪些实体。
  条件是四条：本波已放完、本波一只不剩、后面还有一波、且没有任何东西按着表
  （准备阶段 `holdsNextWave`、轮间 `roundClearPending`、谱面关 `showsWaveCount`）。
  尸体不算存活，所以"打死"与"走掉"都算这一波结束；跨波的散兵不挡按钮，但去重后的
  全部僵尸必须为 0 —— 门还压着到达时按钮不出现，玩家因此不会按下一个不生效的键。
- **请求走 `NextWaveC2S`，效果是"把倒计时判定为已到"**：`callNextWave` 只置一个请求位，
  波次仍由 `tick` 里那一条到达分支发出（横幅、轮次、生成器都在那里），所以提前叫波
  与自然到达走同一条路径，不存在第二套播报。到位后请求位清空，否则后面每一波都会立刻到。
  `WaveProgressS2C` 加 `nextWaveAvailable`，服务端在它变化的那一帧置脏，客户端据此显示按钮；
  协议版本 56 → 57。
- **按钮在 HUD 上是暂停键的第二行**：与暂停键同 x、同宽、高 40、间隔 6，
  即 GUI `1114,606 154x40`；卡片栏右界在 1034，右侧那条空档本来就是暂停键独占的。
  按下后本地先隐藏（请求是一个来回），服务端答案一变就恢复 —— 被拒绝的按键因此不会
  把按钮吞掉。这是本项目第一次把"按钮在不在"的决定权完全交给服务端。
- 关卡可以用 `wave_pacing.next_wave_button: false` 关掉它（编辑器里是「下一波按钮」），
  默认开；谱面关和准备阶段关卡不需要写任何东西就没有。
- 验证：`WaveSystemTest` 新增三条（只在打完时可用、没提供时拒绝、关卡关掉后不出现）；
  一次冒烟 `.smoke/next-wave/`（1-1 先手种豌豆射手打死第一波）拍到按钮出现在暂停键正下方
  的 `button_8600.png`，以及同一局按下去之后按钮消失、进度条前移的 `after_click_9300.png`。
