# 多人页崩溃返修：同帧切屏先初始化再绘制（2026-10-29）

现象：提交选卡后客户端在 `MultiplayerScreen.render` 崩溃，画布为 null。选卡页在自身 tick 中提交卡组并替换当前屏幕，此时本帧的初始化已结束，渲染阶段直接绘制了尚未初始化的新多人页。

- `ScreenStack.render` 负责取得当前屏、调用幂等的初始化入口并绘制；帧循环的初始化仍为 tick 服务，绘制时再确保实际栈顶已初始化。新页不会在切屏当帧额外 tick，也不在具体页面用判空跳过绘制。
- 冒烟结束日志取实际当前屏，不再报告本帧开始 tick 时缓存的旧屏幕。
- 回归模拟 tick 内替换页面，验证新页初始化先于首帧绘制、只初始化一次、旧页不再绘制且新页没有额外 tick；导航、多人选卡、关卡入口与模态输入定向回归通过。
- GUI 范围、关卡入口与文档/分层守门回归通过（`.smoke/multiplayer-frame-init/final-tests.log`），未重跑服务端/API 全量。
- 唯一一次 1080p / 2× UI 游戏冒烟覆盖选卡和提交后的大厅，最终房主显示“已准备”，日志没有异常或 GL 错误。证据：`.smoke/multiplayer-frame-init/film_300.png`、`film_420.png` 与 `smoke.log`。
