> 玩家报告的一批"看着不对"，一轮修完。共同点是：数据里其实都有，只是**没有一处**把它们连起来——
> 或者连起来了但被另一条规则挡住。每个缺陷的判据都落在一个可断言的地方（下表最后一行）。

## 孢子云太大、而缩到 1/4 之后又断成了点线

- **现象**：大喷菇喷出的孢子（`pvzce:fume_cloud`）每颗 0.5 格，铺满整条锥形，比原版那团雾厚一倍不止；
  改成 1/4（0.125 格）之后又变成**虚线**：锥形的 8 个停靠点是按 0.5 格的贴图定的（0.5 格间距，注释里
  写明了"贴图必须比间距宽"），12.5px 的孢子按 25px 的间距排下来就是一条点线。
- **定论**：两个数一起改，且**都写进注释的算术里**：`fume_cloud.scale` 0.5 → 0.125，
  `ConeAttackCapability.DEFAULT_CLOUD_COUNT` 8 → **32**（间距 0.125 格 = 贴图宽度，实测才连成一条雾带）。
  16 个停靠点先试过，截图里仍是断续的点——一次挥发的粒子横向只铺开约 0.2 格，够不到下一站。
  32 站 × 每站 28±8 颗 ≈ 900 颗，贴着 `ParticleEngine.MAX_PARTICLES`（1024）的上限。
  这件事只能靠截图判定：粒子数、间距、生命期三者算得出来，**看起来连不连**算不出来。

## 双发射手看起来和豌豆射手一模一样

- **现象**：`repeater` 的 `count: 2` 从数据到代码都是对的，两颗豌豆确实都生成了——但它们在**同一 tick、
  同一个出生点**生成，速度相同、方向相同，于是永远重合：屏幕上只有一颗豌豆，同一 tick 里打同一个僵尸，
  两份伤害读起来是一份。"双发射手"因此和豌豆射手在画面上没有任何区别。
- **定论**：`ProjectileRef` 新增 **`burst_delay`**（一轮齐射里颗与颗之间隔多少 tick，缺省 0 = 全部同 tick）。
  `ShooterCapability` 为此带一张 `pendingShots` 队列：第 1 颗在开火那一 tick 出膛，其余按 `i * burst_delay`
  排在后面；队列每 tick 先走（`tick` 开头就 `firePendingShots`），所以植物中途缩头或进入冷却都不会吞掉
  已经打出去的子弹。`repeater` 与 `gatling_pea` 都写 12 tick（0.2 秒，按 4 格/秒算是 0.8 格间距）。
  队列**不进存档**：一轮齐射 0.6 秒，存档正好落在里面最多丢一轮的尾巴，而为此让存档认识"一个指向内容定义的队列"不划算。
  用例：`CombatSystemsTest.aBurstVolleyLeavesOnePeaAtATime`（开火 tick 天上只有 1 颗；齐射出完时 2/4 颗彼此相距 > 0.5 格）。

## 直线弹的速度慢了一半

- **现象**：`pea` / `snow_pea` / `puff` 都是 2.0 格/秒，`cactus_spike` / `fume` 2.4。原版豌豆约 4.2 格/秒
  （80px 一格、约 3.3px/帧），所以画面上子弹是"飘"过去的。
- **定论**：直线弹**各自 ×2**：pea/snow_pea/puff → 4.0，cactus_spike/fume → 4.8。抛物线弹（投手）不动——
  它们的 `arc` 速度与重力是一对，翻倍会把弹道压平，那是另一件事。

## 胆小菇缩头之后不会哭

- **现象**：`ScaredyShroom.reanim` 把缩头画成两条 clip（`anim_scared` 把头低下去 + `anim_scaredidle` 保持并流泪），
  美术文件用 `on_end: hide_loop` 说这件事，服务端只发布一个 `hide` 状态。客户端每帧请求 `hide`，
  而 `AnimationManager.isAlreadyPlaying` 把"活动 clip 已经不是这个状态解析出来的那个"读成"这个状态已经结束"——
  于是缩头一播完就被从头重开，**哭泣的循环一次也没上过屏**。
- **定论**：`AnimationPlayback.chained`——由 `on_end: <clip>` 交接来的 clip **仍算同一个状态在播**
  （`isAlreadyPlaying` 见到它就返回 true），重发同一个状态不会把它推回去重播。
  另一条规则一个字没动：`on_end: idle` 的交接**不是**链条（那是"动作结束、回到待机"），
  所以 `shoot`、`explode` 这类要反复触发的动作照旧能重播。
  用例：`AnimationManagerIntegrationTest.aDuckedScaredyShroomHandsOverToItsCryAndStaysThere`
  （等待交接 → 复查 clip 名 / 重发 `hide` 不回到 `hide` / `shoot` 播完仍能重开）。

## 攻击动画比原版慢一半

- **现象**：射击动作的速度从来没人给过，于是按 reanim 自己的 12fps 播：豌豆射手一次出手 2.08 秒、
  大喷菇一次呼气 2.5 秒——比 1.5 秒的射击间隔还长，植物永远在"上一发的收势"里，整条车道像慢放。
- **定论**：`tools/reanim_to_pvzce_all.py` 新增 **`SHOOT_ANIMATION_RATE = 2.0`**，写进 14 种植物 15 条
  `shoot` / `shoot_high` clip（豌豆/寒冰/双发/机枪/三线/裂荚、大喷菇/小喷菇/胆小菇、仙人掌、卷心菜/玉米/西瓜/冬西瓜），
  然后按 `--entity` 逐个重生成。生成器是这些动画文件的唯一出处（重生成与 shipped 文件逐字节一致），所以改的是配置而不是 JSON。

## 樱桃炸弹的动画与爆炸对不上

- **现象**：`CherryBomb.reanim` 是 30fps，转换器把 `anim_idle` 裁成真正在动的 12 帧 = 0.4 秒，
  而引信是 60 tick（1 秒）：炸弹在鼓到第 2.5 遍中间爆掉，读起来像"动画播错了"。
- **定论**：`CHERRY_BOMB_ANIMATION_RATE = 0.4`——0.4 秒 ÷ 0.4 = **1.0 秒正好一发引信**，
  一次鼓起配一次爆炸。`explode` 用同一个倍率（同一条 27 帧轨道、同一个动作的后半），
  配合下面那条 `linger_ticks` 正好播完。

## 爆炸特效：樱桃只有一个小贴图，毁灭菇发的是别人的闪光

- **现象**：两处都缺"组成"这个概念。樱桃炸弹的爆炸只有一颗 `pvzce:pow`（0.2 → 0.5 格，约 40px），
  对着 3x3 的爆炸范围小得可笑；而 `pvzce:powie`（原版的橙色爆炸云）转换出来是 `scale: 0`，
  渲染器直接跳过——**它从转换出来那天起就没画出来过**。毁灭菇发的是同一个 `pvzce:pow`，
  而原版那朵"菌柄 + 七块菌盖 + DOOM 字 + 全屏白闪"的组合早就转好了放在 `data/pvzce/particles/explosion/` 里，
  一行代码都没引用过（`PvzceParticles.DOOM` 是个没人用的常量）。另外 `LINGER_TICKS` 写死 30 tick
  并注释成"比所有 explode clip 都长"，而毁灭菇的 explode 有 **2.75 秒**（火爆辣椒 1.08 秒、倭瓜 0.67 秒也一样）——
  爆炸动画只播了个开头，植物就消失了。
- **定论**：三块拼图。
  1. **出生偏移**：`ParticleDef.ParticleMotion` 新增 `offset_x` / `offset_y`（相对效果触发点的出生位置，单位格），
     `ParticleEngine` 在实例化时应用，`bounce` 的地面线也跟着改成相对**出生点**。原版用 `EmitterOffset`/`SystemPosition`
     摆一朵云，转换器把那两个字段丢掉了——于是"九块美术摆成一朵蘑菇"这件事在数据里无处表达。
  2. **组成是一个列表**：`pvzce:explosive` 新增 **`particles`**（按发射顺序排的粒子 id，缺省 `["pvzce:pow"]`）
     与 **`linger_ticks`**（爆后留在场上的 tick 数，缺省 30）。`detonate` 把列表逐条发在植物自己那一格，
     声音只挂在第一条上（每次 emit 携带整个效果事件，逐条挂会把一次爆炸响九遍）。
  3. **数据**：`pow` 的终点从 0.5 格提到 2.5 格（贴图 136x123，按 3x3 的爆炸范围定）、新增 `pow_flash`
     （0.16 秒的局部亮闪，additive）、修好 `powie`（scale 0 → 0.9 并按外扩方向发散、淡出）；
     `powie` 还顺手把僵尸王锤子的那朵云一起修好了（`HammerCapability` 发的就是它——以前那一下也是什么都不显示）；
     毁灭菇的九块按原版像素尺寸重写（`scale` 是画出来几格高，`aspect = 宽/高 × 1.25` 才是屏幕上的形状，
     `offset` 照抄原版的 `SystemPosition` ÷ 80/100）——整朵云约 3.4 格宽 × 2.8 格高，全屏白闪改成会淡出
     （原转换结果是 `alpha_to: 1.0`，一屏不透明的白）。`cherry_bomb` / `doom_shroom` 的 `linger_ticks`
     分别 70 / 165（= 各自 explode clip 在屏幕上的时长），顺带把 `jalapeno`（65）、`squash`（40）被截断的爆炸动画也补上。
  用例：`AnimationResourceLoaderTest.everyAshPlantStaysLongEnoughToDrawItsBlast`（停留时长 ≥ clip 时长 ÷ rate，
  两边都从文件里读）、`theBlastsNameParticlesThatExistAndArePlaced`（会炸的植物必须点名自己的组成、每个 id 都能解析、
  菌盖至少 5 块带出生偏移）、`ParticleEngineTest`（偏移真的落在引擎里）。

## 顺带：`write_plant_content.py --dry-run` 会写盘

- **现象**：这个脚本的 `--dry-run` 分支写文件**之后**才判断，所以"预演"把 14 个植物 JSON 的
  `render_scale` / `order` 与 5 个投射物 JSON 的 `impact_particle` 抹掉了——那些字段是生成之后手工补的，
  脚本的表里没有。文件改动与 HEAD 的差异当场暴露了这件事。
- **定论**：`write_json` / `update_lang` 收一个 `dry_run` 参数，预演只打印不落盘；文件头的文档写清
  "**这是生成器，不是同步器**"：跑它等于"按表重建这几个定义"，手工加过的字段会被丢掉，先用 `--dry-run` 看差异。
