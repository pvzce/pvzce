# 进行中关卡读档失败：提示与自主重开（2026-10-19）

用户报告旧存档的波次版本为 0、当前要求 2，异常从恢复过程冒泡到网络层，导致断线；
文件无法解压时则直接删档并开新局。用户要求无法进入时提示玩家并允许重开。

- 服务端在读档与构造/恢复边界处理失败，记录具体原因，清理未完成的关卡实例；不发布关卡初始化、不自动删档。
- 复用 `LevelSavePromptS2C`，增加失败标记并提升包协议版本；失败提示立即出现在关卡列表，
  不等待永远不会到达的关卡初始化，也不提供「继续游戏」。
- 「返回关卡列表」保留磁盘存档；「重新开始」才发送丢弃请求，按既有选卡或直接开局规则重开，
  不沿用失败存档的增益。选卡返回时回到列表，不重弹失败存档；丢弃请求核对提示中的世界与关卡。
- 旧版波次与损坏压缩文件经真实内存包链路回归，确认文件未变、列表请求仍可响应、确认重开能创建新局；
  客户端经过实际点击分发验证返回与重开。
- 唯一一次 1920×1080、2 倍 UI 冒烟复现旧版读档失败并点击重开，
  `.smoke/save-recovery/ui_120.png` 为失败提示，`ui_240.png` 为重开后的选卡开场。
  截图发现外挂标题与页签重叠，最终将失败标题收进边框并下移正文；遵守一次启动限制，未重复截图。
- 真实包顺序复验修正了一条旧测试：异步离开后不再跨线程直接恢复，而是发继续包并等提示再丢弃。
  同时修复正常存档确认重开后退出又被写回：等待确认的冻结实例不重复保存，选择继续后恢复正常保存。
- 游戏全量测试通过（复用既有临时初始化脚本将测试堆设为 2 GiB，项目默认配置未改）；
  最终存档、菜单、变异存档、客户端及协议定向回归通过。
