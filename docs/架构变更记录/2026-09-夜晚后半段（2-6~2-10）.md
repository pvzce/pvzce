## 夜关的墓碑一直是手写坐标，而原版是开局随机撒的
- **现象**：2-1 / 2-4 的墓碑写在 `scene` 里，一处一格（`"pvzce:grave": ["6,0"]`）。这与原版是两件事：原版每一关开局把墓碑**随机撒在远离房子的那半场**，同一关每次重开位置都不同，所以"要绕开哪几格"是每局都要重读的信息；手写坐标把这件事变成了一张固定的图。补丁式地"多写几种布局"也不行 —— 关卡文件里没有"七座，随便哪"这种写法。
- **定论**：新增关卡机制 **`pvzce:grave_field`**（`count` / `min_x` / `max_x` / `region` / `designs`），在 `onLevelCreated`（关卡构造完成、棋盘已经铺好之后）把墓碑撒下去。随机的来源是**关卡自己的 `random`**（与掉阳光、分线同一个源），所以撒出来的草坪与其它随机一致；它没有运行状态、也不写存档 —— **棋盘本身就是状态**（`saveScene` 写全部格子，恢复时整块覆盖），续档不会重撒、也不会与旧墓碑叠加。
- **撒的实现只有一处**：`GraveScatter`（`common/level/mechanic/`），`grave_spawner` 补墓碑也走它。实现是**洗牌区域内的格子后逐个 `placeGrave`**，而不是"掷一个点、撞上已有墓碑就放弃"：2-10 是 13 座墓碑落在 5×5 的半场里（25 格），掷点重试实测只撒得出 **8** 座，而"撞上就放弃"在持续补墓碑的路径上是有意的（下一 tick 会重数）。
- 2-1 / 2-4 改成用它（**墓碑的格子还给草坪** —— 手写墓碑时那几格是 `scene` 里的墓碑、不是草坪，改完 `9×5` 才是完整的草坪），2-6~2-10 从一开始就用它。
- **同一条事实的另一半没变**：墓碑是障碍物，最后一波由 `pvzce:graves_spawn_night` 一次性开墓；"会补、持续冒怪"仍然是 `grave_spawner` 的事，两个机制可以同时出现（2-5 就是）。

## 夜晚的植物谱系缺两块：胆小菇与寒冰菇
- **现象**：原版 Night 区的奖励链是 2-6 胆小菇 / 2-7 寒冰菇 / 2-8 毁灭菇，而本项目 2-6 与 2-7 没有东西可发；`refer/anim` 里两个植物的 reanim 一直都在，行为却无处安放 —— "僵尸靠近就缩起来不射"与"全屏冻住"都不是已有能力能表达的。
- **定论**：两个植物 + **两个新行为**，都按"能组合就不特判"的形状加：
  - **胆小菇**（`pvzce:scaredy_shroom`，25 阳光 / 7.5 秒冷却 / 300 血 / 整行射程）不是第二种射手：`ShooterCapability` 多一个 `hide_within`（格，缺省 0 = 从不躲），僵尸进到一格以内就发布 `hide` 并**完全停止射击**（连冷却都不走）。"它会打谁"与"它怕谁"共用同一个 `canBeHitByGround` 判据，所以被魅惑的僵尸与天上的气球都不吓它。模型里的 `hide`（低头，一次性）与 `hide_loop`（保持）由 clip 自己的 `on_end` 串起来，服务端只知道"现在躲着"。
  - **寒冰菇**（`pvzce:ice_shroom`，75 阳光 / 50 秒冷却 / 100 血）的能力是 **`pvzce:freeze_all`**：同一 tick 给**每一行**的每只僵尸上 `IMMOBILIZED` 3.25 秒、20 点 `pvzce:splash` 伤害、16 秒 50% 寒冷，然后植物消失（它的美术里没有"爆炸"这一姿态）。形状是"行"而不是半径 —— 一个够覆盖 9 列的半径在更宽的草坪上会短一截，而"全场"本来就不是一个距离。
  - **"冻不住谁"是标签**：`#pvzce:freeze_immune`（内置气球僵尸、矿工僵尸）里的僵尸照吃伤害与寒冷，只是不被冻住。原版对它们的区别正是这两件事分开，而"哪些僵尸冻不住"是关于内容的一句话，不该由寒冰菇的代码记住。

## 寒冷只减速了腿，没有减速嘴
- **现象**：`ZombieStatus.SLOW` 只有一处读法 —— `ZombieEntity.moveSpeed` 乘 `magnitude`。啃咬间隔是 `def.biteIntervalTicks()`，与状态无关，所以被寒冰射手打中的僵尸走得慢了，却仍然按原速啃植物。原版的"寒冷"是一个状态同时减半移动与啃咬。
- **定论**：啃咬间隔改为 `ZombieEntity.biteIntervalTicks()`（`def` 的数 ÷ `magnitude`），两处 `biteCooldown = ...` 都走它。没有第二个计时器 —— "多久咬一口"本来就只有这一个倒计时。

## 夜晚新僵尸：橄榄球、跳舞与伴舞
- **现象**：Night 区在原版里引入五种僵尸，本项目此前只有读报（2-1）与纱门（2-3），2-6 起的橄榄球、舞王与伴舞都没有；没有它们，2-6~2-10 只能拿更晚世界的僵尸顶替（巨人、气球、矿工），与原版对不上。
- **定论**：三个定义 + 一个能力（美术全部来自原版自己的 reanim，走 `tools/reanim_to_pvzce_all.py`）：
  - **橄榄球僵尸**（`football_zombie`）：200 身体 + **1400 面罩**（`position: top`，与铁桶同一条"平射先撞没有盾的帽子"规则）、**0.43 格/秒**（原版约普通僵尸的 1.88 倍）。面罩三档磨损来自 `Zombie_football_helmet{,2,3}.png` —— 与前两个一样是"未被任何 track 引用的破损贴图"，所以走 `damage_states`；它的 `zombie_football_upperbody2/3`（球衣的另外两个破损档）被 **track 过滤掉**：本项目的僵尸不画身体破损，断臂与掉头另有其道。
  - **跳舞僵尸**（`dancing_zombie`，500 血）+ **召唤能力 `pvzce:summon_dancers`**：以 0.67 格/秒**月亮步**进场（`moonwalk` clip），走到 `summon_at_x` 停下、举手 48 tick，然后按原版的十字队形招出 4 名伴舞（同排前一格 / 同排后一格 / 上一排 / 下一排），此后每 120 tick 检查一次队形、缺人就补。**"哪个位置缺人"是每 tick 按位置重新数出来的**，不是记住自己生成过哪些实体：实体 id 不写进存档，记住的那份名单读档后会指向不存在的实体，舞王会再招一整队。伴舞生成在**舞王当前的队伍**上，所以被魅惑的舞王招出来的伴舞天然帮植物打。
  - **伴舞僵尸**（`backup_dancer`）：200 血、0.18 格/秒（队形的节奏），没有装备、没有特殊行为。
  - **`refer/anim` 里有四个跳舞文件，画的是同一个角色的不同版本**（`Zombie_Jackson` = 2009 年的 MJ 造型、`Zombie_disco` = 后来替换的 afro 造型、`Zombie_dancer` = 第三种服装、`Zombie_backup` = 伴舞）。原版画在草坪上的是 `Zombie_disco`（它也是唯一带 `anim_moonwalk` 的那个），所以舞王取它；`Zombie_dancer`/`Zombie_Jackson` 不使用。

## 传送带没有"这张卡一共发几张"
- **现象**：`LevelBelt.BeltCard` 只有 `id` + `weight`，而原版 2-10 的墓碑破坏者是 **Max Count 13**（草坪上正好 13 个墓碑，第 14 张没有用处）—— 关卡文件里没有地方写这件事，传送带也没有记账的地方。
- **定论**：`BeltCard` 多一个可选 `max_count`（缺省 = 不限），计数由**传送带自己**持有（`ConveyorBelt.dealt`，**发出就算**：用掉没用掉都算，因为这说的是"发过几张"而不是"场上还有几张"）。发满的卡退出池子、其余权重重新归一；一个卡都发不出来时传送带停摆而不是空转。计数与队列一起进 `level.dat`，续档不会补发第 14 张。`LevelValidator` 报 `max_count: 0`（写出来却永远发不到的卡）。2-10 是唯一用到它的关卡。

## 一声"便条"值多少：2-9 与原版同形
- **现象**：原版 2-9 的首通奖励不是植物，是僵尸们送来的一张便条（便条之后才是 2-10 的传送带关）。本项目没有"便条"这种东西。
- **定论**：照 1-9 的先例 —— **不写 `rewards` 块**，走 `LevelRewards.DEFAULT`（首通无额外奖励、重复 100 金币、掉银币 25%），关卡描述里提一句"打完这一关，僵尸们会送来一张便条"。不新增物品，也不新增界面。
