# 架构变更记录 · 修回被删掉的标题页点击处理（托盘与玩家木牌都点不动）

> **归档（冻结）**：这是从 `架构变更记录.md` 分卷出去的原文，只搬家不改写，**不再修订**。
> 索引见 [../架构变更记录.md](../架构变更记录.md)。

> 用户报："然后这两个按钮都点不进去了"（指上一轮搬到左下角托盘的商店与数据包）。

## 现象与根因

- **现象**：左下角两块木牌**画得好、悬停也亮**（悬停提示会弹出），点下去毫无反应；同一个屏的玩家木牌
  也点不动了。
- **根因**：`TitleScreen.onMouseClicked` 在那次改版面时**被删掉了** —— 用一段"按标记取两段再拼"的
  脚本删方法，把夹在两者之间的它一起切掉了。它编译得过（`Screen.onMouseClicked` 有默认空实现），
  而三层验证全都没拦住：纯函数断言验的是几何、截图只看得见绘制（悬停高亮走 `renderTray`，
  与点击无关）、冒烟钩子 `pvzce.smokeTray` 自己调 `dispatchMouseClicked`，**绕过了**屏幕自己的处理函数。
- **顺带查出的第二个缺陷**：冒烟 `pvzce.smokeClick` 走的是"假坐标"那条路，它多转了一次坐标
  （`currentScreen().mouseClicked(rawX, rawY, ...)` 内部又转一次），于是点击落点被除以两遍 GUI 缩放。
  一直没被发现，是因为按目标瞄准的钩子（`smokeClickLabel` / `smokeTray`）走的是 `deliverGuiClick`，
  那条路没有这个 bug。这次顺手把它改成"warp 光标 + 走真实分发"，与真事件循环逐行一致。

## 定论

1. 恢复 `TitleScreen.onMouseClicked`（玩家木牌 → 玩家选择器，托盘格 0/1 → 商店 / 数据包），
   并在它的文档里写明"这个方法丢过一次，症状是点不动而画得出"。
2. `PvzceClient.deliverRawClick/Drag/Release` 去掉自己那次换算，改成
   `warpCursor(raw) + dispatchMouseClicked/Dragged/Released()` —— 与 `pollInput` 走同两条函数。
3. 新增 `MenuProfileFlowTest.clickingACornerCellOpensItsPage`：走 `menu.dispatchMouseClicked(...)`
   再看屏幕换没换（**已验证**：把 `onMouseClicked` 临时删掉，这条用例会红）。
4. 约定写进 `验证约定.md` §7.1：可点区域必须从真实入口验一遍，且至少一条断言经过界面自己的处理函数；
   "悬停亮"只证明绘制路径。
