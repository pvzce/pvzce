# PVZCE 架构 · 扩展点与约定

> 本册是[当前项目架构](当前项目架构.md)的分册，含 §7-8（编号与拆分前一致，跨册引用照旧按 § 号看）。

## 7. 扩展点（mod 怎么做）

| 想加什么 | 做法 |
|---|---|
| 新植物/僵尸/子弹 | 放 `data/<你的ns>/{plants,zombies,projectiles}/*.json`，用已有 capability 组合即可，**不需要写代码**。三线射手的三行齐射、分裂豌豆的向后射都只是 `ProjectileRef` 的字段（`row_offset`/`backward`/`rows`），不是新能力。原版僵尸的"帽子"（路障/铁桶/铁门/旗帜）是 `Zombie.reanim` 主文件里按图片筛选出来的，见 `tools/reanim_to_pvzce_all.py` 的 `ZOMBIE_*_EXCLUDE` |
| 僵尸装备的破损外观 | 僵尸 JSON 的 `equipment`（`art` 骨骼族 + 可选 `piece` 护甲 + `drop_particle`）；破损贴图要在模型里（`tools/reanim_to_pvzce_all.py` 的 `damage_states` 把 `<族>_2`/`_3` 骨骼按宿主骨骼的键复制出来并设为不可见），不需要新 clip、更不需要新动画文件 |
| 一件装备自带的手臂（原版一条手臂两份精灵） | 僵尸 JSON 的 `equipment[].host`（那只手在哪根骨骼上）+ `arm_bones`（该被换掉的普通手臂骨骼）；无条件不画的骨骼写在僵尸 JSON 的 `hidden_bones` |
| 关卡的教学提示文本 | 关卡 JSON 的 `hints` 块（`trigger` / `resource` / `text` / `duration_ticks`），见 `mod-guide/json-reference.md`「提示文本」 |
| 新行为（能力） | 实现 `PlantCapability`（或 Zombie/Projectile 版）→ 注册 `CapabilityType` 到 `BuiltInRegistries.PLANT_CAPABILITIES` → JSON 里就能引用 |
| 新预设 | `PlantBehaviorPresets.register(id, capabilities)` |
| 新粒子/特效 | 放 `data/<你的ns>/particles/<类目>/*.json`（`ParticleDef`），贴图放 `assets/<ns>/textures/particles/`；能力里用 `level.emitEffect(id, x, y, sound)` 触发。把原版 emitter 脚本转成本项目 JSON 的对照表见 `tools/particles_to_pvzce.py`；只要画面而不要粒子时（睡觉的 Zzz）在界面里直接 `client.particles().spawn(...)`，见 §5.2 |
| 植物被消耗时的退场动画 | 能力覆写 `vanishAnimation()` 返回 `VanishAnimation(clip, ticks)`；模型里要有这个 clip（`tools/reanim_to_pvzce_all.py` 的 `animations` 加一条即可），tick 数与 `animation_length` 对齐 |
| 新美术目录 | 模型部件贴图路径写在动画 JSON 的每个 part 里，随便分层；动画文件的位置由内容 JSON 的 `animation_dir` 声明（缺省＝按 id 路径，mod 不用写）|
| 只能种在某一种地形上的植物 | 给地形打一个新标签（`data/<ns>/tags/scene_element/<名>.json`），在 `PvzceTags` 加一个键并登记进 `PLACEMENT_TAGS`，再在 `PlantPlacement.canPlace` 里给它一条规则——墓碑破坏者就是这么做的（`#c:grave_only`） |
| 新注册表 | `PvzceRegistries` 加键、`BuiltInRegistries` 建实例、`PvzceDataLoader.CONTENT_REGISTRIES` 加目录、`byCategory()` 加分类 |
| 新伤害类型 | 放 `data/<你的ns>/damage_types/<名字>.json`（`id` + `ignores_armor` + 可选的 `ignores_front_armor` / `burns` / `dismembers`）即可，不需要写代码；能力里用 `"damage_type": "<你的id>"` 引用 |
| 开局就有的墓碑 | 关卡 `mechanics` 里写 `{"type":"pvzce:grave_field","count":7}`（可选 `min_x`/`max_x`/`region`/`designs`）：关卡建好时用关卡自己的随机源把墓碑撒在远半场。**不要**在 `scene` 里手写坐标——那是每次开局都一样的固定布局，而这个机制要的正是"每次不同" |
| 冻不住 / 冻得住的僵尸 | 打标签 `data/<ns>/tags/zombie/freeze_immune.json`（内置 `#pvzce:freeze_immune` = 气球 + 矿工）。名单里的僵尸照吃寒冰菇的伤害与寒冷，只是不被冻住 |
| 把僵尸变成自己人 | 给植物一个 `pvzce:charm` 能力（或自己实现 `PlantCapability.onBittenBy` 并调 `zombie.setTeam(...)`）；**不要**在攻击代码里加"这个僵尸是魅惑的"分支 —— 所有攻击问的都是 `LevelServer.isEnemyOf` |
| 新包 | `PvzcePackets` 加 id 常量与 `def(...)` 行 + `PacketProtocolTest` 加样本 |
| 新游戏规则 / 环境变量类型 | `BuiltInRegistries.registerGameRules/registerEnvVarTypes`；默认值请引用 `PvzceConstants`/PvzceIds`，不要内联字面量 |
| 新 GUI 界面 | 继承 `Screen`，用 `addWidget`/`showDialog`，不要把焦点和裁剪逻辑写进界面自己 |
| 新关卡 | `data/<ns>/levels/<主题>/<类别>/<名字>.json`（路径即分类，见 §6.2.1）；`LevelValidator` 会在加载时报告问题。小游戏关卡再写 `conveyor` / `placement_zone` / `tool` / `grave_spawner` / `grave_field`（见 §4.9） |
| 关卡自带的工具（点击即用） | 关卡 JSON 的 `mechanics` 里写 `{"type":"pvzce:tool","tool":"<id>","default":true,"cooldown":0,"cost":{"resources":{}}}`；工具本身仍要在 `tools/` 里存在。工具自己的美术在同一份定义里：卡片贴图 `texture`、动画目录 `animation_dir`（木槌的 `idle` = 举起、`attack` = 挥下，光标按这两个 clip 播） |
| 僵尸烧死的样子 | 僵尸 JSON 的 `animations` 里把 `death_burned` 指到一个带该 clip 的动画文件；通用焦尸是 `pvzce:zombie/charred/zombie_charred` |
| 关卡解锁条件 | 关卡 JSON 的 `unlock` 块（见 §4.8）；编辑器有独立的「解锁」页。规则求值只经 `LevelUnlocks.evaluate`，不要在界面里再写一份 |
| 关卡开场对话 | 关卡 JSON 的 `dialogue` 块（见 §6.2.2）；编辑器有「对话」页 |
| 新对话角色 | `data/<你的ns>/dialogue_characters/<名字>.json` + 立绘放 `assets/<ns>/textures/gui/dialogue/<名字>/`；关卡 `dialogue.lines` 里按 id 引用，不需要写代码 |
| 新主题 / 类别 | `data/<ns>/level_themes/*.json` / `level_categories/*.json`（`id` + `order`）；类别无需在任何主题下声明，页签由该主题下实际存在的关卡推出 |
| 注册内容 | 在 `ModInitializer` / `DedicatedServerModInitializer` 里调用 `Registry.register(...)` —— 入口点在数据加载**之前**执行，可以注册 |

## 8. 约定（避免重新长出重复实现）

改相关逻辑时请顺着这条改，不要新开一份：

1. 颜色/音效/队伍/规则的 id → `PvzceSounds` / `PvzceIds`。
2. 数值常量（tick 率、默认棋盘、初始阳光、卡片冷却…）→ `PvzceConstants`；每秒↔每 tick 换算是 `PvzceConstants.TICKS_PER_SECOND`，不要写 `60`。
3. 关卡访问 → `LevelAccess`（不要新开接口）。
4. 植物创建 → `LevelServer.spawnPlant`（不要 `new PlantEntity`）。
5. 卡槽解析 → `SlotResolver`。
6. 内容 id → 纹素/纹理 → `EntityTextures`；实体视觉常量 → `EntityVisuals`。
7. GUI 裁剪 → `Clipping`；GUI 焦点 → `FocusManager`；卡片绘制 → `SeedCardRenderer`；文本/数字 → `GuiText`。
8. 时间线数学 → `Timeline`；日夜 → `DayNightCycle`；缓动/插值 → `MathUtil`（`easeInOut` 只有这一份）。
9. 包字段声明 → `PacketStruct`；集合序列化 → `PacketByteBuf` helper。
10. 路径拼接 → `PackPaths`；注册表目录表 → `CONTENT_REGISTRIES`；注册表分类 → `PvzceRegistries.byCategory()`；**关卡存档目录键 → `LevelKey.of`**（只有这一份，客户端与服务端都调它；**不要再抄第二份**，抄本一定会分叉）。
11. 实体存档 → `saveState/restoreState`（成对实现，不要只写一半）。
12. 关卡数据校验 → `LevelValidator`（新增检查项加在这里，不要散落到构造函数里抛异常）。
13. 编辑器列表操作 → `ListEditorSupport`；背景 cover 适配 → `Screen.coverFit`；命令分类/补全 → `PvzceRegistries.byCategory()`（不要新写 switch）。
13b. 界面自己的鼠标/滚轮判定 → `Screen.onMouseClicked` / `onMouseMoved` / `onMouseScrolled`（**不要**覆写 `mouseClicked`，它是 `final`，模态分发靠它保证）。
14. 场景元素是否液体 → `LiquidTextures.liquidFor`（**读元素定义的 `liquid` 字段**，不要按贴图是否存在判断）；液体参数 → `LiquidDef`；水面绘制 → `LiquidTextures.renderWorld` / `renderGuiBoard`（游戏内与选卡预览共用同一实现，只有一个投影参数不同）。水格画在哪由**舞台的** `LevelStage.LiquidFrame` 给出（`CELL` = 水格即水面），两个绘制入口都收它；**不要**在水面这条 pass 里按液体 id 写偏移。
15. 能不能种 → `PlantPlacement.canPlace`（**纯函数，只读 `#c:` 标签与 `PlacementDef`**）。不要在别处再写一份判定：`LevelServer.canPlacePlant` 只是把关卡适配成 `PlantPlacement.Ctx`，`PlantAIPlayer` 也调它。瓦片能种什么**不写进场景元素定义**，要加地形就在 `data/c/tags/scene_element/` 里打标签。
16. 堆叠层与互斥 → `PlacementDef` 的 `layer`/`count`/`group`（载体 `layer 0`、地面植物 `1`、植物上的植物 `2`；`group` 留空＝同格可多个）。判定只看**比自己层低**的东西，所以种植顺序不影响结果。
17. 关卡属于哪一页 → `LevelGrouping`（**纯函数，只读 id 路径**）。不要在别处再写一份：服务端 `PvzceServer.groupOf`、客户端 `LevelPage`、编辑器的换组都调它；页签顺序与名单由服务端 `LevelTabs` 从注册表推出发给客户端。
18. 卡是否被背包锁住 → `SlotResolver.requiresUnlock`（服务端 `PlayerProfile.owns` 与客户端 `ClientProfile.owns` 都调它）；选卡池 → `SeedOptions.cardPool`（**唯一一份**，"客户端看得到"与"服务端收得下"靠它对齐）。关卡固定卡**永远不过滤**。
19. 玩家档案（金币 / 已解锁卡）→ `PlayerProfile` + `PvzceServer.profileFor/saveProfile`（缓存按世界名，换世界前先 `flushProfile()`）。不要在别处再读一次 `profile.dat`，也不要在关停钩子里写文件。
20. 通关发什么 → 关卡 `rewards` 块 + `RewardSettlement.settle`（首通/重复/掉币的**唯一**结算点）；新增奖励类型要同时改 `LevelRewards` 与 `LevelValidator.validateRewards`。金币掉落只经 `LevelAccess.zombieDied`，实体不读关卡奖励数据。
21. 内容 id → 用哪份美术 → `EntityArt`（动画文件与兜底贴图两个问题一次查表）。不要在渲染器/编辑器/选卡里各拼一次路径：内置美术按类目分层后，路径已经不能从 id 推出来。
22. 命中反馈/特效的粒子 id → `PvzceParticles`（与 `PvzceSounds` 同形）。未定义的效果**不画东西**，只按 id 报一次日志。
22b. 缺失贴图 → `EntityArt.MISSING_TEXTURE`（渲染器、`EntityArt.sprite(null)` 与 `TextureManager` 的采样方式都读它）。不要在绘制处自己造一块纯色占位。
22c. 总卡槽数 → `LevelDef.effectiveMaxSeedSlots(profileSlots)`（关卡声明优先，未声明用背包的 `PlayerProfile.seedSlots`）。判断"关卡有没有自己声明"用 `declaresMaxSeedSlots()`，不要拿 `maxSeedSlots` 和某个数字比 —— 未声明是 `UNSET_MAX_SEED_SLOTS`（-1），不是 6。
24. 「这一格能不能放」的规则只有 `PlantPlacement` 一份；工具点击可否执行由 `LevelServer.applyToolEffect` 返回布尔值表示，**被拒绝的点击不消耗使用次数也不进冷却**。移动植物走 `spawnPlant` + `restoreStateWithoutPosition`：位置由新格子决定，状态（血量、年龄、能力）跟着走 —— 直接 `restoreState` 会把坐标一起写回去，等于没搬。
25. 关卡能不能进 → `LevelUnlocks.evaluate`（**纯函数**，`Context` 里只有已通关/已购买/背包/金币/沙盒）。服务端求值、客户端收结论（`UnlockInfo`），不要在界面里判断；入口门槛在 `PvzceServer.createLevel` 重新求值一次，不要只信列表。购买价只从关卡定义读，永远不信客户端。
26. 实体归类 → 美术目录（`textures/entities/<类目>/…`）与动画目录（`animation_dir`）用**同一套类目**，分类表只有一份：`tools/group_entity_assets.py` 的 `ENTITIES`，以及重新生成美术时 `tools/reanim_to_pvzce_all.py` 的 `EntityConfig.group`。**内容 id 永远不带类目** —— 改目录不会让关卡、标签、存档或语言 key 失效。
27. 实体类别 → `EntityKind` 的四个常量，**它们是类别不是内容 id**：判断「这是不是某个具体资源/植物」一律比内容 id（`defIdString()` / `PvzceIds`），不要比 kind（见 §6.3 的世界点光源）。
28. 捡起一个资源放什么效果 → `ResourceDef.pickup_effect`（可缺省＝不放）。不要在收集代码里按资源分类写分支：阳光与硬币不是同一种拾取，共用一份粒子参数必然有一边是错的。
29. 传送带的产出/容量/消耗/存档 → `ConveyorBelt`（服务端唯一实现）；卡槽条是它的**投影**（`BeltCardSource.rebuildBar`），不要在别处再维护一份"带上有哪些卡"。
30. "这一格能不能种"的第二半（**关卡允许的范围**）→ 关卡 `placement_zone` + `LevelServer.canPlacePlant`。不要写进地形标签：红线是画在普通草地上的，改地形会把草坪一起改掉。客户端画线/悬停从 `LevelPayload` 的同一条矩形读。
31. 爆炸的范围与触发 → `ExplosiveCapability.detonate` 的**不变量「爆炸半径 ≥ 触发范围」**。新写 proximity 内容时 `trigger_range > radius` 也不会静默打不中（`ExplosiveCapability` 会取大），但数据仍应写成想要的值。
31b. 爆炸之后植物还要在场上留多久 → `ExplosiveCapability.LINGER_TICKS`（30 tick）。爆炸是**瞬时**的（伤害当 tick 结算），留下的是那一幅画：植物随即 `occupiesCell` 为假（僵尸走过去、铲子够不着），计数归零自己 `remove()`。**不要**在关卡里另开一份「爆炸植物延迟移除」名单，也不要在客户端补一段「等动画播完再删」。
32. 植物是否占格（僵尸能否啃、工具能否取）→ `PlantCapability.occupiesCell` + `LevelServer.plantAt`。不要在僵尸的啃咬循环或工具里判断具体植物 id。
32b. **一次命中吃不吃护甲** → 注册的 `DamageTypeDef`（`pvzce:ash` / `pvzce:projectile` / `pvzce:impact` / `pvzce:splash` / `pvzce:mower`）。所有伤害都从 `ZombieEntity.damage(amount, type, level)` 走，不要在能力里另开一条「直接扣血」的路；要新的护甲规则就给类型加字段，不要在第 4 个方法里再写一遍。
32c. **植物能不能被打死** → `PlantCapability.invulnerable` + `PlantEntity.damageFrom`。「咬不动」与「铲不掉」是两件事：前者问 `invulnerable`，后者问 `occupiesCell`（灰烬类在引信期间只回答前者）。
33. 这一行有没有小推车、它在哪 → `MowerMechanic` 的 `Rig`（服务端唯一实现，状态经 `LevelServer.mechanicState` 存在关卡上，客户端镜像在 `ClientLevel.mechanicState`）。**不要另开一份"哪行有推车"的判断**：默认值（每行一辆）只由 `LevelMechanics.effective` 加，行列表只由 `MowerData.rowsFor` 展开。
34. 一条不绑定实体的动画（机制道具、以后可能的 UI 表演）→ `ArtTarget` + `AnimationManager`。它的 `fileFor` 认得这种目标并直接读文件 id；不要在机制里另写一个渲染器。
35. 僵尸身上会磨损的装备 → `EquipmentDef`（`art` 骨骼族 + 可选 `piece` 护甲 + `drop_particle`）。档位判定与"这帧该画哪一张"只有 `EquipmentArt` 一份（`BoneArt` 钩子）；**不要把状态编译成动画 clip**（三个档位 × 六个 clip × 800KB），也不要再加第二个"挨打时掉什么"的分支：伤害吸收只经 `ArmorCapability.absorb`，掉落粒子从定义里取。
36. "这一关有没有得选卡" → `SeedOptions.hasNothingToChoose(pool, maxSlots, lockedIds)`（**纯函数**）。选卡屏的预览模式与存档提示框的重开都问它；判据是**总卡槽数 − 关卡固定卡数**，不是"已选卡数"。
37. 屏幕上那句提示 → `HintBox`（唯一实现）+ `LevelHints`（唯一触发点）。不要在界面里另写一个"显示一行字两秒"的东西：拒绝优先、一条一条来、墙钟计时都在里面。
38. 僵尸画哪些骨骼 → `EquipmentArt.visibleBones`（唯一实现）。装备的档位、断臂、`hidden_bones`、装备自带手臂与普通手臂的互斥，全部在这一个函数里决定；**不要**在渲染器或 clip 里加特例。
39. 粒子落地后的水平行为 → `ParticleMotion.ground_friction`（缺省 1 = 保留"一直滑"的手感）。要"原地停下"就在**数据**里调小，不要改引擎。
40. 小推车的"还在 / 没了" → `MowerMechanic.Rig`（服务端）+ `ClientMechanics.consumeParkedMowers`（客户端核销）。不要在界面里再维护一份"哪些车已经变成金币了"。
41. 实体画在哪个坐标 → `ClientEntity.visualCellX/Y/Height`（**渲染用**；`cellX()` 永远是服务端的数）。不要在渲染器里自己补间，也不要把补间写回 `cellX()`：那会让命中测试和存档读到没有权威性的中间值。
42. 一个状态要持续多久 → **服务端计数器**（`biteCooldown`、`corpseTicks`、`vanishTicks`、`expireTicks`），不是"客户端自己播完再说"。服务端不知道 clip 有多长，也不该知道；它只知道"这个状态现在成立"，而客户端用一个带 transition 的 clip 把它演出来。
43. 植物睡不睡 → `PlantCapability.asleep`（由 `LevelAccess.isNight()` 与咖啡豆的唤醒标志推出）+ `PlantEntity.tick` 的跳过规则。**不要在能力里各自判断白天黑夜**：睡着时"什么都不做"是实体统一跳过的，新能力默认就被覆盖；`pvzce:nocturnal` 只负责发布 `sleep` 动画与永久唤醒。
44. 一发子弹能飞多远 → `ProjectileRef.range`（0 = 不限），**同一个数**既是"值不值得开火"（`ProjectileRef.covers`）也是"子弹何时消失"（`ProjectileEntity` 从出膛点量起）。不要把射程写进子弹定义：同一个孢子可以被不同射程的植物发射。
45. 关卡列表的顺序 → `LevelGrouping.compareIds`（自然序：数字段按数值比）。服务端下发列表与页签推导都调它，**不要**再写一份 `String.compareTo`——`1_10` 会跑到 `1_2` 前面。
46. 开局两波多久出一只 → `WaveDef.holdUntilDead(waveIndex)`（**唯一**的规则出处）+ `LevelServer` 的两处门（波内 `PendingWaveSpawn`、波间 `openingWaveStillOnTheField`）。**不要**靠调大 `spawn_interval` 来"放慢前期"：那是在替玩家猜速度，而门控问的是玩家自己。
47. 一张卡冷却多久 → 卡自己的数（`Slot.cooldownTicks`，建条时从 `SlotResolver` 抄）× 关卡规则 `pvzce:seed_cooldown_multiplier`，换算只有一处：`LevelServer.effectiveCooldownTicks` / `CardCooldown.effective`。**消耗时才算**（种植物与用工具两条路都调它），`SlotInfo.cooldownTotal` 把同一个数发给客户端当充能条的分母 —— 不要在某一处直接 `startCooldown(卡自己的数)`，也不要在客户端拿本地的规则再推一遍。
48. 列表行上那枚奖杯 → 类别定义的 `trophy` + `LevelInfo.cleared`（**通关过至少一次**），判定只在 `LevelSelectScreen.showsTrophy`。**不要读 `status` 字符串**：有存档时它写的是"进行中"，而奖杯不该被一局重玩收回去。
49b. **空手点击做什么** → 关卡 `mechanics` 里的 `pvzce:tool`（`default: true`），读法只有 `ToolMechanic.defaultTool/declared`。不要在界面里按关卡 id 判断"这一关是打地鼠"。
49c. **谁在玩这一关** → `LevelDef.playableTeamDefs()` / `offersTeamChoice()`（服务端求值，客户端读 `TeamInfo.playable`）。不要在界面里写"僵尸方没有卡组所以不可选"。
49d. **爆炸打多大一片** → `pvzce:explosive` 的 `radius` + `square`（格）或 `trigger: "row"`（整行），落到 `LevelAccess.damageArea(..., square)` / `damageRow`。不要用一个大到能覆盖整行的方格来假装"整行"。
49f. **这一下打谁** → `LevelAccess.enemiesInRow(row, team)` / `LevelServer.isEnemyOf`（"不是同一队"），`zombiesInRow` 只用于"这一行有几只"。不要在攻击代码里判断某个实体是不是被魅惑的：阵营本身就是答案。
49g. **被消耗的植物怎么退场** → `PlantCapability.vanishAnimation()`（clip + tick）。它让玩法结束与画面结束分开，但只有这一处：`isRemoved()` 一为真就不再占格、不再被瞄准，剩下的只是 `PlantEntity.vanishing()` 在倒数。不要在关卡里另开一份"等动画播完再删"的名单。
49e. **这一下算不算"烧"** → 伤害类型的 `burns`（`DamageTypeDef`），到 `ZombieEntity.damageBody(amount, level, burns)` 与 `EntityAnimations.DEATH_BURNED`。不要在死亡代码里排一张"哪些伤害 id 会烧"的名单。
49h. **一张传送带卡发多少张** → `LevelBelt.BeltCard.maxCount`（不写 = 不限）。计数在传送带自己身上（`ConveyorBelt.dealt`，**发出就算**，用掉没用掉都算），发满的卡退出池子，计数与队列一起进存档。**不要**在关卡里另开一份"这一关只给几张墓碑破坏者"的名单。
49i. **开局草坪上的墓碑** → `pvzce:grave_field` 机制 + `GraveScatter`（**唯一**一处"把墓碑放到某个格子"的实现，`grave_spawner` 补墓碑也走它）。关卡文件**不写**墓碑的坐标：位置是每次开局随机撒的，写在 `scene` 里就失去这个机制的意义。
49. 关卡发的"东西"而不是"钱" → `rewards` 的 `resource` 条目（面值来自资源定义的 `default_value`）+ `LevelRewardS2C.rewardItem`，客户端三处（草坪掉落、领取动画、结算页相框）都从包里那一个字段决定画什么。不要在客户端按关卡 id 判断"这一关发钻石"。
50. **一个背景图用哪套舞台几何** → `LevelStage.geometryFor(background)`（**唯一**的查表点：`background3`/`background4` → `LevelStage.POOL`，其余含"没写背景"与未知贴图 → `LevelStage.YARD`）。格子尺寸、草坪矩形与液面帧都随它走，棋盘只由 `LevelStage.board(w, h, columns, rows, geometry)` 算，`PvzceCamera` 拿同一份几何（`geometry()` / `liquidFrame()`），`PvzceClient.camera()` 的缓存键也要带上它。**不要**在界面或渲染器里按关卡 id、行数或宽高判断"这是不是泳池"——多一行、换一张背景，判断要跟着数据走。
51. **一个波次条目从哪几行出怪** → `WaveDef.Entry.rows`（空 = 任意行；`WaveDirector` 把行列表抄进放怪队列，出怪时按列出的顺序轮取）。**不要**在出怪代码或机制里按僵尸 id 猜行（"会游泳的走水里"）：行是波次表自己的字段，越界行由 `LevelValidator.validateWaves` 报出来；存档里的 `ZombieRows` 与 `Zombies` 平行，缺键读回"任意行"。
52. **某一行放哪种小推车** → `MowerData.kinds`（行 + 内容 id + 可选启动音效）。行集合 = `rows`（未写＝每行）∪ `kinds` 点名的行，`kindFor(row)` 是唯一读法；车型是**内容 id**，客户端按 `mechanic/<path>` 取动画（`MowerClientMechanic.animationFor`）、服务端按它取启动音效。**不要**给 `MowerMechanic` 按行号或按关卡写分支，也不要为车型加包字段：它来自关卡数据，线上只有位置与状态。
53. **浇水做什么** → `LevelServer.waterPlant`（`applyToolEffect` 的 `pvzce:water` 分支）挨个问 `PlantCapability.water(plant, level)`：能力回答"这水用来做什么了"（今天只有 `ProducerCapability` 的催熟），回满血与 15 秒的加速时钟则是实体的事（`PlantEntity.water` / `watered` / `actionStep`）。**不要**在工具效果里按植物 id 判断"这株能不能催熟"，也不要把倒计时各自写在能力里——射手与生产者都走 `PlantEntity.actionStep()`。
54. **一株植物的"工作速率"** → `PlantEntity.actionRate(extraRate)`（关卡倍率 × 浇水 × 调用方自己那一份），每一步的进度由**每个能力各自持有的** `common/level/RateClock` 累计。**不要**把累加器放回 `PlantEntity`：一株植物可以同时有射手与生产者两个能力，共用一个累加器时先跑的那个会把整 tick 的进度花光（太阳菇因此只在每两 tick 产出一次）。**也不要**把 `ticks * rate / 3` 写成 float 除法：`(int)` 截断前必须提升到 double，否则 `3.0f/3` 会算出 0.999… 被截成 0。
55. **一关的变异列表** → `LevelServer.mutations()`（`MutationManager`），`null` 表示这关不声明 `pvzce:mutation`。变异本身注册在 `BuiltInRegistries.MUTATIONS`，必须**无状态**（共享单例），一切每局状态走 `apply` 的返回值或 `LevelServer.mechanicState` 那样的关卡槽位。**不要**把变异做成关卡机制：机制由关卡声明、按 id 查数据块，而变异是引擎随机抽出来、还要能被撤销的。
56. **卡槽条的种类在运行时会变** → `LevelServer.cardSourceKind()` / 客户端 `MutationStateS2C.cardBarKind`，客户端据此在 `InGameScreen.cardBar()` 里换 `CardBar` 实现。**不要**再让任一侧从关卡定义直接推"这一关是不是传送带"：变异可以让同一关在两条卡槽条之间来回切，定义是静态的。
57. **一个挡位开出多少条变异、多久一条、数值多强** → `MutationDifficulty`（关卡规则 `pvzce:mutation_difficulty`），首条延迟是 `pvzce:mutation_initial_ticks`。**不要**在变异自己里写死间隔或上限：档位是这一整关的四个数，写在 18 条变异里就是 18 份可以互相矛盾的副本。
58. **长出来的墓碑不回收** → `placeGrave`（`MutationManager` 的墓碑生长、`grave_spawner`、`grave_field` 共用）。变异被挤出时**不**清掉它长出来的墓碑与水草：那是地形与玩家的植物了，删掉会连带删掉玩家围着它做的东西。变异"拥有"的只有它自己的时钟。

59. **变异自己的状态怎么进存档** → `Mutation.saveState()` / `loadState()` / `applyFromSave()`（`MutationManager` 把整份列表写进 `level.dat` 的 `Mutations` 块）。要区分**两件事**：变异对世界做过的事（弹坑、墓碑、水草、卡槽条内容）由存档的既有分区承担，恢复时**不要重放**；变异**自己**的倒计时、预算、以及它拥有的那一份游戏规则，存档里没有对应物，必须由 `applyFromSave` 重新建立。只改规则的变异（`RateMutation`、`BowlingNutMutation`）在恢复时再写一次规则，因为存档里的规则是关卡自己的值、不含变异那一份。**不要**把状态塞进 `Mutation` 的字段：注册表条目是共享单例，save/load 之间那两个暂存字段是唯一允许的例外（见 `SlotReplaceMutation.savingPlayer`）。
60. **一条卡槽条自己的状态** → `CardSource.collectSave/applySave`（写进调用方给的块里），与 `CardSource.save/restore`（写进关卡根部）分开。分歧点在于**谁拥有那份状态**：关卡自己声明的那条属于关卡，变异装的属于变异（所以进 `Mutations.CardSource`）。**不要**给卡槽条加第三条路径。
