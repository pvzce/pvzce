## 7. 扩展点（mod 怎么做）

| 想加什么 | 做法 |
|---|---|
| 可注册的单体数值属性 | `Registry.register(BuiltInRegistries.ATTRIBUTES, ...)` 或 `data/<ns>/attributes/` 定义；实体 `attributes()` 添加、改基值和具名修饰。生成 JSON 支持 `attributes`，语义见实体册「单体数值属性」 |
| 新植物/僵尸/子弹 | 放 `data/<你的ns>/{plants,zombies,projectiles}/*.json`，用已有 capability 组合即可，**不需要写代码**。三线射手的三行齐射、分裂豌豆的向后射都只是 `ProjectileRef` 的字段（`row_offset`/`backward`/`rows`），不是新能力。原版僵尸的"帽子"（路障/铁桶/铁门/旗帜）是 `Zombie.reanim` 主文件里按图片筛选出来的，见 `tools/reanim_to_pvzce_all.py` 的 `ZOMBIE_*_EXCLUDE` |
| 僵尸装备的破损外观 | 僵尸 JSON 的 `equipment`（`art` 骨骼族 + 可选 `piece` 护甲 + `drop_particle`）；破损贴图要在模型里（`tools/reanim_to_pvzce_all.py` 的 `damage_states` 把 `<族>_2`/`_3` 骨骼按宿主骨骼的键复制出来并设为不可见），不需要新 clip、更不需要新动画文件。**没有 `piece` 而族里有两张以上贴图**时按血量三等分换（冰车的车体就是这样）；带 `piece` 的按护甲档位换 |
| 植物被啃出裂纹 | 同一个 `damage_states`（宿主是身体骨骼，新骨骼名以 `cracked_` 开头），客户端由 `client/renderer/PlantDamageArt` 按血量三等分选一张。**不要**给植物加"受伤"clip：clip 是一种外观，每个受伤档位都要复制一遍整份动画 |
| 模型里要一块原版没有的美术（板子、支架） | `tools/reanim_to_pvzce_all.py` 的 `extra_bones`：`{宿主骨骼: ((新骨骼, png, y偏移), ...)}`，贴图按 `refer/anim/<png>` 找。默认在所有 clip 里不可见，要让某一段画它就写**片段级** `force_visible`（配置级 `force_visible_bones` 故意复活不了它） |
| 一个部件跟着另一个部件动（原版只有平铺坐标） | `tools/reanim_to_pvzce_all.py` 的 `bone_parents`：`{子骨骼: 宿主骨骼}`，导出器把子骨的键改写成宿主空间并在模型里声明 `parent`，引擎自己的骨骼变换就会带着它。三线射手的三个头挂三根茎就是这样 |
| 一件装备自带的手臂（原版一条手臂两份精灵） | 僵尸 JSON 的 `equipment[].host`（那只手在哪根骨骼上）+ `arm_bones`（该被换掉的普通手臂骨骼）；无条件不画的骨骼写在僵尸 JSON 的 `hidden_bones` |
| 关卡的教学提示文本 | 关卡 JSON 的 `hints` 块（`trigger` / `resource` / `text` / `duration_ticks`），见 `mod-guide/json-reference.md`「提示文本」 |
| 新行为（能力） | 实现 `PlantCapability`（或 Zombie/Projectile 版）→ 注册 `CapabilityType` 到 `BuiltInRegistries.PLANT_CAPABILITIES` → JSON 里就能引用。要一种新攻击就同时回答 `holdsFire()`（"我是按时钟开火的"）与 `strike()`（"被点名时打一次"）：节奏关卡按这两个答案决定谁在平时停手、谁能被音符指挥 |
| 新预设 | `PlantBehaviorPresets.register(id, capabilities)` |
| 新粒子/特效 | 放 `data/<你的ns>/particles/<类目>/*.json`（`ParticleDef`），贴图放 `assets/<ns>/textures/particles/`；能力里用 `level.emitEffect(id, x, y, sound)` 触发。把原版 emitter 脚本转成本项目 JSON 的对照表见 `tools/particles_to_pvzce.py`；只要画面而不要粒子时（睡觉的 Zzz）在界面里直接 `client.particles().spawn(...)`，见 `架构-实体与能力.md` §5.2 |
| 植物被消耗时的退场动画 | 能力覆写 `vanishAnimation()` 返回 `VanishAnimation(clip, ticks)`；模型里要有这个 clip（`tools/reanim_to_pvzce_all.py` 的 `animations` 加一条即可），tick 数与 `animation_length` 对齐 |
| 新美术目录 | 模型部件贴图路径写在动画 JSON 的每个 part 里，随便分层；动画文件的位置由内容 JSON 的 `animation_dir` 声明（缺省＝按 id 路径，mod 不用写）|
| 只能种在某一种地形上的植物 | 给地形打一个新标签（`data/<ns>/tags/scene_element/<名>.json`），在 `PvzceTags` 加一个键并登记进 `PLACEMENT_TAGS`，再在 `PlantPlacement.canPlace` 里给它一条规则——墓碑破坏者就是这么做的（`#c:grave_only`） |
| 新注册表 | **四行**：`PvzceRegistries` 加键、`BuiltInRegistries` 用 `ACCESS.newRegistry(...)` 建实例、`PvzceDataLoader.CONTENT_REGISTRIES` 加目录、`PvzceRegistries.byCategory()` 加分类（与 `架构-框架层.md` §3.1 是同一份清单） |
| 新伤害类型 | 放 `data/<你的ns>/damage_types/<名字>.json`（`id` + `ignores_armor` + 可选的 `ignores_front_armor` / `burns` / `dismembers`）即可，不需要写代码；能力里用 `"damage_type": "<你的id>"` 引用 |
| 开局就有的墓碑 | 关卡 `mechanics` 里写 `{"type":"pvzce:grave_field","count":7}`（可选 `min_x`/`max_x`/`region`/`designs`）：关卡建好时用关卡自己的随机源把墓碑撒在远半场。**不要**在 `scene` 里手写坐标——那是每次开局都一样的固定布局，而这个机制要的正是"每次不同" |
| 冻不住 / 冻得住的僵尸 | 打标签 `data/<ns>/tags/zombie/freeze_immune.json`（内置 `#pvzce:freeze_immune` = 气球 + 矿工）。名单里的僵尸照吃寒冰菇的伤害与寒冷，只是不被冻住 |
| 把僵尸变成自己人 | 给植物一个 `pvzce:charm` 能力（或自己实现 `PlantCapability.onBittenBy` 并调 `zombie.setTeam(...)`）；**不要**在攻击代码里加"这个僵尸是魅惑的"分支 —— 所有攻击问的都是 `LevelServer.isEnemyOf` |
| 新包 | `PvzcePackets` 加 id 常量与 `def(...)` 行 + `PacketProtocolTest` 加样本 |
| 新游戏规则 / 环境变量类型 | `BuiltInRegistries.registerGameRules/registerEnvVarTypes`；默认值请引用 `PvzceConstants`/PvzceIds`，不要内联字面量 |
| 新 GUI 界面 | 继承 `Screen`，用 `addWidget`/`showDialog`，不要把焦点和裁剪逻辑写进界面自己 |
| 新关卡 | `data/<ns>/levels/<主题>/<类别>/<名字>.json`（路径即分类，见 `架构-客户端.md` §6.2.1）；`LevelValidator` 会在加载时报告问题。小游戏关卡再写 `conveyor` / `placement_zone` / `tool` / `grave_spawner` / `grave_field`（见 `架构-服务端.md` §4.9） |
| 关卡自带的工具（点击即用） | 关卡 JSON 的 `mechanics` 里写 `{"type":"pvzce:tool","tool":"<id>","default":true,"cooldown":0,"cost":{"resources":{}}}`；工具本身仍要在 `tools/` 里存在。工具自己的美术在同一份定义里：卡片贴图 `texture`、动画目录 `animation_dir`（木槌的 `idle` = 举起、`attack` = 挥下，光标按这两个 clip 播） |
| 僵尸烧死的样子 | 僵尸 JSON 的 `animations` 里把 `death_burned` 指到一个带该 clip 的动画文件；通用焦尸是 `pvzce:zombie/charred/zombie_charred` |
| 关卡解锁条件 | 关卡 JSON 的 `unlock` 块（见 `架构-服务端.md` §4.8）；编辑器有独立的「解锁」页。规则求值只经 `LevelUnlocks.evaluate`，不要在界面里再写一份 |
| 关卡开场对话 | 关卡 JSON 的 `dialogue` 块（见 `架构-客户端.md` §6.2.2）；编辑器有「对话」页 |
| 新对话角色 | `data/<你的ns>/dialogue_characters/<名字>.json` + 立绘放 `assets/<ns>/textures/gui/dialogue/<名字>/`；关卡 `dialogue.lines` 里按 id 引用，不需要写代码。立绘的透明边距用 `portrait_insets` 量出来（一行/一列有 5% 像素不透明才算"有画"），量法见 `架构-客户端.md` §6.2.2 |
| 新主题 / 类别 | `data/<ns>/level_themes/*.json` / `level_categories/*.json`（`id` + `order`）；类别无需在任何主题下声明，页签由该主题下实际存在的关卡推出 |
| 注册内容 | 在 `ModInitializer` / `DedicatedServerModInitializer` 里调用 `Registry.register(...)` —— 入口点在数据加载**之前**执行，可以注册 |
| **一株植物**（完整清单） | ① `data/<ns>/plants/<名>.json`（数值 + `capabilities` + `animation_dir` + 图鉴 `order`）；② `data/<ns>/slots/<名>.json`（卡：`kind: plant`、价格、图标）；③ 动画 `assets/<ns>/animations/<animation_dir>/<名>.json`（**必须有 `idle`**；被消耗的要有 `vanishAnimation` 指定的 clip，睡觉得有 `sleep`）；④ 卡面 `assets/<ns>/textures/gui/cards/<名>.png`（`tools/render_controller_icons.py`，目录分组表在 `ANIMATION_DIRS`）；⑤ 语言键 `plant.<ns>.<名>` / `.desc` / `.flavor` / `slot.<ns>.<名>`；⑥ 需要的标签（水草 `#c:water_plant`、墓碑专属 `#c:grave_only`…）。图鉴 `order` **不许重复**（`AlmanacEntriesTest` 守着） |
| **一个关卡机制**（准备阶段、传送带、雾…） | 注册一个 `LevelMechanic<D>`（`LevelMechanics.register`，id 进 `PvzceIds`），D 是 `MechanicData`；客户端要画东西就在 `ClientMechanics.register` 里配一个 `ClientMechanic`（状态走 `MechanicSyncS2C.of(...)`，**只声明一次 codec**，两边共用）。准备阶段（`PreparationMechanic`）是最小的一个例子：一个布尔状态 + 两条 tick 门（出怪、天上阳光） |
| **斗转星移（传送门）** | `pvzce:portal` 机制 + `PortalData.pairs`（每对四个数：a 与 b 两个格子）。地面僵尸**走过**某端中心（上一拍在右、这一拍在左）就从另一端出来，出来时带 30 拍免疫（否则出口就在自己的触发线左边，会同一条僵尸来回弹）。飞行与地下僵尸不传送，判据是僵尸自己的层。客户端画圈：`PortalClientMechanic`，一对门的两端**脉动方向相反**（那是原版美术里唯一区分两端的东西） |
| **种子雨（天上掉卡）** | `pvzce:seed_rain` 机制 + `SeedRainData`（`interval_ticks` / `initial_delay_ticks` / `cards` 池，支持 `weight` 与 `max_count`）。它只做一件事：按拍在**没有包的空格**上 `LevelServer.spawnCardDrop(card,x,y)`。包本身不是新东西 —— 就是 `CardDropEntity`，捡起来拿在手上、种下去免费（见"一张卡在运行时进条"那一行） |
| **一张紫卡（升级植物）** | 植物 JSON 的 `"upgrade": {"base": "pvzce:底植物", "adjacent": 0}` 决定默认升级规则（种在底植物上、把它吃掉）与紫包卡面（`CardPainter.packetFor`）；获得入口放在关卡 `rewards.first_clear` 的 `unlock`，内置商店不出售紫卡。`adjacent: 1` 是玉米加农炮那种"同行相邻还要再站一株"的 2×1（两张都吃掉），其余七张是 0。是否要求前置由 `PlantPlacement.requiresUpgradeBase` 按上下文决定，融合关卡允许按一般种植规则直接种下；占地仍由植物定义提供。**别忘 `order`**：图鉴与选卡页按它排 |
| **一张节奏谱面** | 关卡文件里写 `{"type":"pvzce:rhythm","bpm":…,"offset_ticks":…,"approach_ticks":80,"perfect_sun":25,"attack_volleys":3,"plants_hold_fire":true,"end_beat":…,"lanes":[{"kind":"col","index":2,"notes":[4,8]}]}`：音符是**拍号**不是 tick（`RhythmChartData.ticksPerBeat`），`kind` 取 `row`/`col`，但**一张谱面只能有一种**（混用是校验错误：每关只有一个操作逻辑，草坪上的按键提示才有唯一的位置）。**判定窗口不是写死的 tick**：`approach_ticks`（默认 80）是音符飞的时长，三档窗口是它的 5% / 10% / 15% = PERFECT / GOOD / FAIR，所以画面（音符离判定线多远）与判定是同一个数。`end_beat` 是歌的最后一个小节，走到它清场判胜。客户端按键（`KeyBindings` 的 `RHYTHM_*`；**已发布内容用六列 `S D F J K L`**，行键与第七~九列默认不绑、留给手写谱面自己绑）由 `RhythmPlay` 判定后发 `RhythmHitC2S`，服务端 `RhythmMechanic.judge` 决定算不算、并按 `volleys(grade)` 让**那一列/那一行每株植物各打 N 次自己的攻击**（`PlantCapability.strike`）；谱面的**起点由服务端下发**（`RhythmMechanic.Status` 的第一项；同一条消息还带能量条、战况、乘数与辣椒数，**一个机制只有一种载荷**），客户端不自己推。四档关卡用编辑器的「节奏谱面」页一次生成，**生成器是 `common/level/RhythmCharts`**（`RhythmChartsTest` 钉着已发布四关与它一致）。生成器跟着**曲子的鼓点分析**出音符（每首歌一条 `RhythmCharts.Song`：`SONGS` 里现在两首——终极之战 110 BPM / 340 拍、小游戏 94 BPM / 295.75 拍，分析都由 `tools/rhythm_onsets.py` 量出、`--check` 可复核）；曲目没有分析时退回匀速拍点谱。**一首歌 = 一条记录 + 四张关卡**，新歌按同一形状加一条即可（`RhythmChartsTest` 钉着已发布的八关与生成器一致） |
| **一种僵尸卡（我是僵尸）** | `slots/<僵尸>.json` 写 `"kind": "zombie"` + `"content": "pvzce:<僵尸>"` + 卡自己的太阳价（`cost.resources.pvzce:sun`），**价格不进 `ZombieDef`**；卡面要在 `textures/gui/cards/<僵尸>.png` 并写进 `icon`（僵尸的 `texture` 是一目录，指不过去），由 `tools/render_controller_icons.py` 从模型画；关卡写 `"playable_teams": ["pvzce:zombie_team"]` 就把玩家换到另一边（`LevelDef.humanTeam()`），放置走 `PlaceZombieC2S` → `LevelServer.placeZombie` |
| **一株要玩家瞄准的植物** | 能力里存"装填好了没有"（`CobCannonCapability` 的 `loaded()` / `chargeLeft()`），客户端点它进**本地**瞄准模式、第二次点格子发 `FireAtC2S(entityId, x, y)`；服务端 `LevelServer.fireAt` 只做归属与状态校验，真正开炮由能力自己做（`LevelServer.launchAimedProjectile` 瞄格子的抛物线 + `pvzce:splash` 的 `square: true`）。**不要**在客户端把"能不能开火"再算一遍：能不能由服务端答，客户端只画准星 |
| **一种僵尸**（完整清单） | ① `data/<ns>/zombies/<名>.json`（血量/速度/咬伤 + `capabilities` + `animations` + 图鉴 `order`）；② 动画（原版 reanim 走 `tools/reanim_to_pvzce_all.py` 的 `EntityConfig`，或像植物僵尸那样用 `tools/make_zombotany_assets.py` 合成）；③ 语言键 `zombie.<ns>.<名>` / `.desc` / `.flavor`；④ 进哪个池子（`#pvzce:mutation_crisis` 之类的标签）；⑤ 出怪时**行要写**（`WaveDef.Entry.rows`，见 §8.51） |
| **一种新机制** | `api/content/mechanic/<名>Data.java`（`MechanicData` + `MAP_CODEC`）+ `common/level/mechanic/<名>Mechanic.java`（钩子：`onLevelCreated` / `tick` / `canPlacePlant`（含显式 surface 重载） / `zombieSpeedMultiplier` / `sendState` / `collectSave` / `applySave` / `validate` / `editorFields`）+ 注册进 `LevelMechanics.bootstrap`（id 常量在 `PvzceIds`）+ 客户端镜像 `ClientMechanic`（按 id 注册，状态走 `MechanicSyncS2C`；可选 `renderHud`）。`sendState` 用于进场全量同步，避免暂停时等不到 `tick` 状态；速度钩子由 `LevelAccess.zombieSpeedMultiplier` 组合各机制的倍率。要在运行时给关卡装一个机制（变异用）走 `LevelServer.installMechanic/removeMechanic` |
| **一条变异** | 见 §8.61 的六处清单；写规则的必须实现 `MutationManager.RuleMutation`，带状态的必须实现 `MutationManager.SaveHandle`；客户端表现走 `MutationEffects` 位，不另开包 |
| **一个增益** | `api/content/LevelBuff` 加钩子（默认值＝不生效）→ `common/buff/BuiltInBuffs` 注册 + id 常量 → 图标 `assets/<ns>/textures/gui/buff/<id>.png`（`tools/gen_ui_icons.py`）→ 语言键 `level_buff.<ns>.<名>`（两个 lang 文件）→ 关卡 `buffs` / 奖励 `{"type":"buff"}` 引用 |
| **一件商店商品** | 目录与价格只在 `common/shop/ShopItems`（纯数据，**不能** import server，`LayerDependencyTest` 守着）；"这个玩家有没有"由 `server/shop/ShopPurchases` 从档案推出；新商品要同时能被 `apply` 发出去（卡 / 工具 / 卡槽数 / 增益） |
| **一个新页面** | 继承 `Screen`；入口在 `TitleScreen`（按钮数组与 `blockHeight` 的乘数**一起**改）；文案走 `GuiLang`；要显示服务端回执的话用标题页那行消息（`PvzceClient.recentServerMessage`），否则"服务端拒绝了但菜单里看不见" |
| **节奏草坪的僵尸时钟** | 关卡只写 `pvzce:rhythm` 的 `difficulty`（0 = 关，照旧用关卡自己的波表）：池子与曲线在 `EndlessSchedules.rhythmLawn()`（一份共享的 `EndlessScheduleDef`，数据包可用 `data/<ns>/endless_schedules/rhythm_lawn.json` 覆盖），生成器是无尽的 `EndlessWaves.wave(schedule, 轮, ...)`，**"轮"由 `RhythmWaves.roundFor` 从谱面进度 × 系数算出来**。改难度改系数，改池子改调度表；不要再写波表（校验会拒），也不要漏 `end_beat`（那是这一关唯一的赢法） |
| **一个关卡集合**（1-x 那种盒子） | `data/pvzce/tags/levels/collections/<名字>.json`（`{"replace": false, "values": [...]}`，**顺序就是列表顺序**）→ tag `#pvzce:collections/<名字>`，`LevelCollections` 在服务端把它读成列表里的一行盒子。**页、图标、排序键全部取自第一个成员**（所以"变异"的第一条必须是 easy），名字写 `level_collection.<ns>.<去掉 collections/ 的名字>`（两个 lang 文件都要）。成员从页面列表上隐藏、只在盒子里出现；`collection/` 前缀是"什么算集合"的唯一约定，别的 level tag 不会变成盒子 |
| **代码定义的关卡** | 照 `server/level/EndlessLevels` / `common/level/mutation/MutationLevels` 的形状写：构造一个 `LevelDef`，用参数化 helper 把四个难度/两张地图的重复收掉；关卡 id 决定它落在哪一页（`LevelGrouping`，路径＝主题/类别）；能数据化的部分优先放 JSON |
| **一张卡在运行时进条** | 覆写 `CardSource.receiveCard(LevelServer level, LevelServer.ServerBridge bridge, Identifier cardId)`（默认 `LevelServer.addCardToBar`，传送带覆写成"放到带子上"）。**不要**直接往 `player.replaceSlots` 塞：条可能是别人的投影（§8.29）。**但容器里砸出来的植物不走这条路**：它掉成地上的种子包（`LevelServer.spawnCardDrop` → `CardDropEntity` → 捡起来拿在手上 → 免费种下），只有"不是植物、拿不了手上"的卡才回到这条钩子 |
| **一个掉在草坪上、要玩家点一下的东西** | 照 `CardDropEntity`（`EntityKind.CARD_DROP`）的形状：`PvzceEntity` 子类 + kind 常量 + `EntityVisuals` 一行（它与 `ResourceDropEntity` 分别回答"点击后进银行"与"点击后进手里"）+ 客户端 `drawEntityArt` 一条分支 + 拾取报文 + `LevelServer.createEntity` 一条 `case`（掉在地上还想活过存档的话） |
| **关卡要固定出某个变异 / 定时台词** | 变异：`pvzce:mutation` 块的 `random:false` + `schedule`（§8.57b）；台词：`dialogue.timed`（`at_tick` 是**关卡自己的** tick，客户端读 `ClientLevel.levelTickCount()`，不是全局 `debugTickCount()`） |

## 8. 约定（避免重新长出重复实现）

改相关逻辑时请顺着这条改，不要新开一份：

> **编号是引用键，不是序号**：别处的文字按 `§8.<n>` 指这一条，所以只增不改、不重排
> （缺号表示那一条已经并进别的条目或删掉了）。字母后缀是"同一件事的后续补充"，
> 例如 §8.49b~§8.49i 都是 §8.49 那一族。要加一条就接在末尾，不要插进中间。

1. 颜色/音效/队伍/规则的 id → `PvzceSounds` / `PvzceIds`。
2. 数值常量（tick 率、默认棋盘、初始阳光、卡片冷却…）→ `PvzceConstants`；每秒↔每 tick 换算是 `PvzceConstants.TICKS_PER_SECOND`，不要写 `60`。
3. 关卡访问 → `LevelAccess`（不要新开接口）。
4. 植物创建 → `LevelServer.spawnPlant`（不要 `new PlantEntity`）。
5. 卡槽解析 → `SlotResolver`。
6. 内容 id → 纹素/纹理 → `EntityArt`（`sprite` / `animationFile`，唯一出处）；`EntityTextures` 只是它上面的兼容转发，新代码直接用 `EntityArt`。实体视觉常量 → `EntityVisuals`。
7. GUI 裁剪 → `Clipping`；GUI 焦点 → `FocusManager`；卡片绘制 → `SeedCardRenderer`；文本/数字 → `GuiText`。
8. 时间线数学 → `Timeline`；日夜 → `DayNightCycle`；缓动/插值 → `MathUtil`（`easeInOut` 只有这一份）。
9. 包字段声明 → `PacketStruct`；集合序列化 → `PacketByteBuf` helper。
10. 路径拼接 → `PackPaths`；注册表目录表 → `CONTENT_REGISTRIES`；注册表分类 → `PvzceRegistries.byCategory()`；**关卡存档目录键 → `LevelKey.of`**（只有这一份，客户端与服务端都调它；**不要再抄第二份**，抄本一定会分叉）。
11. 实体存档 → `saveState/restoreState`（成对实现，不要只写一半）。
12. 关卡数据校验 → `LevelValidator`（新增检查项加在这里，不要散落到构造函数里抛异常）。
13. 编辑器列表操作 → `ListEditorSupport`；背景 cover 适配 → `Screen.coverFit`；命令分类/补全 → `PvzceRegistries.byCategory()`（不要新写 switch）。
13b. 界面自己的鼠标/滚轮判定 → `Screen.onMouseClicked` / `onMouseMoved` / `onMouseScrolled`（**不要**覆写 `mouseClicked`，它是 `final`，模态分发靠它保证）。
14. 场景元素是否液体 → `LiquidTextures.liquidFor`（**读元素定义的 `liquid` 字段**，不要按贴图是否存在判断）；平面液体 underlay → `LiquidTextures.liquidSceneId`；液体参数 → `LiquidDef`；运行时水面绘制 → `LiquidTextures.renderSurface`（占位取基础地形、高度取 `SceneBoard`）；平面预览 → `renderGuiBoard`（使用舞台 `LevelStage.LiquidFrame`）。**不要**在水面 pass 或实体锚点按液体 id 添加高度补偿。
15. 能不能种 → `PlantPlacement.canPlace`（**纯函数，只读 `#c:` 标签与 `PlacementDef`**）。不要在别处再写一份判定：`LevelServer.canPlacePlant` 把关卡适配成 `PlantPlacement.Ctx`，并叠加关卡机制的临时格子保留规则，`PlantAIPlayer` 也调它。`#c:unplantable` 先行拒绝普通植物，墓碑专用植物除外。瓦片能种什么**不写进场景元素定义**，要加地形就在 `data/c/tags/scene_element/` 里打标签。
16. 堆叠层、互斥与横向占格 → `PlacementDef` 的 `layer`/`count`/`group`/`width`（载体 `layer 0`、地面植物 `1`、植物上的植物 `2`；`group` 留空＝同格可多个）。支撑判定只看**比自己层低**的东西，所以种植顺序不影响结果；`width` 是横向占格，原点和覆盖统一走 `PlantPlacement`。
17. 关卡属于哪一页 → `LevelGrouping`（**纯函数，只读 id 路径**）。不要在别处再写一份：服务端 `PvzceServer.groupOf`、客户端 `LevelPage`、编辑器的换组都调它；页签顺序与名单由服务端 `LevelTabs` 从注册表推出发给客户端。
18. 卡是否被背包锁住 → `SlotResolver.requiresUnlock`（服务端 `PlayerProfile.owns` 与客户端 `ClientProfile.owns` 都调它）；选卡池 → `SeedOptions.cardPool`（**唯一一份**，"客户端看得到"与"服务端收得下"靠它对齐）。关卡固定卡**永远不过滤**。
19. 玩家档案（金币 / 已解锁卡）→ `PlayerProfile` + `PvzceServer.profileFor/saveProfile`（缓存按世界名，换世界前先 `flushProfile()`）。不要在别处再读一次 `profile.dat`，也不要在关停钩子里写文件。
20. 通关发什么 → 关卡 `rewards` 块 + `RewardSettlement.settle`（首通/重复/掉币的**唯一**结算点）；新增奖励类型要同时改 `LevelRewards` 与 `LevelValidator.validateRewards`。金币掉落只经 `LevelAccess.zombieDied`，实体不读关卡奖励数据。
21. 内容 id → 用哪份美术 → `EntityArt`（动画文件与兜底贴图两个问题一次查表）。不要在渲染器/编辑器/选卡里各拼一次路径：内置美术按类目分层后，路径已经不能从 id 推出来。
22. 命中反馈/特效的粒子 id → `PvzceParticles`（与 `PvzceSounds` 同形）。未定义的效果**不画东西**，只按 id 报一次日志。
22b. 缺失贴图 → `EntityArt.MISSING_TEXTURE`（渲染器、`EntityArt.sprite(null)` 与 `TextureManager` 的采样方式都读它）。不要在绘制处自己造一块纯色占位。
22c. 总卡槽数 → `LevelDef.effectiveMaxSeedSlots(profileSlots)`（关卡声明优先，未声明用背包的 `PlayerProfile.seedSlots`）。判断"关卡有没有自己声明"用 `declaresMaxSeedSlots()`，不要拿 `maxSeedSlots` 和某个数字比 —— 未声明是 `UNSET_MAX_SEED_SLOTS`（-1），不是 6。
24. 「这一格能不能放」的规则只有 `PlantPlacement` 一份；工具点击可否执行由 `LevelServer.applyToolEffect` 返回布尔值表示，**被拒绝的点击不消耗使用次数也不进冷却**。移动植物走 `spawnPlant` + `restoreStateWithoutPosition`：位置由新格子决定，状态（血量、年龄、能力）跟着走 —— 直接 `restoreState` 会把坐标一起写回去，等于没搬。
25. 关卡能不能进 → `LevelUnlocks.evaluate`（**纯函数**，`Context` 里只有已通关/已购买/背包/金币/沙盒）。服务端求值、客户端收结论（`UnlockInfo`），不要在界面里判断；入口门槛在 `PvzceServer.createLevel` 重新求值一次，不要只信列表。购买价只从关卡定义读，永远不信客户端。
26. 实体归类 → 美术目录（`textures/entities/<类目>/…`）与动画目录（`animation_dir`）用**同一套类目**，分类表只有一份：`tools/group_entity_assets.py` 的 `ENTITIES`，以及重新生成美术时 `tools/reanim_to_pvzce_all.py` 的 `EntityConfig.group`。**内容 id 永远不带类目** —— 改目录不会让关卡、标签、存档或语言 key 失效。
27. 实体类别 → `EntityKind` 的四个常量，**它们是类别不是内容 id**：判断「这是不是某个具体资源/植物」一律比内容 id（`defIdString()` / `PvzceIds`），不要比 kind（见 `架构-客户端.md` §6.3 的世界点光源）。
28. 捡起一个资源放什么效果 → `ResourceDef.pickup_effect`（可缺省＝不放）。不要在收集代码里按资源分类写分支：阳光与硬币不是同一种拾取，共用一份粒子参数必然有一边是错的。
28b. **"玩家看不见那里"有两种遮法，别把它们混起来**：雾走"**画在实体之上**"这条路
   （`WorldOverlay.renderOver`，`InGameScreen` 的实体循环之后），实体照画不误，是云把它们盖住；
   雷雨走"实体之下的一层黑 + 实体循环跳过它"这条路（`StormClientMechanic.hides()`，不看位置）。
   一个机制要遮东西时先问自己属于哪一种：**遮法可见、边缘是画面的一部分（雾）就画在上面；
   遮法是一个整屏的量、没有边缘（雷雨）就让实体别画**。雾这一侧没有 `hides()`——
   "看不见"只剩"云盖在这儿"（`FogClientMechanic.covers(x,y)`），只有 HUD 标签那种画在云之上的东西
   才问它，否则标签会把雾要藏的东西说出来。
28c. 雷雨的循环位置与亮度 → `StormState.Wire(pulse, exposure)`（`StormMechanic.tick` 每 tick 发一次，
   12 字节）。**不要在客户端自己计时、也不要自己算亮度**：暂停、倍速、续档都由服务端那一份说了算，
   闪电的形状表（`StormState.PATTERNS`）也只有一份 —— 客户端拿到曝光就直接画，"什么时候打雷"
   与"什么时候藏起来"因此必然是同一个 tick。
28d. 黑暗/天气盖到哪 → `camera.worldLeft/Right/Bottom/Top`（可视矩形，单位是格）。**不要用棋盘尺寸近似**：
   一块只盖棋盘的夜色看起来是贴在画面上的滤镜（马路、房子、天空还亮着），而"这一关天黑了"是整屏的事。
29. 传送带的产出/容量/消耗/存档 → `ConveyorBelt`（服务端唯一实现）；卡槽条是它的**投影**（`BeltCardSource.rebuildBar`），不要在别处再维护一份"带上有哪些卡"。
30. 据点前沿范围 → `OutpostPlan.allowsPlacement`（几何两侧共用，真实驻守由服务端检查）。"这一格能不能种"的第二半（**关卡允许的范围**）→ 关卡 `placement_zone` + `LevelServer.canPlacePlant`。不要写进地形标签：红线是画在普通草地上的，改地形会把草坪一起改掉。客户端画线/悬停从 `LevelPayload` 的同一条矩形读。**僵尸那一侧是同一个记录、另一个机制**：`zombie_zone` + `LevelServer.canPlaceZombie`（`LevelMechanic.canPlaceZombie`），数据仍是 `PlacementZone`，只有校验消息里的名字不同。玩家放僵尸与 AI 放僵尸走同一道门，所以"僵尸只能在右边四列"不是 AI 的自觉。
31. 爆炸的范围与触发 → `ExplosiveCapability.detonate` 的**不变量「爆炸半径 ≥ 触发范围」**。新写 proximity 内容时 `trigger_range > radius` 也不会静默打不中（`ExplosiveCapability` 会取大），但数据仍应写成想要的值。
31b. 爆炸之后植物还要在场上留多久 → `ExplosiveCapability.DEFAULT_LINGER_TICKS`（缺省值；JSON 用 `linger_ticks` 覆写，运行时读 `ExplosiveCapability.lingerTicks()`，正文不抄那个数）。爆炸是**瞬时**的（伤害当 tick 结算），留下的是那一幅画：植物随即 `occupiesCell` 为假（僵尸走过去、铲子够不着），计数归零自己 `remove()`。**不要**在关卡里另开一份「爆炸植物延迟移除」名单，也不要在客户端补一段「等动画播完再删」。
32. 植物是否占格（僵尸能否啃、工具能否取）→ `PlantCapability.occupiesCell` + `LevelServer.plantAt`。不要在僵尸的啃咬循环或工具里判断具体植物 id。
32b. **一次命中吃不吃护甲** → 注册的 `DamageTypeDef`（`pvzce:ash` / `pvzce:projectile` / `pvzce:impact` / `pvzce:splash` / `pvzce:mower`）。所有伤害都从 `ZombieEntity.damage(amount, type, level)` 走，不要在能力里另开一条「直接扣血」的路；要新的护甲规则就给类型加字段，不要在第 4 个方法里再写一遍。
32c. **植物能不能被打死** → `PlantCapability.invulnerable` + `PlantEntity.damageFrom`。「咬不动」与「铲不掉」是两件事：前者问 `invulnerable`，后者问 `occupiesCell`（灰烬类在引信期间只回答前者）。
33. 这一行有没有小推车、它在哪 → `MowerMechanic` 的 `Rig`（服务端唯一实现，状态经 `LevelServer.mechanicState` 存在关卡上，客户端镜像在 `ClientLevel.mechanicState`）。**不要另开一份"哪行有推车"的判断**：默认值（每行一辆）只由 `LevelMechanics.effective` 加，行列表只由 `MowerData.rowsFor` 展开。
34. 一条不绑定实体的动画（机制道具、以后可能的 UI 表演）→ `ArtTarget` + `AnimationManager`。它的 `fileFor` 认得这种目标并直接读文件 id；不要在机制里另写一个渲染器。
35. 僵尸身上会磨损的装备 → `EquipmentDef`（`art` 骨骼族 + 可选 `piece` 护甲 + `drop_particle`）。档位判定与"这帧该画哪一张"只有 `EquipmentArt` 一份（`BoneArt` 钩子）；**不要把状态编译成动画 clip**（三个档位 × 六个 clip × 800KB），也不要再加第二个"挨打时掉什么"的分支：伤害吸收只经 `ArmorCapability.absorb`，掉落粒子从定义里取。
36. "这一关有没有得选卡" → `SeedOptions.hasNothingToChoose(pool, maxSlots, lockedIds)`（**纯函数**）。选卡屏的预览模式与存档提示框的重开都问它；判据是**总卡槽数 − 关卡固定卡数**，不是"已选卡数"。
37. 屏幕上那句提示 → `HintBox`（唯一实现）+ `LevelHints`（唯一触发点）。不要在界面里另写一个"显示一行字两秒"的东西：拒绝优先、一条一条来、墙钟计时都在里面。
38. 僵尸画哪些骨骼 → `EquipmentArt.visibleBones`（唯一实现）。装备的档位、断臂、`hidden_bones`、装备自带手臂与普通手臂的互斥，全部在这一个函数里决定；**不要**在渲染器或 clip 里加特例。
38b. 植物画哪些骨骼 → `PlantDamageArt.visibleBones`（唯一实现，`BoneArt` 的第二种）。它只回答一件"被啃到哪一档"，认模型里 `cracked_N` 这一族；**不要**给植物加"受伤"clip（每个档位都要复制整份动画），也不要在渲染器里按 `defId` 写植物特例——`AnimationManager.boneArtFor` 是按 kind 分派这两种 override 的唯一入口。
39. 粒子落地后的水平行为 → `ParticleMotion.ground_friction`（缺省 1 = 保留"一直滑"的手感）。要"原地停下"就在**数据**里调小，不要改引擎。
40. 小推车的"还在 / 没了" → `MowerMechanic.Rig`（服务端）+ `ClientMechanics.consumeParkedMowers`（客户端核销）。不要在界面里再维护一份"哪些车已经变成金币了"。
41. 实体画在哪个坐标 → `ClientEntity.visualCellX/Y/Height`（**渲染用**；`cellX()` 永远是服务端的数）。不要在渲染器里自己补间，也不要把补间写回 `cellX()`：那会让命中测试和存档读到没有权威性的中间值。
42. 一个状态要持续多久 → **服务端计数器**（`biteCooldown`、`corpseTicks`、`vanishTicks`、`expireTicks`），不是"客户端自己播完再说"。服务端不知道 clip 有多长，也不该知道；它只知道"这个状态现在成立"，而客户端用一个带 transition 的 clip 把它演出来。
43. 植物睡不睡 → `PlantCapability.asleep`（由 `LevelAccess.isNight()` 与咖啡豆的唤醒标志推出）+ `PlantEntity.tick` 的跳过规则。**不要在能力里各自判断白天黑夜**：睡着时"什么都不做"是实体统一跳过的，新能力默认就被覆盖；`pvzce:nocturnal` 只负责发布 `sleep` 动画与永久唤醒。
44. 一发子弹能飞多远 → `ProjectileRef.range`（0 = 不限），**同一个数**既是"值不值得开火"（`ProjectileRef.covers`）也是"子弹何时消失"（`ProjectileEntity` 从出膛点量起）。不要把射程写进子弹定义：同一个孢子可以被不同射程的植物发射。
45. 关卡列表的顺序 → `LevelGrouping.compareIds`（自然序：数字段按数值比）。服务端下发列表与页签推导都调它，**不要**再写一份 `String.compareTo`——`1_10` 会跑到 `1_2` 前面。
46. 开局两波多久出一只 → `WaveDef.holdUntilDead(waveIndex)`（**唯一**的规则出处）+ `LevelServer` 的两处门（波内 `PendingWaveSpawn`、波间 `openingWaveStillOnTheField`）。**不要**靠调大 `spawn_interval` 来"放慢前期"：那是在替玩家猜速度，而门控问的是玩家自己。
47. 一张卡冷却多久 → 卡自己的数（`Slot.cooldownTicks`，建条时从 `SlotResolver` 抄）× 关卡规则 `pvzce:seed_cooldown_multiplier`，换算只有一处：`LevelServer.effectiveCooldownTicks` / `CardCooldown.effective`。**消耗时才算**（种植物与用工具两条路都调它），`SlotInfo.cooldownTotal` 把同一个数发给客户端当充能条的分母 —— 不要在某一处直接 `startCooldown(卡自己的数)`，也不要在客户端拿本地的规则再推一遍。
48. 列表行上那枚奖杯 → 类别定义的 `trophy` + `LevelInfo.cleared`（**通关过至少一次**），判定只在 `LevelRowRenderer.showsTrophy`。**不要读 `status` 字符串**：有存档时它写的是"进行中"，而奖杯不该被一局重玩收回去。
49. 关卡发的"东西"而不是"钱" → `rewards` 的 `resource` 条目（面值来自资源定义的 `default_value`）+ `LevelRewardS2C.rewardItem`，客户端三处（草坪掉落、领取动画、结算页相框）都从包里那一个字段决定画什么。不要在客户端按关卡 id 判断"这一关发钻石"。
49b. **空手点击做什么** → 关卡 `mechanics` 里的 `pvzce:tool`（`default: true`），读法只有 `ToolMechanic.defaultTool/declared`。不要在界面里按关卡 id 判断"这一关是打地鼠"。
49c. **谁在玩这一关** → `LevelDef.playableTeamDefs()` / `offersTeamChoice()`（服务端求值，客户端读 `TeamInfo.playable`）。不要在界面里写"僵尸方没有卡组所以不可选"。
49d. **爆炸打多大一片** → `pvzce:explosive` 的 `radius` + `square`（格）或 `trigger: "row"`（整行），落到 `LevelAccess.damageArea(..., square)` / `damageRow`。不要用一个大到能覆盖整行的方格来假装"整行"。
49e. **这一下算不算"烧"** → 伤害类型的 `burns`（`DamageTypeDef`），到 `ZombieEntity.damageBody(amount, level, burns)` 与 `EntityAnimations.DEATH_BURNED`。不要在死亡代码里排一张"哪些伤害 id 会烧"的名单。
49f. **这一下打谁** → `LevelAccess.enemiesInRow(row, team)` / `LevelServer.isEnemyOf`（"不是同一队"），`zombiesInRow` 只用于"这一行有几只"。不要在攻击代码里判断某个实体是不是被魅惑的：阵营本身就是答案。
49g. **被消耗的植物怎么退场** → `PlantCapability.vanishAnimation()`（clip + tick）。它让玩法结束与画面结束分开，但只有这一处：`isRemoved()` 一为真就不再占格、不再被瞄准，剩下的只是 `PlantEntity.vanishing()` 在倒数。不要在关卡里另开一份"等动画播完再删"的名单。
49h. **一张传送带卡发多少张** → `LevelBelt.BeltCard.maxCount`（不写 = 不限）。计数在传送带自己身上（`ConveyorBelt.dealt`，**发出就算**，用掉没用掉都算），发满的卡退出池子，计数与队列一起进存档。**不要**在关卡里另开一份"这一关只给几张墓碑破坏者"的名单。
49i. **开局草坪上的墓碑** → `pvzce:grave_field` 机制 + `GraveScatter`（**唯一**一处"把墓碑放到某个格子"的实现，`grave_spawner` 补墓碑也走它）。关卡文件**不写**墓碑的坐标：位置是每次开局随机撒的，写在 `scene` 里就失去这个机制的意义。
50. **一个背景图用哪套舞台几何** → `LevelStage.geometryFor(background)`（**唯一**的查表点：`background3`/`background4` → `LevelStage.POOL`，其余含"没写背景"与未知贴图 → `LevelStage.YARD`）。格子尺寸、草坪矩形与液面帧都随它走，棋盘只由 `LevelStage.board(w, h, columns, rows, geometry)` 算，`PvzceCamera` 拿同一份几何（`geometry()` / `liquidFrame()`），`PvzceClient.camera()` 的缓存键也要带上它。**不要**在界面或渲染器里按关卡 id、行数或宽高判断"这是不是泳池"——多一行、换一张背景，判断要跟着数据走。
51. **一个波次条目从哪几行出怪** → `WaveDef.Entry.rows`（空 = 任意行；`WaveDirector` 把行列表抄进放怪队列，出怪时按列出的顺序轮取）。**不要**在出怪代码或机制里按僵尸 id 猜行（"会游泳的走水里"）：行是波次表自己的字段，越界行由 `LevelValidator.validateWaves` 报出来；存档里的 `ZombieRows` 与 `Zombies` 平行，缺键读回"任意行"。
52. **某一行放哪种小推车** → `MowerData.kinds`（行 + 内容 id + 可选启动音效）。行集合 = `rows`（未写＝每行）∪ `kinds` 点名的行，`kindFor(row)` 是唯一读法；车型是**内容 id**，客户端按 `mechanic/<path>` 取动画（`MowerClientMechanic.animationFor`）、服务端按它取启动音效。**不要**给 `MowerMechanic` 按行号或按关卡写分支，也不要为车型加包字段：它来自关卡数据，线上只有位置与状态。
53. **浇水做什么** → `LevelServer.waterPlant`（`applyToolEffect` 的 `pvzce:water` 分支）挨个问 `PlantCapability.water(plant, level)`：能力回答"这水用来做什么了"（今天只有 `ProducerCapability` 的催熟），回满血与 15 秒的加速时钟则是实体的事（`PlantEntity.water` / `watered` / `actionStep`）。**不要**在工具效果里按植物 id 判断"这株能不能催熟"，也不要把倒计时各自写在能力里——射手与生产者都走 `PlantEntity.actionStep()`。
53a. **一轮生产拆成几颗资源** → `ProducerCapability` 的 `drop_count`（默认 1）；`amount` 保持整轮总量，
分配余数、弹出队列与队列存档都由此能力处理。横向分离经 `LevelAccess.spawnProducedResource` 传到服务端资源创建入口；
间隔与间距只有 `PvzceConstants` 一处。不要在双子葵 id 分支、客户端或资源定义中重复减半/加倍产量。
54. **一株植物的"工作速率"** → `PlantEntity.actionRate(extraRate)`（关卡倍率 × 护理 × 网络加速 × 天气 × 调用方自己那一份），每个能力各自持有 `common/level/RateClock`，只累积本 tick 的倍率并保存小数余量。**不要**让同时具有攻击与生产的能力共用一个累加器，先跑的能力会花掉另一能力的进度。铃兰网络的拓扑、承载关系与倍率只有 `EchoNetwork` 一处：共鸣苔延伸线路，上层通过同队底座接入；只计铃兰数量决定强度。铃兰自己的有限接力钟直接消费同一网络倍率，不再与普通植物的网络倍率重复乘算；客户端只读取 `EchoNetworkS2C`。
55. **一关的变异列表** → `LevelServer.mutations()`（`MutationManager`），`null` 表示这关不声明 `pvzce:mutation`。变异本身注册在 `BuiltInRegistries.MUTATIONS`，必须**无状态**（共享单例），一切每局状态走 `apply` 的返回值或 `LevelServer.mechanicState` 那样的关卡槽位。**不要**把变异做成关卡机制：机制由关卡声明、按 id 查数据块，而变异是引擎随机抽出来、还要能被撤销的。
56. **卡槽条的种类在运行时会变** → `LevelServer.cardSourceKind()` / 客户端 `MutationStateS2C.cardBarKind`，客户端据此在 `InGameScreen.cardBar()` 里换 `CardBar` 实现。**不要**再让任一侧从关卡定义直接推"这一关是不是传送带"：变异可以让同一关在两条卡槽条之间来回切，定义是静态的。
57. **一个挡位开出多少条变异、多久一条、数值多强** → `MutationDifficulty`（关卡规则 `pvzce:mutation_difficulty`），首条延迟是 `pvzce:mutation_initial_ticks`。**不要**在变异自己里写死间隔或上限：档位是这一整关的四个数，写在 38 条变异里就是 38 份可以互相矛盾的副本。
57b. **这一关要不要按脚本出变异** → `pvzce:mutation` 块的 `random` / `schedule`
（`MutationData`）。`random: false` 表示这一关不掷骰，只按 `schedule` 到点加；
两者可以并存。已演条目数进存档（`Mutations` 块的 `ScheduledFired`），所以续档不会重演。
教程关是第一个用户（见 `架构-服务端.md` §4.10）。

58. **长出来的墓碑不回收** → `placeGrave`（`MutationManager` 的墓碑生长、`grave_spawner`、`grave_field` 共用）。变异被挤出时**不**清掉它长出来的墓碑与水草：那是地形与玩家的植物了，删掉会连带删掉玩家围着它做的东西。变异"拥有"的只有它自己的时钟。

58b. **这一关的波次表从哪来** → `tools/original_levels.py`（原版四张表 + 波次生成的**唯一**出处）与 `tools/write_adventure_levels.py`（1-1～5-10 及自定义 6-1～6-3 的**唯一**生成者）。1-1～5-9 的 `waves` 是"把原版那一局掷一次定死"的产物，5-10 则明确采用用户指定的屋顶传送带配置，**不要手改关卡 JSON 里的波次**：改一行就会与 `OriginalAdventureLevelsTest` 复算的答案对不上，而那张表才是"这是原版的第几关"的答案。要调手感就在生成器里改（或换 `LEVEL_SEED` 重掷），改完重跑生成器。
58c. **一关怎么算赢，如果不是"波次出完"** → `LevelServer.declareVictory()`，由机制自己在条件满足时调用（今天的用户是 4-5 的 `scary_potter`：一关 0 波的关卡永远等不到 `allWavesReleased`，`checkEnd` 那条路是死的）。
58d. **场景里那只是花瓶还是恐怖花瓶** → 玩家的工具放的是 `pvzce:vase` / `pvzce:vase_full`（`LevelServer.vaseContents` 记里面那张卡），关卡摆的是 `pvzce:pot_question` / `pvzce:pot_leaf`（`ScaryPotterMechanic` 记里面是卡还是僵尸）。判断"这一格是不是恐怖花瓶"只有 `ScaryPotterMechanic.isPot/contentsAt` 一份；**不要**把两种物件混成一个 id，它们的归属、内容的归属与锤子砸下去的结果都不一样。
58e. **雪橇小队落在哪一行** → `LevelServer.rowHasIce(row)`（"这一行有没有冰"，读 `pvzce:ice` 场景元素）+ 生成路径的两处：`LevelServer.spawnRowFor`（把领队挪到最近的冰行）与 `WaveDirector.spawnQueued`（整块场地没有冰时改出四只普通僵尸）。**不要**在关卡文件里给雪橇写死行：冰是雪橇车跑出来的，开局不存在。

59. **变异自己的状态怎么进存档** → `Mutation.saveState()` / `loadState()` / `applyFromSave()`（`MutationManager` 把整份列表写进 `level.dat` 的 `Mutations` 块）。要区分**两件事**：变异对世界做过的事（弹坑、墓碑、水草、卡槽条内容）由存档的既有分区承担，恢复时**不要重放**；变异**自己**的倒计时、预算、以及它拥有的那一份游戏规则，存档里没有对应物，必须由 `applyFromSave` 重新建立。只改规则的变异（`RateMutation`、`BowlingNutMutation`）在恢复时再写一次规则，因为存档里的规则是关卡自己的值、不含变异那一份。**不要**把状态塞进 `Mutation` 的字段：注册表条目是共享单例，save/load 之间那两个暂存字段是唯一允许的例外（见 `SlotReplaceMutation.savingPlayer`）。
60. **一条卡槽条自己的状态** → `CardSource.collectSave/applySave`（写进调用方给的块里），与 `CardSource.save/restore`（写进关卡根部）分开。分歧点在于**谁拥有那份状态**：关卡自己声明的那条属于关卡，变异装的属于变异（所以进 `Mutations.CardSource`）。**不要**给卡槽条加第三条路径。

61. **加一条变异要碰的六处** → ① `PvzceIds.MUTATION_*` 常量；② `common/level/mutation/<名>Mutation.java`（包内 `final class`）；③ `Mutations.bootstrap()` 注册（**位置＝掷骰顺序＝面板顺序**）；④ `MutationText.baseName` 的中文名（服务端横幅用）；⑤ 两个 lang 文件的 `mutation.<ns>.<名>`（客户端面板读它，`MutationHud` 里**没有**第二份名字表）；⑥ `MutationCatalogTest` 的 id 清单（条数也钉在那里）。一条命令查漏：`grep -rn "<新id>" pvzce-game/src | wc -l` 应当覆盖这六处。
62. **变异的"正在行动"必须按条目记，不能按 id 记** → `MutationManager` 的 `entries` / `applied` 用**条目对象**（注册表允许同一条变异出现两次，两份 id 相同）。任何"按内容 id 索引"的集合在这里都会让被压制的那一份继续 tick。
63. **加一个能力** → 实现 `PlantCapability` / `ZombieCapability` / `ProjectileCapability` 的**你需要的钩子**（其余用默认值），注册 `CapabilityType`；钩子清单在 `docs/架构-实体与能力.md`；新放置走 `onPlaced`，恢复后的运行时登记走 `onRestored`，不要重放一次性放置行为。**加钩子时顺手加一个"它会被调用"的用例**。
64. **僵尸的每个动画状态都要有对应 clip** → 状态名找不到 clip 时**静默回落 `idle`**，症状是"站着不动却在做别的事"。合成出来的僵尸（`tools/make_zombotany_assets.py` 那类）要逐个点名检查；改动画文件时先看 `EntityAnimations` 里有哪些状态名。
65. **加一个协议包要同步的六处** → ① `common/network/packet/<名>.java`（用 `PacketStruct.builder()` 声明字段 + `direction()`）；② `PvzcePackets` 的 id 常量与注册；③ `PROTOCOL_VERSION` 加一并在注释里写清"为什么"；④ `PacketProtocolTest.samplePackets()` 加一个**每个字段都非默认值**的样本；⑤ 同一测试里的 `EXPECTED_WIRE_FORMAT` 用 `-Ppvzce.smoke=pvzce.printWire=true` 重新生成；⑥ 需要时在 `PvzceClientPacketListener` / `PvzceServer` 接上分支。漏掉④⑤不会编译失败，只会在别人连上来时炸。
66. **机制的 JSON 块：默认值写进 codec，sentinel 不要在构造器里 clamp** → `optionalFieldOf("x", 默认)`；用 0/-1 当"没写"的字段**不要在紧凑构造器里 Math.max(1, …)**，否则"没写"变成"写了 1"（`DeathBlastCapability` 的 damage 就是这么错的）。校验放 `LevelMechanic.validate` / `LevelValidator`，让它报在关卡加载时而不是运行时。
67. **增益的钩子默认值＝不生效** → `LevelBuff` 的每个新钩子都 `default` 返回"没这事"（`0F` / `false` / 原值），这样没装增益的关卡行为逐字节不变。倍率类钩子读的时候**乘进既有那一处**（例如 `StatusDurations.scale`），不要在每个调用点各乘一次。
68. **代码定义关卡的取舍** → 内容能用 JSON 表达就写 JSON（关卡、内容定义）；只有"同一形状 × N 个变体"（四个难度档、四条无尽）或者"必须和代码常量对齐"（变异目录、无尽 schedule）才写代码，并且用一个参数化 helper 收掉重复。**复用既有 schedule 之前先问一句它在无水的棋盘上会怎样**：`EndlessWaves.composition` 在没有水行时根本不会查询水那一半池子，所以泳池的 schedule 直接用在草坪上是安全的。
69. **运行时装/卸机制** → `LevelServer.installMechanic(TypedMechanic)` / `removeMechanic(id)` / `hasMechanic(id)`。装完要**强制发一次状态**（`FogMechanic.publish(level, true)` 那类），因为 `onLevelCreated` 只填关卡自己的槽、不发包 —— 中途装机制时状态槽与线上一致，比较逻辑会判定"没变化"，玩家什么都看不到。
70. **内容在上下文里成立吗** → 新的一张卡/一种僵尸/一条变异/一关机制进入某个上下文（棋盘、卡池、这一关的敌人）之前，写一句它成立的判据：能不能在这块地形种下去、有没有成本与上限、玩家手里有没有对付它的东西。答不上来的改内容，或者在关卡/卡池那一层加过滤（`SeedOptions` 是既有的那一层）。
71. **"捡到手"只有一个计数点** → `LevelMechanics.onResourceCollected`，在 `LevelServer` 的收集路径上、**记到账之后**调用；玩家的点击与 AI 的自动拾取走的是同一条路（`collectResourceFor`），所以"收集了多少阳光"两边同源。要按阵营限制收集就改**归属判定**（掉落物属于谁），不要在收集侧另写一份"谁能捡"。
72. **外部的决策模型（Jev）只有一条路落地** → `JevPrompt`（问什么）/ `JevDecision`（答案怎么读）/ `JevClient`（怎么送）分三层，落子在 `JevBrain.play` 里**重新过一遍服务端自己的规则**（阵营、钱、区域、格子，全部 `canPlace*` / `spawn*`）。任何"让外部决定一个格子"的新入口都照这个形状写：**先复核、再落地、失败回退**，并且要有一个真的跑一次的用例——`JevDecision` 的行/列与棋盘的 x/y 顺序第一次就写反了，只有端到端用例能发现（`踩坑清单.md` 第 178 条）。
73. **凭据只有一个出处** → `AiSettings`（URL + 模型 + key，两个具名工厂 `jev()` / `commander()`）。客户端存在 `config/pvzce-client.toml` 并在进关/保存时用 `AiSettingsC2S` 交给服务端；服务端只在内存持有，**永不进存档、永不进日志**（`toString` 打 `***`、`redacted()` 给日志用）。无头与测试走启动参数或环境变量（`-Dpvzce.jev.*` / `PVZCE_JEV_*`），**启动参数优先**——否则一个没配 key 的客户端会把服务端的凭据抹掉。

74. 地表高度与覆盖恢复 → `SceneBoard`；元素曲线声明 → `SceneElementDef.profileFor`；位置投影 → `WorldPosition.projectedY`。
    鼠标格子与格子截图中心 → `PvzceCamera.cellY` / `cellScreenY`，必须读取当前操作层。
    篮球与蹦极拦截 → `UmbrellaLeafCapability.block`；不要在两个攻击入口各写一套九宫格搜索。
75. 护理倍率 → `PlantEntity.actionRate`：水壶与肥料取较高倍率；工具冷却由工具定义和 `SlotResolver` 提供。
    玉米黄油概率 → `LevelAccess.butterChance`，增益默认不改变其它投手。

76. 天气数值 → `PvzceConstants` 的天气常量；种类到各倍率的查询 → `WeatherState`。
    `WeatherData` 只保存预报，`WeatherMechanic` 负责分类、阶段切换与充能比例；
    能力通过 `LevelAccess` 天气钩子取值，不在客户端或每个能力里各写一份天气表。
77. 波次触发后的机制状态 → `LevelMechanic.onWaveChanged`，由 `LevelServer` 在植物行动前派发。
    同一 tick 的攻击、种植冷却和全量镜像必须读取同一天气阶段。
78. 溅射的伤害与状态范围 → `LevelAccess.enemiesInArea`。能力只决定中心和运行时范围，
    友军排除、轴向距离与方块半格边界不能在状态能力另写一份。
79. 寒冰持续时间 → `StatusDurations.cold` / `coldFreeze`；施加时组合天气，
    剩余时长还原不再乘天气。黄油等普通状态仍由 `StatusDurations.scale` 处理。

80. **通路归属与叠放层不能混用** → `Entity.surfaceId` / `PlantPlacement.layerIndex`。
    能力使用携带来源 surface 的查询、生成和效果入口；空间范围统一走 `LevelAccess.reachedByBlast` / `enemiesInArea`，
    障碍统一走 `SceneBoard.firstObstruction`。新增桥面通过 `SceneSurfaceDef` 声明，不增加背景 id 特判。

81. **单体数值与修饰器** → `PvzceEntity.attributes()`；类型与内置 id 只有 `BuiltInRegistries.ATTRIBUTES` / `EntityAttributes`。
    内容定义提供基值，效果用具名修饰器加/移除；实例的最大生命、装备损耗阈值和绘制大小不能再按内容 id 猜。
    生成覆盖在首次发布前初始化，恢复替换持久修饰器，客户端只读属性包；不要为同种实体的数值差异注册新内容。

82. **一张场景贴图是不是瓦片表** → `SceneElementArt.tiled`（元素自己的声明）+ `EntityTextures.sceneTiled`；
    不要在渲染器里按内容 id 写死。声明了就是 `TILE_CELLS×TILE_CELLS` 的图集、格子按 `(x mod 6, y mod 6)` 取样，
    没声明就整张当一格画；`pvzce:grass` / `pvzce:ground` 的旧拼写是这条判定的兼容回落。
    自定义地形要借内置图集（如 `pvzce:hillside_mid` 用草地、`hillside_bank_*` 用裸地）时**声明一次**即可，
    不要复制一份美术、也不要新增"看起来像草地"的 id 特例。

83. **一行算不算水行** → `LevelServer.rowIsWater(row)`，而它是**逐行**的：一行里只要有一格水，整行都算水行。
    它决定陆行僵尸能不能来（`spawnRowFor` 会把不能游的挪到 `landRows()`）、耙子跳不跳过这一行、
    以及泳池清洁机配在哪一行。所以"整片海"的关卡（如 `yard/minigame/reef_passage`）只能放会游泳的僵尸——
    陆行僵尸没有"陆行"可落脚（`landRows()` 为空时会原地保留，落在水里就淹死）；反过来，
    一行里想同时安全地容纳水陆两种僵尸是做不到的，要混编就照泳池关那样让整行要么全是水、要么全是陆。
    水行的最后一层防线 → `MowerData.poolRig` / `MowerData.kindFor`（`pvzce:pool_cleaner`），不要在水里放普通小推车。

- **植物的能力配方** → `PlantRecipes.recipe`（完整材料列表，排序且保留重复份数，不看参数）；
  合成的背包候选只有 `PlantRecipes.candidates`。变异能力分组也复用同一配方入口，不另写能力归类规则。
  组合能力的材料展开只有 `PlantRecipes.components` 一处，购买和掉落池复用 `PlantRecipes.abilities`，不另建材料注册表。
  现有材料能凑出的完整配方只有 `PlantRecipes.availableRecipes` 查询，核对重复份数并按配方去重，不按植物数量加权。
  未声明组合规则的模组能力仍以自身ID作为材料，植物注册后自动参与；材料名称沿用植物能力语言键。

- **融合击杀掉几份能力** → `FusionDrops`（强度分档与互斥抽取），数量概率与散落间距只在 `PvzceConstants`。
  关卡通过 `FusionData.dropMultiplier` 统一调整概率，不在各关、客户端或击杀入口复制僵尸掉落表。
