# 代码规范

> 这份文件是**写代码与改代码时唯一需要遵守的规范**。`架构-扩展点与约定.md` §8 的"约定"讲的是
> **某个事实只能有一个出处**（架构性约束），这份讲的是**写出来的东西长什么样**。
> 两者冲突时以架构约定为准：一处实现胜过一处漂亮的重复。
>
> 每条规则后面标了执行方式：
> `[lint]` = 可以用一条正则/一条 grep 在 CI 里查；`[test]` = 应该写成一个 JUnit 用例；
> `[review]` = 只能靠人看，评审时点名。
>
> **本文件描述的是现状 + 少数几条现状正在违反的规则**，不是一份外来风格指南：
> 下面绝大多数条目，项目里 95% 以上的代码已经这么写了，写下来是为了让剩下那几处能被指出来。

---

## 0. 三种语言，各管一层

| 面 | 语言 | 说明 |
|---|---|---|
| `docs/**` | 中文 | 面向本项目维护者 |
| Java 标识符、注释、javadoc、日志与异常消息 | **英文** | 与包名/类名同一种语言，也让 `grep` 有意义 |
| 面向玩家的文本（按钮、提示、结算、对话） | 中文，但**只存在于 `assets/*/lang/*.json`** | 见 §6 |

`[lint]` `pvzce-game/src/main/java` 下不应新增含中文字符的注释；现状基线 21 行，只减不增。
`[lint]` `server/**` 与 `common/**` 不应出现中文字符串字面量（现状基线见 §6）。

## 1. 命名

### 1.1 骨架（现状 100% 符合，钉住它）

- 类型/接口/枚举/record：`UpperCamelCase`；方法/字段/参数/局部变量：`lowerCamelCase`；
  常量（`static final`）：`UPPER_SNAKE_CASE`。`[lint]`
- **全仓库类型名唯一**。重名时后出现者加限定：`HintKind` / `PaletteKind` / `SlotKind`；
  `WireTab` / `GroupTab` / `PageTab`；`GridCell` / `SceneCell`；`MowerRow` / `FormRow`。`[lint]`
  > 现状有 13 组重名（`Kind` 4 处、`Config` 4 处…），改到哪处顺手改哪处，不专门开一轮。
- 布尔取值方法用 `is*` / `has*` / `can*`；record 组件访问器不受此限。`[lint]`

### 1.2 动词分区（**这条现状正在漂移，是本规范最需要执行的一条**）

同一个动作在不同层必须叫同一个名字。"创建"现在有 6 个动词（`create` 28、`build` 38、
`instantiate` 22、`add` 32、`spawn` 19、`of/from`），读者无法从名字判断它会做什么。

| 动作 | 唯一用词 | 约束 |
|---|---|---|
| 实体进入关卡 | `spawn*` | **只允许出现在 `LevelServer`**；`new XxxEntity` 只允许出现在 `spawn*` 方法体内 |
| 装配一个内容/注册表实例 | `create*` | 禁用 `instantiate*`；`build*` 只允许给 Builder 或私有构造辅助 |
| 字符串/JSON → 对象 | `parse*` | 禁用 `fromJson` / `toJson`，用 `parseJson` / `json` |
| 单源转换 | `from` | 例：`ClientEntity.from(packet)` |
| 多参数或无源的工厂 | `of` | 例：`LevelKey.of(id)` |
| 画一个图元 | `draw*` | **只允许是 `PvzceClient` 的绘制原语**（`drawTexture` / `drawSolid` / `drawTextureRegion`） |
| 画一个复合场景/组件 | `render*` | 界面与渲染器的"这一帧归我"（`renderCardBar` / `renderWaveBar`） |
| 推进模拟时间 | `tick*` | |
| 推进时钟/时序 | `advance*` | 禁用 `update*` 表示"推进时间" |
| 把服务端状态写进镜像 | `apply*` | 例：`ClientEntity.apply(EntityUpdateS2C)` |

`[lint]` `new (Plant|Zombie|Projectile|ResourceDrop)Entity` 出现在 `spawn*` 之外即失败。
`[lint]` 新增 `instantiate*` 公共方法即失败。

### 1.3 数值常量必须带单位

`_CELLS`（格）、`_TICKS`、`_SECONDS`、`_NANOS`、`_PX`、`_ALPHA`、`_CHANCE`。
现有的 `GRASS_VISUAL_MARGIN_CELLS` / `REWARD_DROP_CELLS` / `DEFEAT_PAN_CELLS` 是模板，推广它。
`[lint]` `private static final (float|int|long)` 且名字里没有任何单位后缀、值又像是时间/长度的，评审时点名。

## 2. 结构

- **每个 `.java` 恰好一个顶层类型**（现状 382/382）。`[lint]`
- `com.pvzce.api.*` 只允许存在于 `pvzce-api` 模块；`pvzce-game` 不新增该前缀的包。`[lint]`
- **`server/**`、`api/**`、`common/**` 不允许 public 可变字段**（现状 0 个，钉住它）。`[lint]`
  编辑器 DTO（`*Model` / `*Config`）是唯一例外，且必须在类 javadoc 里写明是 Gson 目标。
- `screens/` 下每个类必须 `extends Screen`；`*Model` / `*Config` 只承载数据，不含业务逻辑。`[lint]`
- **为测试开放的成员一律先降为包私有 + 同包测试**（测试树已镜像主包结构，零成本）；
  跨包时必须写 `// visible for testing`。`[lint]`
- 新增依赖方向：`api` ← `common` ← `server` / `client`。`common` 不得 import `client`
  （现状 0 处，钉住）；`server` 不得 import `client`（现状 0 处，钉住）。`[lint]`

## 3. 风格

现状：无 tab、K&R 100%、无通配符导入、无"一个文件多个顶层类"、无 `TODO/FIXME`、无 `@Deprecated`
—— 这一节基本是把现状写下来，只有 import 顺序与内联全限定名两条需要执行。

- 缩进 4 空格；大括号 K&R；控制语句必须带大括号。`[lint]`
- 行宽 ≤ 120 字符；禁止行尾空白。`[lint]`
- import 分三段、**段间不空行**：`com.pvzce.*` → 第三方 → `java.*`。禁止通配符导入。`[lint]`
- **禁止内联全限定名**，用 import。唯一例外是与同名类冲突需要消歧，且同一文件内保持一致。`[lint]`
  > 现状 2,482 处 `com.pvzce.*` 内联 + 817 处 `java.*` 内联（`java.util.List` 186、
  > `java.util.ArrayList` 110）。改到哪个文件就清哪个文件，不专门开一轮。
- 局部变量与参数**不用 `final`**（现状 2 处，保持现状）。
- `var` 只允许"右侧构造函数已写全泛型"或"静态工厂且返回类型显而易见"；禁止
  `var x = someMethod()` 这种要读两跳才知道类型的写法。`[review]`
- 浮点字面量带 `F` 后缀（GLSL 文本块与 `double` 上下文除外）；long 用大写 `L`。`[lint]`
- 禁止未使用的 import。`[lint]`

## 4. 常量与数值：一个事实一个出处

- 数值常量 → `PvzceConstants`；id（音效/粒子/队伍/规则/资源）→ `PvzceIds` / `PvzceSounds` /
  `PvzceParticles`。
- **tick ↔ 秒 ↔ 纳秒换算只允许走 `PvzceConstants.TICKS_PER_SECOND` / `NANOS_PER_TICK`**，
  禁止裸 `60`。`[lint]`
  > 已清零（原先 7 处 + `ClientLevel` 的一份私有换算常量）。注意剩下的 `/ 60` 是把**秒**换成分，
  > 与 tick 无关，不在此列。
- **同一个数不得在多个类里各写一遍**：跨类共享的几何/时长/上限必须有唯一宿主。
  规则的上限也不例外 —— 编辑器滑块的范围读 `GameRuleType.bounds()`，不要另抄一张表
  （抄过，而且抄错了：`sun_value` 曾经只能调到 500，服务端却收 10000）。`[test]`
  > 已修：阳光银行的矩形、卡条给银行让出的宽度、拾取动画的飞行目标原先分居两处且**已经不同**
  > （78 画出来、70 留位、边距 8 对 12，于是"8 像素的间隔"实际是 4），现在同属
  > `CardBarLayout`，`CardBarLayoutTest` 钉住它们的关系。
- **默认值不得内联字面量**：注册 `GameRuleType`、写 codec 的 `optionalFieldOf` 时，默认值引用
  常量（例：`CardCooldown.DEFAULT_MULTIPLIER` 就是那条规则的默认值）。`[lint]`
- 游戏规则的读取只有一个方向：能改的数（阳光面值、速度倍率…）必须读 `GameRules`，
  不得在另一条路径上写死。
  > 已修：`/summon` 与关卡初始实体原先写死 `25`（`sun_value` 改成 100 之后那两条路径仍然发 25，
  > 而且不分资源种类 —— 召唤一颗钻石也只发 25）。现在读资源自己的 `default_value`。`[test]`

## 5. 错误处理与日志

- **禁止新增 `System.out/err.println`**。用
  `private static final Logger LOGGER = LoggerFactory.getLogger("PVZCE/<模块>")` +
  `LOGGER.debug/info/warn/error`。`[lint]`
  > 现状：**主源码只剩 6 处 `System.out`，全部是 `PvzceClient` 里冒烟钩子的 `[SMOKE]` 行** ——
  > 那是测试脚手架与脚本之间的协议输出（`冒烟与截图指南.md` 按它判断"走到没走到"），
  > 刻意不走日志设施，也不加时间戳。除此之外 23 个 logger 全部是 `"PVZCE/<模块>"` 一种风格。
  >
  > 由 `-Dpvzce.trace*` 开关保护的诊断走 `LOGGER.info`（不是 `debug`）：logback 的默认级别是
  > INFO，用 `debug` 会让这些开关静默失效。
- `printStackTrace()` 一律改 `LOGGER.error(msg, t)`（现状 0 处）。`[lint]`
- **禁止空 `catch` 块**；`catch (X ignored)` 只允许 `InterruptedException` +
  `Thread.currentThread().interrupt()` 这一种形态。`[lint]`
- 吞掉异常必须有理由：`catch` 里返回 `null` / `false` / 兜底值的位置至少 `LOGGER.debug` 一行，
  写清"为什么可以吞"。`[review]`
  > 已清零（原先 8 处）。其中"通关标记文件损坏 → 静默当成未通关 → 关卡被重新锁上"这条
  > 后果最重，现在会明确说"标记存在但读不了，按未通关处理"。
- **同一子系统内的编码/解码失败必须同策略**：不能一处 `throw new IllegalStateException`、
  另一处静默 `return null`。
  > 已修：`LevelMechanics` 的编码失败现在在丢块处告警（解码那半边的报告在
  > `ClientLevel.applyMechanics`），与 `createCardSource` 的 fail-fast 一起构成一套说法：`[test]`
- 频率 > 1/秒的日志必须去重或限流，模式照抄 `SlotResolver.REPORTED` /
  `ClientMechanics.REPORTED_MISSING` / `ParticleEngine` 的 1 秒限流。`[test]`
  > 已修：每放一张卡一行的 `Planted …` 与每 10 秒一行的 `tick check` 现在是 `debug`；
  > 关卡校验、未知卡、畸形场景坐标、缺音效/贴图都改为 `warn` 逐条，不再走 `System.err`。
  > 现状：每放一张卡打一行 `[PVZCE] Planted …`、每 10 秒一行 `tick check`、每次构造关卡把
  > 校验问题全量重打一遍（重开关卡也算），且都没有 `-D` 开关。
- 异常与日志消息一律英文。`[lint]`
- 诊断输出（贴图缺失、动画缺失、音效缺失、协议不符）保留现有的"按 id 只报一次"做法，
  这是这个项目做得最好的一处，不要退化成每条一次。

## 6. i18n：机制已经建好，规则是把它用起来

`GuiLang` + `assets/<ns>/lang/<locale>.json`（`zh_cn` / `en_us` 各 220 键且完全对齐）是
**唯一**的玩家可见文本来源。

- 界面上的字一律 `GuiLang`；`GuiLang.raw(key, fallback)` 的 **fallback 不得是中文**，缺键时
  回退到 `key` 本身并 `debug` 记一条。`[lint]`
  > 现状 69 个 `raw(...)` 调用点里 62 处 fallback 是中文，其中 56 处与 `zh_cn` 完全一致 ——
  > lang 文件里的值被复制了一份进 Java，翻译改一边就分叉（已经有 3 处分叉了）。
- **各语言文件的键集合必须相等**。`[test]`
- **源码里引用的每个 lang 字面量键都必须存在于内置 lang 文件**。`[test]`
  > 现状缺 3 个：`pvzce.player.create` / `.delete` / `.use`（`PlayerPickerDialog`），
  > 它们永远不会被翻译。
- 服务端下发的玩家可见文本必须走 key + 参数，不得内联中文。`[lint]`
  > 现状 73 处（`PvzceServer` 34 + `PvzceCommands` 39），只减不增。

## 7. 注释与 javadoc

现状是项目最大的资产：注释块中 34% 显式写了因果（because / so that / otherwise / rather than），
中位长度 24 词。**这条规范的目的不是少写注释，而是别写错。**

- **每个成员最多一个 javadoc 块**。禁止 `*/` 紧跟 `/**`（字段重排后文档没跟着走）。`[lint]`
  > 已清零（原先 12 处，全部会误导读者：`MathUtil.easeInOut` 头上顶着 `easeOutCubic` 的说明、
  > `LevelServer.ZOMBIE_HALF_WIDTH_FACTOR` 头上顶着 `effectiveCooldownTicks` 的说明…）。
- **注释写"现在是什么、为什么这么做"**；"以前是什么"写进 `docs/架构变更记录.md`，
  正文里用一句约束代替：`// 约束：…（原因见 架构变更记录）`。`[review]`
  > 现状 219 处 `used to / no longer / 曾经 / 以前`。这批注释**大部分有价值**（它们解释了
  > 为什么不能改回去），要改写句式而不是删除。
- 不要写"获取 X"这种把方法签名翻译一遍的注释。`[review]`
- 公共类型与公共方法必须有 javadoc；类型覆盖率 87% 是当前基线，只增不减。`[lint]`

## 8. 测试

现状：588 个 `@Test`、0 个 `@Disabled`、0 个 `@Order`、0 个 Mockito、测试名 100% 是
描述行为的一句话 camelCase、真起 `PvzceServer`/`PvzceClient` + `Connection.createMemoryPair()`。
这套纪律很好，下面几条是补缺口。

- 测试方法名是**描述行为的一句话** camelCase（现状即规范）：禁止 `test` 前缀、禁止下划线。`[lint]`
- 临时目录一律 `@TempDir`，**禁止 `Files.createTempDirectory`**（JUnit 会自动清理）。`[lint]`
  > 已修：45 处全部改完 —— 逐用例的用 `@TempDir`（33 个字段）；
  > harness 里"给调用方建目录"的两处走 `testutil/TestDirs.create`（静态目录 + JVM 退出时
  > 递归删除）。`TestContent` 顺手从"每次调用建一个新目录"改成"整个 JVM 一个"：
  > 它被每个需要内容的测试类调用一次，原来每次全量测试泄漏四十几目录。
  > `@TempDir` 加在**静态**字段上也合法（JUnit 会在 `@BeforeAll` 之前建、类结束后删），
  > `LevelRestartFlowTest` 的静态 setup 用的就是这种写法。
- 断言一律 JUnit5 `Assertions.*`；helper 里"没有可测对象"统一用 `testutil` 的
  `requireFound(...)`，不再手写 `throw new AssertionError`。`[review]`
- **禁止新增 `Thread.sleep` 与墙钟断言**；要等就等 harness 的超时轮询。`[lint]`
  > 已修：`ClientLevelTimeTest` 原来断言"80ms 只前进约 5 tick"（写死 `< before + 60`），
  > 在负载高的机器上睡过头就会红。它测的两条性质是"客户端时钟不冻住、也不跑飞"，所以上界
  > 改成由**实测流逝时间**推出（`elapsed × 60tps + 2`）而不是由"请求睡 80ms"推出。
  > 全仓库再无墙钟断言（`Thread.sleep` 仍出现在少数 harness 的轮询里，那是等包/等文件）。
- **等待服务端状态要等"包"，不要轮询 `LevelServer` 的内部状态**。模拟是单线程的，
  `entities` / 队伍资源这类字段没有任何同步，测试线程去读可能**一直读到旧值** —— 症状是
  "5 秒超时，像是服务端没生成僵尸"，实际是可见性问题（`ServerHarness.packets()` 在测试线程
  上排空，所以它是唯一安全的观察通道）。`[review]`
  > 已修：`BackpackAndCoinsTest.aDyingZombieLeavesTheLevelsConfiguredCoinDrop` 原来
  > `waitForCondition(() -> level().aliveZombieCount() == 1)`，12 次里红 3 次；改成等
  > `EntitySpawnS2C` 之后 10 次全绿。
  > 同一轮清完剩下的：`waitForCondition(() -> level()...)` 全仓库**归零**。五处交给包：
  > `LevelRestartFlowTest` 3 处等"植物被放到场上的 `EntitySpawnS2C`"；
  > `BackpackAndCoinsTest` 等僵尸的 spawn 与**死亡 clip**（不是 `aliveZombieCount() == 0` ——
  > 尸体要在场上留几秒，那个计数和"客户端看见了死亡"不是同一件事）；
  > `SaveSystemTest` 直接读 spawn 包上的 `armor()`/`cellY()`，不再伸进 `entities()`。
  > 两份重复的 `winLevel` 助手（`BackpackAndCoinsTest` / `SleepDeprivationTest`）合并成
  > `ServerHarness.winByClearingTheField()`，用 `GameStateS2C` 判定胜利。
  > **还不是零**：断言式的同步读取（测试线程自己 tick 的单线程 harness）是安全的，保留；
  > `damageArea` 仍从测试线程调用（服务端没有"清场"命令），`winByClearingTheField` 的注释
  > 写明了这一处重叠。要根治得加一条调试命令，那是功能改动，不是测试整理。
- **每个 `throw new *Exception` 站点至少一个 `assertThrows`**（现状 6 个 vs 53 处抛点，
  错误路径几乎没测）。`[review]`
- 用例的增删按 `验证约定.md` §2：只有修掉真 bug 才加，重叠用例删之前先给出"谁被谁覆盖"。
- 同一个 fixture 不要在多个测试类里各写一份。`[review]`
  > 已修：`CapturingBridge` 的 16 份 → `testutil/ServerHarness`（一份）；
  > `LevelDef` 的 5 处 23 参克隆助手 → `testutil/TestLevels.copy(...)`。
  > 后者**已经分叉**：`CharmTest` 那份记得 `playableTeams`，其余几份漏了 ——
  > 也就是说"同一关但没有波次"在不同文件里不是同一关。
  > 结论：record 的字段清单不要抄进测试；要"改一两个字段的副本"就用 `TestLevels`，
  > `LevelDef` 以后加第 26 个字段时它一处改完，而不是 21 处。

## 9. 落地顺序

不是一次全改完，按"改到哪清到哪"执行：

1. **新增代码**必须合规（`[lint]` 类规则可以直接拒绝）。
2. **改动的文件**顺手清掉该文件里的违规（未使用 import、内联全限定名、错位 javadoc、
   `MathUtil` 克隆）。
3. **专项批次**（各自一轮，边界见 `当前项目架构.md` §9 的已知缺口）：日志设施收敛、i18n 迁移、
   `common→server` 收口、编辑器列表页去重。
4. `[lint]` 类规则攒到一批后写成 `DocumentedSymbolsTest` 那样的一个守卫测试，
   而不是每轮人工 grep。**已有三类源码级守卫**（都读源码文本，不依赖运行期对象）：
   文档符号（`DocumentedSymbolsTest`）、分层依赖（`LayerDependencyTest`）、
   协议连线（`PacketWiringTest`）。加新守卫时用 `testutil/SourceTree` 找仓库根，
   不要再写第四份"向上找 docs/"的循环；写完**注入一次违规**确认它会红 ——
   不会红的守卫比没有守卫更糟。

## 10. 可复用写法模式（内容一族、目录级规则、生成器）

这一节不是风格，是**这一年里反复用到的四种写法**：它们各自解决过一类"写第二遍就分叉"的问题，
新内容照用可以少踩一遍。

### 10.1 一族内容用一个类参数化

同一个句子里只有名词不同时，**写一个类 + 一张参数表**，不要写 N 份：

| 族 | 一个类 | 参数 |
|---|---|---|
| 数值类变异（9 条） | `RateMutation` | 规则 id、上下限、是否倒数 |
| 僵尸突袭（5 条） | `RaidMutation` + `Spec` | 点名的僵尸或标签、几只、基础间隔、行的限制、从哪来 |
| 割草机（2 条） | `MowerMutation` + `Duty` | 补一台 / 放一台 |

判据：**钩子的实现完全一样、只有数据不同** → 合并；钩子里的分支多到要靠 `if (kind == …)` 才
读得懂 → 分开。合并的收益是"存档、撤销、节流这些容易写错的一半只写一次"。

### 10.2 全目录规则要遍历着测

"后到的覆盖先到的""两两之间只允许一个生效"这类**覆盖整个目录**的规则，测试必须**遍历组合**，
不能只挑一对例子：挑出来的那一对通过、下一对出问题，是全目录规则最常见的失败方式。

```java
for (Identifier first : bar) {
    for (Identifier second : bar) {
        if (first.equals(second)) continue;
        // 断言"后到的那条在生效、先到的被压制但留在面板上"
    }
}
```

### 10.3 生成器优先：改产物必须同时改生成器

美术/关卡/图标这类"由脚本生成的文件"（`tools/*.py` 的输出），**手改产物等于改了一个会被覆盖的副本**。
要么改生成器再重新生成，要么当场承认它是手写的（从生成器的输入表里摘掉）。
改完生成器后跑一遍**重新生成**并把 diff 看一遍：只改产物不改生成器的 bug，会在下一次生成时复活。

### 10.4 名字与清单一处

同一份名单写两遍，一定会有一遍过期。已经因此删掉的第二份：客户端的中文名表（改用语言文件）、
写死的关卡 id 列表（改断言形状）、硬编码的图鉴下标（改断言规则）。
新增"清单"时先问：**它能不能由既有的注册表/数据推出**？能推的就不写，要写就只写一处并给它一个守卫测试。

### 10.5 状态放哪：谁必须与它同时正确

一个状态存在哪里，由"谁必须和它同时正确"决定，而不是由"哪个类用起来方便"决定：

- 花瓶的画面（`vase_full`）与"里面是哪张卡"必须同时正确 → 内容表跟 `scene` 分区走同一个存档。
- 变异自己的时钟与它拥有的规则 → 变异自己的状态（`saveState`/`applyFromSave`），因为它能被撤销。
- 关卡的"这一局长什么样"（弹坑、水、墓碑）→ 存档的场景分区，**不要**让变异在恢复时重放。

### 10.6 钩子与回调：加之前先确认有调用方

新增一个钩子/回调时，顺手写一个"它会被调用"的用例，或者在实现里留一行注释写明调用点。
反例：`PlantCapability.onRemoved` 从存在那天起没有任何调用方，直到一年后路灯花需要它才发现。
