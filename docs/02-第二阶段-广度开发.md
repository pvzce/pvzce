# 第二阶段：广度开发（能用优先，不求精）

> 目标：把第一阶段的骨架**扩散式铺满**——所有设计中的功能都要"跑得通、连得上"；渲染劣化、手感生硬、数值不平都允许，**唯一不允许的是缺环**。
> 每小节给"最小实现 = 什么 + 参考哪里 + 验收怎么算能用"。

### 2.0.2 实现纪律（本阶段特有）

- **数据优先**：凡可注册表化的内容一律 JSON 化，代码只提供行为骨架（`BehaviorClass` 字符串引用 + `ClassLoader` 反射实例化）；
- **先客户端可见**：每个新系统先保证"客户端能看到变化"，服务端准确性其次；
- **命令兜底**：任何功能都有一个 `/pvzce:*` 命令可触发，方便调试与验收；
- **质量红线**：不允许崩溃（未实现的功能返回空/日志警告并禁用），不允许卡死主循环。

### 2.1.3 卡槽条 UI（Pvz 核心交互）

- 关卡选择/准备页的操作按钮使用 `seed_chooser_button` 样式（禁用时使用 disabled 版本）；
- 顶部条形：`PlantCard` 使用 `SeedPacket_Larger` 背景（植物图在上、费用数字在下），资源卡/工具卡复用；铲子卡使用 `ShovelBank` 背景；
- 顶部卡槽条：按 资源卡 → 植物卡 → 工具卡 分组显示（组内保持玩家点击顺序），铲子/锤子等工具卡固定排在卡槽条最右侧，与选卡页顶部已选行顺序一致；SunBank 不占卡槽；
- 左上 `SunBank` 是可选槽位：选卡页里的 `pvzce:sun` 槽显示为 SunBank 卡面；选中后关卡内才绘制阳光银行并允许收集阳光，未选中则既不显示银行也不允许收集；SunBank 只作为 HUD 元素，不再出现在顶部卡槽条里，因此不会同时出现两个 bank；
- 资源卡/工具卡区分高亮（资源卡可拖到植物上"使用"，工具卡拖到场景"作用"）；
- 卡片数量超过顶部可视宽度时支持鼠标滚轮横向滚动；
- 拾起（pick）：渲染一个跟随鼠标的精灵；放回/取消右键；
- 悬停格子：场景高亮（绿色=可种、红=不可）+ 叠放预览。

参考原版 PvZ 布局，资源位于 `assets/pvzce/textures/gui/`：按钮/卡槽/对话框/HUD/页面背景/图标分别放在 `gui/button`、`gui/cards`、`gui/dialog`、`gui/hud`、`gui/screen/<page>`、`gui/icon`。

赛前选卡由 `ChooseSeedsScreen` 承担：进入关卡后镜头从房门/草坪向右平移到马路；草坪在镜头移动前已按关卡 `scene` 渲染好，不会被裸地替代。马路区域使用实体动画（`AnimationManager`）预览本关 `waves` 中去重后的僵尸类型；随后左侧 `SeedChooser_Background`（原图 465×513）木质面板滑入，木质边框/中段按原图像素比例九宫格平铺而非横向拉宽。面板**宽度按内容自适应收缩、纵向铺满**：卡片尺寸只随 GUI 尺寸推导（屏高 12.2%，夹在 44~96 之间）并在面板内**固定**，每行张数不设上限——按面板可用宽度能塞几张塞几张，面板再回缩到最宽一行（宽度上限 70% 屏宽、下限 40%）。纵向则铺满「已选卡槽行正下方 → 屏幕底部」，把下方的关卡背景整个盖住；面板内部内容紧凑并**顶端对齐**（块间距保持 ≈1.7 倍卡距），因此卡片紧贴标题栏、面板下部不显示内容、只留木纹，已选行上方也不会出现空白带。「选择你的种子」与「已选 N/M」画在面板顶框那条木质标题栏上（垂直居中于顶框，左侧留出金饰位置，标题字号会按顶框高度自适应以免溢出），清空/开始按钮贴面板底部。卡池按卡种分块，顺序为 资源 → 工具 → 植物（植物通常卡片最多、放在最下；工具最常用、紧跟资源，无分区标题），块内左对齐并在超宽时自动换行；第一块紧贴标题栏下方，块间保持紧凑间距。卡池高于面板可视区时可在面板内部用滚轮纵向滚动（右侧出现细滚动条），卡片尺寸不缩放；不滚动时卡片区的裁剪范围会跟随网格实际高度，避免最后一行被裁掉。已选卡槽行使用与卡池相同的卡片尺寸，浮在面板上边缘正上方并以面板内容左边缘对齐，与木质面板完全不重叠；该行按 资源 → 植物 → 工具 分组（组内保持点击顺序），与关卡内顶部卡槽条一致——注意卡池分区顺序与已选行/关卡内卡槽条不同是有意为之：卡池为了浏览（工具靠上、植物沉底），已选行与关卡内为了与原版一致（铲子/锤子固定最右）。点击卡片后播放 `seedlift`、一张卡从背包飞向顶部卡槽，取消/清空播放 `tap`，按钮沿用全局 `buttonclick`；植物/工具卡下方显示阳光费用，`pvzce:sun` 槽直接以 `SunBank` 卡面显示。与原版一致：卡池中**未选中的卡保持全亮、已选中的卡变暗**（不再绘制黄色描边），顶部已选卡槽始终全亮。默认按“世界+关卡”记住上次选择（`config/pvzce-seed-selections.json`），首次进入自动预选 `slots` 前 `max_seed_slots` 张；重开时重新进入选卡页并预填当前卡组。若该关卡已有存档，点“开始游戏”后不再先选卡，而是服务端**先加载存档**并下发 `LevelInitS2C`（含场景、实体、卡组），客户端进入关卡画面后弹出“继续游戏 / 重新开始”对话框；等待选择期间服务端冻结该关卡 tick；选择“重新开始”后才进入选卡页并预填存档卡组，返回则回到继续/重开对话框。未选对应资源卡时无法收集该资源。

关卡内使用原版 `background1unsodded`（已确认原图 1400×600）作为布景：左侧房门、中间 9×5 裸地、右侧马路；真正可种植的裸地区域是图像中的 `x=256..976, y=80..580`（720×500，单格 80×100），而不是整张 600 高图像。`PvzceCamera` 把棋盘按统一比例映射到该区域：9×5 正好铺满；其他尺寸只填满宽或高其中一条轴，另一方向露出裸地/背景空白，横向靠房门、纵向居中。草地 `grass.png` 是 1254×1254 的 6×6 方形格纹理，因此场景层按方形像素等比绘制并裁剪到棋盘矩形（再向外多渲染约 0.12 格的草边，避免边缘看起来被切掉），不再被 80×100 格子横向压扁；植物/僵尸/影子也按同一 `unitY/unitX` 做横向补偿，保持原版精灵像素比例。

### 2.2.3 行为类映射（Codec）

```jsonc
{
  "id": "pvzce:pea_shooter",
  "behavior": "pvzce:shooter",            // 行为注册表：shooter/thrower/ash/producer/defense/environment/support
  "cost": { "resources": { "pvzce:sun": 100 }, "cooldown": 300 },
  "health": 300,
  "attack": { "interval": 90, "shots": [ { "projectile": "pvzce:pea", "damage": 20, "offset_y": 0 } ] },
  "produce": { "resource": "pvzce:sun", "amount": 25, "every": 1440 },
  "placement": { "layer": 1, "count": 1, "group": "plantable" },  // 地面植物层
  "tags": [ "pvzce:basic" ]
}
```

### 2.2.4 堆叠规则（与用户设计一致）

> **已落地（见 `PlantPlacement` / `PlantPlacementTest`）**。本节后来收敛成"标签 + 分层"，
> 不再是 `accepts` 字符串矩阵：地形侧的 `#c:ground`/`#c:plantable`/`#c:water`/`#c:unplantable`，
> 植物侧的 `#c:carrier`/`#c:plantable`/`#c:requires_ground`/`#c:water_plant`/`#c:plant_only`，
> 层与互斥组由 `placement{layer,count,group}` 给出。完整矩阵与标签清单见
> [mod-guide/json-reference.md](mod-guide/json-reference.md#约定标签c-命名空间)。

| 概念（旧称） | 落在哪 | 说明 |
|---|---|---|
| Ground（可承载） | 地形 `#c:ground` / 植物 `#c:carrier` | 花盆、莲叶是**植物**（载体），草坪/裸地/屋顶/水面是**地形** |
| Plantable（可种植） | 地形 `#c:plantable` / 植物 `#c:plantable` | 绝大多数植物；花盆与莲叶也在这张表里，所以它们上面能再种 |
| Plant（植物上） | 植物标签 `#c:plant_only` | 咖啡豆（激活）等；下方任意植物都算 |

`PlantPlacement.canPlace(plant, ctx, x, y)`：纯函数，只读上述标签 + `PlacementDef`，
只考虑**层号低于自己**的支撑物，因此种植顺序不影响结果。

### 2.2.5 大招（charge/alt-fire）

- 每植物配 `super_charge` 招式（能量豆激活）：如豌豆射手 4 连发、向日葵瞬产 20 阳光、樱桃炸弹 3 连爆；机制=行为类接口 `ChargeablePlant`（`onActivate(ChargeReason)`）；
- 触发链：能量豆资源卡拖到植物上 → UseResource(C2S) → 服务端校验 → `super_charge` 事件广播。

### 2.4.1 分类（对齐用户设计）

### 2.4.2 定义 JSON

```jsonc
{
  "id": "pvzce:pea",
  "behavior": "pvzce:linear",
  "damage": 20,
  "speed_cells_per_second": 2.0,
  "layer": "ground",                // ground/air —— 命中判定层

  "effects": [ "pvzce:hit_flash" ],
  "sprite": "pvzce:projectile/pea"

```

- **一次函数/二次函数**：`LinearProjectile` 位置 = `p0 + v*t`；`ArcProjectile`（`pvzce:arc`）位置 = `p0 + v*t + 0.5*g*t²`（g 由 thrower 提供、写入子弹定义）；

## 2.5 卡槽、资源与工具

### 2.5.1 卡槽三分（对齐用户设计）

```java
public sealed interface SlotCard {
    SlotCardType type();     // RESOURCE / PLANT / TOOL
    Identifier defId();
    int stackCount();
}

public final class SlotBar {        // 关卡级配置：列表内容 + 顺序 + 每格冷却
    List<SlotCard> cards;
    int rows, columns;              // 大关卡可多行（默认 1×10）
}

public interface Draggable<T> { }   // 拖放目标类型：PLANTABLE_CELL / PLANT_ENTITY / SCENE_CELL / SELF
```

- **资源卡**：`drop_on = ["plant", "cell"]`——拖到植物=使用（回血/激活），拖到格子=放置（红石）；
- **植物卡**：`drop_on = ["cell"]`——种植；成本 = 资源配方（`cost.resources` map，同一植物可配置多资源方案：`cost.alternatives`）；
- **工具卡**：`drop_on = ["cell", "plant", "zombie"]`，`consume`、`cooldown`、`#ofUses`——铲子（每次点击只移除当前格子最上一层植物，可连续点击逐层向下，不返还资源）、手套（加速自己的植物/一次性）、锤子（对僵尸击退/砸毁场景元素）。

### 2.5.2 资源定义

```jsonc
// data/pvzce/resources/sun.json
{
  "id": "pvzce:sun",
  "icon": "pvzce:textures/resource/sun.png",
  "collectable_without_card": false,      // 无资源卡无法收集
  "max_stack": 9990,
  "drop_anim": "pvzce:sun_fall"
}
```

内置资源：`pvzce:sun`（阳光）、`pvzce:redstone`（红石——供 mod 内容）、`pvzce:energy_bean`（能量豆——大招）；

### 2.5.3 收集门槛

- 资源必须同时满足：本关已解锁（`Team.unlockedResources`，来自关卡 `unlock_resources` / 资源卡槽）且玩家当前卡槽中带有对应资源卡（`collectible_without_card=false` 时）；
- 关卡配置 `unlock_resources: { "pvzce:sun": true }`；
- 选卡时未带对应资源卡：服务端拒绝收集并提示“没有对应资源卡”，掉落物不会被计入资源；
- 收集成功后客户端播放“资源飞向左上角资源区并收缩”的表现动画，数值按当前选择立即到账。

### 2.5.4 工具与冷却

`ToolDef`：`use_cost`（可选资源消耗）、`cooldown`、`targets`、`effect`（行为类注册表自定义：`shovel/glove/hammer/...`）。继承方式与植物行为类一致（`BehaviorRegistry` 反射实例化）。

## 2.10 声音系统

- 注册表：`SoundEvent`（`pvzce:sfx/plant/shoot_pea`、`pvzce:music/grasswalk` 等）——`assets/<ns>/sounds.json`（对齐 MC 格式：`{"sfx/plant/shoot_pea": {"subtitle": "…", "sounds": ["pvzce:sounds/sfx/plant/shoot_pea"]}}`）+ `.ogg`；
- 播放：`SoundEngine.play`（参考 [client/sounds/SoundManager.java](../refer/decompiled-26.1.2-client/net/minecraft/client/sounds/SoundManager.java)、[MusicManager.java](../refer/decompiled-26.1.2-client/net/minecraft/client/sounds/MusicManager.java)）；
- `assets/pvzce/sounds/` 已全量纳入 `refer/sounds` 的原版 PvZ OGG（180 个文件，注册 200 个声音/音乐事件）：音乐轨放 `sounds/music/*.ogg`，音效按用途放 `sounds/sfx/{plant,zombie,projectile,ui,effect,ambient,misc}/*.ogg`；`sounds.json` 仍按 MC 约定保留在 `assets/<ns>/sounds.json`，并支持数组变体、`weight`、`volume`、`pitch`，播放时随机选取变体并加 ±5% pitch，同一事件 130ms 节流防刷屏；
- 数据驱动逐实体音效：`PlantDef`/`ZombieDef`/`ProjectileDef` 增加嵌套 `sounds` 对象（place/shoot/explode/produce/melee、spawn/hit/armor_hit/bite/death/special、impact），JSON 未配置时回退行为默认事件；
- 事件点：射击/命中/啃咬/放置/收集/爆炸/铲子/手套/锤子/波次/终波/开局 readysetplant/胜负；UI 按钮统一使用 `pvzce:sfx/ui/click`（buttonclick）；
- 网络：音效为**客户端本地触发**（动画/粒子事件携带 `sound` 字段），服务端不包音频流；
- 音量：设置页（主音量/音乐/音效）实时作用 SoundEngine，资源包可覆盖声音文件。

### 2.10.1 背景音乐控制器（`PvzceMusicController`）

- 4 条固定命名轨道：`menu` / `background` / `battle` / `stinger`，每条轨道可独立 play/stop/loop；
- 每条轨道持有 2 个 OpenAL 源，同轨换曲淡入淡出（默认 1.0s）；循环轨持续播放，单次轨（loop=false）播完自动停止；胜负时淡出 `background`/`battle` 并在 `stinger` 一次性播放 `pvzce:music/win` / `pvzce:music/lose`；
- 页面曲：标题页 `music/crazy_dave`，世界/关卡/准备页 `music/choose_your_seeds`，设置/模组/控制台/暂停/编辑器保持当前曲；
- 关卡音乐数据驱动：`LevelDef.music.cues` 为 `{at_tick, track, event, loop, stop, volume, fade_seconds}` 时间线，服务端按 tick 通过 `MusicEventS2C` 下发；未配置时默认 background 循环 `music/grasswalk`；`yard/adventure/1_1`、`yard/adventure/combat_test` 已配置最终波次/Boss 波切到 `music/ultimate_battle`。

## 2.12 AI 玩家

### 2.12.1 僵尸侧（默认 AI，对齐原版出怪）

- `WaveSpawner`：关卡 `waves` 显式列表 → 服务端维护波次进度条，按相对 delay 推进并触发下一波；
- 每波组成：`entries: [{id, count}]` 精确配置，展开后随机打乱，每 15 tick 生成一只（每行随机且尽量均匀）；
- 波次类型：`small` / `huge` / `final`；大波在进度条上带旗帜，进入 `warning_ticks` 窗口显示预警；最终波自动视为大波；
- 间隔曲线：`wave_interval_end_multiplier` 控制从第一波到最后一波的线性递减倍率；
- 音效：小波静音，大波播 `pvzce:sfx/ambient/hugewave`，最终波播 `pvzce:sfx/effect/awooga` + `pvzce:sfx/ambient/hugewave`；
- 特殊行为：夜间（night_length>0）墓碑产怪；Boss 关卡：阶段表 `phases: [{at_hp: 0.8, summon: [...], ability: "slam"}]`。

### 2.12.2 植物侧（AI 帮打）

- `PlantAIPlayer`：读取环境变量/规则（`pvzce:ai_efficiency`），在格子空位按优先级（防御→生产→攻击）补种；资源自动管理；
- 用途：单人测试僵尸方 Team、观战模式（第二阶段末）、教程。

### 2.12.3 玩家接管规则

- 关卡启动：每 Team 检查真人玩家数，0 人 → AI 接管（`ai_controller` 注册表按关卡 `team_ai` 字段指定）;
- 中途加入：`/join team pvzce:zombie_team` → 接管 AI 控制权（AI 暂停）。

## 2.14 存档系统完整

### 2.14.1 布局（对齐 MC 分层）

```
~/.pvzce/
├─ mods/
├─ resourcepacks/  datapacks/
├─ config/*.toml
├─ saves/
│   ├─ <world>/
│   │   ├─ levels/<level_key>/              # 每关卡独立运行存档
│   │   │   ├─ level.dat                    # NBT：LevelId、tick、波次进度、植物、僵尸状态、阳光
│   │   │   └─ data/
│   │   │       ├─ level_state.dat          # 该关卡格子状态/植物实体清单
│   │   │       ├─ team/<team_id>.dat       # 该关卡 Team 资源、解锁
│   │   │       └─ player/player.dat        # 该关卡玩家卡槽/冷却
│   │   ├─ level_status/<level_key>.dat     # 一次性关卡胜负状态（只记录通关）
│   │   ├─ icon.png
│   │   └─ session.lock                     # 防多开（参考 MC session.lock）
├─ logs/latest.log
└─ crash-reports/                    # 仿 MC CrashReport（参考 net/minecraft/CrashReport.java）
```

> `<level_key>` 由关卡 Identifier **单射地**编码（`LevelKey`）：命名空间转十六进制 + `__` + 路径（`%`→`%25`、`/`→`%2F`），
> 如 `pvzce:yard/adventure/1_1` → `70767a6365__yard%2Fadventure%2Flevel_1`。旧键（把 `/` 折成 `_`）不单射，
> `a/b` 与 `a_b` 会共用目录。旧键改名那次扫描随后也删掉了（未发布 ⇒ 不存在旧档）。

序列化：全部 `Tag`→`CompoundTag`；NBT 结构版本号 `DataVersion`（int）写进每份存档。当时计划的 `NbtMigrations` 迁移链表最终没有保留 —— 项目未发布、不存在旧档，与其维护一条永远走不到的分支，不如读到旧格式就当没有存档。

### 2.14.2 世界流程

- 主菜单：创建世界（名称/版本/默认数据包集合）→ 关卡选择 → 游玩；
- 关卡选择：服务端按当前世界读取每个关卡的 `level_status`，列表显示“进行中/已通关”；
- 进入已有运行存档的关卡：关卡准备页点“开始游戏”后**跳过选卡**，服务端**先加载存档**并下发 `LevelInitS2C`（含场景、实体、卡组），客户端直接进入关卡画面后弹窗“继续游戏 / 重新开始”（无取消按钮），等待选择期间服务端冻结该关卡 tick；
  - 继续：恢复 tick、波次进度、波内待生成队列、植物、场地僵尸（位置/血量/护甲/减速定身状态/行为计时）、阳光和卡槽冷却；
- 重新开始：不删除存档、保持关卡冻结，进入选卡页并预填当前存档卡组；选定后发送 `StartLevelC2S(restart=true)`，服务端删除该关卡运行存档、对该 `LevelServer` 实例执行 `shutdown()`（清空实体/待处理队列、断开 bridge、标记 closed）并按当前选卡从头开始；在选卡页返回则关闭对话框重新显示“继续/重新开始”；从暂停菜单重开时，旧关卡会保持暂停直到新卡组提交，不会在选卡期间继续推进；
- 没有存档的关卡：仍在准备页后先进入选卡页，选完再创建新关卡；
- 一次性关卡通关：写 `level_status/<level_key>.dat`（`GameState=completed`）并删除运行存档；失败只删除运行存档，不写通关状态；
- 旧版世界级 `saves/<world>/level.dat` 不再读取（本轮不做自动迁移，新布局从空存档开始）；
- 关卡内退出：`PauseScreen → 退出并保存`；异常退出：`crash-report` + 下次启动恢复提示。
