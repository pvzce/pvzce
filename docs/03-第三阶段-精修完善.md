## 3.2 玩法平衡与数值校准

### 3.2.1 方法论

1. **建立基准**：第二阶段数值表（PvZ1 近似）→ 转为可调"内容注册表"默认值；所有数值**不得硬编码**，只存在于 `data/pvzce/plants|zombies|projectiles/*.json` 与规则；
2. **可观测**：`/pvzce stats` 输出每关：僵尸生成数/击杀数/植物经济（总收入/花费）/平均存活时长/最弱植物（使用率+胜率）；
3. **度量指标**：
   - 经济曲线：关卡 1/10 时间点的阳光存量与产出速率（对目标曲线差值 < ±15%）；
   - 单位效率：每植物 DPS/费用、每僵尸 HP/费用——两两比较矩阵（表 3.2.3）；
   - 难度标定：目标胜率区间（单人 60%~75%、AI vs AI 20%~35%）。
4. **校准流程**：调参 → 自动化跑局（AI vs AI，见 3.6）→ 指标回归 → 提交到"平衡基线"数据包；每版本附 `balancing_report.md`。

### 3.2.2 校准工具与调试能力

- `/pvzce balance diff`：对比当前内容包与基线包的数值差；
- `/pvzce balance simulate <seed> <n>`：无界面模拟 N 局输出统计（服务端 headless）；
- 复盘回放：`/replay record|play`（本阶段实现"轻量回放"：记录 tick 向量 + 决策包 + 随机种子，回放仅重演逻辑——对平衡定位极有用）。

### 3.2.3 效率矩阵（示例模板）

| 植物 | 费用 | DPS | 效率(DPS/费用) | 问题诊断 |
|---|---|---|---|---|
| 豌豆射手 | 100 | 13.3 | 0.133 | 基准 |
| 双发射手 | 200 | 26.7 | 0.133 | 同上（线性） |
| 机枪射手 | 250 | 40 | 0.16 | 略优（可接受） |
| 冰豌豆 | 175 | 13.3 | 0.076 | 减速价值需另计 |
| 西瓜投手 | 200 | 61.5 | 0.308 | 疑似过强 → 校准溅射半径/伤害 |

> 校准规则：效率差 > ±25% 即触发再平衡；角色定位差异（防御/控制/经济）单独建模。

### 3.2.4 关卡难度曲线模板

| 关卡 | 波数 | 首波(t) | 每波间隔 | 僵尸总量 | 类型构成 | 目标难度 |
|---|---|---|---|---|---|---|
| 1-1 | 3 | 600 | 1200 | 12 | 全普通 | 新手（胜率 90%） |
| 1-5 | 6 | 300 | 600 | 45 | 普通+路障+铁桶 | 标准（75%） |
| 2-10 | 8 | 200 | 450 | 90 | 全型+巨人×2 | 进阶（55%） |
| 无尽 | ∞ | 60 | 递减 | ∞ | 曲线 | 生存（随波数指数） |

## 3.3 新手体验与可访问性

### 3.3.1 新手引导流程

```
首次启动 → 语言/画质快速选择 → 简介动画（窗口内视频帧序列）
→ 引导关卡（level: pvzce:tutorial_1：只允许 3 种植物与 10 只僵尸）
   内置引导层：
   ├─ 第一步：拖第一张卡种植（高亮 + 箭头 + 文字提示）
   ├─ 第二步：阳光收集（资源脉冲圈提示）
   ├─ 第三步：豌豆命中僵尸（慢镜头 0.5×）
   ├─ 第四步：僵尸啃咬/植物死亡（教学"失败机制"）
   └─ 完成 → 主菜单 → 关卡选择解锁
```

- 引导由"引导数据包"实现（`data/pvzce/tutorials/*.json`），mod 可写自定义教程；
- 失败复盘：`/replay` 自动录制新手局，"复盘视图"标注失败原因（经济不足/防线缺口/放置时机）。

### 3.3.2 难度选项（每关卡可覆盖）

- 难度三档：简单（伤害×0.7 僵尸速度×0.8）/ 标准 / 困难；
- "辅助模式"：阳光生产×1.5、卡槽无冷却（作为**环境变量/规则**流入逻辑，不特判代码）。

### 3.3.3 可访问性

- 字号/UI 缩放（RenderSystem 投影无关，GUI 字号倍率）；
- 色弱模式：资源颜色编码 + 形状双重提示（阳光☀+黄、红石◆+红）；
- 动效减弱（particles_off 规则：关闭屏幕震动/慢镜头）；
- 键鼠完全可操作 + 可选手柄（后置，接口预留 InputProvider）。

## 3.4 联机打磨

> 第一阶段已有包分离架构、第二阶段有 `TcpConnection` 骨架；本阶段做"完整可用"。

### 3.4.1 会话模型

```
主机（集成服务器）          客户端
  └─ 房间/关卡状态             │ 发现：局域网广播（UDP multicast/MDNS）或 直连 IP:port
  └─ 加入 → 身份注册（PlayerHandshakeC2S：账号/昵称/Team 请求）
      ├─ 服务端校验：Team 空位（max_players_per_team）、win_team 解锁状态
      ├─ S2C LevelSnapshot：注册表同步（SYNCHRONIZED_REGISTRIES 全量 + 差分）→ 实体快照
      └─ 正式开始（双方所有玩家就绪后 server 广播 GameStart）
```

### 3.4.2 同步策略（MC 风格分档）

| 数据 | 策略 |
|---|---|
| 实体（植物/僵尸/子弹） | 位置增量（每 5 tick 一次或变化超阈值时）+ 事件驱动（攻击/动画/死）——参考 MC 实体同步思想 |
| 资源/卡槽 | 命令式增量（S2C ResourceDelta） |
| 环境变量/规则 | 全量 on Join + 增量 on Change |
| 动画 | 事件广播（状态 id + 起播时刻 t） |
| 输入 | **服务器权威**：C2S 仅意图（place/collect/use），服务端重演判定（防作弊） |

断线重连：客户端保留 `SessionToken`（NBT 加密? 本阶段明文 id+secret），重连 → `ResumeS2C(delta since last ack)`；实现为"实体状态全量 + 自上次 ack 的事件重放"（简化版回放）。

### 3.4.3 观战与回放

- 观战席位：`/spectate <team>`（无卡槽 HUD、自由相机、旁白显示双方资源）——**服务器视角，非 tps 结算**；
- 回放：`ReplayRecorder`（tick 数 + 随机种子 + 输入意图流 + 规则变更流——记录体积小）；
- 回放文件：`replays/<world>/<gameId>.pvzreplay`（NBT）。

### 3.4.4 服务器运维

- `dedicated` 启动：`java -jar pvzce-server.jar`（同 jar `--server` 参数走 KnotServer 路径——loader 的 [KnotServer.java](../refer/fabric-loader/src/main/java/net/fabricmc/loader/impl/launch/knot/KnotServer.java) 已天然支持）；
- `eula` 式首次运行许可 + `server.properties`（端口/最大玩家/白名单——对齐 MC 字段语义）；
- 远程管理：控制台命令（同 2.15 全套）；RCON 后置（第四阶段）。

### 3.4.5 防作弊下限（本阶段）

- 服务端权威判定全部交互；客户端仅表现；
- 校验包：明文（无加密）——声明"PVZCE 联机为娱乐级防作弊"（文档诚实标注），后续可挂 TLS（第四阶段）。

## 3.5 AI 打磨

### 3.5.1 僵尸侧（出怪策略器）

| 维度 | 第二阶段（可用） | 第三阶段（精修） |
|---|---|---|
| 波次 | 固定 JSON 表 | 程序生成 + 主题曲组（waveTheme：普通/游泳?/飞行/巨人）× 难度参数（存活时间、经济动量） |
| 行分配 | 随机 | 目标线感知：玩家防线薄弱行权重 +"多线施压"（参考原版"某行连续 3 波不出现则增援"） |
| 特化 | 无 | 类型组合预算（每波成本点：普通=1/铁桶=3/巨人=6……） |
| 反应 | 无 | Boss 阶段规划（召唤时机/技能循环参数化） |

实现：`WaveGenerator`（`ServerLevelEvents` 回调驱动，纯逻辑可单测）。

### 3.5.2 植物侧（AI 玩家）

- 决策循环：每 20 tick 一次「评估 → 计划 → 执行」；
- 评估输入：钱包、防线缺口（僵尸密度图）、威胁窗口（僵尸到达时间）、环境变量；
- 计划：`Planner` 输出动作序列（种 X 在 (r,c) / 用能量豆 / 铲除）；
- 可调：`/pvzce ai profile <plant|rush|eco|defense>` + 难度标定用开关（`rules.pvzce:ai_efficiency` 0~1 缩放）。

### 3.5.3 自动化平衡测试

- Headless（无窗口）跑 N 局 AI vs AI（不同策略参数组合）；
- 输出 CSV：`round,winner,plant_eco,zombies_killed,time,effective…`；
- 成为 3.2 平衡校准的回归测试基座。

## 3.7 发布与版本管理

- 语义化版本：`1.0.0`；内容包版本 `data_version`（NBT 迁移链）+ `pack_format`（资源包兼容）；
- 发布产物：`pvzce-<ver>.jar`（本体）+ `pvzce-<ver>-server.jar`（可选瘦身版，裁剪 client 与 LWJGL-GL 依赖，用 KnotServer 入口）；
- 升级路径：旧存档 `level.dat.data_version < 当前` → 迁移链逐级升级（每一级一个 `Migration` 类，参考 MC `DataFixer` 分层思想）；
- mod API 版本：`@Deprecated` 标记 + `com.pvzce.api` 模块版本化（mod 在 fabric.mod.json `depends: { "pvzce-api": ">=1.0.0" }`）。
