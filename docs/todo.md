## 玩法与内容

### 金币没有消费去处

钱包、掉币、通关结算、结算页都做了，商店页也做了，但**只有三件商品**（钉耙 / 卡槽 +1 / 阳光铲 I）；
Crazy Dave 的商店全套与图鉴式商品栏都没做。金币目前主要是进度展示，这是有意的阶段性取舍。
增益槽（`PlayerProfile.buffSlots`）与卡槽一样留了升级入口（`addBuffSlots`），同样没有商店去卖。

### 僵尸方没有背包

`PlayerProfile` 只记录植物/工具；"僵尸也一张张解锁"要等僵尸方能被玩家操作（对战模式）时才有意义。

### 世界 5 的八株植物还没发出去

`卷心菜投手 / 花盆 / 保龄球 / 机枪射手 / 玉米投手 / 万寿菊 / 西瓜投手 / 冰西瓜`：定义与美术都在
（连图鉴条目都有），只是**没有任何关卡发它们**。世界 5 预计 10 关，正好够八株植物加两关的增益/工具。

### 图鉴不显示"这一关给这张卡"

未解锁的植物在图鉴里只有一句「未解锁」，玩家看不到"通关 1-9 就能拿到它"。
`LevelRewards` 只记"谁发"、不记"发给谁"，所以显示这一行要反查全部关卡定义（`BuiltInRegistries.LEVELS` 的 `rewards`），
或者在 `PlayerProfile` 旁边存一份反向表。与「没获得的增益没有说明」是同一件事的两半，真要做得一起做。

### 图鉴不显示原版那两行档位（"类型 / 强壮度"）

原版卡片背面有 `类型：攻击 - 远程`、`强壮度：中等` 这类档位，本项目没有对应字段：`PlantDef` 没有类型分类，
僵尸只有真实血量而没有"低/中/高"的档位。现在图鉴列的是**本项目自己的数**（植物的阳光/冷却/血量、僵尸的血量/速度/咬伤、
资源的价值）。要补原版那两行就得给内容加字段并逐条填五十多个值 —— 那是一次内容活，不是显示层的活。

### 图鉴里的僵尸没有"未解锁"

原版的图鉴是**奖品**：僵尸见过才进图鉴，没见过的格子里是一句 "not encountered yet"。这一版全列（26 只全在）。
要做成原版那样，需要一个跨关卡、跨世界的见过记录（`PlayerProfile` 旁边加一个 `SeenZombies` 集合，
`ZombieEntity` 第一次生成时登记），并且要决定它在沙盒世界里怎么表现。

### 没获得的增益靠挂锁表达，没有"为什么锁着"的说明

池子里未获得的增益画的是与固定卡同一个挂锁（`ChooseSeedsScreen.drawLockBadge`），点它只响一声。
玩家看不到"通关 1-9 就能拿到它"。最省事的是把它接到已有的提示框上（`client/gui/hud/HintBox` + `LevelHints` 的
`on_card_refused` 那条路），文案里点名是哪一关发的 —— 但 `LevelRewards` 只记"谁发"、不记"发给谁"，
所以要反查全部关卡定义，或者干脆在 `PlayerProfile` 旁边存一份"这个东西是哪一关给的"。

### 泳池的"潜水"只有美术那一层

`pvzce:submerge` 让潜水僵尸在水下时 `canBeHitByGround()` 为假、并播 `swim` 片段（那份片段的 mask 只画水面上的头与呼吸管），
但**没有"水面盖住身体"的那一趟渲染** —— 引擎的层级是"场景 → 实体"，水永远画在僵尸后面，
所以一只在水里的僵尸看上去是站在水面上而不是浸在水里。要做得像原版，需要在实体之后再画一趟只覆盖水格的半透明水面
（并且只盖到水线以下的部分），那是一件独立的渲染活。

### 潜水僵尸的"出水"是一个片段没用上

`Zombie_snorkle.reanim` 的 `anim_uptoeat`（浮出水面再开咬）没有对应的服务端状态钩子 —— 僵尸一开始啃植物就是 `eat`，
所以浮出的那几帧跳过了。要接上得给 `ZombieCapability` 一个"进食状态"钩子（现在只有 `walkState`）。

### 弹坑只有草坪那一版

原版还有屋顶（`crater_roof_left/center`）与水面（`crater_water_day/night`）的弹坑美术，都在 `refer/im7/images` 里，
但 `LevelServer.isBareGround` 只把草坪与裸地变成弹坑 —— 屋顶与水面需要各自的贴图与尺寸，是一件内容活。

### 杨桃只打了四个方向里的两个

`ProjectileRef` 只有横向的 `direction()`，弹丸的移动与命中判定都按"同一行"写。杨桃在原版是**五个方向**：
前、后、上、下、自身格。现在它打前和后。做法（四步）见 `架构-扩展点与约定.md` §8.44b：
加纵向标记 → 移动改成按 `(dx, dy)` → 命中改成"同一格" → 目标搜索按方向选；既有弹丸的 `dy` 全是 0，
要用既有测试证明行为不变。

## 关卡与编辑器

### 编辑器不认识 `buffs`

关卡编辑器的信息页/卡池页都没有"这一关的增益"这一项：

- **不会丢数据**：`InfoPage.buildLevelJson` 从载入的 JSON 出发，只覆盖自己拥有的字段，
  所以手写的 `"buffs"` / `"max_buff_slots"` **会被原样写回去**；
- **但也没有 UI 去编辑它们** —— 今天配增益只能手写关卡 JSON，或者用 `LevelBuffPlan.mapCodec()` 认的两个字段写在文件里。

最小的形状是在卡池页（`CardsPage`）下面加一行"关卡的增益"：一个多选列表（列出 `BuiltInRegistries.LEVEL_BUFFS` 的全部 id
+ 一个 `pvzce:player_choice` 复选项）加一个 `max_buff_slots` 数字框。`MechanicPages` 那种"按注册表生成一页"的做法可以直接抄。

### 编辑器不认识 `conveyor` 与 `placement_zone`

同上一条：手写的这两块不会被保存动作删掉，但也没有 UI 去编辑它们——小游戏关卡目前是手写数据。

### 编辑器不认识 `dialogue.timed` 与 `mechanics.schedule`

对话页会把整个 `dialogue` 块按自己认识的字段重写，所以**用编辑器保存一个带 `timed` 的包关卡会把定时台词丢掉**；
`MutationMechanic.editorFields()` 仍然是空的，脚本变异只能手写 JSON。要补的话：对话页加"定时台词"一栏
（一个 `at_tick` + 一行台词的列表），变异机制加一个只读提示 + "在 JSON 里编辑"的说明就够 —— 一个可视化的脚本编辑器不值得做。

### 编辑器不认识 `endless_schedule`，无尽关卡也不进编辑器

`pvzce:endless_schedule` 是数据注册表，编辑器不认识它，也没有"轮"这个概念的 UI。而
`pvzce:yard/survival/` 下的九关（泳池无尽、四条草坪无尽、四个变异难度档、变异教程）由代码构造
（`server/level/EndlessLevels` 与 `common/level/mutation/MutationLevels`），编辑器对它们只能编辑文件里有的东西
—— 而它们根本没有文件。想改这几关就得改代码；反过来，变异目录（38 条）也只能是代码，这是有意的取舍。
> 出道题的曲线**是**数据：`pvzce:endless_schedule`（`data/<ns>/endless_schedules/*.json`）决定一轮多长、
> 哪些僵尸第几轮解锁、节奏怎么收紧，内置两份（`pool_endless` / `mutation_endless`）。
> 所以"难度太陡"是一行 JSON，不是一次改代码。

### 编辑器只编辑一个首通解锁

`rewards.first_clear` 手写多条时，编辑器只认第一条 `unlock` 并在保存时把**多余的 unlock** 规范化掉（会打一行日志）。
它没有 UI 的条目（今天的 `resource`）会**原样读写回去**，不会被保存动作删掉 —— 判定在 `InfoPage.readRewardLists`
（纯函数，`InfoPageRewardsTest` 钉住）。

### 编辑器画布不画关卡背景、仍按草坪几何画泳池关卡

关卡可以指定 `background`，游戏与选卡预览都按它画，但画布仍然是"地形画在一块空底上"——作者选完背景图看不见它，
也看不见 `hidden_scene_elements` 的效果（画布故意不隐藏，否则作者看不见自己画了什么）。而且画布不读关卡的 `background`，
所以泳池关卡在编辑器里按 9×5 的草坪格几何显示、水面也按格画。要补齐得让画布按 `LevelStage.cover` 的那套投影
把 1400x600 的舞台画进它自己的小视口。

### 编辑器画布不显示装备档位

画布上的僵尸是满血预览实体，`armor` 取 `NO_ARMOR`，`EquipmentArt` 把它当成"没磨损"画完整的那一张。
想在编辑器里摆"破了的路障"需要一个新的预览状态。

### 选卡页的棋盘预览在僵尸种类多时文字会挤在一起

`.smoke/w3b/seed.png`（3-6 的选卡页）里，右侧棋盘预览上的僵尸名**纵向重叠**，糊成一片。3-6 有 11 种不同的僵尸，
是第一批把这个问题暴露出来的关卡。`ChooseSeedsScreen.drawPreview` 逐只按 `cellY` 算标签位置，字号是
`clamp(previewH / count / 90, 0.45, 0.62)` —— 最小值 0.45 在种类多时会赢，而**一个名字可能折成两行**
（`ducky_tube_buckethead_zombie`），于是行距不够。要看的是"名字长到换行时怎么办"：要么预先算行数、
要么把列表截断并加一个"…"、要么把名字缩短到只留最后一段。**没有查清之前不要猜着改。**

### 奖励页上的增益卡用的是种子包的框

1-9 / 2-9 首通时，草坪上落下的与结算页相框里放的是**增益自己的图标 + 种子包的框**（`SeedCardRenderer` 的
`CardKind.BUFF` 只决定"不印价格"）。这不是占位，只是取舍：项目里没有第二套"奖励卡"边框，而且这一页说的是
"你拿到了新东西"，与种子包同一个语义。要给增益做一套自己的卡片边框的话，`SeedCardRenderer` 已经有 `chrome(...)`
（铲子卡就是那么换的），加一个 `BUFF_CARD_BACKGROUND` 即可。

### 奖项页自己的排版仍偏矮

`AwardScreen` 的相框与羊皮纸是照 4:3 底图坐标写死的，宽屏下 `coverFit` 会把顶部木牌裁掉、下方文字挤在一起
（"金币 +100 / 金币总数"两行会叠到羊皮纸外）。与提示框、白光无关，是这一页自己的缩放问题。

## 数值与美术

### 粒子单位只覆盖"抛掷物"那一族

`tools/particles_to_pvzce.py` 的 `PROP_SPEED_DIVISOR` 只作用于原版用 `GroundConstraint` 标出的抛掷物
（头/手臂/帽子/旗帜等 20 条定义）。剩下 122 条仍按"像素/帧"换算，所以它们的速度比原版小 60 倍、自旋大 60 倍
——碎片类本该四散飞开，现在是原地淡出；同样的单位问题还让自旋读成 15000 度/秒、`ParticleScale .5,60 0` 被读成尺寸 0。
结构与修法见 `架构-实体与能力.md` §5.2 的注：把判据从 `thrown` 放宽到"没有 Friction 的弹道发射器"可一次修好，
但要单独过一遍截图。

### 关掉 shader 的水面仍是不含原版贴图的静态帧

`pvzce:water` 的水面贴图是原版 `pool_base.jpg`（`tools/gen_water_surface.py` 做成九格一张的 tile），
但 `renderFallback` 走的是 `textures/scene/water_frames/*` 那几张预烘焙帧，里面只有水色与岸线泡沫
——低画质开关或没有 shader 的环境下看不到云纹**也看不到那张漂移的焦散图**。泳池关卡 `disable_shaders: false`，
正常路径不受影响；要把降级路径也补上，得让 `tools/gen_water_frames.py` 把底图与焦散烘进帧里。

### 小推车只有两种车型

`MowerData.kinds` 是"哪一行放哪种车"（内容 id，客户端按 `mechanic/<path>` 取动画），泳池两行因此跑
`pvzce:pool_cleaner`；屋顶的 `RoofCleaner`（`refer/anim/RoofCleaner.reanim`）还没转，也没有屋顶关卡去用它。

### 焦尸美术的细分

`Zombie_charred_*`（巨人 / 矿工 / 小鬼各有自己的焦尸）还没转，今天所有僵尸都用同一具通用焦尸。

### 其余场景的蘑菇

夜晚的八种蘑菇到 2-10 为止已经集齐（小喷菇 / 阳光菇 / 大喷菇 / 魅惑菇 / 胆小菇 / 寒冰菇 / 毁灭菇 + 咖啡豆），
缺的是**其余场景的蘑菇**：忧郁菇、磁力菇、海蘑菇（它们属于泳池/浓雾/屋顶）。

## 系统与工具

### 联机（TCP 未接线）

TCP 骨架（`TcpPacketTransport`）在清理轮删除：它已修好语义但从未接线，与其留一个没人构造的实现，
不如等真做联机时按当时的需求写。缺的是握手、`server.properties`、玩家身份/Team 占位、断线重连与 delta 重放。
协议层不受影响：`PacketTransport` 是接口，换一个实现即可。

### 注册表同步与客户端资源同步

客户端目前依赖本地资源/数据包自行解析注册表（`PvzceClient.run` 里另建了一个 `PvzceResourceManager`）；
联机时应改为服务端按注册表下发定义。`PvzceDataLoader.RegistryData` 预留了"哪个注册表需要同步"的位置，
但目前只有目录名与 codec 两个字段。
> **语言键已规范化，界面串没有**：内容键是 `<注册表>.<命名空间>.<路径>`，界面串仍是手写的 `pvzce.*` /
> `gui.pvzce.*` 两套前缀。合成一套要动 200 个键与 38 个文件，是纯重命名，见 `架构-框架层.md` §3.1b。

### 注册式集成测试与渲染冒烟未建

`@PvzceGametest` 注册式集成测试与渲染冒烟（离屏 FBO + 图 diff）**未建**，所以界面没有自动化验证 ——
这批工具是第三阶段的规划（见 `03-第三阶段-精修完善.md` §3.6.1）。现状是 JUnit 单测/集成测试。
服务端/客户端流程可以直接起真的 `PvzceServer`/`PvzceClient` + `Connection.createMemoryPair()` 来测：
`testutil/ServerHarness` 与 `testutil/ClientHarness` 是这两个 harness 的唯一实现。

### 逐字号的字形缓存没有淘汰，只有"整页重来"

`FontFace` 的字形缓存以 `(码点, 设备像素尺寸)` 为键，页面满了（4 页）就 `recycle()` 全部丢掉重光栅。
一屏文字装不满一页，所以现状够用；但"同一个面以很多不同字号画很多不同的字"（编辑器里缩放预览、mod 自己传 scale）
会让缓存反复重建。要做的话是 LRU + 页内空洞回收，而不是加页数 —— 加页数只是把问题推后，显存却是实打实的。

### 变异的数值区间只有档位倍率，没有逐条调参

18 条变异里只有 6 条（`RateMutation` 那五条 + 危机/打地鼠/墓碑的间隔）真的用了难度档的倍率，其余是
"有/没有"或"一次性"的效果。如果以后要给单条变异配权重或强度曲线，`Mutation.weight()` 已经在接口上
（今天都是默认值 10），改法是给它加一个"档位 → 权重"的重载，而不是在 `MutationRegistry.roll` 里写按档位的特判表。

### 变异关卡没有专门的战报

四个变异关卡与普通关共用选卡页与结算页：失败时结算页显示"存活 N 波 · 击杀 M · 用时 T"（`GameStateS2C` 的三个字段）。
但没有"本局经历了哪些变异"的战报 —— 而这份数据现在是现成的：变异的 id 与抽到的数字已经在 `level.dat` 的
`Mutations` 块里，缺的只是把它读出来画一页。

### 增益选择没有"每关一份"的记忆

自动启用名单是**每世界一份**（`PlayerProfile.autoBuffs`），这是设计阶段定的：玩家勾一次"自动拾取"，
是想在所有关卡都自动拾取。如果以后想要"某些关卡自动开、某些关卡自动关"，那要改成按关卡存
（`saves/<world>/buff_prefs.dat` 之类），`LevelBuffSelection.planForRun` 是唯一的入口。

### 增益只在关卡开始前可选

`StartLevelC2S` 是唯一带增益的包，也就是"一局开始了就不能再改"。这是有意的（增益是选卡的一部分），
但如果以后要加"关卡中途开关增益"（调试命令、mod 覆盖、奖励解锁），需要一个新的包与一处
`LevelServer.activeBuffs` 的写入口 —— 现在那个字段只在构造与 `restore` 时被写，
`sporeRangeMultiplier` 每发射一次都重读，所以"中途改了立刻生效"这半边已经成立。

### 渲染批合并与图集

现状、成因与"要做对必须满足哪三条"见 `架构-客户端.md` §6.3。省 draw call 的收益几乎全在图集那一半，
而图集是一次独立的资源活（今天每个 texture id 一张贴图，实盘 1140 张 PNG / 170MB）。

### 骨骼混合与 Spine 后端未接入

今天的骨骼动画是逐部件贴图，没有骨骼空间插值，也没有第二条后端；`AnimationHandle` 的返回值在调用点被丢弃
（没有任何地方读它，也就没有"播完了"的回执）。

### 包只认目录，不认 `.zip`，也不校验 `pack.mcmeta`

数据包页（`PackScreen` / `PackSelection`）扫的是 `resourcepacks/` 与 `datapacks/` 下的**顶层目录**。
三件明确不做，做了才有必要改这一页：`.zip` / `.jar` 形式的包；`pack.mcmeta` 的依赖解析与 `pack_format` 校验
（现在只读它的 `description`）；**世界级**数据包目录（`saves/<world>/datapacks`）—— 今天只有 `gameDir/datapacks`。

### 砸花瓶掉的是"直接进卡槽的卡"，不是地上可以捡的卡片实体

用户的原话是「在原地掉落一个植物卡片，可以捡起来种植」，这一轮做成了**直接进卡槽**（`CardSource.receiveCard`）：
本 build 没有卡牌掉落物实体，而一张躺在草坪上捡不起来的卡比直接递给玩家更糟。要做成原版那样得新增
`CardDropEntity`（照 `ResourceDropEntity` 的形状：`collectResource` 的兄弟、渲染走卡面图标、`SaveSystem` 的一条
`entityKind`），`LevelServer.useVase` 里那一次 `receiveCard` 换成 `spawnCardDrop(...)`。

### 花瓶里的卡不会因为"这一关发不了这张卡"而换成别的

`vase_field` 的 `card` 写的是**卡 id**，校验只问"这个 id 能不能解析成一张卡"，不问"这一关的卡池里有没有它"。
今天四只花瓶里的卡都是玩家自己也可能选的普通植物，但这意味着一个关卡作者可以在一关里塞进一张该关根本不给选的卡
—— 玩家拿到它之后能不能种下去取决于 `canPlacePlant`，多半能种。要不要收紧（例如"必须在 `SeedOptions` 的池子里"）
是个设计问题：花瓶本来就有"关卡白送一张你没有的卡"的用法，所以先留着。
