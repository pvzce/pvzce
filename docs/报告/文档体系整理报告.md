## 8. 反思：这套机制现在能保证什么、还差什么

**能保证的（有守门，忘了会红）**

1. 文档里写了不存在的类/方法 → `DocumentedSymbolsTest` 红。
2. 规模统计块与实际不符 → `DocStatsTest` 红（并给了写回开关）。
3. 新增一份文档却没登记台账、或归档卷没被索引链到 → `DocLedgerTest` 红。
4. 主文件的轮次超过 3 份（分卷规则被忘掉）→ `DocLedgerTest` 红（已用注入验证会红）。
5. 改了文档但没重跑测试 → 不可能：`docs/**` 与 `AGENTS.md` 是 `:pvzce-game:test` 的输入。

**还差的（只能提醒，不能判定）**

1. **"行为变了但变更记录没写"没有机器判据**：`doc_check.py` 能看出"改了源码没改文档"，
   但分不清"纯重构"与"真的改了行为"——那需要理解 diff 的语义。这一条留给人和 agent 的判断，
   写进 `AGENTS.md` 的收尾七步。
2. **"as-built 只写现状"没有守门**：`曾经…` 这类句式可以 grep，但 grep 判不出
   "这句是在讲约束还是在讲历史"。这一轮手工改了最长的六处，句式的规则写在 `验证约定.md` §8。
3. **台账的"档位"是声明，不是事实**：把一份活文档标成"冻结"不会让任何人停下，
   只有评审能发现。这是清单类机制的固有上限。

**这一轮自己踩到、值得记住的两条**

- **搬家会丢东西，而且丢得没有声音**：把 `§9` 拆到三处之后，用"原 bullet 的关键词逐个回查"的审计
  才发现 `palette.selected()` 这一处没落地（已补回）。所以搬家式整理的验收判据是
  **"关键词全部还能找到"**，不是"看起来搬完了"。
- **`git status --porcelain` 的中文路径默认是八进制转义**：`tools/doc_check.py` 因此
  "跑成功、什么也没说"，而它本该点名候选文档。判据是输出里看得见中文文件名。
