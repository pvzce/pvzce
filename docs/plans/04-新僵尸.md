### 1.1 火爆辣椒头僵尸的爆炸要遵守哪一条上限

用户的原话是"**僵尸爆炸**的伤害最大只能杀死普通僵尸"。火爆辣椒头僵尸的爆炸属于**僵尸爆炸**，
所以它的 1800 点伤害同样被夹到"普通僵尸的血量"这一档。

**但它的目标是植物。** 按同一句话的字面意思，"僵尸爆炸"的伤害上限说的是对**僵尸**的伤害；
对**植物**的伤害则归"植物爆炸"那一档（上限 = 豌豆射手血量的一半）。
→ 采用后者：**火爆辣椒头僵尸烧植物时，单株最多掉豌豆射手血量的一半（150）**，
这样它不会一键清行，与用户"防止连环炸"的意图一致。写进 `架构变更记录.md` 明确标注。

## 2. ZomBotany 四只的动画怎么来（没有原版 reanim）

> **进度**：全部完成。§1 的六只与 §2 的合成方案、§3 的四个能力（`pvzce:bungee` / `pvzce:zamboni` / `pvzce:zombie_shooter` / `pvzce:death_blast`）都已落地并提交。

原版这 4 只是"普通僵尸的身体 + 植物头"，那份素材不在 `refer/` 里。方案是**合成**：

1. 写一个一次性脚本 `tools/make_zombotany_assets.py`：
   - 读已转换好的 `assets/pvzce/animations/zombie/basic/basic_zombie.json`
     （22 根骨头，头骨名字是 `head`）；
   - 在 `model.bones` 里追加一根 `plant_head`，`parent = "head"`（继承头部的位姿，
     所以 walk/eat/death 全都自动跟随），
     `parts` 指向植物头贴图，`offset` 调成"顶在僵尸头上"（先按 `head` 部件的尺寸估，
     再用探针截图量一次——`验证约定.md` §5：位置问题**放探针量，不推导**）；
   - 每个 clip 里给 `plant_head` 加一条 `visible` 轨，值与 `head` 的 `visible` 一致
     （僵尸头没了，植物头也该没了）；
   - 输出 4 份 JSON（豌豆头/坚果头/机枪头/辣椒头），只有贴图与 `plant_head` 的部件不同。
2. 植物头贴图从已有的植物美术里取：
   `assets/pvzce/textures/entities/plant/attacker/pea_shooter/head.png`（豌豆头）、
   `wall_nut/`（坚果头）、`gatling_pea/`（机枪头）、
   火爆辣椒用 `assets/pvzce/textures/entities/plant/special/jalapeno/`（辣椒本体）。
3. **必须截图核对**：一次冒烟拍一条帧带（4 只僵尸各走一段 + 各咬一口 + 各死一次），
   确认植物头的位置与朝向；位置不对就调 `offset` 再来一次（这是允许的"一次探针"）。

### 2.1 为什么不做"换头"这套通用机制

引擎里没有"给僵尸换一个头骨"的运行时机制，做一套（按 id 覆盖某个骨头的贴图）
会引入一个新的内容维度。**四只僵尸四份动画文件**与本项目既有的
"同一具身体、另一套数值只能写多份定义"（`踩坑清单.md` 第 19 条）是同一个取舍，
而且这 4 只本来就是小游戏专属内容，不值得为它加一层抽象。

## 3. 需要的三个新僵尸能力

### 3.1 `pvzce:zombie_shooter` — 僵尸开火

- 文件：`common/capability/zombie/ZombieShooterCapability.java`。
- 现在**没有任何僵尸能发射弹丸**：`ProjectileEntity` 的 `owner` 是植物。
  需要先看 `LevelServer.spawnProjectile(...)` 能不能接受一个"僵尸方的发射者"
  （`ProjectileRef` 的 `team` / `sourceTeam` 参数），不能就把签名泛化一点。
- 行为：每 `interval` tick 找**本行最靠右的植物**（僵尸往左走，所以是它正前方最近的一株），
  从嘴里发一颗 `pvzce:pea`（伤害与 `ProjectileRef.damage` 由定义给）。
  打不到植物就不发（与 `ShooterCapability.hasTarget` 对称）。
- 动画状态：`EntityAnimations.SHOOT` 已经存在，僵尸美术里没有 `shoot` 片段 →
  会静默回落 `idle`（`踩坑清单.md` 第 2 条）。
  → 合成动画时**每个 clip 都要留一个 `shoot`**：直接复制 `eat` 的张口姿势、
  去掉前后位移即可（吃与射的姿势本来就接近）。

### 3.2 `pvzce:bungee` — 蹦极僵尸

- 文件：`common/capability/zombie/BungeeCapability.java`。
- 状态机（`EntityAnimations` 加三个新状态）：
  1. `bungee_drop` —— 从屏幕上方降到自己那一列的随机一株植物上方（约 90 tick）；
  2. `bungee_grab` —— 抓住植物（约 60 tick），期间**无敌**（原版抓的时候打不死）；
  3. `bungee_rise` —— 带着植物升回屏幕外，然后 `remove()`，被带走的植物 `remove()`。
- 若这一列**没有植物**：原版会随机换一列重试（最多 3 次），仍没有就直接飞走。
- 层：`EntityLayers.AIR`（飞在天上，地面植物打不到它，这与原版一致）。
- 美术：`tools/reanim_to_pvzce.py` 转 `Zombie_bungi.reanim`，`anim_*` 清单要先列全
  （`验证约定.md` §3 第一条）。

### 3.3 `pvzce:zamboni` — 雪橇车僵尸

- 文件：`common/capability/zombie/ZamboniCapability.java`。
- 行为：
  - 每 tick 前进（速度来自定义），**压过**所在格的植物：
    对 `#c:crushable`（普通植物）直接 `remove()`，对地刺也 `remove()`（车压地刺是原版行为）；
  - 走过的格子留下**冰面**：`level.setScene(x, y, pvzce:ice)`——需要一个新场景元素
    `data/pvzce/scene_elements/ice.json`（`surface` 复用既有的、`liquid` 无），
    并把它 `#c:unplantable`（冰面上不能种）；
  - 冰面上的僵尸获得移速加成（复用批次 8 的"结冰地面"那套判定，写成一个共用函数）；
  - 死亡时：`pvzce:zombie_blast_on_death` 的冰版本——周围一圈僵尸被冻住（`FreezeAllCapability`
    的冻结入口），冰面不消失。
- 车体比一格大，**判定宽度**按定义里的 `hitbox` 走（先看 `ZombieDef` 有没有这个字段，
  没有就用 `render_scale` 近似，并把结论写进注释）。

### 3.4 `pvzce:zombie_blast_on_death` — 死亡时炸一次

- 文件：`common/capability/zombie/DeathBlastCapability.java`。
- 参数：`damage`、`radius`、`damage_type`、`particles`、`freeze`（布尔，雪橇车用）。
- 复用 `MutantBlast` 的伤害路径（**含缺陷 3 定下的两档上限**），所以
  `MutantBlast` 的"取上限"逻辑要抽成一个可复用的静态方法，别抄两遍。

## 4. 每种僵尸要写的五处

1. `data/pvzce/zombies/<id>.json` —— 定义（`health` / `speed` / `armor` / `can_swim` /
   `capabilities` / `sounds` / `animation`（借父定义时用）/ `render_scale` / `almanac_order`）。
2. `assets/pvzce/animations/zombie/<族>/<id>.json` —— 转换或合成。
3. `assets/pvzce/textures/entities/zombie/<族>/<id>/` —— 零件贴图。
4. `assets/pvzce/lang/{zh_cn,en_us}.json` —— `zombie.pvzce.<id>` / `.desc`。
5. `data/pvzce/tags/zombie/*.json` —— 变异用的分组标签
   （`#pvzce:mutation_zombotany`、`#pvzce:mutation_airdrop` 等）。

`ZombieDef` 的 `almanac_order`（原版图鉴号）要按原版插进去；
按 `当前项目架构.md` §9，图鉴的僵尸页目前**全列**（没有"见过才进图鉴"），所以新僵尸会自动出现。
