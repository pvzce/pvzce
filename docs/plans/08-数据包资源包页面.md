# 批次 11：数据包 / 资源包查看与管理页面

> 用户答复：**入口放标题页**。
> 现状盘点（动工前）：目录扫描只认**顶层文件夹**、不支持 `.zip`、**没有任何元数据**
> （`pack.mcmeta` 只被编辑器写出、从没被读过）、**没有启用/禁用机制**、
> 客户端**没有热重载入口**（`PvzceClient.run():215-241` 只在启动时跑一次）。

---

## 1. 四件必须新做的基础设施

### 1.1 启用/禁用名单（有持久化）

现在 `PvzceResourceManager.reload()`（`common/resource/PvzceResourceManager.java:45-56`）
无条件把每个目录都加进包栈：

```java
packs.clear();
packs.add(new ClasspathPack(classLoader));
if (gameDir != null) {
    addDirectoryPacks(gameDir.resolve("resourcepacks"));
    addDirectoryPacks(gameDir.resolve("datapacks"));
}
```

→ 新增 `common/resource/PackSelection.java`：一个 `Set<String> disabled`（按**目录名**做键，
与 `DirectoryPack` 的 id 规则一致），可从 `config/pvzce-packs.json` 读写。
`addDirectoryPacks`（`:58-69`）在加之前问一句。

**为什么不用 `PvzceClientConfig`**：那份配置是客户端专属（`config/pvzce-client.toml`），
而资源管理器在**客户端与服务端各建了一份、指向同一个 `gameDir`**
（`PvzceClient.java:215`、`PvzceServer.java:119`）。名单必须两边读同一份文件，
所以它不能住在客户端配置里。→ 独立的 `config/pvzce-packs.json`，两边都读。

### 1.2 枚举"有哪些包"（含被禁用的）

`PvzceResourceManager.packs()`（`:185`）只返回**已加载**的，而 `DirectoryPack` 的
`root` 是私有的、没有 getter。→ 新增
`PvzceResourceManager.scanAvailable(gameDir)`：按 `addDirectoryPacks` 的同一条规则
（顶层目录、字典序）扫出 `resourcepacks/` 与 `datapacks/` 下的全部目录，
返回 `record AvailablePack(String name, Kind kind /* DATAPACK | RESOURCEPACK */, boolean enabled, Path path)`。

**只有一处实现这条规则**：把 `addDirectoryPacks` 里的扫描提出来给两边共用
（`踩坑清单.md` 第 30 条：两个地方都"顺手做一下"，结果不是更保险，是平方）。

### 1.3 元数据（可选但便宜）

`pack.mcmeta` 已经会被编辑器写出来（`EditorScreen.java:479-483`），但没有读者。
→ 扫包时顺手读一下，有 `description` 就显示，没有就显示目录名。
**不做**依赖解析、不做 `pack_format` 校验——那是另一件事，记进 `todo.md`。

### 1.4 热重载

| 侧 | 现在 | 要做 |
|---|---|---|
| 服务端 | `/reload` → `PvzceServer.reloadData(true)`（`:329-356`）：重载资源栈 + 重跑数据加载 + 重载标签 + `SlotResolver.resetReported()` + 推新关卡列表 | **已经完整**，只需要一个包入口 |
| 客户端 | `PvzceClient.run():215-241` 的初始化序列只在启动跑 | 抽出 `PvzceClient.reloadContent()`：`resources.reload()`、`animations.invalidate()`、`fonts.invalidate()`、`LiquidTextures.invalidate()`、`GuiLang.reload(resources)`、`PvzceTags.MANAGER.reload(...)`，**再加** `TextureManager` 与 `SoundEngine` 的缓存失效（这两个今天没有失效入口，要新加一个 `invalidate()`） |

新包 `ReloadPacksC2S`：客户端改完名单 → 写配置文件 →
发这个包 → 服务端 `reloadData(true)` 并回一条 `ServerMessageS2C` →
客户端收到回执后调 `reloadContent()`。

**为什么不各自 reload**：单机是"内存包队列"的两个端点，但**关卡定义与注册表是服务端推给客户端的**
（`LevelListS2C`），所以顺序必须是"服务端先重载、再让客户端重载"，
否则客户端会拿着旧注册表去解析新资源。

## 2. 页面（`client/gui/screens/PackScreen.java`）

### 2.1 入口

`TitleScreen` 的按钮表加第 6 项（与商店一起改，见 `06-商店与增益.md` §1.1）：
`{"开始游戏", "商店", "数据包", "模组列表", "设置", "退出"}`，
`blockHeight` 的乘数相应改成 6。

### 2.2 布局

照 `ModsScreen`（`client/gui/mods/ModsScreen.java:19`，"左列表 + 右详情"）的形状：

- **左侧列表**：`AbstractSelectionList`，每行一个包。行内容：
  `[✓/✗] 名字   (数据包 | 资源包)   N 个文件`；
  顶部两个小节标题"资源包"与"数据包"（同一份列表，用不可点的行分组）；
  最上面一行是**内置包**（`ClasspathPack`，名字 `pvzce`，**不可禁用**，画成灰的）。
- **右侧详情**：选中的包显示
  - 类型与目录名；
  - `pack.mcmeta` 的 `description`（有就显示）；
  - **内容摘要**：`assets/` 与 `data/` 下各注册表的条目数
    （按 `PvzceDataLoader.REGISTRIES` 的目录名分组，
    如 `plants 12`、`zombies 3`、`levels 2`、`textures 40`）；
  - 两个按钮：`启用 / 禁用`、`重新加载`。
- **底部**：一行提示"改动会在重新加载后生效"；一个"返回"。

### 2.3 交互

- 点一行的 `启用/禁用` → 改内存里的名单 → 写 `config/pvzce-packs.json` →
  发 `ReloadPacksC2S` → 等回执 → `reloadContent()` → 重新扫一遍刷新页面。
- 加载失败（目录不是合法包、JSON 解析失败）**不静默**：
  详情区显示一条红色错误行，并复用既有的 `ServerMessageS2C` 通道把服务端的报错带回来。
  这正好治 `冒烟与截图指南.md` §2.1 记的那个坑（"服务端拒绝后只发一条消息，而菜单里没有显示通道"）
  —— **顺手在 `TitleScreen` 加一个消息显示区**（一行文字，收到 `ServerMessageS2C` 时显示 5 秒），
  这样标题页上的任何服务端回执都看得见。

## 4. 验收

| 内容 | 怎么验 |
|---|---|
| 扫包规则只有一处 | 新 `PackSelectionTest`：断言"扫描与加载用的是同一条目录规则"（把两者的结果对拍） |
| 禁用后不加载 | 同上：禁用一个测试包，断言它的资源读不到、注册表里没有它的条目 |
| 持久化 | 同上：写文件 → 新起一个管理器 → 断言名单还在 |
| 热重载 | 扩 `ReloadTest`（已存在）：加载一个会改内容的数据包 → 重载 → 断言注册表变了 |
| 内置包不可禁用 | 单测断言禁用内置包会抛/被拒 |
| 界面 | 一次冒烟：标题页 → 数据包页，确认列表、详情、启用状态、错误行 |
| 服务端消息可见 | 手动触发一次失败加载，确认标题页那行消息出现（这条同时是 `冒烟与截图指南.md` §2.1 那个坑的修复） |
