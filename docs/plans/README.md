## 3. 每一批的固定流程

按 `../验证约定.md`：

1. **盘点**：先列素材与既有实现（动画 `anim_*` 清单、`refer/` 里有什么、有没有现成机制）。
2. **改代码**。
3. **按需验证**：纯函数 → 相关测试类；服务端逻辑 → 全量单测（约 20s）；
   界面 / 渲染 / 动画 → 全量单测 + **一次**截图冒烟（`-Ppvzce.smoke=…`，
   `GRADLE_USER_HOME=$PWD/.gradle-user`，路径落 `.smoke/<主题>/`）。
4. **写文档**：`../架构变更记录.md`（现象 → 定论）、`../todo.md`（做完的删掉）、
   `../当前项目架构.md`（能力或已知差距真的变了才改）、`../踩坑清单.md`（新教训）。
5. **提交**。

硬性约束（会再犯的坑，`../踩坑清单.md` 已记）：

- 一次改动**最多 1 次**冒烟启动；要看多个时刻就用 `captureEvery` 拍帧带。
- 冒烟输出**必须在仓库内**（`.smoke/`），写 `/tmp` 会被静默吞掉。
- Gradle 必须带 `GRADLE_USER_HOME=$PWD/.gradle-user`。
- **文档不要先写**，画面/行为确认通过之后再写。
- **不记用例数**（`验证约定.md` §6）。
- 跑全量红了，先分辨"我改坏的"还是"它本来就这样"——仓库里有 3 条读真实掷骰的偶发用例
  （`GameplaySimulationTest.finishedLevelSaveDoesNotRestorePlants`、
  `MutationManagerTest.aReplacedBarComesBackAsTheReplacedBar`、
  `MutationManagerTest.theApocalypseDoesNotGoOffTwice`）。**这一轮顺手把它们改成确定性断言**。

## 4. 全批次的共同验收标准

一条改动"做完了"的意思是：

- 玩法类：**我自己在测试里模拟玩过**（起真 `LevelServer` + `Connection.createMemoryPair()`，
  跑够 tick，断言结果），不是"编译过了"。
- 动画类：**至少按代码分析过**动画文件与状态机的配对（状态 ↔ clip），
  能截图的一次截图核对（`captureEvery` 拍帧带）。
- 界面类：能用 `Screen.dispatchMouseClicked` + `ClientHarness` 断言的**写单测**，
  只有"画面对不对"才拍图。
- 内容（植物/僵尸/关卡）：`BuiltInLevelsValidateTest` 一类的校验必须过；
  新内容要有"点名每一件"的测试（`踩坑清单.md` 第 31 条：缺省值可能是别人的答案）。
