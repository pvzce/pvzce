int blockHeight = 4 * buttonHeight + 3 * gap;   // → 5 * buttonHeight + 4 * gap

改成 5 项，插入位置**在"开始游戏"之后**：

### 1.2 页面形状

没有就退化成 `SettingsScreen` 那种纯色 + 按钮的简版，并把这件事记进 `todo.md`。

- 左：图标（`SeedCardRenderer` 的 `CardKind` 里有现成的卡面绘制）；
- 中：名字 + 一行说明 + 价格；
- 右：购买按钮 / "已拥有" / "已达上限"。

底部显示钱包（照 `LevelSelectScreen.drawCoinCounter()` `:935-944`），

## 2. 购买协议

### 2.1 新包

`common/network/packet/BuyShopItemC2S.java`：`record BuyShopItemC2S(String itemId, String world)`。
照 `UnlockLevelC2S` 的形状（`PvzceServer.java:1187` 的分发点）。

### 2.2 服务端

`PvzceServer.buyShopItem(player, world, itemId)`：

1. 从 `ShopItems` 查这一件；查不到 → 一条 `ServerMessageS2C`，什么都不做；
2. 已经拥有/达上限 → 拒绝；
3. `profile.coins() < price` → "金币不够"，拒绝；
4. `profile.setCoins(coins - price)` → 应用效果 → `worlds.saveProfile(world, profile)`
   → `connection.send(profilePacket(profile))` → `refreshLevelList()`
   （最后这一步会顺带把 profile 再发一次，与买关卡同一条路径）。

### 2.3 客户端镜像要补的洞

`ClientProfile`（`client/ClientProfile.java:20`）**丢掉了 `unlockedLevels` 与 `unlockedBuffs`**
（`apply(...)` 的签名里没有），所以今天客户端答不出"这个增益我有没有"。
商店页必须知道"已拥有/未拥有"，所以：

- 扩 `ClientProfile.apply(...)` 带上这两个集合，
- 同时更新 `PvzceClientPacketListener.java:153-154` 的调用点，
- 顺带把 `ProfileS2C` 加上"是否拥有钉耙"与"卡槽已买次数"
  （或者更省事：把 `rake` 当成 `unlocked` 集合里的一张卡，
  卡槽次数直接由 `seedSlots` 推出来 —— **选后者**，`ProfileS2C` 不用动）。

## 3. 钉耙（`pvzce:rake`）

### 3.1 形态（用户答复）

> "开局随机一行放一把，一次性。"

- 关卡开始时，在**随机一行**的左端一格（棋盘左外侧半格，与小推车共用锚点）放一把钉耙；
- 该行第一只走到它面前的僵尸被压死，钉耙消失（一次性）；
- 只在该世界**拥有钉耙**时出现（`PlayerProfile` 的一个布尔）。

### 3.2 实现：一个新机制 `pvzce:rake`

照 `MowerMechanic`（`common/level/mechanic/MowerMechanic.java:51`）复制形状：

| 部分 | 做法 |
|---|---|
| 数据 | `api/content/RakeData.java`：`record RakeData(Optional<List<Integer>> rows)`（默认"随机一行"）；`MAP_CODEC` 照 `MowerData.java:50-53` |
| 机制 | `common/level/mechanic/RakeMechanic.java implements LevelMechanic<RakeData>`：`onLevelCreated` 抽一行、`tick` 检测触发、`collectSave`/`applySave` 存"还在不在" |
| 触发 | 该行有 `layer() == GROUND` 的僵尸 `cellX() <= 0.05` 时触发（照 `MowerMechanic.triggered:212-219`） |
| 杀死 | `zombie.damage(100_000, damageType(DAMAGE_MOWER), level)` + `emitEffect(EXPLOSION_POWIE)` |
| 美术 | **`refer/anim/Rake.reanim` 已存在** → 转成 `assets/pvzce/animations/mechanic/rake.json`；`MowerClientMechanic.animationFor:51-57` 会自动按 `kind` 取 `animations/mechanic/<path>.json`，所以**客户端一行都不用改** |
| 音效 | `refer/sounds/` 里找一声；没有就复用 `sfx/ambient/pool_cleaner` |
| 格子锚点 | 与小推车**共用** `MowerMechanic.IDLE_X = -0.5`（`踩坑清单.md` 第 21 条：这个锚点两种车共用，别再发明一个） |

### 3.3 谁把钉耙装上

关卡不写它（否则没买钉耙的玩家也见得到）。做法：
`MowerMechanic` 的兄弟——在 `LevelMechanics.effective()` 之后，
`LevelServer` 构造时如果 `profile` 有钉耙、关卡又**没有**显式声明 `pvzce:rake`，
就补一个默认块（"随机一行"）。

**注意** `LevelMechanicTest.java:91,103,287,299` 断言了 effective 列表，
所以这个"补"不能放进 `LevelMechanics.effective()`（那会让列表变化），
要放在 `LevelServer` 构造里、`effective()` 之后、机制实例化之前，并且**只在真有钉耙时补**。

## 4. 花瓶工具（`pvzce:vase`，4-4 的奖励）

用户要求："阳光零消耗，冷却 10s，使用植物花瓶的材质，可以被放下，放下后可以用手套换位置，
点击后就直接砸掉。选择植物卡，然后点击花瓶后，可以把植物卡放进花瓶里，
砸掉后掉落该植物卡（就像砸花瓶一样）。"
用户补充："在原地掉落一个植物卡片，可以捡起来种植。"

### 4.1 定义

`data/pvzce/tools/vase.json`：

```json
{ "id": "pvzce:vase",
  "use_cost": { "resources": {}, "cooldown": 0 },
  "cooldown": 600,
  "targets": ["plant"],
  "effect": "pvzce:vase",
  "uses": -1,
  "texture": "pvzce:textures/gui/cards/flower_pot",
  "animation_dir": "tool" }
```

（"使用植物花瓶的材质"= 卡面用 `flower_pot` 的贴图；`animation_dir` 指 `tool` 族，
需要 `assets/pvzce/animations/tool/vase.json` —— 如果找不到合适的水壶式动画，
就复用 `flower_pot` 的植物动画做一次"举起/放下"。）

### 4.2 两条使用路径（同一个 effect 字符串里的分支）

`LevelServer.applyToolEffect` 加 `case "pvzce:vase" ->`：

1. **点到空格子** → 放一个花瓶（`level.setScene(x, y, pvzce:vase)`），
   走 `setScene` 的既有客户端同步；花瓶格因此自动变成 `#c:unplantable`。
2. **点到已有花瓶** → **砸掉**：花瓶格恢复成原来的地形，
   播放 `sfx/effect/vase_breaking`（素材已存在但从未被引用，见盘点），
   如果里面有卡就把它交回卡槽（`CardSource.receiveCard`：普通卡组是往条上加一张，
   传送带是**放到带子上**——带子的卡槽是它自己队列的投影，塞在旁边的卡下一次重建就没了）。
   **"把卡塞进花瓶"不在这条路上**：服务端不知道客户端手上选了什么，
   所以那一条是落卡报文（`PlacePlantC2S`）里的分支，见 `05-关卡与迷雾.md` §3.3。
3. **手套换位置**（已实现）：花瓶是场景元素不是实体，所以手套（`movePlant`）本来不认识它。
   加了 `carriedVaseFrom`（打包的出发格）+ `carriedVaseCard`（里面那张卡），
   与既有的 `carriedPlantId` 同一套形状：**拿起时不改任何格子**（于是超时放弃什么都不用还原），
   放下时才把旧格复位、新格写入，卡跟着走。放到自己那一格是空操作 ——
   这一条必须在"这格已经有东西"之前判，因为它自己那一格当然是有东西的。

### 4.3 新东西汇总

| 新东西 | 位置 |
|---|---|
| 场景元素 | `data/pvzce/scene_elements/vase.json` + `vase_full.json`，都在 `#c:unplantable` 里 |
| 机制 | `common/level/mechanic/VaseFieldMechanic.java`（`pvzce:vase_field`，只负责开场摆格）；**内容表在 `LevelServer.vaseContents`**，随存档的 `VaseContents` 分区 |
| 发卡 | `CardSource.receiveCard(cardId)`（默认 `level.addCardToBar`，传送带覆写成"放到带子上"） |
| 工具 | `data/pvzce/tools/vase.json` + `data/pvzce/slots/vase.json` |
| 语言键 | `tool.pvzce.vase` / `.desc` |

## 5. 三个新增益

增益接口（`api/content/LevelBuff.java`）现在只有 4 个成员，本批要加 3 个钩子：

| 增益 | id | 新钩子 | 消费者 |
|---|---|---|---|
| 水草蔓延 | `pvzce:kelp_spread` | `default boolean spreadsKelp() { return false; }` | `LevelServer.spawnPlant` 成功后调 `KelpSpread.spreadFrom(...)`（批次 6 §2.2 抽出的纯函数） |
| 迷雾退缩 | `pvzce:fog_retreat` | `default float fogRetreat() { return 0F; }` | `FogMechanic`（批次 2 §1.4） |
| 阳光铲 I | `pvzce:sun_shovel` | `default float shovelRefundFraction() { return 0F; }`（值 `0.20F`） | `LevelServer.applyToolEffect` 的 `"pvzce:shovel"` 分支 |

**阳光铲的判定**（用户答复："按这一局的卡是不是免费发的判定"）：
铲掉一株植物时，如果这一局 `level.cardSource().dealsItsOwnCards()` 为真
（`BeltCardSource` 与变异传送带都是），**不返还**；否则返还
`round(植物阳光价 × 0.20)`，`plantPlayer.grantResource(SUN, n)` 并飘一个"阳光 +N"的提示。

- 植物阳光价从 `PlantDef.cost().resources().get(PvzceIds.SUN)` 读（**不是**卡槽上的价，
  因为卡槽价可能被关卡或变异改过；用定义价才是"这株植物本身值多少"）。
- `BeltCardSource` 之外的**固定卡组关卡**（`slots` 写满的关卡）照样返——
  玩家的卡也是"买"来的（选卡时花了阳光），这与"传送带免费"是两回事。

三个增益的图标照 `todo.md` 第 1 条的规范放
`assets/pvzce/textures/gui/buff/<id>.png`（新目录），
语言键 `level_buff.pvzce.<id>` 加进两个 lang 文件。
