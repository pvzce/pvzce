# 架构变更记录

> 记历史：**现象 → 定论**。现状看 `当前项目架构.md`，取舍看 `决策记录.md`，教训看 `踩坑清单.md`。
> 写法：只记**最终落地的做法**；被回退的尝试最多留一行（"曾试 X，已回退，原因 Y"），
> 不给每个错误写长文。写之前先确认行为通过 —— 回退时这份记录要重写第二遍。

> **结构**：§1 是**定论索引**（一条一行，链到归档全文），§2 是**最近 3 轮全文**。
> 更早的每一轮在 `架构变更记录/` 目录里按 `YYYY-MM-<轮名>.md` 分卷（冻结不改）。
> 归档只搬家不改写：分卷前的每一节都在，找一条旧定论用 §1 的索引，或直接在该目录里搜索。
> 分卷规则：主文件留最近 3 轮，其余每轮一份；一条定论只在一个归档文件里，主文件不重复正文。
> 文件名不带空格（`/` 写成 `、`），这样链接可以直接写中文路径。

# 触控支持：单指点击与滑动，六处"滚动区域"声明让滑动接管滚轮

> 用户要求："只做一个简单的支持：Linux X11 和 Windows……目前只需要单指点击逻辑和滑动这两个逻辑，
> 并且允许使用启动参数关闭触控支持。"（五条问答见 `决策记录.md` §1）

## 现象与根因

- **点击与拖动本来就能用，缺的是"滑动 = 滚轮"**：Windows 把单指事件提升成鼠标消息、X11/XInput2 对首个
  触点做指针模拟，所以这轮没有任何原生代码（不用 FFM、不用升 Java、不用动 loader）；而滑动不能天真地合成 ——
  点击是**按下即发**（`PvzceWindow` 只收 `GLFW_PRESS`），全仓库没有位移阈值，滑动会在起点**多触发一次点击**：
  商店行按下就是买、玩家选择器按下就是切换玩家、卡条按下就是选卡。
- **够不到的东西是主线级的**：默认画质（1280x720 auto → GUI 427×240）下卡条可视宽 120、卡距 44，只看得见
  2~3 张，而 `DEFAULT_SEED_SLOTS = 8`；滚轮是唯一的滚动手段，所以触控下大部分卡**点不到**。选卡页卡池、
  `AbstractSelectionList`（11 个宿主）同理。

## 定论

1. **手势只接管"按下点落在滚动区域里"的那一次按下**（`client/input/PointerGesture`）：区域内把点击留到松手，
   位移超过 `TAP_SLOP`（8 GUI px）就只发滚动、不发点击；区域之外一个字不变 —— 棋盘的按住扫阳光、
   拖卡到格子、小推车按住 500 ms 放车都依赖"按下即发 + 每帧拖动"，因此全部照旧。
2. **滚动区域是声明出来的，且必须复用滚轮处理器已有的那个矩形**（`ScrollRegion`）：`AbstractSelectionList`
   （纵向，一步 = `entryHeight`）、卡条（横向，一步 = `cardWidth + cardGap`）、选卡页卡池、关卡网格、图鉴、
   控制台。判据只有一份：`InGameScreen.cardBarScrollsAt` / `ChooseSeedsScreen.poolScrollsAt` /
   `LevelSelectScreen.gridTurnsPageAt` 同时喂滚轮与手势，所以"能滚"和"滑得动"不会分家。
3. **方向由区域自己的版式决定**（`ScrollRegion.Swipe`）：`AbstractSelectionList` 的行是自下而上排的，
   镜像滚轮即自然；卡池与关卡网格从上往下排，跟手；横向两者等价。
4. **滚轮下沉带坐标**（`PointerGesture.ScrollSink` → `PvzceClient.dispatchGuiScrolled`）：下游要命中判定
   （`SeedCardBar.scroll` 的 `contains`），而"从实时鼠标位置取坐标"只在帧循环驱动时成立。
5. **对话框替子控件回答**：`PlayerPickerDialog` / `CardPoolEditorDialog` / 编辑器各页的列表不在
   `Screen.widgets` 里，`Dialog.scrollRegionAt` 少这一步它们就滑不动。
6. **`Slider` 声明 `claimsDrag()`**：压在列表上的滑条不会被抢走"按下-拖动-松手"三连。
7. **开关是 `-Dpvzce.touch=false`**（默认开）：系统级的鼠标提升关不掉，这个开关关的是我们这层。
8. **验证**：`PointerGestureTest`（12 例）+ `ScreenScrollRegionTest`（4 例）；冒烟新增 `pvzce.smokeSwipe`
   （`smokeDragTo` 直接调 `dispatchMouseDragged`，绕过事件循环，验不了手势路径）。
   一次启动拍四帧（`combat_test`，14 槽）：第 90 帧卡条正好位移一张卡**且没有任何卡被高亮**
   （选中态是 `SeedCardRenderer` 的 `(1,1,0.2)×0.35` 黄罩，量化后蓝色通道 108 未降），第 120 帧那次点击
   让卡片变黄（蓝色通道降到 70）—— 滑动不误点与点击仍生效在同一卷胶片里。

# 修回被删掉的标题页点击处理（托盘与玩家木牌都点不动）

> 用户报："然后这两个按钮都点不进去了"（指上一轮搬到左下角托盘的商店与数据包）。

## 现象与根因

- **现象**：左下角两块木牌**画得好、悬停也亮**（悬停提示会弹出），点下去毫无反应；同一个屏的玩家木牌
  也点不动了。
- **根因**：`TitleScreen.onMouseClicked` 在那次改版面时**被删掉了** —— 用一段"按标记取两段再拼"的
  脚本删方法，把夹在两者之间的它一起切掉了。它编译得过（`Screen.onMouseClicked` 有默认空实现），
  而三层验证全都没拦住：纯函数断言验的是几何、截图只看得见绘制（悬停高亮走 `renderTray`，
  与点击无关）、冒烟钩子 `pvzce.smokeTray` 自己调 `dispatchMouseClicked`，**绕过了**屏幕自己的处理函数。
- **顺带查出的第二个缺陷**：冒烟 `pvzce.smokeClick` 走的是"假坐标"那条路，它多转了一次坐标
  （`currentScreen().mouseClicked(rawX, rawY, ...)` 内部又转一次），于是点击落点被除以两遍 GUI 缩放。
  一直没被发现，是因为按目标瞄准的钩子（`smokeClickLabel` / `smokeTray`）走的是 `deliverGuiClick`，
  那条路没有这个 bug。这次顺手把它改成"warp 光标 + 走真实分发"，与真事件循环逐行一致。

## 定论

1. 恢复 `TitleScreen.onMouseClicked`（玩家木牌 → 玩家选择器，托盘格 0/1 → 商店 / 数据包），
   并在它的文档里写明"这个方法丢过一次，症状是点不动而画得出"。
2. `PvzceClient.deliverRawClick/Drag/Release` 去掉自己那次换算，改成
   `warpCursor(raw) + dispatchMouseClicked/Dragged/Released()` —— 与 `pollInput` 走同两条函数。
3. 新增 `MenuProfileFlowTest.clickingACornerCellOpensItsPage`：走 `menu.dispatchMouseClicked(...)`
   再看屏幕换没换（**已验证**：把 `onMouseClicked` 临时删掉，这条用例会红）。
4. 约定写进 `验证约定.md` §7.1：可点区域必须从真实入口验一遍，且至少一条断言经过界面自己的处理函数；
   "悬停亮"只证明绘制路径。

# 商店钱包的"必须先进一次关卡"、左下角托盘的尺寸与标题页排版

> 用户第二批反馈："左下角按钮太小了，你在测试 UI 合不合适的时候，最好按照 1080p 2x UI 来测试，
> 这是大部分玩家的环境（记得写入文档便于之后的工作）"；"商店有 bug，必须要点击一次开始游戏，
> 再回到主菜单，点进去商店才显示金币数量，否则显示的就是 0（可能是因为存档还没有被加载到内存的缘故？）"

## 钱包显示 0：档案只在关卡列表那条路上来

- **现象**：全新会话里直接从标题页进商店，钱包写 **0 金币**；开一局、退回主菜单、再进商店就对了。
- **根因**（与用户的猜测一致，只是"存档"的落点更具体）：客户端在**每次换世界**时都会
  `profile.reset()`（这是有意的：新世界的列表还在加载时不能显示上一个世界的钱），而档案
  （钱包 / 卡槽 / 解锁）**只**由 `ProfileS2C` 填进来，那个包只有 `sendLevelList` 会发 ——
  商店却可以在**从不打开关卡列表**的情况下进去（标题页左下角的托盘直达）。
- **定论**：新增 `RequestProfileC2S(worldName)`（协议 34 → **35**，C2S id 27）。标题页那两个格子在
  `openScreen` 之前先 `client.requestProfile()`；`PvzceClient.profileLoaded` 在换世界时清掉、
  由到达的快照置位（**发送时也置位**，否则两次点击就是两个包），所以"问一次"是幂等的，
  而先开过关卡列表的客户端**一次都不会问**。服务端沿用 `menuWorld()` 与 `profilePacket`，
  与关卡列表那条路回答的是同一个世界。
- **判据**：`MenuProfileFlowTest.theServerAnswersWithTheWorldsWallet`（真起服务端，内存连接，
  世界 `aaa` 的存档里 1234 金币 → 收到的 `ProfileS2C.coins == 1234`）、
  `…theRequestIsNotRepeatedOnceTheProfileHasArrived`（两次问只发一个包；快照到达后再问不发；
  换世界后可以再问）。

## 左下角托盘：尺寸改成随菜单按钮与窗口算

- **现象**：1080p + 2x UI 下（GUI 960x540）菜单按钮 68 单位高，托盘却还是固定的 22 单位图标，
  像个涂鸦；而按"随按钮放大"改之后，它在默认窗口又压到了玩家木牌上 —— 木牌的点击判定在托盘之前，
  于是点商店格子弹出的是**玩家选择器**。
- **定论**：托盘几何抽成一个纯函数 `TitleScreen.TrayLayout.forCorner(buttonHeight, availableWidth)`，
  两个约束取小者：
  - **纵向**：一格 = 1.5 个菜单按钮高（图标因此始终与旁边的按钮同量级）；
  - **横向**：两格 + 留白必须放得进**窗口左缘到菜单列左缘**之间（`menuGap`），
    因为菜单列居中且 280 宽 —— 默认窗口只有 65 单位，这正是"图标 + 文字"当年放不下的原因。
  - 图标下的木牌按**图标宽度**取，不按格子高度取：短格子里"牌子占三分之一高度"会把图标压成一条
    （GUI 427x240 下只剩 8 单位）。
  - 托盘与菜单列**共处同一条带**（都锚在底边）。曾经按玩家木牌的下沿定位，而木牌锚在**顶边**，
    1080p 下托盘被摆到屏幕外 —— 截图上是"左下角什么都没有"。
- **判据**：`TitleScreenTrayTest`（三档窗口尺寸：托盘在窗口内、不越菜单列、图标 ≥ 按钮的 40% 且 ≤ 110%）。
- **冒烟**：新增 `pvzce.smokeTray=<格>@<帧>`（坐标由 `TitleScreen.trayCell` 给，与命中判定同一处）
  与 `pvzce.smokeCoins=<n>`（走 `/profile coins` 真命令路径，等关卡列表回来再发）。

## 验界面的参考环境写进文档

- **1080p + `gui_scale=2`（GUI 960x540）**，写进 `冒烟与截图指南.md` §2.3 与 `决策记录.md`。
  窗口尺寸与 GUI 缩放只能写在 `config/pvzce-client.toml`，所以要事先把那份 toml 放进占位游戏目录。
  默认的 1280x720 只有参考环境**六分之一**的面积，不能当"够不够大"的判据 —— 左下角托盘连着三版
  都是"在 1280x720 看着挺好"放过去的。

- `PacketProtocolTest` 的样本集与黄金字节流跟着新增的包更新（`RequestProfileC2S:1b05776f726c64`，
  `LevelInitS2C` 里的协议号 0x22 → 0x23）。
