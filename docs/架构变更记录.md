# 架构变更记录

> 记历史：**现象 → 定论**。现状看 `当前项目架构.md`，取舍看 `决策记录.md`，教训看 `踩坑清单.md`。
> 写法：只记**最终落地的做法**；被回退的尝试最多留一行（"曾试 X，已回退，原因 Y"），
> 不给每个错误写长文。写之前先确认行为通过 —— 回退时这份记录要重写第二遍。

> **结构**：§1 是**定论索引**（一条一行，链到归档全文），§2 是**最近 3 轮全文**。
> 更早的每一轮在 `架构变更记录/` 目录里按 `YYYY-MM-<轮名>.md` 分卷（冻结不改）。
> 归档只搬家不改写：分卷前的每一节都在，找一条旧定论用 §1 的索引，或直接在该目录里搜索。
> 分卷规则：主文件留最近 3 轮，其余每轮一份；一条定论只在一个归档文件里，主文件不重复正文。
> 文件名不带空格（`/` 写成 `、`），这样链接可以直接写中文路径。

# Wayland 触控：自己接 libwayland 读 wl_touch（FFM），顺带升到 Java 25

> 用户报："在 Wayland 下发现，完全无法点击。"；拍板："必须做 wayland 支持，因为新版本 ubuntu 移除了 XOrg。
> 你可以进行升级 java 版本和引入 FFM API。"

## 现象与根因

- **Linux 上"手指 = 鼠标"不是自动的**：Windows 由系统把主指针提升成鼠标消息；X11/Xorg 由 XInput2 为首个触点
  做指针模拟（GLFW 的 X11 后端只选核心事件，恰好收到那对模拟事件）；**Wayland 什么都不做** —— GLFW 3.4 的
  Wayland 后端源码里一处 touch 处理都没有（上游 issue #2876 / #7501 同现象），所以 Wayland 会话下（以及
  Xwayland 下）手指点击完全没有事件。上一轮那句"X11/XInput2 对首个触点做指针模拟"写得像普适事实，是错的。
- 用户机器上另一处独立现象：探针只建窗口不画东西 → **屏幕上什么都没有，Dock 里只有图标**。Wayland 的
  surface 没有 attach buffer 就是不可见的，这不是"窗口没建出来"。

## 定论

1. **不 fork GLFW，自己接 libwayland**：拿 `GLFWNativeWayland.glfwGetWaylandDisplay()/glfwGetWaylandWindow()`
   的句柄，用 **FFM（Java 25）** 走 `wl_proxy_marshal_array_flags` / `wl_proxy_add_listener` 绑 `wl_seat`
   → 读能力位 → `get_touch` → 监听。GLFW 的 Wayland 事件循环用的是默认队列
   （`wl_display_prepare_read/read_events/dispatch_pending`，无自定义 queue），所以我们建的对象会被
   `glfwPollEvents()` 一起派发，**不需要额外线程**，代价是几百行 FFM 而不是每平台一份打过补丁的原生库。
2. **平台偏好反转**：Wayland 会话（`WAYLAND_DISPLAY` 有值）优先**原生 Wayland**，`-Dpvzce.platform=x11` 仍可强制；
   否则"新 Ubuntu 上能玩、装了 Xwayland 的 Ubuntu 上不能"这种随发行版漂移的行为无法解释。启动时打一行
   `GLFW platform = …` 便于排查。
3. **触摸翻译成鼠标流，而不是新机制**：`client/input/TouchTranslator` 只跟第一根手指，把它变成
   `press/drag/release`（外加把触点记为指针位置，让种植幽灵跟着手指）；下游就是上一轮的 `PointerGesture`
   与帧循环那两条路，所以六处滚动区、按住扫阳光、拖卡到格子、小推车长按全部自动可用。
   `cancel`（合成器随时能收走触摸）按"松手"处理，不会让游戏一直抓着一张卡。
4. **失败永不致命**：没有 libwayland、seat 没有触摸、任何协议意外 → 一行日志 + 触摸层关闭，游戏照常能用鼠标键盘。
   `-Dpvzce.touch=false` 仍然一键关掉整条触控路径。
5. **Java 25**：FFM 在 22 定稿，且自 24 起每个入口都是 restricted method，需要
   `--enable-native-access=ALL-UNNAMED`（`run`/`test` 已在构建里带上，外部启动脚本也要带）。loader 侧无阻塞：
   ASM 9.10.1 认识 V25（还有 V26/V27）、Mixin 支持到 `JAVA_25`、fork 自己声明的上限就是 `JAVA_25`。
   `gradle.properties` 的 `java_version` 与 root build.gradle 里手写的 `options.release` 合成了一处。
6. **验证三件套**（这次没有靠"读代码觉得对"）：① 独立探针在用户真机上证明 seat 有触摸能力、`wl_touch`
   事件真的到达、坐标是 surface-local 逻辑像素；② 原生 Wayland 冒烟：`GLFW platform = 393219` +

## 用户报的后续两件事（同一轮修完）

### 全屏下窗口"压根不出现"

- **现象**：窗口模式（`fullscreen=false`）一切正常、触控也能用；全屏时窗口完全看不到，而且不在别的显示器上。
- **根因**：Wayland 下 GLFW 的 xdg_toplevel 是**在 `glfwShowWindow` 里才创建**的
  （`_glfwCreateWindowWayland` 只在 `window->monitor || wndconfig->visible` 时建；我们 `VISIBLE=FALSE`
  且创建时不带 monitor），而全屏请求在 `acquireMonitor` 里被 `else if (window->wl.xdg.toplevel)` 挡着。
  旧顺序"先 `setFullscreen(true)`、再 show"于是**把请求丢掉了**：GLFW 内部状态已记成全屏、idle inhibitor
  也开了，游戏按显示器尺寸渲染，而合成器从没被告知要全屏。"窗口压根不出现"就是这个状态的样子。
- **定论**：`PvzceWindow` 的构造顺序改成**先 show、再进全屏**（X11 无害：那边窗口一创建就存在）。
  启动行补报主显示器模式，下一次这类报告第一眼就能确认"全屏落在哪块屏、多大"。

### 用户报的第三件事：按钮亮着但点不动（坐标空间混用）

- **现象**："点击按钮，按钮显示被压下去了，但根本点不动，感觉就像只是把鼠标移上去了一样"；连「退出」也点不动
  （窗口不关，用鼠标排除后确认是触摸这条链）。
- **根因**：`wl_touch` 给的是 **surface 像素**（= 光标回调那一套坐标），而 `PointerGesture` 的滚动区判定与
  `Screen.dispatchMouseClicked` 要的是 **GUI 逻辑像素**。接线时把像素原样喂给了两者 —— 指针位置
  （`setPointerPosition`）恰好要像素，所以**悬停是对的、按钮会亮**（`Button.render` 里 `active && hovered`
  就是"按下"贴图），而点击落在"GUI(753,365)"这种 UI 从未听说过的地方（那一屏的 GUI 空间只有 427×240），
  于是什么都不会发生。`guiScale = 1` 时两个空间恰好相等，所以只有缩放 UI 才暴露。
- **为什么绿的冒烟没挡住**：`deliverGuiTouch` 这个钩子收的是 **GUI 坐标**、直接喂翻译器，**绕过了真实设备
  经过的那次换算**——它验的是一条真机上不存在的路径。
- **定论**：换算收在唯一入口 `PvzceClient.touchSink`（native 像素进来就换一次，指针位置留像素、
  手势与点击拿 GUI），`TouchTranslator` 的契约写明"逻辑 GUI 像素"；**冒烟钩子改走同一个 sink**
  （先把 GUI 换算成屏幕坐标再喂），从此截图验的就是真路径。验证：触摸点「退出」窗口直接关闭、
  点「开始游戏」玩家选择器打开。

# 触控支持：单指点击与滑动，六处"滚动区域"声明让滑动接管滚轮

> 用户要求："只做一个简单的支持：Linux X11 和 Windows……目前只需要单指点击逻辑和滑动这两个逻辑，
> 并且允许使用启动参数关闭触控支持。"（五条问答见 `决策记录.md` §1）

## 现象与根因

- **点击与拖动本来就能用，缺的是"滑动 = 滚轮"**：Windows 把单指事件提升成鼠标消息、X11/XInput2 对首个
  触点做指针模拟，所以这轮没有任何原生代码（不用 FFM、不用升 Java、不用动 loader）；而滑动不能天真地合成 ——
  点击是**按下即发**（`PvzceWindow` 只收 `GLFW_PRESS`），全仓库没有位移阈值，滑动会在起点**多触发一次点击**：
  商店行按下就是买、玩家选择器按下就是切换玩家、卡条按下就是选卡。
- **够不到的东西是主线级的**：默认画质（1280x720 auto → GUI 427×240）下卡条可视宽 120、卡距 44，只看得见
  2~3 张，而 `DEFAULT_SEED_SLOTS = 8`；滚轮是唯一的滚动手段，所以触控下大部分卡**点不到**。选卡页卡池、
  `AbstractSelectionList`（11 个宿主）同理。

## 定论

1. **手势只接管"按下点落在滚动区域里"的那一次按下**（`client/input/PointerGesture`）：区域内把点击留到松手，
   位移超过 `TAP_SLOP`（8 GUI px）就只发滚动、不发点击；区域之外一个字不变 —— 棋盘的按住扫阳光、
   拖卡到格子、小推车按住 500 ms 放车都依赖"按下即发 + 每帧拖动"，因此全部照旧。
2. **滚动区域是声明出来的，且必须复用滚轮处理器已有的那个矩形**（`ScrollRegion`）：`AbstractSelectionList`
   （纵向，一步 = `entryHeight`）、卡条（横向，一步 = `cardWidth + cardGap`）、选卡页卡池、关卡网格、图鉴、
   控制台。判据只有一份：`InGameScreen.cardBarScrollsAt` / `ChooseSeedsScreen.poolScrollsAt` /
   `LevelSelectScreen.gridTurnsPageAt` 同时喂滚轮与手势，所以"能滚"和"滑得动"不会分家。
3. **方向由区域自己的版式决定**（`ScrollRegion.Swipe`）：`AbstractSelectionList` 的行是自下而上排的，
   镜像滚轮即自然；卡池与关卡网格从上往下排，跟手；横向两者等价。
4. **滚轮下沉带坐标**（`PointerGesture.ScrollSink` → `PvzceClient.dispatchGuiScrolled`）：下游要命中判定
   （`SeedCardBar.scroll` 的 `contains`），而"从实时鼠标位置取坐标"只在帧循环驱动时成立。
5. **对话框替子控件回答**：`PlayerPickerDialog` / `CardPoolEditorDialog` / 编辑器各页的列表不在
   `Screen.widgets` 里，`Dialog.scrollRegionAt` 少这一步它们就滑不动。
6. **`Slider` 声明 `claimsDrag()`**：压在列表上的滑条不会被抢走"按下-拖动-松手"三连。
7. **开关是 `-Dpvzce.touch=false`**（默认开）：系统级的鼠标提升关不掉，这个开关关的是我们这层。
8. **验证**：`PointerGestureTest`（12 例）+ `ScreenScrollRegionTest`（4 例）；冒烟新增 `pvzce.smokeSwipe`
   （`smokeDragTo` 直接调 `dispatchMouseDragged`，绕过事件循环，验不了手势路径）。
   一次启动拍四帧（`combat_test`，14 槽）：第 90 帧卡条正好位移一张卡**且没有任何卡被高亮**
   （选中态是 `SeedCardRenderer` 的 `(1,1,0.2)×0.35` 黄罩，量化后蓝色通道 108 未降），第 120 帧那次点击
   让卡片变黄（蓝色通道降到 70）—— 滑动不误点与点击仍生效在同一卷胶片里。

# 修回被删掉的标题页点击处理（托盘与玩家木牌都点不动）

> 用户报："然后这两个按钮都点不进去了"（指上一轮搬到左下角托盘的商店与数据包）。

## 现象与根因

- **现象**：左下角两块木牌**画得好、悬停也亮**（悬停提示会弹出），点下去毫无反应；同一个屏的玩家木牌
  也点不动了。
- **根因**：`TitleScreen.onMouseClicked` 在那次改版面时**被删掉了** —— 用一段"按标记取两段再拼"的
  脚本删方法，把夹在两者之间的它一起切掉了。它编译得过（`Screen.onMouseClicked` 有默认空实现），
  而三层验证全都没拦住：纯函数断言验的是几何、截图只看得见绘制（悬停高亮走 `renderTray`，
  与点击无关）、冒烟钩子 `pvzce.smokeTray` 自己调 `dispatchMouseClicked`，**绕过了**屏幕自己的处理函数。
- **顺带查出的第二个缺陷**：冒烟 `pvzce.smokeClick` 走的是"假坐标"那条路，它多转了一次坐标
  （`currentScreen().mouseClicked(rawX, rawY, ...)` 内部又转一次），于是点击落点被除以两遍 GUI 缩放。
  一直没被发现，是因为按目标瞄准的钩子（`smokeClickLabel` / `smokeTray`）走的是 `deliverGuiClick`，
  那条路没有这个 bug。这次顺手把它改成"warp 光标 + 走真实分发"，与真事件循环逐行一致。

## 定论

1. 恢复 `TitleScreen.onMouseClicked`（玩家木牌 → 玩家选择器，托盘格 0/1 → 商店 / 数据包），
   并在它的文档里写明"这个方法丢过一次，症状是点不动而画得出"。
2. `PvzceClient.deliverRawClick/Drag/Release` 去掉自己那次换算，改成
   `warpCursor(raw) + dispatchMouseClicked/Dragged/Released()` —— 与 `pollInput` 走同两条函数。
3. 新增 `MenuProfileFlowTest.clickingACornerCellOpensItsPage`：走 `menu.dispatchMouseClicked(...)`
   再看屏幕换没换（**已验证**：把 `onMouseClicked` 临时删掉，这条用例会红）。
4. 约定写进 `验证约定.md` §7.1：可点区域必须从真实入口验一遍，且至少一条断言经过界面自己的处理函数；
   "悬停亮"只证明绘制路径。
