# 架构变更记录

> 记历史：**现象 → 定论**。现状看 `当前项目架构.md`，取舍看 `决策记录.md`，教训看 `踩坑清单.md`。
> 写法：只记**最终落地的做法**；被回退的尝试最多留一行（"曾试 X，已回退，原因 Y"），
> 不给每个错误写长文。写之前先确认行为通过 —— 回退时这份记录要重写第二遍。

> **结构**：§1 是**定论索引**（一条一行，链到归档全文），§2 是**最近 3 轮全文**。
> 更早的每一轮在 `架构变更记录/` 目录里按 `YYYY-MM-<轮名>.md` 分卷（冻结不改）。
> 归档只搬家不改写：分卷前的每一节都在，找一条旧定论用 §1 的索引，或直接在该目录里搜索。
> 分卷规则：主文件留最近 3 轮，其余每轮一份；一条定论只在一个归档文件里，主文件不重复正文。
> 文件名不带空格（`/` 写成 `、`），这样链接可以直接写中文路径。

## W1 · 钉耙不是工具，而是一把原版的钉耙

> 这一轮是十项长线功能的第一个工作流（W1），改动最小、依赖最少、能立刻验。
> 用户报的是"钉耙不应该作为工具"，但顺着它查下去发现**四个**独立的错，每一个都能追到
> "某一层说错了"。

### 现象与根因

1. **钉耙是一张点了没反应的死卡** —— `data/pvzce/tools/rake.json` 与 `slots/rake.json` 把它注册成
   工具卡，效果 id 写的是 `pvzce:rake_placed`，而 `LevelServer.applyToolEffect` 的 `switch` 里
   **没有这一条**（落到 `default -> false`）。买了钉耙的玩家因此多出一张永远点不动的卡：
   服务端不扣费、不进冷却、也不回一句话，客户端只会重发一次 `SlotSyncS2C`。
2. **它同时在棋盘上存在（另一半是对的）** —— `RakeMechanic` 早就是完整的：开局在一条随机车道铺一把、
   第一只走到它那格的地面僵尸死、用过即消失、进存档。两半靠 `PvzceIds.RAKE` 一个字符串连着，
   于是"钉耙"这件事在代码里有两个身份。
3. **伤害写的是 `100_000`** —— 注释还写着"读小推车的数"，于是巨人僵尸也一钉死，与"钉耙是一条车道
   一次性的先手"这个定位矛盾。
4. **买来的钉耙客户端根本画不出来** —— 这是最隐蔽的一条：`LevelServer.payloadFor(def, seeds)` 发的是
   `LevelMechanics.payloads(def)`，也就是**关卡文件声明的**机制表；而玩家那把钉耙只存在于
   `LevelServer.mechanics()`（构造时由 `withPlayerMechanics` 加进去的解析结果）。客户端
   `ClientMechanics.worldOverlays` 遍历的是 `level.mechanicIds()`（= 下发的那张表），所以 overlay
   从来没有被创建过 —— **僵尸死得无声无息，草坪上一根草都没动**。没有关卡声明过 `pvzce:rake`，
   所以这条路一次都没被走过。

### 定论

- **钉耙不是卡**：删掉 `tools/rake.json` 与 `slots/rake.json`。`SlotResolver.resolve(pvzce:rake)`
  从此为空，选卡池再也不可能把它端出来。`ShopItems.Item.Kind.TOOL` 改名 `UNLOCK`（它本来就只是
  `profile.unlock(id)`），并新增 `STANDALONE_UNLOCKS` = "买了但不是一张卡的解锁"，只放钉耙。
  `ShopTest.theRakeIsNotACard` 把这个"不存在"钉成断言 —— 这是最容易被数据长回来的东西。
- **它站在从右数第 2 列**：`RakeMechanic.COLUMNS_FROM_RIGHT = 2`，9 列草坪即第 7 列，
  触发线就是那一格的中心。**位置只有一处**：客户端画的是服务端发来的 `x`，服务端算的是
  `columnX(level)`。它不再是"小推车锚点"的别名 —— 那个共用常量已经解开。
- **它值 1800 点**：普通/路障/铁桶/橄榄球都死（`pvzce:mower` 伤害类型 = 无视护甲 + 会分尸，
  与原版"踩上去头会掉"一致），巨人 3000 血扛得住。一条数值窗口，不是特例。
- **它只在草地上**：`Rig.place` 把候选车道里是水的那些剔掉 —— "哪几行是水"是棋盘的事实，
  `RakeData.rowsFor` 是文件的事实，两者不在一个地方回答。
- **它替玩家决定第一只僵尸走哪条道**：`WaveDirector.Host.forcedOpeningLane(zombieId)`（默认 -1）
  由 `LevelServer` 用"钉耙还在就报它的行"回答，导演只问**本关第一只**。这一条是"原版保证"
  的直接翻译：一把第一只僵尸永远走不到的钉耙，是一次什么都没做的购买。强制是**建议而不是覆盖** ——
  僵尸走不了那条道（走路的被塞进泳池）时照旧按普通规则发牌，所以 `rowFor` 的"按能不能走筛一遍"
  被提成 `usableLanes`，两条路共用。
- **"这里没有钉耙"要说出来**：以前 `rows: []` 让 `place` 直接 return，一个包都不发；现在仍然发一次
  `State(x, row = -1, spent)`，因为客户端无论如何都有一个 overlay，而"没有"与"没说"不该长得一样。
- **发出去的是解析后的机制表**：`LevelMechanics.payloads(List<TypedMechanic>)` 是新的一半，
  `LevelServer.sendFullState` 用它发**自己正在跑的那张表**。`payloadFor(def, seeds)` 保留给关卡列表 ——
  那张表是预览，钉耙的行是关卡创建时掷的，预告没有意义。**"服务端在跑什么"与"文件里写了什么"
  从这一刻起在下发路径上第一次分开**：以后再加"玩家带来的机制"（紫卡、节奏关）不会重犯这个错。
- **沙盒世界也有钉耙**：`PlayerProfile.ownsRake()` = `unlockAll || unlocked.contains(RAKE)`。
  以前直接问 `unlocked()` 集合，于是"全部解锁"的沙盒世界是唯一一个永远见不到钉耙的世界。
- **三个关卡明确说不要**：1-5（保龄球）、2-5（打地鼠）、4-5（恐怖花瓶）各写一条
  `{"type":"pvzce:rake","rows":[]}`。这三关里"免费杀一只"都不是这一关的意思，而
  "关卡声明了就由关卡说了算"这条三态语义正好用来表达它。
- **冒烟多一个钩子**：`pvzce.smokeSetup=<命令>`，在**开局请求之前**发控制台命令。
  `smokeCommands` 要等关卡起来才发，而"这个世界拥有什么"是关卡创建时读一次的，
  所以拍"有钉耙的棋盘"以前根本拍不到。发送顺序有保证：命令走服务端命令队列（每帧开头清空），
  开局请求走包连接（同一帧稍后清空），不会倒过来。

### 验到了什么

- `RakeTest`（13 例）：位置、1800 打不死巨人、水里不铺、第一只僵尸走钉耙那行、
  用过就不再指挥出怪、存档往返、`level init` 里真的有 `pvzce:rake`、没买的玩家没有、
  沙盒有、三个关卡声明 `rows: []` 时没有。
- 一次冒烟胶片（`.smoke/rake/s_*.png`，160 帧 / 每 15 帧一张，`smokeSetup=profile+unlockall`）：
  第 25 帧钉耙躺在第 7 列、第 40 帧第一只僵尸正好走到它脚下、第 55 帧僵尸中钉（powie + 头飞出去，
  原版的分尸表现）而钉耙消失、第 100 帧第二只僵尸踏着同一条道走进来。

## W2 · 编辑器图标、数据包文件夹、结算页的物品简介

### 现象与根因

1. **编辑器三个调色板全是品红/黑格子**：植物 41 行、僵尸 36 行、卡池 44 行。两处叠加——
   `PaletteList` 先问 `AnimationManager.iconTexture(id)`，而它拼的是 `animations/<id.path()>.json`
   （内置内容全在 `animations/<animation_dir>/<leaf>.json`，根目录下**零个** JSON），于是永远落空；
   兜底的 `EntityArt.sprite(id)` 给出的是**部件目录**（`textures/entities/plant/attacker/pea_shooter`
   是一堆零件 PNG），`TextureManager` 找不到文件就画缺失贴图那一格。两处都不报错。
2. `AnimationManager.iconTexture` 是**从上线那天起的死代码**（唯一的调用者就是调色板），
   而 `docs/架构-客户端.md` 一直写着它有效——文档与代码各说各话。
3. 数据包页只有"启用/停用"和"重新加载"，**没有打开文件夹**：想手改一个包得自己去猜
   `<gameDir>/datapacks/`。全仓库唯一的系统集成是模组列表里的 `Desktop.browse(URL)`。
4. 结算页的羊皮纸写的是 `金币 +{0}` / `金币总数：{0}`，与"这一页讲的是带走了什么"相反；
   而且 `LevelRewardS2C` 是**三个单值字段**（一个解锁 / 一个增益 / 一个物品），
   一次通关发两张卡时第二张照发不显示。

### 定论

- **一行图标是三种东西之一**：`PaletteList.Item.Icon` 是 `Texture` | `Rig` | 空（画色块）。
  判据只有一处——`EntityArt.animationFile(id) != null` 就是骨架，交给新的
  `components/EntityPreview`（把活骨架画进小方框的**有界**缓存，最多 24 具，在**绘制路径**上
  启播而不是等 `tick()`：预览是第一帧才建的，那一帧的 tick 已经过去了，图鉴当年就是这么让
  "每张僵尸卡都是空的"）。编辑器三页各持一个池，`onClosed` 里 `releasePreviews()`。
- **卡面行不走这条路**：卡池页改问 `CardPainter.icon(cardId)`——卡槽条与地上的种子包问的同一个答案。
  48 个卡槽里 44 个画的是一张与实体美术无关的卡面，问实体链必然问错人。
- **`AnimationManager.iconTexture` 删掉**（死代码），`docs/架构-客户端.md` 里那段"优先取动画资源"
  的说明重写成了上面这条。
- **守门测试 `EditorIconTest`**：每个卡槽的图标都指向真的存在的 PNG；每个植物/僵尸都以**骨架**
  形态到达调色板；并且断言植物声明的那张"贴图"确实不是一个文件。这三条正是当年该拦住它的东西。
- **数据包页多一个"打开文件夹"**：`client/gui/OSFolder` 是"把路径交给桌面"的唯一实现
  （先试 `Desktop.open`，失败退到 `xdg-open` / `open` / `explorer`；headless 与精简 Linux 上 AWT 会直接抛，
  所以两条路都要）。内置包没有目录、按钮说一句而不是打开别处；启动失败在页面上报一行。
- **奖励包从三个单值字段改成一张 `grants` 列表**（`CARD` / `BUFF` / `ITEM`，顺序即页面绘制顺序）：
  `headline()` 取表头 = "这一局最大的新闻"，相框与草地上掉的东西都用它；`hasUnlock()` /
  `unlockedCard()` / `unlockedBuff()` / `hasRewardItem()` 这些旧问题全部**由表头回答**，
  所以 `InGameScreen` 与掉落表现一行没改。协议 36 → 37。
- **结算页的正文变成"你拿到了什么"**：每样东西一行名字 + 它自己的 `.desc`（图鉴里那句话，不另写一份），
  金币降成页脚一行。放不下时按"**名字优先于句子**"贪心填，剩下的写成"还有 N 件"而不是截断。
  两个锚点：正文从美术的 `NOTE_TOP` 往下排，金币行锚在 `NOTE_BOTTOM` 与「继续」按钮上沿的**较高者**
  （按钮是这一页唯一必须按得到的东西，而 4:3 底图被 16:9 窗口上下裁过）。`Screen.CoverFit` 为此补了
  两个逆映射（`textureX` / `textureY`），免得调用点自己再写一遍 cover-fit 公式。
- **增益有了自己的 `.desc`**（5 条，中英各一份）：结算页要"简介"，而增益此前只有名字。
- **冒烟多一个钩子**：`pvzce.smokeEditorPages=<帧>:<页>,…`，一次启动拍多个编辑器页
  （与 `smokeAlmanacShots` 同一形状）。`pvzce.smokeScreen=award` 的合成奖励也换成"一卡 + 一增益 + 一物品"，
  否则新页面的列表、简介与金币降级一条都拍不到。

### 验到了什么

- `EditorIconTest`（3 例）全绿；全量 1177 例只有 `DocStatsTest`（统计块，按规矩由测试写回）。
- 一次 1080p+gui_scale=2（参考环境）的胶片：
  - `.smoke/w2/s_70.png` / `s_120.png` / `s_170.png`：植物调色板、僵尸调色板、卡池页画的全是**真美术**
    （僵尸那一页出现一个没有语言键的 id 回退，是 `.smoke/gd` 里遗留的测试数据包带来的自定义僵尸，不是缺陷）。
  - `.smoke/w2/s_270.png`：数据包页三个按钮——始终启用 / **打开文件夹** / 重新加载。
  - `.smoke/w2/f_120.png`：结算页一次发三件——「获得新植物！」+ 向日葵 + 它的一句简介 + 自动拾取 +
    「还有 1 件」+ 降级后的金币行。
  - `.smoke/w2/f_220.png`：纯金币那一支，三行全部落在羊皮纸里。

# 十三条美术/玩法缺陷：逐条定位到"哪一层说错了"

> 用户一次报上来十三条。它们的共同点是**每一条都能追到一个说错了的地方**，而不是十三处
> 画得不好——所以这一轮的做法是先把每一条定位到"数值/机制/素材里的哪一处是错的"，再改那一处。

## 现象与根因（按报告顺序）

1. **撑杆/海豚的落地位置与实际位置不符** —— `VaultCapability` 用自己发明的
   `AIRBORNE_FROM/TO` 缓动把位移摊在窗口上，而美术画的是另一条曲线（脚从帧 13 抬起到帧 36 落下）。
   两条曲线在落地时差**半格**。另外僵尸自己的 `height` 一直是 0，所以美术收起的腿被画在
   地面线以下。
2. **商店点击无效** —— `ShopScreen` 把购买写在 `onMouseClicked` 里，而
   `AbstractSelectionList.mouseClicked` 会吃掉点击并只调它自己的回调。行点击因此完全没反应。
3. **倭瓜会被啃掉 / 只压一只** —— `SquashCapability` 是单目标，且没有 `walk_over` 标签。
   用户拍板"可啃，但是激活时无敌"，于是改成 `invulnerable()` 在 `look/fuse/linger` 三态为真。
4. **三线射手头不跟着动 / 三发分开** —— 导出器把每根骨头都挂在 root 上，而动画里三个头的位置
   是"静态"的：原版靠 `anim_head1/2/3` 控制轨移动它们，转换器看不到没有图的轨。另
   `plants/threepeater.json` 三个 entry 的 `initial_delay` 是 0/30/60。
5. **坚果被啃后外观不变** —— `Wallnut_cracked1/2.png`、`Tallnut_cracked1/2.png` 不被任何轨
   引用，转换器不会发现它们；引擎那时也**没有**"按血量换植物贴图"这条路。
6. **传送带关卡没有铲子** —— 六个传送带的 `slots` 全是 `[]`，而 `BeltCardSource.rebuildBar`
   会把玩家的非植物卡留在带子右侧。校验器却禁止"传送带 + 任何 slots"。
7. **火爆辣椒用樱桃炸弹的特效** —— `ExplosiveCapability` 的默认粒子是 `EXPLOSION_POW`；
   原版那趟火是 `refer/anim/fire.reanim`，没转过。
8. **冰车该被地刺扎毁 / 要有破损 / 爆炸动画错** —— `ZamboniCapability` 无差别压碎格里所有植物；
   `Zombie_zamboni_1_damage1/2.png` 与 `ZamboniExplosion{,2}.xml` 的五个发射器都没接。
9. **高坚果体积不对** —— `tall_nut` 与 `wall_nut` 共用 `PLANT_BOX`，146px 的身体被塞进 0.76 格。
10. **雪橇没被显示** —— `Zombie_bobsled.reanim` 里只有骑手，`refer/` 全库没有那块板子。
11. **工具花瓶用了花盆贴图** —— `tools/vase.json` 写着 `gui/cards/flower_pot`，
    `make_vase_tool_anim.py` 就是照花盆控制器生成的。
12. **花瓶大小错误** —— `scene/vase.png` 是项目自画占位，比例不是原版那只。
13. **阳光铲贴图错误** —— `gui/buff/sun_shovel.png` 是一张 1254² 的写实插画，风格与游戏无关。

## 定论

1. **跳跃僵尸按美术自己的曲线走**：`VaultCapability` 的 `VAULT_TRAVEL_KEYS` / `VAULT_LIFT_KEYS`
   由新工具 `tools/vault_curve.py` 从**转换后**的 `jump` 片段里读出来（躯干管水平、最低的脚管
   抬升），`DEFAULT_JUMP_DISTANCE` 改成实测的 1.0908 格，`advanceVault` 同时写 `cellX` 与
   `height`。pogo 没有水平位移，继续用缓动。`PoleVaultTest` 新增一例把两张表钉在片段上。
2. **商店是"选中 + 购买按钮"**：行点击走 `setOnRowClick`（列表先吃点击是既定规则），右侧
   1/3 是详情栏，购买按钮钉在面板内右下角（`MenuPageCanvas.Canvas.widgetAtInterior`）。
3. **倭瓜激活即无敌，落地压整格**：`land()` 按落地格筛 `enemiesInRow` 逐个 `crush`。
4. **导出器支持真实的父子骨**（`EntityConfig.bone_parents`）：子骨的键被改写成宿主空间，
   模型里声明 `parent`。三线射手三个头分别挂 `stem_1/2/3`；`initial_delay` 全改 0。
5. **植物按血量换图**：新 `client/renderer/PlantDamageArt`（`BoneArt` 的第二种实现，与
   `EquipmentArt` 并列），认模型里 `cracked_N` 这一族，按原版的三等分选；两个坚果的
   `damage_states` 在导出器里声明。`AnimationManager` 现在按 kind 分派两种 override。
6. **传送带的工具/资源跟着带子**：五个传送带关卡的 `slots` 加 `pvzce:shovel`；
   `ConveyorMechanic.validate` 从"不许有任何 slots"改成"不许有**植物**卡"。
7. **辣椒是整行火**：新粒子 `pvzce:jalapeno_fire`（`tools/gen_jalapeno_fire.py` 从
   `fire.reanim` 的 12 帧切出），`ExplosiveCapability` 对 `Trigger.ROW` 逐格发一条。
8. **冰车被地刺扎毁 + 破损 + 原版爆炸**：`ZamboniCapability.tickMovement` 见到
   `#c:walk_over` 的植物就同归于尽；`damage_states` 接上两张破损图（经 `equipment` 的
   健康驱动族）；死亡发 `PvzceParticles.ZAMBONI_WRECK` 五件套。
9. **高坚果按自己的比例**：`target_box` 换成按绘制框换算的 (0.623743, 1.093202)。
10. **雪橇是同一模型里的新骨头**：导出器新增 `EntityConfig.extra_bones`（宿主键 + 自己的
    贴图 + 模型空间的 y 偏移），板子只在 `walk` 片段 `force_visible`；美术是新画的
    （`tools/gen_bobsled_sled.py`），因为原版那张**不在 refer 里**。
