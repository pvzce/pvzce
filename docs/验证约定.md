# 验证约定（按需，不是每轮全量）

> 这份文件是**验证强度**的唯一出处。其它文档（`00` 的导航、`01`/`02`/`03` 的阶段验收、
> `关卡机制与拼装式编辑器-设计方案` 的推进方式、`当前项目架构.md` §9）只指向这里，不再各写一份。
> 冒烟钩子本身（`pvzce.smoke*` 的完整参数表、坑与典型组合）在 `冒烟与截图指南.md`。

---

## 1. 一句话

**默认不跑全量、不拍截图。** 一轮改动验到什么程度由改动面决定，没有硬性分级，也没有
"每轮必须测试全绿 + 截图冒烟"的约定。判断留给人（或 agent），在交付说明里写清跑了什么即可。

| 改动面 | 跑什么 | 代价 |
|---|---|---|
| 纯函数 / 数据 / Codec / JSON / 工具类 | 相关测试类：`./gradlew :pvzce-game:test --tests "com.pvzce.<包>.*"` | 数秒 |
| 服务端逻辑 / 网络 / 存档 / 关卡加载 | `./gradlew :pvzce-game:test`（全量单测） | 约 20s |
| 界面 / 渲染 / 动画 / 输入 | 上面 + **一次**截图冒烟（`-Ppvzce.smoke=…`，一次一个画面） | 一次约 12s |
| 发版 / 跨模块重构 | 全量 + 一份覆盖主要画面的冒烟清单 | — |

没有"必须"的一档：改一行常量不必跑全量，改一处界面也不必把每个屏幕都拍一遍。
**入口只用 Gradle 原生 `--tests`**（不额外包 task、不写脚本）。

---

## 2. 用例的增删判据

- **加**：只有**修掉了一个真 bug** 才给它加回归用例。已有不变量覆盖的行为不重复加；
  "顺手补一个也更保险"不是理由。
- **删 / 合**：与别的用例重叠、只锁实现细节、或断言同义反复的用例可以直接合并或删除；
  删之前先给出清单（谁被谁覆盖），不要静默删。
- **不记数**：文档不再写"测试全绿（N 例）"。例数不是指标，也不作为验收条件：
  它只会让每一轮都倾向于"再加几个用例"而不是"改对"。
- **偶发失败必须当成缺陷处理**：要么改成确定性断言，要么删掉，不允许留着"单独跑必过"的用例 ——
  那会让"全绿"这个信号本身失效。

## 3. 界面为什么是"按需"而不是"每轮"

`@PvzceGametest` 注册式集成测试与离屏 FBO 图 diff **都还没建**（规划见 `03-第三阶段` §3.6.1），
所以界面目前**没有自动化验证**，只能截图人工核对。这正是"按需"的原因：

- 单测能断言的（控件树、屏幕栈、客户端发了哪个包）**用单测，不要拍图** ——
  `Screen.dispatchMouseClicked` + `Connection.createMemoryPair()` 就是为这条路留的口子。
- 只有"画面对不对"这一类问题才拍图，并且一次只拍要看的那个画面。
- 拍图时**务必带 `-Ppvzce.gameDir=<临时目录>`**，否则会写进真正的游戏目录（见冒烟指南 §2.2）。

## 4. 文档维护

- **as-built 文档只写现状**：`当前项目架构.md` 与 `UI切换与导航架构.md` 描述"现在是什么样"，
  不写"以前是什么样"。历史（现象 → 定论）放 `架构变更记录.md`，正文里不再出现「曾经…」。
- **一个事实只写一处**：能被别处指过去的内容（如冒烟参数表）不在两份文档里各维护一份 ——
  两份就会漂移，改一次要改两处，这正是文档回写变贵的来源。
- **改动没有传遍所有文档的义务**：只有该文档描述的行为真的变了才改它。
  规划文档（`01`/`02`/`03`）记录的是路线，不随每次实现同步回写。
